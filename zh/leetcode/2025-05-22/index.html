3362. Zero Array Transformation III 的解法
2025年5月22日 · 1 分钟

Today’s problem#

https://leetcode.com/problems/zero-array-transformation-iii/

Intuition#

这个问题要求我们找到“有用”的 section 的数量，或者换句话说，是使数组变为 zero array 所需的最少 section 数量。

解决这个问题的关键是改变看待问题的方式：如果我们单独看待数组中的每个元素，那么我们可以使用 greedy algorithm 来解决这个问题。

问题在于，如果我们单独看待每个元素，即为了使整个数组成为 zero array，我们必须使每个元素都变为零。

在这种情况下，对于每个元素，最好的方法是找到一个包含该元素的 section，同时它具有更远的 tail。这是因为更远的 tail 意味着在未来可以覆盖更多的元素，与具有较短 tail 的 section 相比，这总是更好的。

因此，现在我们需要一个数据结构来存储当前的“最远 tail”。这个数据结构需要动态添加元素并删除最大的项，此时使用 heap 将是存储 “tail” 的最佳方式。

Approach#

因此，我们可以构建我们的算法。

  1. 首先，我们需要使用 query 的左端点作为关键字对数组进行排序。在这种情况下，我们可以找到哪些 query 的左端点位于我们当前 index 的左侧。
  2. 然后，我们需要创建一个 difference array 来处理 section 的加法操作；一个 heap 来存储 query 的右端点；以及一个 index 来显示我们在遍历所有 query 时的当前位置。
  3. 下一步是遍历数字数组：对于数字数组中的每个元素，我们首先需要将所有左端点小于当前 index 的 query 推入。这使得 heap 中的所有元素都可能被用来减少当前元素。
  4. 然后我们将处理当前元素，找到当前元素所有可用的 query，然后处理 section 的减法操作。（在这种情况下，我们通过检查 heap 顶部的终点是否大于或等于当前 index 来确保每个操作都是有效的，从而使数组的左端点小于或等于当前 index，且数组的右端点大于或等于当前 index。因此，我们保证了操作的有效性）。
  5. 最后，如果数字仍然大于 0，我们将返回 -1；否则，我们将返回 h 中剩余的元素，即所有未使用的元素。

Complexity#

  • Time complexity:

O(N×log(m))O(N \times log(m))

  • Space complexity:

O(N+M)O(N + M)

Code#

class Solution:
    def maxRemoval(self, nums: List[int], queries: List[List[int]]) -> int:
        queries.sort(key = lambda x: x[0])
        diff = [0] * (len(nums) + 1)
        h = []
        idx, now = 0,0

        for i in range(len(nums)):
            while idx < len(queries) and queries[idx][0] <= i:
                heappush(h, -queries[idx][1])
                idx += 1
            
            now += diff[i]

            while h and now < nums[i] and -h[0] >= i:
                now += 1
                diff[-heappop(h) + 1] -= 1

            if now < nums[i]:
                return -1
            
        return len(h)
