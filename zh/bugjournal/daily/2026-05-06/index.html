问题与解决方案#

关键问题#

1. FloatBall 无法显示 codex/cursor 速率限制利用率，尽管主窗口能正确显示#

解决方案： 从 primary_window_utilization 中移除 is_window_expired() 过滤机制，将逻辑从选择主窗口 ID 改为选择所有窗口中利用率最高的窗口，无论类型或过期状态如何，同步前端使用 Math.max() 策略。

关键洞察： 托盘逻辑中的过期窗口宽限期过滤对空闲会话过于激进；FloatBall 应始终显示最关键的限制（最高利用率），以便让用户意识到最紧急的约束问题。

2. 仓库结构混乱，包含约 90+ 个脚本，其中许多是特定 GPU 或实验的一次性特殊情况#

解决方案： 按流水线阶段和用途系统地对脚本进行分类，删除了约 40 种冗余变体（特定 GPU 的启动器、一次性调试脚本、SLURM 包装器），仅保留定义可复现流水线的核心入口脚本。

关键洞察： 研究代码库随时间积累大量实验脚本；公开发布需要积极精简，只保留能定义可复现基准的规范执行路径。

3. 论文提到“每帧阶段标签”但未解释其来源和必要性#

解决方案： 人类质疑其来源，发现如果 can_inject() 直接使用物理状态条件，则可能不需要阶段标签，避免声称未实现的功能。

关键洞察： 学术论文中的每个技术术语都需要明确定义和实现验证，以避免审稿人提问；在跨章节传播依赖关系前，需确认其实际是否被使用。

4. 实施两阶段进度反馈后 SSH 同步耗时过长#

解决方案： 通过移除独立测试阶段来消除重复的 SSH 连接；sync_ssh_host 已包含内部连接测试，因此单遍迭代配合逐步 UI 更新可实现相同的用户体验，而无需额外性能开销。

关键洞察： 过于激进的优化可能引入新的瓶颈。在添加包装逻辑之前，务必先检查下游函数是否已提供所需功能。

5. AI修改了错误的文件（将 neurips_2026_zgl.tex 替换成了 neurips_2026_tzj.tex），导致约 30 次编辑需要完全回退。**解决方案：**通过将填充值恢复为占位符来手动回退所有更改，然后在明确目标后重新应用编辑以修正文件#

**关键洞察：**在批量编辑之前必须明确确认文件目标；缺乏git仓库使得回退工作繁琐且易出错

6. RBG C/D/E的图3阶段覆盖情况与表2的注入阶段合并不一致#

**解决方案：**详细对照显示C缺少pre_reach/pre_grasp，D错误包含了pre_reach，E缺少reach/pre_grasp/grasp/lift阶段

**关键洞察：**必须从详细表格中自动生成可视化总结，以避免手绘不一致；图表和表格必须保持严格的双向一致性

7. 用户创建的v3版本将BibTeX更改回手动参考文献格式#

**解决方案：**解释了差异并提供重新应用BibTeX格式的建议，但尊重用户在起草阶段保留手动格式的选择

**关键洞察：**作者在协作起草过程中可能出于工作流程原因偏好手动参考文献（更易于分享，无需BibTeX工具链依赖，合并更简单）；正式化可以等到最终提交时进行

8. 对仓库结构存在不确定性（本地3部分重组与服务器单一目录结构）#

**解决方案：**用户决定使用服务器的权威结构（error_benchmark/单一目录），从服务器重新同步以放弃本地重组工作

**关键洞察：**当存在多个版本时，在投入修改之前需明确哪个是权威版本；避免未经确认真实来源就进行推测性重构

一般问题#

9. Windows上无法使用rsync命令从Linux服务器同步文件#

**解决方案：**使用ssh + tar管道：ssh tianhe ’tar cf - –exclude=pattern files’ | tar xf -实现带有排除模式的选择性文件传输

**关键洞察：**Windows缺乏许多Linux工具，但ssh + tar可提供类似的远程文件同步功能及选择性排除

10. 在重新同步后尝试重新添加子模块时出现“子模块已存在于索引”错误#

**解决方案：**使用git rm -rf –cached清除缓存条目，删除 .git/modules/shared目录，然后干净地重新添加子模块

**关键洞察：**Git子模块状态同时记录在索引和 .git/modules/中；两者都需要清理才能重新开始

11. 复杂的正则表达式在grep搜索LaTeX引用命令时失败#

**解决方案：**简化为基本模式’\cite{’，而不是尝试用转义大括号捕获组

**关键洞察：**ripgrep (rg)的正则表达式语法与标准grep不同——更简单的模式在LaTeX转义场景中更可靠

AI 局限性#

关键局限性#

  • 未质疑论文中“阶段标签”的来源或必要性，导致多个章节和图表中出现了可能未实现的功能，未针对代码库进行验证

  • 最初接受“扩展 MimicGen 并添加 X”的表述，未意识到这是过度承诺，因为并未修改算法，仅改变了应用场景

经验教训#

关键经验#

  • 过期窗口过滤的速率限制应属于展示层问题（UI 下划线/颜色），而非数据层过滤；在源端进行过滤会剥夺用户查看完整状态并做出明智决策的能力
  • 当 UI 显示多窗口数据中的单一值（FloatBall 条）时，选择最大利用率比任意窗口选择提供更好的用户体验，因为它能突出最关键的约束条件
  • NeurIPS 2026 将“数据集与基准”赛道更名为“评估与数据集”（E&D）赛道，并新增强制要求 Croissant 元数据（JSON-LD 格式）描述数据集结构和 RAI 字段
  • 学术论文写作要求主张与实现现实严格一致；如“扩展”、“提出”、“新颖”等术语带有特定的证明责任预期，从而区分应用与贡献
  • 双盲投稿匿名化不仅需检查作者姓名，还需检查：路径中的用户名（pytest 输出）、硬编码的服务器路径、机构名称（缩写和全名）以及任何暴露地理身份的语言
  • 为发表而清理研究代码需区分：（1）定义可复现流程的核心入口脚本；（2）特定硬件的便捷包装器；（3）一次性实验脚本——仅第 1 类应被发表
  • 在填充模板数据时，始终验证交叉引用：如果图 X 声称显示 Y，需机械验证 Y 在图 X 中呈现且值正确；视觉总结必须从详细表格中获取
  • 学术论文流程在起草阶段通常偏好更简单的引用管理——手动参考文献允许更容易协作，无需 BibTeX 工具链依赖；正式化可待最终投稿时进行
  • 版本比较能揭示用户意图：当用户独立回退更改时，表明是偏好或约束而非疏忽——应询问理由以理解工作流程需求
  • 对于复杂数据驱动论文，维护单一真实数据文件（如 per_subtype_results.csv）可确保所有章节中的表格、图表和叙述一致
  • Tauri IPC 命令暴露后端数据结构（StatusWidgetSummary）造成紧密耦合；改变“主要”含义需协调后端+前端更改及全面测试更新

实际经验#

  • Git 子模块状态保存在三个地方：.gitmodules（配置）、.git/modules/（仓库数据）和工作树（checkout）；冲突需清理所有三个位置
  • 引用研究流程：对于机器人学/机器学习论文，arXiv ID 是最可靠的标识符；会议论文可能比预印本发布晚数月
  • Windows 没有 rsync，但 ssh + tar pipe 可实现类似功能：ssh 远程执行“tar cf - –exclude=pattern files” | tar xf - 可提供带排除项的选择性传输
