Problems & Solutions#

Critical Issues#

1. TokenMonitor 的 model classification 和 pricing lookup 紧密耦合。#

Solution: 实现了 normalized model key (usage tracking) 与 pricing key (cost calculation) 之间的分离。

2. ‘Visual Memory Harness’ 的 storyline 面临被视为现有方法简单组合的风险。#

Solution: 通过分析代码来识别并突出特定的 mechanistic differences，例如 phase-based visual prompting。

3. 学术 API rate limits (Google Scholar/OpenAlex) 以及 author disambiguation 错误。#

Solution: 实施了使用 Crossref, arXiv 以及通过唯一标识符 (DOI/IDs) 直接 scraping 官方大学/lab 网站的多源 fallback 策略。

4. 数据完整性问题，包括 preprint 与正式 publication 的混淆，以及 textbook 被误认为 research papers。#

Solution: 对非研究类项目应用了显式的 exclusion rules，并维护了一个独立的 ‘audit-only’ 文件以保持原始 dataset 的完整性。

5. Browser automation 因涉及 URL verification 的安全策略而中断。#

Solution: 记录了失败情况，并准备通过人工干预来导航至受保护的课程页面。

AI Limitations#

Critical Limitations#

  • Browser automation 受限于安全策略，如果当前 URL 无法获得高置信度的验证，则无法继续执行。

General Limitations#

  • 在学术搜索引擎上频繁遇到 API rate limits (HTTP 429/403)，阻碍了完整的实时自动化检索。
  • 难以通过纯粹的公开网络数据验证诸如 ’lab pressure’ 或 ‘mentoring culture’ 等主观定性指标。
  • 在没有高级权限访问专有学术数据库的情况下，automated scraping 中的 author disambiguation 容易出错。

Learnings#

Key Learnings#

  • 准确的学术审计需要区分 preprint release dates、DOI registration 和正式 publication dates，以避免数据污染。
  • 为了防御针对“简单组合”的 research contribution 质疑，必须记录特定的、代码层面的 mechanistic differences。
  • 针对可变计费的系统架构必须将 usage-grouping keys 与 cost-lookup keys 解耦，以支持不同的 service tiers。
  • 多层验证策略 (Crossref $\rightarrow$ arXiv $\rightarrow$ Official Sites) 对于克服大规模学术审计中的 rate limits 至关重要。
