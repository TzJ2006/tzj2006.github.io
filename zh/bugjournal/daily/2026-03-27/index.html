问题与解决方案#

关键问题#

1. 由于 SetWindowPos IPC 调用与 CSS 重排周期之间的 1 帧延迟，footer 和应用程序底部边缘在窗口缩放时持续移动。#

解决方案： 将 footer 移出动态 flex 容器，应用 position: fixed; bottom: 0 以绕过布局队列。通过 JS 预设置 #app min-height，然后在发送 IPC 命令前实现 DOM 与原生同步，从而填补延迟差距。

关键洞察： 原生 C API 窗口管理与 WebView2/CSS 之间的跨栈帧延迟无法完全通过 Flexbox 或 CSS 过渡来补偿；绝对视口锚定和预布局同步是实现像素级稳定的必要条件。

2. 窗口底部边缘在高度变化后向上跳动，在 Windows 系统下有时会低于任务栏区域。#

解决方案： 将锚定检测从固定阈值改为直接间隙比较（top_gap <= bottom_gap），使用当前矩形边界而非工作区域限制修正底部锚点 Y 值计算，并更新了跨平台的限制逻辑。

关键洞察： 边缘锚定必须动态跟踪最近的物理边界，而不是依赖静态像素阈值；限制应保留初始位置，仅在跨越安全区域时进行干预。

一般问题#

3. 图表悬停细节面板在条状变化期间出现闪烁和跳动，这是由于 DOM 销毁/重建和定时器竞争条件导致的。#

解决方案： 将淡出时间从 500ms 缩短至 150ms，移除 {#key} 触发块以保持 DOM 元素完整，合并两阶段隐藏流程，并添加布局测量效果的边界保护机制。

关键洞察： Svelte 的关键块强制完全销毁组件；在更新反应式属性时保持 DOM 节点存活，可避免快速状态变化时的视觉重复。

学习心得#

关键学习点#

  • 当原生窗口管理 API（如 Win32 SetWindowPos）和网页渲染以异步方式运行时，为了保证视觉稳定性，需要绝对固定视口锚点，或在通过 IPC 调用之前在 JavaScript 侧预先测量并应用尺寸。
  • 使用 position: fixed 可以完全绕过与父容器动画相关的 CSS 布局重排队列，是动态主机尺寸变化期间稳定 UI 元素的最可靠方法。

实际学习点#

  • 以假设为驱动的调试工作流通过强制并行调查和强制记录证据，显著减少了确认偏差。
