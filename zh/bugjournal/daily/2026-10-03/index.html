Daily Report — 2026-10-03#

Daily Overview#

  • 完成工作： 在 16 个 RoboMME 任务中评估了 OmniJev visual-only robotic memory arm，并针对高难度任务中 GPT-6 Astra 与 Gemini 3.1 Pro 的 visual prompt 生成质量进行了对比实验。
  • 实施方式： 为 OmniJev 实现了一个 ‘chat shim’ 和 wrist-camera proprioception，并开发了一套配对的 offline replay 和 online closed-loop testing 框架，使用相同的视频序列来对比 Astra 和 Gemini。
  • 影响： 证明了通过 structured state machines，轻量级的 2B 模型可以达到与 Gemini 相当的性能，并发现了一个显著的性能差距：Astra 在 spatial/temporal reasoning 和 target identity tracking 方面优于 Gemini。

评估了 OmniJev visual-only arm，其达到了 77.5% 的成功率，并进行了 GPT-6 Astra 与 Gemini 3.1 Pro 之间的对比测试，发现 Astra 在 long-term object identity tracking 和 visual prompting 方面具有优势。

Architecture & Strategy#

  • ✅ OmniJev Protocol Implementation — 构建了一个 chat shim，将 Gemini protocol calls 转换为受限的 OmniJev 问题类型（yes/no, multiple choice），并实现了一个独立的 evaluation directory。
  • ✅ Closed-loop Evaluation — 在 tianhe3 上使用 visual-only arm 对 16 个任务进行了完整的 closed-loop evaluations，总成功率为 124/160。

  • ✅ Wrist-Camera Proprioception Integration (I-173) — 在 BinFill, PickXtimes, 和 InsertPeg 任务中，将 high-level proprioceptive data 替换为 wrist-camera visual readings，包括将 BOARD_R threshold 调整为 60px 以适应 visual noise。

  • ✅ Infrastructure Setup and API Debugging — 开发了 astra_route_pilot.py, 并将其与 tianhe3 集成，解决了 API 参数不匹配（max_tokens vs max_completion_tokens）以及 LiteLLM proxy 限制的问题。
  • ✅ Optimization of Patch Embeddings — 将缓慢的 bf16 conv3d patch embedding 替换为等效的 linear layer，将每张图像的 latency 从 16s 降低到 0.06ms。

Problems & Solutions#

Critical Issues#

1. OmniJev 无法进行 long-term temporal reasoning (VideoPlace/Repick)。#

Solution: 将 temporal sequencing 和 event retrieval 逻辑从 VLM 转移到了基于 code 的 state machine（即 ‘Memory’ 部分）。

General Issues#

2. BinFill 任务在 closed-loop 中由于 wrist-camera pose error (visual noise) 而失败。#

Solution: 根据在 training set 中观察到的最大误差，将 BOARD_R threshold 从 40px 增加到 60px。

3. API 兼容性和 proxy 错误：参数名称不匹配（max_tokens vs max_completion_tokens）以及 Astra 模型不支持 ‘reasoning_effort’。#

Solution: 对 compare_eval_entry.py 进行了 patch 以正确映射参数，并应用了 ‘allowed_openai_params’ flag，通过 LiteLLM proxy 允许使用 reasoning 参数。

4. 尝试向 Duke EGR LiteLLM proxy 发送 demonstration images 时触发了自动安全拦截。#

Solution: 通过 secure prompt 请求用户明确授权以继续实验。

AI Limitations#

General Limitations#

  • 未能识别出单张 snapshot 的 side-by-side comparison 是不够的，忽略了对 progressive (video-based) visual prompts 的需求。
  • 最初未能定位 OmniJev 的工作，因为它存储在之前 session 的 scratchpad 中，而不是主 repository。
  • 提议评估 RouteStick/PatternLock，这在测试 deep memory 方面不如 VideoRepick 有效。

Learnings#

Key Learnings#

  • 如果 ‘memory’ (sequence/counting) 由 structured state machine 和 visual prompts 处理，那么轻量级的 2B 模型对于 perception tasks 是足够的。
  • GPT-6 Astra 在一系列动作之后（例如 VideoPlaceButton）‘记住’ target 方面显示出比 Gemini 3.1 Pro 显著的优势，而 Gemini 往往会丢失特定的 object identity。
  • 在 expert demonstrations (training set) 上优化的 rules 在 policy rollout 期间经常由于 visual appearance 的 distribution shift 而失败。
  • Visual prompt quality (circles/badges) 可以通过 matched-replay videos 独立于 policy success 进行评估，从而实现将模型的 ‘writing’ 能力与 ‘driving’ 能力分离。
