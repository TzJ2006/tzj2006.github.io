Problems & Solutions#

Critical Issues#

1. 初始论文叙述包含“自我削弱”的语言和面向过程的描述，降低了结果的价值。#

Solution: 应用 Press-Release Principle 重新构建结果框架，将弱点转化为讨论点，并将叙述重点放在赢得特定的 evaluation dimensions 上。

2. W4A8 evaluation 结果在报告中显示出微小的统计差异。#

Solution: 部署了使用多个 agents 的 adversarial verification workflow，从原始 episode files 中重新推导所有 claims 和 p-values。

3. Non-paused Gemini calls 中的高 latency 导致 protocol breakdown 和任务 skipping。#

Solution: 确定需要 continuous/streaming logic 或更高频率的 planning，以避免当 TTR 超过 polling interval 时发生 step-skipping。

General Issues#

4. 大量堆积的 orphaned processes 和过时的 model copies 导致系统臃肿。#

Solution: 手动清理了 processes，更新了 tunnel script 以 kill child sleep processes，并清理了 /tmp files。

5. Minecraft server logs 显示 client disconnects，但没有 server-side errors。#

Solution: 分析了 debug logs，确定问题出在 client-side（OOM 或 mod mismatch）而非 server-side。

Human vs AI Approaches#

Strategic Level#

Paper Writing Strategy#

Role Approach
Human 将 ‘Press-Release Principle’ 定义为论文叙述结构的严格 meta-rule。
AI 使用该原则系统地审计现有 storyline，识别并分类了 15 个具体的防御性或非战略性写作实例。

Difference Analysis: Human 提供了战略哲学/约束，而 AI 执行了将该哲学应用于文本的具体细粒度操作。

Experimental Validation#

Role Approach
Human 设计了隔离变量（如 latency）的 protocols，并要求验证特定的 statistical claims。
AI 自动化了 parallel tasks 的启动，并创建了复杂的 multi-agent adversarial workflows 来数学化地重新推导 p-values。

Difference Analysis: Human 指导了实验逻辑和资源管理，而 AI 从一个 reporter 转变为主动的 ‘adversarial’ verifier，以确保数学严谨性。

AI Limitations#

General Limitations#

  • AI 最初未能考虑到 A2 ‘constraint removal’ 的全部范围（它仅识别了 ‘preflight check’ 的移除），需要人类纠正以包含基于 code 的 positioning 和 tracking。
  • 执行速度和渲染 charts 的能力取决于外部因素，如 cluster node load 和缺失的 system dependencies (playwright, cairosvg)。

Learnings#

Key Learnings#

  • 当叙述围绕单一最强优势展开，而非按时间顺序列出任务时，论文最为有效。
  • 在 LIBERO-PRO 上进行 W4A8 quantization 会导致约 1.6 点的性能下降，主要影响 object replacement 和 paraphrased instructions。
  • 增加 model ’thinking intensity’ 并不一定能弥补几何复杂任务中的性能差距，这强化了对 hard-coded constraints 的需求。
  • Zero-shot 4B models 在 temporal sequencing (‘what happened’) 方面表现出色，但在 continuous state/contact detection (‘is it still happening’) 方面较为吃力。
