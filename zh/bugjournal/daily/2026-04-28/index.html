问题与解决方案#

关键问题#

1. 当悬停在图表条上时，细节面板扩展导致窗口调整，使窗口底部从任务栏偏移#

解决方案： 引入 SCROLL_THRESHOLD_CAP = 500 常量；修改 resolveScrollThresholdHeight 以返回基于比例计算的最小值和阈值；内容现在在固定高度的窗口内滚动，而非调整大小

关键洞察： 用户指定的固定阈值（500px）可在所有显示器尺寸下提供可预测的行为，而现有的滚动机制处理溢出情况；基于比例的方法（0.75 * 工作区域）在较大显示器上过于宽松

2. 初始 v0.12.1 发布未能通过 cargo fmt 和 clippy 的 CI 检查#

解决方案： 对 window.rs 应用 cargo fmt 以修复导入顺序和行宽限制；删除 config.rs 中的不必要的 return 语句；删除旧标签并重新发布以修复问题

关键洞察： 预发布本地验证应包含完整的 CI 检查套件（fmt、带有 -D 警告的 clippy），以避免标签变更；rustfmt 和 clippy 规则在 CI 流水线中是不可妥协的

一般问题#

3. 编辑工具在尝试更新版本号时出现“文件尚未读取”错误#

解决方案： 在编辑前读取所有三个版本文件（package.json、Cargo.toml、tauri.conf.json）；工具在写入前需要读取操作

关键洞察： Claude Code Edit 工具有严格的“读取后写入”要求；工作流程应为：读取 → 编辑，而不是直接编辑

AI 限制#

关键限制#

  • 在初始发布标签前没有主动进行本地 cargo fmt/clippy 检查，导致 CI 失败和标签变更

一般限制#

  • 试图编辑文件而不先读取，违反工具要求；必须在编辑前通过读取操作重试
  • DesktopLinux 上认证失败（“您的组织无法访问 Claude”），但未提供任何故障排除建议

经验教训#

关键经验#

  • 预发布验证必须在本地包含完整的 CI 检查套件；cargo fmt –check 和 cargo clippy – -D 警告可防止标签变更并保持干净的发布历史
  • 硬编码的 UI 阈值比基于比例的计算更可预测，适用于跨设备一致性；500px 限制确保 1080p、1440p 和 4K 显示器下行为一致
  • 公共发布的 git 标签管理需要删除/重建流程（git tag -d、git push –delete、重新打标签、推送），而不是 force-push 或 amend 以保持完整性

实际经验#

  • MCP 工具（mcp__hex-line__edit_file）和标准编辑工具有不同的读取要求；MCP 工具在读取操作中接受 edit_ready 标志，以简化工作流程
