问题与解决方案#

关键问题#

1. AI Companion 工作流因绝对路径注入导致不同克隆版本的可移植性受损。并行 AI 代理工作流遇到了 API 速率限制（429 错误）。#

解决方案： 提出混合架构：将供应商第一级工具作为相对路径，将重负载引擎外部化。将并行 LLM 分发改为受速率限制的顺序后台工作流。

关键洞察： 绝对路径破坏了可移植性；大规模并行 LLM 使用需要严格的速率限制和人工提供的真实数据，以恢复“幻影”项目中的分析质量。

2. “编辑前规范”保护器与现有 ECL（DEC-004/001）在绝对路径和自授权风险方面存在冲突（BF-03）。#

解决方案： 分析了威胁模型：自动化的预编辑保护器不能依赖 AI 生成的状态。实现了一种设计，其中钩子阻止 Claude 编辑，git 预提交锚定验证人类意图。

关键洞察： 自动化保护器必须基于不可变信号（git 历史）而非内部标志，以缓解自授权攻击。

3. QueST 作业因 UnboundLocalError 失败：在 benchmark_rm_ideal.py 中在赋值前使用了‘sections’。HD Slurm 作业停滞超过 24 小时。#

解决方案： 将变量赋值移动到合适的作用域并重新运行作业。通过变体脚本将不可用的 a6000 GPU 更换为可用的 gc500Ada 卡。

关键洞察： Python 变量作用域要求严格的顺序预赋值；如果严格请求特定硬件类型但不可用，异构 GPU 分区可能导致死锁。

学习成果#

关键学习点#

  • MIHD 的 StaigFusionTrainer 在默认路径下与原始 STAIG 几乎相同；差异源于 n_clusters 源代码差异，而非架构问题。将 AI Companion 的管道与 gadget 的可移植安装方式合并可以解决核心冲突。
  • 要使 TypeScript CLI 工具可移植，必须依赖供应商依赖或采用 npx 式解析方式。对于大型 Python 仓库，/cconboard 分阶段方法非常有效，但如果工作树脏，则需要执行预置测试。
  • 对于“编辑前规范”门控，自我授权攻击（BF-03）是真实存在的；门控必须依赖外部状态（git/ask），而非内部标志。异构 GPU 分区需要精确的节点状态诊断，以避免队列停滞。
