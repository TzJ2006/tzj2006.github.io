问题与解决方案#

关键问题#

1. E2E 训练刚性及自适应边缘丢弃机制不匹配导致跨模态性能下降#

解决方案： 用明确的预处理路由（自动/标准/裁剪/无）替代硬编码的 gene_encoder 约束，调整边缘权重方向以强制跨域惩罚梯度。

关键洞察： 灵活的输入嵌入接受与精确的丢弃掩码相结合对于确保对齐而非域内相似性捕获至关重要。

2. LeRobot-HuggingFace 数据集库不兼容导致 parquet 元数据 TypeError#

解决方案： 将 huggingface/datasets 依赖项锁定在 4.0 版本以下，以恢复与 LeRobot v0.1.0 张量栈的兼容性。

关键洞察： 核心数据库中的 API 变更会无声地破坏模式验证；框架迁移期间严格的环境锁定是必须的。

3. 密集自监督相似度矩阵中的数值溢出导致训练分歧#

解决方案： 应用 L2 归一化并结合 LogSumExp 稳定化，强制使用 float64 计算以防止 softmax 操作中的指数饱和。

关键洞察： 高温度下的 float32 余弦相似度矩阵会迅速饱和；在梯度下降初始化前需进行数学稳定处理。

4. 集群资源死锁、EGL/CUDA 映射不匹配及硬依赖阻塞#

解决方案： 从 SSH 直接执行转向标准 srun/sbatch 队列，将 MuJoCo 物理设备 ID与 CUDA 虚拟环境对齐，为网络下载实现动态回退路由。

关键洞察： 硬件抽象层必须手动同步；强制使用标准调度器接口比策略调整更可靠地解决权限死锁问题。

一般问题#

5. 基础模型 VLA OOM 限制、端口绑定冲突及基线延迟计算错误#

解决方案： 降低批量尺寸，分配更大的 GPU 层级，实施预启动端口扫描，根据经验性的健康推理速度重新调整评估节奏。

关键洞察： 不同场景下的基础模型成功差异决定了实际吞吐量；动态资源分配和真实延迟分析必须取代静态估计。

学习成果#

关键学习点#

  • 基础模型的性能上限：纯视觉编码器在细粒度空间分层方面固有停滞，缺乏自监督约束或多模态融合；任务与特征不匹配是架构特性而非实现缺陷。
  • 核心算法机制：自适应边缘丢弃通过惩罚过度依赖高置信度内部边缘来强制跨模态对齐，而 OpenPI 的自动 JAX 分片能透明处理多 GPU 扩展。

实用学习点#

  • 工程与基础设施最佳实践：框架迁移需要严格的依赖固定（例如 LeRobot 的数据集版本 <4.0），重型 CLI 工具需要防御性参数验证以防止上下文漂移，战略文档需要在增量补丁基础上定期重构结构。
