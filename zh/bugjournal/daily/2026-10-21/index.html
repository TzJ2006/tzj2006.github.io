Problems & Solutions#

Critical Issues#

1. Ground truth leakage and system ‘cheating’ via environment state access.#

Solution: 部署 prediction_boundary.py 以将可见性限制在 camera-only 数据，并拦截 ground truth subgoals。

2. Scientific invalidity due to test-set contamination or parameter tuning on test splits.#

Solution: 进行了回顾性审计，在正式的 ledger 中记录了 tuning 实例，并更新了 launchers 以严格强制执行 ‘val’ split 的使用。

3. AI model hallucination of pending tasks from negative facts (e.g., ’not published’ becoming a task).#

Solution: 更新了 canonical system prompt，通过明确的 negative constraints 禁止从动作的缺失中推导意图。

4. Data corruption in .npz/trajectory files resulting in truncated image streams.#

Solution: 提取完整的 state data，并生成带有清晰标签的 re-rendered image 补充内容，在不修改原始数值 payload 的情况下保持数据来源的完整性。

5. Discrepancy in rendering methods (GPU vs. Software) between main systems and historical baselines.#

Solution: 将历史结果归类为仅供 diagnostic 使用，并强制执行严格的新 GPU-only comparison protocol。

6. Extreme disk space pressure and redundancy in summarization logic.#

Solution: 对数据进行分类以进行迁移/清理，并将单一的 ‘gadget’ repository 指定为逻辑的 source of truth。

7. Risk of results invalidation through silent reuse of stale or mismatched planner caches.#

Solution: 实施了 cache provenance 机制，要求 cache 与当前的 input/model/code state 严格匹配。

8. Inconsistencies in academic metadata regarding author order, publication years, and identity.#

Solution: 使用个人 faculty homepages、institutional affiliations 和 Google Scholar IDs 作为主要锚点进行 cross-validation。

General Issues#

9. API rate limiting (429/403 errors) and access restrictions from academic databases.#

Solution: 转为多源策略，使用 OpenAlex、official homepages 和 search engine snippets 作为 fallback。

10. TokenMonitor UI refactor caused budget and price information to be hidden.#

Solution: 将 forecast、confidence 和 budget 详情整合进一个信息密集型的 single tooltip 中。

AI Limitations#

Critical Limitations#

  • 逻辑幻觉，模型将负面状态误解为待处理任务。
  • 无法从损坏的压缩流中重建原始像素；只能通过重新渲染来生成衍生图像。

General Limitations#

  • 难以获取主观指标（如 ’lab pressure’ 或 ‘admission difficulty’）的可靠定量数据。
  • 遇到数据检索障碍，包括来自学术数据库的速率限制（429 errors）和访问限制（403 Forbidden）。
  • 仅通过 web scraping 难以区分 ‘official research line’ 和 ‘current active research’。
  • AI 对推荐行的 UI refactor 导致了回归问题，隐藏了现有的 budget/price 数据。
  • AI 默认采用一种防御性且自我削弱的写作风格，不适合高影响力的学术提交。
  • AI 最初犹豫是否宣布审计完成，将固有的证据缺口标记为 ‘unresolved’。
  • 无法直接编辑或合并到远程 repositories (GitHub/Hugging Face)，必须采用基于 staged/PR 的工作流。

Learnings#

Key Learnings#

  • 对于顶级出版物而言，系统级的集成叙述（例如 ‘Visual Memory Harness’）比关注孤立的组件改进更具鲁棒性。
  • ‘Press-Release Principle’——专注于优势并避免过程导向的描述——是一种强大的学术写作方法论。
  • Benchmark 对比中的科学完整性要求在 rendering engines 上保持严格的一致性，并明确披露特定任务的 priors。
  • 在未经身份验证且隔离的环境中验证 releases 对于保证真正的可复现性至关重要。
  • 为了防止任务幻觉，canonical prompts 必须明确说明负面状态不是请求或待处理任务。
  • 一个具有模块化、可验证能力的 ’thin’ 核心比一个庞大的、单体式的编排系统更稳定且更容易调试。
  • 直接将大型数据集提交到 Git history 中会导致 .git 文件夹膨胀至数十 GB。
  • Rust/Cargo 的 ’target’ 目录是可重建的，可以安全清除以缓解存储压力。
  • 在处理损坏的数据集成员时，提供一个排除清单（exclusion manifest）和修正后的候选对象，比默默删除数据更好。
  • 实现基于 fingerprint 的 caching 可将相同 summary 请求的冗余模型调用从几秒钟减少到毫秒级。
  • 使用 ‘audit file’ 方法记录差异而不是直接修改原始文件，可以保留数据来源（data provenance）。
  • 通过使用明确标记的伴随文件来维护衍生数据的统计计数，优于修改原始 payloads。
  • 集成个人主页和替代候选对象等多样化数据源，能显著提高自动文献验证的效果。
  • 将 caches 与 input digests 进行严格的加密/逻辑绑定，对于保证缓存计划的来源至关重要。
  • 机构计算资源的可用性（例如 shared clusters）比未经证实的资金更能可靠地反映课题组资源。
