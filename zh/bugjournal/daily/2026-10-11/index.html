Problems & Solutions#

Critical Issues#

1. 优化 PhD outreach emails 以兼顾专业性和影响力。#

Solution: 从通用的介绍重构为 ‘gap-filling’ 策略：将用户的研究（failure recovery）与教授的工作（prediction/expectation models）联系起来，作为一种必要的扩展。

Key Insight: 最有效的 hook 是识别现有研究 (Y) 如何可以被扩展以解决新的 gap (Z)。

2. JEV 在动态任务（VideoRepick, MoveCube, Route/Pattern）中的性能差距。#

Solution: 提出 ’timer-driven segment’ 和 ’timer-based drawing changes’，以在没有连续 judge loops 的情况下模拟/维持 visual feedback。

Key Insight: 一个 ’non-paused’ agent 的成功高度敏感于 visual feedback (drawing) 的时机和频率。

3. 为 PhD applications 连接不同的研究方向（Biomedicine vs. Robotics）。#

Solution: 通过 ‘Computer Vision Foundation Models’ 和 ‘Sequence Data’（RNA vs. robotic time-series）来构建转型框架，以展示方法论的演进。

Key Insight: 学术转型最好被呈现为方法论的演进，而不是兴趣的改变。

4. tianhe3 上的数据传输超时和资源竞争。#

Solution: 在 rclone 中禁用了逐文件的 remote MD5 checks 以提高速度，并实施了严格的基于 VRAM 的预留规则（保持 4 个 GPU 空闲且 VRAM >=40GB），以遵守 cluster 礼仪。

Key Insight: 在高延迟的 SSH 环境中，批量 manifest 验证比逐文件完整性检查更高效。

5. PersonalAgents WeChat VM 崩溃和 blog 部署失败。#

Solution: 在 UI 操作之前实现了执行意图（execution intent）的 atomic persistence，并使用严格的 build flags 分离了 preview/public build directories。

Key Insight: 意图必须在不可逆的 UI 操作之前进行持久化，以应对潜在的系统崩溃。

6. Quantization 精度损失和部署调试。#

Solution: 将 quantized operators 对比 FP16 进行追踪以定位错误；确认 operator approximation error 是可以忽略不计的 (<=0.003)，从而将错误归因重点放在 quantization (A/B) 上。

Key Insight: 系统性的逐 operator 错误分析对于区分 approximation errors 和 quantization errors 至关重要。

AI Limitations#

Critical Limitations#

  • 在没有用户明确更新的情况下，AI 无法验证 ‘under review’ 论文的当前状态或实时的发表数量。
  • 当前实验中的 ‘one call’ 限制阻止了在高度多变的速率任务中使用高频 model feedback。

General Limitations- AI 可能会使用过于谨慎的学术措辞，从而稀释研究影响力，或在草稿中错误地反转比较方向。#

  • AI 无法加速 physical compute jobs，也无法访问缺少特定命令（如 ss）的 remote systems。

Learnings#

Key Learnings#

  • 有效的研究陈述必须从“我做了什么”（结果）过渡到“我意识到了什么”（差距），再到“我将解决什么”（未来方向）。
  • ‘Plan-once + JEV’ 架构由其信息可用性约束来定义，这确立了其独特的研究范围。
  • 系统级错误（例如 feature-cache drift）经常被误认为是 policy failures。

Practical Learnings#

  • 在 multi-tenant GPU 环境中，基于 VRAM 的预留通常比简单的 GPU 数量对于成功运行更为关键。
