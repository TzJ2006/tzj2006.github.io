Problems & Solutions#

Critical Issues#

1. 集成后观察到 Pi0.5 model output variances。#

Solution: 诊断结果为 JAX compilation cache 中的 XLA GPU autotuner (Triton GEMM) 非确定性，而非代码 regression。

2. draft approvals 中的并发问题导致重复的 calendar events。#

Solution: 重构了 approval flow，在最终确定已批准的 draft 之前，先将旧的 drafts 标记为 ‘rejected’ 并推送其更改。

3. LifeCopilot 集成存在在 auto-restarts 期间破坏 WeChat connectivity 的风险。#

Solution: 实现了严格的 variable isolation，对 HTTP calls 使用了 asyncio.to_thread，并确保了 pre-deployment compilation。

4. TokenMonitor 无法读取新的 OpenAI GPTdot 功能的 usage。#

Solution: 使用 chat IDs 对 local Codex app-server API 进行探测，尝试进行 thread-specific usage retrieval。

5. Critic agent 发现 F1, G1, 和 B7 reports 之间存在差异。#

Solution: 发起了后续的 fixup workflows，以协调 retraining run list 并将 demo audit 正确链接到下游 trackers。

6. 由于编码不匹配，非-ASCII credentials 在 Bearer authentication 期间失败。#

Solution: 对 tokens 实现了 byte-level comparison，并确保 validator 在启动时拒绝非-ASCII secrets。

7. Workflow execution error: advisor audit 中的 writer-agent stage 失败，导致文件截断。#

Solution: 开发并运行了一个自定义 Python script，从原始 workflow journal logs 中重建特定学校的 evidence files。

8. 在 idle-shutdown 期间可能误将 EC2 终止 (termination) 而非停止 (stop)。#

Solution: 实现了一个 safety check mechanism，并在 AWS Console 中提供了明确的警告。

9. Benchmark 的 operator kit 存在 bug，导致 self-tests 和 human recordings 共享同一个目录。#

Solution: 开发了一个 patch，将 self-test outputs 与 human-recorded demonstrations 分离。

General Issues#

10. CV/application 文件中技术数量错误（136 vs 24 error subtypes）。Solution: 在整个 repository 中执行了全局搜索和替换以确保一致性。#

11. MIHD N-03 configuration 错误地将 UCE 列为 ‘blocker’。#

Solution: 采用了“大胆且主动”的策略，使用影响力驱动的动词，并将关键结果置于 bullet points 的开头。

13. Uvicorn startup 未能返回特定的 exit codes 或优雅地处理 Ctrl+C。#

Solution: 将 uvicorn server 执行封装在 try-except block 中，以捕获 startup errors 并管理 signals。

14. 由于资源争用，在 evaluation 期间发生 GPU OOM。#

Solution: 手动将 libero_10 suite 迁移到 GPU 2，以避免与 GPU 0 上的 libero_goal 发生冲突。

15. 在 Hyper-V ‘Enhanced Session Mode’ 中，关闭窗口会锁定桌面，影响 UI automation。#

Solution: 在关闭前切换到 ‘Basic Session’，或者简单地最小化窗口以保持桌面处于活动状态。

Human vs AI Approaches#

Strategic Level#

Role Approach
Human 提出将复合连续错误分解为特定的、细粒度的原子 ‘Error Skills’。
AI 将此识别为将工作与现有方法区分开来的关键战略设计决策。

Difference Analysis: Human 提供了研究直觉；AI 为高影响力写作进行了框架构建。

Error Definition Implementation#

Role Approach
Human 定义了特定的物理阈值（例如：真实碰撞 vs. gripper-object contact，预期运动 vs. pause）。
AI 尝试将这些实现为 code-level changes 和 automated verifiers。

Difference Analysis: Human 提供了概念上的物理严谨性，而 AI 必须将其转化为程序逻辑。

Project Architecture: WeChat as a Port#

Role Approach
Human 提出使用现有的 WeAgent (AstrBot plugin) 作为 LifeCopilot 的无缝第三通道。
AI 研究 AstrBot 的内部 plugin registration 和 toolset management，以支持用户的愿景。

Difference Analysis: Human 驱动了战略方向，而 AI 提供了技术可行性研究。

GR00T Model Observation#

AI 将其综合为假设：’error-after-state’ 与 ‘arbitrary starting state’ 是不同的。

Difference Analysis: Human 提供经验性的细微差别；AI 将其转化为学术逻辑。

Minecraft Server Control Strategy#

Difference Analysis: Human 关注用户体验；AI 关注安全性与成本架构。

AI 通过高影响力动词，从保守的方法转向战略性的“大胆”。

Difference Analysis: Human 提供了心理学方向；AI 将其转化为写作策略。

AI Limitations#

Critical Limitations#

  • 在没有显式 global synchronization 的情况下，难以协调 cross-agent 数据的一致性。
  • 在复杂的多 agent workflow 中，automated file writing 阶段失败，需要从 logs 中进行手动重建。

General Limitations#

  • AI 最初尝试写入外部 repository (WeAgent)，这被 project guardrails 拦截。
  • 无法直接防止 physics engine crashes 或 hardware-level OOMs，但可以反应性地重新调度任务。
  • 由于触及 API/rate limits 导致 Agent workflow 失败。
  • 由于环境限制，难以执行多命令 bash strings；需要手动进行分解。
  • 最初在 CV 建议中未能区分 ‘accuracy’ 与 ‘methodological impact’。

Learnings#

Key Learnings#

  • 在处理多通道系统时，身份验证必须区分人类用户和自动化 agents，以实现 scoped access。
  • 在移动文件之前，使用只读的 ‘Scout-and-Design’ workflow 进行项目重构会更安全。
  • 可靠的 robot learning 必须区分 ‘arbitrary starting state’ 与 ‘state following an execution error’。
  • 鲁棒的 error definitions 需要区分微小的物理变化与有意义的任务状态退化。
  • 在将外部 APIs 集成到 reactive bot 时，严格的身份验证（使用 wxid）对于安全性至关重要。
  • 对于个人 Pro accounts，标准 APIs 可能会针对 thread-specific data 返回 null，需要进行本地 CLI probing。
  • GPU kernel autotuning 可能会引入细微的数值差异，从而模拟出 code regressions。

Practical Learnings#

  • 必须显式地将 TMPDIR 设置为 /home 上的目录，以避免在 QuantSim ONNX exports 期间填满 / 分区。
  • Hyper-V ‘Enhanced Session’ 本质上是 RDP（关闭即锁定）；‘Basic Session’ 则保持桌面运行。
