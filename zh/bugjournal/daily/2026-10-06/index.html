Critical Issues#

1. 报告中的 claims 与原始 JSON 之间的差异 (例如 K/V cache medians, opcheck frame counts)#

Solution: 使用对抗性的 ‘Sonnet checker’ 重新推导了报告中的每一个数字。修正了所有 24 处发现的问题。

Learnings#

Key Learnings#

  • 接触密集型 robotic tasks（如 coffee pod insertion）对跨平台 floating-point 差异高度敏感，即使起始状态相同，也会导致指数级的 divergence。
  • 约束 VLM 行为（从 ‘reporting coordinates’ 转变为 ‘making selections’）能显著提高 robotic manipulation 的任务成功率。
  • 即使文件已从 working directory 中删除，Git history 仍是一个主要的 leak vector；.gitignore 仅能防止未来的 commits。
  • 即使在受控环境中，由于 GPU 操作中的 floating-point non-determinism，相同的 noise seeds 也无法保证 bit-identical rollouts（已通过 ‘dupagree’ check 确认）。
  • 使用 harness 时 ‘counting’ 的成功率可能会较低，因为瓶颈在于 policy 的 action response，而非 memory accuracy（如 Oracle 与 Harness 之间的差异所示）。

Practical Learnings#

  • WeChat 的表情包收集上限约为 999 个，且原生不支持 WebP 格式的表情包。
  • 图像模型中的 patch-size 不匹配（504 vs 256）必须在 notebook metadata 中明确记录，以防止与标准 training protocols 混淆。
  • 图像 interpolation/resizing 的微小差异可能会显著改变低 margin 任务（如 ‘holding’ (PickXtimes)）的 AUROC。
  • Visual prompts 本身不能取代文本，但可以在无需结构性更改或更长输入的情况下实现 policy 的使用。
