Problems & Solutions#

Critical Issues#

1. Advisor 担心由于不同任务使用不同问题，导致方法看起来像是 ‘handcrafted’。#

Solution: 开发了一个统一的 formalism，其中每个 task 都是在 grounded point 提取的 (Glyph, Predicate, Anchor) 三元组。

Key Insight: 不同的 task behaviors 只是从 closed library 中选择了不同的参数 (statement, region, view)，并应用于同一个 unified loop。

2. DLPFC ‘gene-only’ arms 在 mclust runs 期间静默回退到 KMeans，导致比较失效。#

Solution: 在 seed_matrix pipeline 中添加了专门的 ‘kmeans’ cluster_backend mode，以产生明确匹配的 controls。

3. Cloud models (Astra/Claude) 验证失败，因为为了防止 file access 而禁用了 Codex call entry。#

Solution: 实现了一个专门的、隔离的 Codex call implementation，在路由之前显式剥离所有 tools 和 file access。

4. JEV latency (Version B) 在 SwingXtimes 和 ButtonUnmaskSwap 等对时间敏感的任务中导致了显著的性能下降。#

Solution: 确定性能下降是由于 visual feedback 的延迟（约 26 steps）而非模型的 reasoning quality 造成的；发现 ’non-pausing’ advantage 仅在 latency 低于 ~0.5s 时才成立。

Key Insight: 只有当 JEV latency 保持在 ~0.5s 以下时，’non-pausing’ advantage 才成立；较大的延迟会导致 policy 超过目标值。

5. 会议摘要包含数值差异并夸大了结论（例如，在结果仅为 7/8 时声称其对“所有”情况都成立）。#

Solution: 部署了一个 adversarial verification workflow (agent harness) 来根据 CSV 数据检查每一个数字，然后手动修正了草案。

6. 自动发送失败，因为 WeChat 输入框名称被附加了 IME (Input Method Editor) 状态文本。#

Solution: 修改了逻辑，在保持严格的 contact name 验证的同时，剥离了 IME 输入状态字符串。

7. 尽管收到了文本，但 assistant 未能响应群聊中的 @ mentions。#

Solution: 发现 WeChat 元数据是经过 Zstandard 压缩的，并更新了 parser 以正确解压并提取 mention list。

8. Semantic Scholar API rate limiting (HTTP 429) 导致无法检索所有论文的完整 abstract。#

Solution: 实现了一种使用 OpenAlex 和 arXiv 的 fallback mechanism，以找回缺失条目的 abstracts。

9. 由于发送过程中的 UI focus 转移或窗口激活，agent 错误地识别了 contact 变更。#

Solution: 实现了 input box reuse logic，以防止对 UI element 进行重复的重新定位和重新搜索。

General Limitations#

  • AI 尝试通过简单的 UTF-8 decoding 来验证文本内容，未能考虑到 WeChat data stream 中的 Zstandard 压缩。
  • 无法在 Artifact 环境中直接测试交互式 JavaScript 功能（Save/Draft buttons）。
  • AI 未能识别出 27B model 在 StopCube 上的表现受限于 cube 与 target 之间的颜色相似性，需要人工引导进行 rule refinement。
  • AI 最初未能检测到 ‘df.gt’ 是一个 method call 而不是列访问，导致了 runtime TypeError。
  • AI 最初未能识别出 ‘Astra’ model 的错误是由于 routing/isolation 配置引起的，而非 subscription/login 问题。

Learnings#

Key Learnings#

  • 一个用于 CVPR 的统一 system story 应该强调：特定任务的 protocols 是 generalized formalism (Plan + Pointer) 的 emergent properties。
  • Fusion method 的排名（例如 NCL vs Concat）可能会根据使用的 clustering algorithm 而波动；单一的 clusterer 对于稳健的 benchmarking 是不够的。
  • NCL 相对于 gene-only methods 的性能提升源于 spatial topology，而非视觉特征本身，这一点从 image-shuffled trials 中缺乏显著性得到了证实。
  • 有效的 model isolation 需要一种 ‘Provider-mediated’ 架构，由 application 处理工具执行，并仅将 text/result 反馈给 model。
  • 为大规模数据集扩展数据检索需要稳健的多源 fallback 策略 (Semantic Scholar -> OpenAlex -> arXiv) 以应对 API rate limits。
  • WeChat 中的 UI automation 对 IME status 的变化高度敏感，这可能会意外改变 element names/attributes。
