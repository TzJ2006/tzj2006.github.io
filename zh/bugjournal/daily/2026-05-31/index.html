问题与解决方案#

关键问题#

1. Claude Code 因环境变量冲突（CLAUDE_CODE_USE_BEDROCK=1 仍存在于会话历史中）以及缺失 CLAUDE_CODE_USE_ANTHROPIC_AWS 标志而拒绝更换提供方。#

解决方案： 通过环境检查确定具体的变量冲突，移除 Bedrock 覆盖项，将 AWS 平台标志添加到 settings.json 中，并通过验证脚本强制重新启动。

关键洞察： 持久性 shell 配置文件中的环境变量可以覆盖 JSON 配置文件；配置更改需立即生效需进行明确的会话清除。

一般问题#

2. Git 在部署过程中忽略了简历 PDF/DOCX 文件，因为它们属于 .gitignore 中的通配符模式（website/static/pdfs/）。#

解决方案： 修改 .gitignore 以排除该目录，但使用否定模式 (!filename) 明确列出特定简历文件，然后重新构建并提交。

关键洞察： Git 的忽略规则是递归应用的；除非在忽略规则中使用通配符模式（/*），否则目录级别的忽略无法覆盖文件级别的否定。

3. 从父目录调用时工作目录上下文错误导致 deployment script update.ps1 失败，引发 config.yml 路径解析错误。#

解决方案： 在 PowerShell 命令中明确设置位置为特定网站项目根目录，再执行脚本。

关键洞察： 依赖相对路径的 Shell 脚本非常脆弱；从不同目录调度时需明确设置上下文。

学习成果#

关键学习点#

  • 迁移基于云的 LLM 提供方时，始终检查当前 shell 会话中的冲突环境变量（Env：变量），因为它们优先于 JSON 设置文件。
  • Git 的 .gitignore 通配符模式（例如，folder/）阻止否定模式 (!file) 对文件夹内的单个文件生效；使用特定文件模式或目录特定的忽略来解决问题。

实际学习点#

  • 自动化部署脚本常因工作目录不一致而失败；在人工智能辅助的工作流程中，运行构建/工具脚本前务必确保明确的目录变更。
