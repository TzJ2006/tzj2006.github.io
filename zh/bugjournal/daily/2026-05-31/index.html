问题与解决方案#

关键问题#

1. Claude Code 因环境变量冲突（CLAUDE_CODE_USE_BEDROCK=1 仍存在于会话历史中）以及缺失 CLAUDE_CODE_USE_ANTHROPIC_AWS 标志而拒绝更换提供方。#

**解决方案：**通过环境检查识别具体的变量冲突，移除 Bedrock 覆盖项，将 AWS 平台标志添加到 settings.json 中，并通过验证脚本强制重启。

**关键洞察：**持久性 shell 配置中的环境变量可以覆盖 JSON 配置文件；需要显式清除会话才能使配置更改立即生效。

一般问题#

2. Git 在部署过程中忽略了简历 PDF/DOCX 文件，因为这些文件属于 .gitignore 中的通配符规则范围（website/static/pdfs/）。#

**解决方案：**修改 .gitignore 以排除该目录，但使用否定模式 (!filename) 明确允许特定简历文件，然后重新构建并提交。

**关键洞察：**Git 的忽略规则是递归应用的；除非在忽略规则中使用通配符（/*），否则目录级别的忽略无法覆盖文件级别的否定。

3. 从父目录调用时工作目录上下文错误导致 deployment script update.ps1 失败，引发 config.yml 路径解析错误。#

**解决方案：**将执行封装在 PowerShell 命令中，明确设置位置为特定网站项目根目录后再调用脚本。

**关键洞察：**依赖相对路径的 shell 脚本非常脆弱；从不同目录协调运行时必须明确设置上下文。
