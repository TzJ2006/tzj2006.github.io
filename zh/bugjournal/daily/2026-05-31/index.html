Problems & Solutions#

Critical Issues#

1. Claude Code 由于存在冲突的 environment variables (session history 中仍处于激活状态的 CLAUDE_CODE_USE_BEDROCK=1) 以及缺失 CLAUDE_CODE_USE_ANTHROPIC_AWS flag 而拒绝切换 provider。#

Solution: 通过 env inspection 识别了具体的变量冲突，移除了 Bedrock 的覆盖项，在 settings.json 中添加了 Platform on AWS flag，并使用验证脚本强制进行了 clean restart。

Key Insight: 持久化 shell profiles 中的 environment variables 可能会覆盖 JSON 配置文件；若要使配置更改立即生效，需要进行显式的 session clearing。

General Issues#

2. Git 在部署期间忽略了简历 PDF/DOCX 文件，因为它们属于 .gitignore 中的宽泛通配符模式 (website/static/pdfs/)。#

Solution: 修改了 .gitignore 以排除该目录，但使用取反模式 (!filename) 显式地将特定的简历文件列入白名单，然后重新进行 re-staged 和 commit。

Key Insight: Git 的 ignore rules 是递归应用的；目录级忽略会掩盖文件级的取反操作，除非在 ignore rule 本身中使用通配符模式 (/*)。

3. 由于从父目录调用时 working directory context 不正确，导致 deployment script update.ps1 失败，从而引起 config.yml 的路径解析错误。#

Solution: 将执行封装在一个 PowerShell 命令中，在调用脚本之前显式地将 location 设置为特定的 website 项目根目录。

Key Insight: 依赖相对路径的 shell scripts 是脆弱的；在从不同目录编排它们时，显式的 context setting 是必要的。

Learnings#

Key Learnings#

  • 在迁移基于云的 LLM providers 时，务必检查当前 shell session 中的冲突 environment variables (Env: variables)，因为它们的优先级高于 JSON settings files。
  • Git 的 .gitignore wildcard patterns (例如 folder/) 会阻止 negation (!file) 在该文件夹内的单个文件上生效；请使用特定的文件模式或目录特定的忽略来解决此问题。

Practical Learnings#

  • 自动化 deployment scripts 经常因为 cwd mismatches 而失败；在 AI-assisted workflow 中运行 build/utility scripts 之前，务必确保显式的 directory changes。
