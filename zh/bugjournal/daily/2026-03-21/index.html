问题与解决方案#

关键问题#

1. 从 Python 子进程调用时 npx @ccusage/codex@latest 无限挂起#

解决方案： 在 npx 调用中添加 –yes 标志，避免子进程.run(capture_output=True)因无 stdin 而无法回答的 ‘Ok to proceed? (y)’ 交互式提示

关键洞察： 使用 capture_output=True 的 subprocess.run 没有 stdin，因此任何交互式提示都会无限挂起；在自动化脚本中始终使用 –yes 或 -y 标志用于包管理器

2. 尽管每日导出收集了数据，月度摘要未能汇总或显示 Codex 令牌使用情况#

解决方案： 在 aggregate_token_usage() 中添加单独的 codex_token_usage 汇总路径，创建 combine_usage_summaries() 用于合并概览，更新 format_monthly_markdown() 以渲染 Codex 部分

关键洞察： 当向聚合管道添加新数据源时，不仅需要更新输入解析，还需要更新聚合逻辑、LLM 输入清洗（去除机械字段）和输出格式

一般问题#

3. Windows Path().parent 产生的反斜杠会破坏 rclone 远程路径（例如 ‘gdrive:gadget/website\personal’）#

解决方案： 使用 Path.as_posix() 将 Windows 路径转换为正斜杠，用于 rclone 远程路径构建

关键洞察： rclone 远程路径在 Windows 上必须使用正斜杠；在构建远程 URI 时，路径操作需要显式的 .as_posix() 转换

4. PowerShell 执行策略阻止 .ps1 包装器用于 npx 和 codex 命令#

解决方案： 建议立即使用 .cmd 包装器（npx.cmd、codex.cmd）作为临时解决方案，并使用 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned 作为永久修复方案

关键洞察： 在 Windows 上，npm 安装会同时生成 .cmd 和 .ps1 包装器；当 PowerShell 执行策略受限时，.cmd 包装器可通用使用，而 .ps1 需要策略修改

5. 从本地更改后从远程拉取时 Git 合并冲突#

解决方案： 使用 git stash，git pull，然后通过接受上游版本（–theirs）并丢弃 stash 解决剩余冲突

关键洞察： 在本地清理后与远程同步时，如果本地更改应被丢弃，接受远程版本并通过 –theirs 是比手动解决冲突更简洁的方式

学习成果#

关键学习点#

  • subprocess.run 中设置 capture_output=True 没有 stdin——任何交互式提示都会无限卡住；在自动化过程中，对于包管理器和 CLI 工具，始终使用 –yes/–non-interactive 标志
  • 在将新数据源添加到聚合管道时，必须更新：(1) 输入收集，(2) 聚合逻辑，(3) LLM 输入清理（从提示中移除新字段），(4) 输出渲染——缺少任何一步都会导致数据无声丢失
  • Windows 路径对象生成反斜杠；在构建需要正斜杠的 URI 或远程路径时（如 rclone、URL、Unix 路径），必须明确使用 Path.as_posix() 以确保跨平台兼容
  • Claude Code (ECC) 插件架构的所有部分：5 层形成闭环——技能（被动知识）→代理（专业推理）→命令（面向用户）→钩子（自动化触发）→持续学习（反馈捕获）→技能

实际学习点#

  • 在具有限制性 PowerShell 执行策略的 Windows 系统上，npm 安装的命令都有 .ps1（被阻止）和 .cmd（可运行）包装器；.cmd 是通用替代方案
  • ECC 的 effortLevel 有 4 个层级：低/中/高/最大；“最大”是最近更新的新功能，可启用最大的思考令牌数（31999）和最深入推理
