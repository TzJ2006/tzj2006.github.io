问题与解决方案#

关键问题#

1. 各章节独立的 PCA/STAIG 训练导致无法比较的嵌入空间，使得跨章节检索失败（命中率 14-29%）#

解决方案： 使用基础模型（scGPT 基因 FM、UNI2 视觉 FM），这些模型对所有章节应用相同的预训练权重，从而产生可比较的嵌入。scGPT 的命中率为 100%，平均 SL@50=0.416

关键洞察： 零样本跨章节检索需要共享嵌入空间；联合 PCA/Procrustes 或联合训练都违反了零样本约束，因为它们需要同时使用两个章节的数据。只有预训练的基础模型才能提供真正的零样本能力。用户立即意识到这一约束，避免了在不可行方案上浪费精力

2. 学术数据库名称歧义处理失败——多个同名研究人员被合并到同一个个人资料中，论文列表跨越 5-6 个不相关的领域，内容混乱（影响约 30% 的分析研究人员）#

解决方案： 在 trajectory_summary 字段中添加明确的警告机制，标记 h-index/引用数量差异和领域不一致情况；建议在分析前通过语义相似性、机构隶属关系和合著者网络对论文进行聚类预处理

关键洞察： 名称冲突是一个系统性问题，需要多信号方法：h-index 与领域一致性、引用时间分布、机构元数据、合著者网络分析。单一数据源（Semantic Scholar）不足以实现可靠的歧义处理

3. 咖啡机模型在 env.reset() 时模拟中显示分解状态（盖子漂浮、底座偏移），但 HDF5 演示重放显示正确组装#

解决方案： 追踪 MimicGen commit 398af01b，发现 missing locations_relative_to_corner 坐标转换问题。恢复了两个代码块：带有断言的实例属性存储，以及 _append_object() 中的坐标转换，将相对角落位置转换为相对中心位置

关键洞察： set_sim_state_flat() 覆盖 XML 身体位置为保存状态，掩盖了错误。只有 env.reset()（从 XML 生成新的初始状态）暴露了错误的放置方式。这解释了尽管每天使用仍需要 3 个月延迟的原因

4. 收集 6 项任务 × 29 种子类型的错误恢复演示需要 1,740 个样本（174×10），成本过高#

解决方案： 根据运动原语将 29 种子类型分为 5 个 Recovery Behavior Groups（RBG），每项任务每个 RBG 收集 5-10 个演示；使用 MimicGen/IntervenGen 增强技术为每种子类型生成 100+ 个样本

关键洞察： 恢复动作在不同错误类型中具有结构相似性；通过轨迹分割和对象/姿态随机化增强技术，可以将 10 个源演示扩展到 100+ 个训练样本，同时保留恢复能力

5. 在经过 4 轮环境修复后，研究分析器在使用 –api anthropic 后端时因“请设置 ANTHROPIC_API_KEY”而失败#

解决方案： 用户明确指示切换至 –api claude_cli 后端，后者调用本地 ‘claude –print’ 命令而非云 API

关键洞察： AI 花了 4 轮时间修复环境变量、conda 路径和模块安装问题，却认为 –api anthropic 是正确的；直到用户干预才质疑后端选择。认证失败的模式本应更早触发对根本原因的追问

6. LLM 奖项识别的召回率几乎为零——13 个查询中有 12 个因保守的“仅在特定情况下标记”策略而返回空结果#

解决方案： 当前方法更重视精确性而非召回率；LLM 确实不会生成虚假奖项，但无法获取最新的会议论文集；人类接受这种权衡

关键洞察： 奖项元数据在训练数据中稀疏且动态变化（每年都有新会议）；可靠的奖项检测需要与实时 API（OpenReview、DBLP）集成，而非单纯依赖 LLM 生成

7. discover_homepage_urls() 函数即使 S2 主页已存在也调用 LLM，浪费 API 成本#

解决方案： 添加了提前返回逻辑：当 S2 主页可用时，直接跳过 LLM 调用阶段

关键洞察： LLM 调用是昂贵的操作；应仅在所有确定性数据源（S2 API、主页字段）都失败后作为后备使用，而非无条件运行

8. 生成具有嵌套结构的中文分析时 JSON 格式不稳定——6 个输出（20%）需要通过专门的修复提示手动修正#

解决方案： 实施两阶段方法：（1）生成分析；（2）如果解析失败则通过 JSON 修复提示处理；人类需严格执行模式，要求使用精确的键名

关键洞察： 中文嵌套 JSON 处于 Claude 格式稳定性的边缘；添加带有示例结构的明确模式验证提示可显著改善合规性。英文 JSON 则更可靠

9. DiskCache._path_for() 在每次读取操作中都执行 mkdir，导致热路径中不必要的文件系统调用#

解决方案： 将 mkdir 逻辑移动到 put() 方法中（仅用于写入路径）；读取路径假设目录存在或文件不存在

关键洞察： 热路径优化黄金法则：读取路径假设资源存在，写入路径创建资源。适用于文件系统、数据库、缓存——所有持久化层

AI 局限性#

关键局限性#

  • 会议奖项知识严重过时且不完整——能够可靠回忆 2-3 年前的主要奖项（NeurIPS/CVPR 最佳论文），但对中级会议、研讨会奖项或近期（2024+）荣誉的覆盖几乎为零。保守地拒绝猜测是正确的，但限制了实用性。奖项 ID 回忆率：约 0%（12/13 次查询无结果）。
  • 在提出联合 PCA 和 Procrustes 对齐时未考虑零样本约束；这些方法需要同时访问两个部分的数据，违反部署要求。直到用户明确指导后才修正。
  • 没有外部信号无法区分同名研究人员——缺乏机构知识图谱或时间一致性检查；除非字段不连贯程度极严重，否则盲目接受来自上游数据库的合并档案。影响了约 30% 被分析的研究人员。
  • 在用户明确说明基本需求（使用 claude_cli，而非 anthropic API）之前，花了 4 轮时间修复 conda/环境/路径问题。重复类似的失败模式本应触发更早的根本原因询问。
  • 中文嵌套 JSON 生成不稳定——20% 的失败率（30 个输出中 6 个需要修复）；错误表现为未闭合字符串、中文文本中的未转义引号、截断结构。英文 JSON 则更可靠。
  • 当用户说“实施以下计划”时，试图进入计划模式，误将详细计划文本解释为规划工作流的触发条件而非直接执行的规范。用户必须明确拒绝并澄清意图。

经验教训#

关键经验- 基础模型在跨样本任务中的关键优势：无需联合训练即可提供共享嵌入空间；预训练权重确保不同输入下的可比性。零样本交叉截面检索本质上需要这一特性——任何样本级优化都无法替代。#

  • 名称歧义是自动化学者画像中数据质量的首要问题——影响约30%的分析研究人员。需要多信号方法：h指数与领域连贯性、引用时间分布、机构元数据、合著者网络分析。单一数据源远远不够。
  • 恢复演示数据增强三层策略：场景配置（以不同错误场景作为起始状态）、交叉程度（通过旋转扰动从D0到D1/D2）、交叉类型（RBG内部交叉增强）。结合MimicGen轨迹分割，可将数据需求降低81%（从1,740个演示降至329个）。
  • 复合模型系统中的坐标变换错误可通过状态重放机制（set_sim_state_flat）掩盖，该机制会覆盖XML定义的位置，仅在全新初始化（env.reset）时显现。这解释了在演示播放过程中通过视觉检查无法发现的长期隐藏错误。
  • “为何不在之前”反事实推理框架揭示了突破性的时间依赖关系：技术前提（GPU/预训练模型）、数据可用性（大规模数据集）、理论基础（新概念）。学术成功高度依赖于“技术栈成熟度”与“时间窗口”的匹配——不仅仅取决于个人天赋。
  • 用户偏好的工作流：本地claude_cli后端（claude –print），而非带有密钥的云API。必须记住这一偏好，以便未来调用工具或开展研究。反复认证失败的模式应触发对后端假设的质疑。
  • 基于LLM的奖项识别无需实时API集成，存在根本的召回率限制——训练数据无法跟上会议论文的更新速度。需要混合方案：(1) LLM筛选候选者，(2) DBLP/OpenReview API验证，(3)人工解决冲突。

  • 热门路径优化黄金法则：读取路径假设资源存在，写入路径创建资源。DiskCache mkdir从读取端（频繁调用_path_for）移至写入端（很少调用put()），效率提升10倍。适用于文件系统、数据库、缓存——所有持久化层。
  • Claude Code中的后台Bash任务不会继承conda init；必须使用“conda run -n ENV”或绝对Python可执行文件路径（${CONDA_PREFIX}/bin/python）。在非交互子shell中直接调用conda activate会引发CondaError错误。
  • 结构化输出验证应在架构上与生成分离——两阶段“生成然后修复”模式比单次完美输出更适合复杂的嵌套 Schema；可实现模型无关的验证层。
  • 恢复行为组（RBG）抽象：根据所需的运动原语（重新抓取、检索、缩回、转向、重新对齐）对29种错误类型进行分类，而非基于错误分类法。允许组内数据共享——比按错误类型收集更实用。
