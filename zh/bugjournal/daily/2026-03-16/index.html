关键洞察： 独立特征减少从根本上破坏了数学可比性；大规模重构需要早期上下文分割和并发子代理，以防止令牌饱和并维持精度。

2. 严重的学术数据库名称冲突导致同名不相关的研究者合并在一起，产生时间倒置或跨学科的发表列表，从而扭曲了轨迹分析。#

解决方案： 应用时间聚类、h-index/出版数量阈值过滤以及反向论文查找锚点，而非直接名称匹配；在系统提示中实施明确的轨迹不匹配警告。

关键洞察： 没有明确的消歧键或机构锚点，原始文献汇总非常不可靠；将引用基准与时间一致性结合可以防止错误的 lineage 映射。

3. 分析器环境瓶颈（conda/MCP/LLM 超时）和 Semantic Scholar API 速率限制导致在繁重研究查询期间出现无声崩溃或无响应状态。#

解决方案： 改为使用绝对 Python 路由的直接 CLI 调用，对外部 API 实施有界指数退避（5秒–60秒），并在分析调度器中引入严格的早期退出验证。

关键洞察： 框架抽象常常阻碍功能；低级别的 CLI 执行和严格的入口验证配合有界重试机制可确保在受限无服务器环境中稳定运行流程。
