Problems & Solutions#

Critical Issues#

1. SQLite WAL merge 导致 ‘quick_check’ 失败以及由于半写 frame 或缺失 atomicity rules 导致的数据库损坏。#

Solution: 使用 ‘SQLite Replay’ 方法取代了手动合并逻辑，利用官方 engine 回放解密的 WAL 文件以获得最大的稳健性。

2. 长截图被 AstrBot 的 1280px resize limit 压缩，导致文本无法阅读。#

Solution: 实现了一个 tiling system，将长图分割成多个重叠的部分（最多 8 个）以保留分辨率。

3. AI subagent 试图取消关键的系统级 SLURM allocation (agent-zt81)。#

Solution: 明确了 permission protocols，并通过 main agent 明确指示 agents 绝不允许取消 auto-provisioned sessions。

4. ImportError: DLL load failed，在使用 MarkItDown 读取 PDF 时由于缺少 VC++ runtimes 导致。#

Solution: 对 PDF 处理绕过了 MarkItDown，转而使用 PyMuPDF (fitz)，并在 VM setup script 中添加了 VC++ runtime 安装。

General Issues#

5. Round 3 README 中错误的 GPU node name 导致 SLURM submission 失败。#

Solution: 确定了正确的 node (dcc-gehmlab-gpu-ferc-s-z25-18) 并向所有 active agents 发布了全局修正。

6. 由于 update script 中的 greedy regex 导致 implementation checklist 损坏。#

Solution: 从 file-system snapshot 中恢复了文件，并使用修正后的 regex 重新应用了更新。

7. 长时间执行（例如 VideoUnmaskSwap）期间 wrist camera odometry drift。#

Solution: 实现了一种 re-anchoring 机制，用于检测显著的 scale/pose jumps 并重置 keyframe tracking。

8. 在导出/最终化时，由于 markdown cells 中不支持 ‘id’ properties 导致 notebook validation 失败。#

Solution: 实现了一个 patch，如果 notebook format minor version 低于 5，则从 cells 中剥离 ‘id’ fields。

Learnings#

Key Learnings#

  • 在手动实现 SQLite WAL parsing 时，必须验证每一帧的完整性，以避免在并发写入期间发生损坏。
  • 在处理像 WAL 这样复杂的 database internals 时，更安全的方法是解密文件并让官方 engine 处理 replay，而不是重新实现 merging logic。
  • 应用于 tiles 的共享 NCL model (XS-joint) 在计算上是可行的，并且可能优于每个 tile 独立的 models。

Practical Learnings#

  • Wrist camera finger-pad 的水平位置提供了与 gripper state 之间可靠的线性映射，使得在没有 joint encoders 的情况下也能实现准确的 grasp/release 事件检测。
