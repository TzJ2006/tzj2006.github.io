Problems & Solutions#

Critical Issues#

1. 由于使用基于 CPU 的 lavapipe rendering 以及 compute-only containers 中缺失 NVIDIA graphics capabilities 导致的 simulation speeds 过低。#

Solution: 提取了 user-space NVIDIA graphics libraries (libGLX, libEGL, Vulkan ICD) 并配置了环境变量，以便在无需 root access 的情况下启用基于 GPU 的 Vulkan rendering。

2. 审稿人可能针对 RoboMME 的 baseline consistency 以及缺乏 mechanistic novelty 提出的质疑。#

Solution: 主动调整论文结构以包含 real-world experiments，并将叙述重心从 “planning” 转向 “local visual event verification”，从而提供清晰的 “why”。

3. 使用 test set 进行 parameter tuning 导致的数据泄露风险。#

Solution: 实施了严格的评估协议：在 validation set 上进行参数微调，并在 test set 上报告最终结果。

4. Astra 和 Claude 模型无法原生处理 temporal media (GIFs/MP4s) 或处理特定的 WeChat integration nuances (identity parsing, @mentions)。#

Solution: 为媒体分析实现了 frame-sampling fallback，更新了用于 @mentions 的 bridge protocol，并为 sender ID index 添加了定期刷新机制。

5. Gemma 4 reasoning processes 耗尽 token window，导致 empty replies 或 timeouts。#

Solution: 开发了一种恢复策略：如果初始尝试失败或达到 context limits，则触发一个禁用 “thinking” 的重试。

6. Rebuttal 数字与发布的 dataset counts 之间存在差异，以及特定研究人员数据的不准确。#

Solution: 将正文中的文本转为定性描述，将具体计数移至 Appendix，并使用 deep-web evidence (YouTube/landing pages) 来验证细节。

7. 最初的 AI skill recommendations 缺乏社区验证和可靠性。#

Solution: 通过优先考虑 GitHub star counts、forks 和 active maintenance records 来重新评估所有候选对象。

Human vs AI Approaches#

Strategic Level#

Project Architecture (Modularization)#

Role Approach
Human 提出了一个轻量级的、模块化的 “core + plugin” 架构，其中独立的 repositories 作为 tools 运行，以避免复杂性和重写。
AI 最初专注于单个 features，随后转向使用 Model Context Protocol (MCP) 作为插件互换性的标准化 interface。

Difference Analysis: Human 优先考虑长期可维护性和解耦，而 AI 通过 MCP 专注于技术标准化。

Research Storytelling Strategy#

Role Approach
Human 提供高层级的 objectives，并授权使用特定的 research-architecting skillsets (例如 sci-story-skill)。
AI 将经验证据 (success rates, ablation results) 与 formal frameworks 相结合，提出了一个具有辩护力的、经过架构设计的科学主张。

Difference Analysis: Human 驱动了 tool/method 的选择和战略方向，而 AI 提供了结构严谨性和竞争定位。

Evaluation Methodology & Statistical Rigor#

Role Approach
Human 强制执行严格的 split，即使用 validation set 进行 tuning，而 test set 保持不动用于最终报告，以防止数据泄露。
AI 最初建议在 test set 上运行 evaluation，以便与已发布的 benchmarks 进行即时比较。

Difference Analysis: Human 优先考虑统计严谨性和防止数据泄露，而 AI 优先考虑比较的便捷性。

Human Suggested changing trajectory counts to cleaner numbers (e.g., 109 to 110) for aesthetic/numerical simplicity.

Difference Analysis: AI 将 Scientific Integrity 和实验一致性置于 Human 提出的数值简洁性之上。

AI Limitations#

Critical Limitations#

  • 最初未能考虑到在 Deep Reasoning 过程中 context window exhaustion 的问题，也未能考虑到像 Astra/Claude 这样的模型缺乏原生的 temporal-media 支持。

General Limitations#

  • Web search budget exhaustion 以及 403 Forbidden/bot challenges 阻碍了对某些第三方 reputation/academic URLs 的彻底检查。
  • 在尝试修改 shared nodes 上的资源时触发了 security classifiers，并且在旧架构与新架构之间的 persona transitions 管理上存在困难。
  • 由于 real-robot experiments 尚未进行，无法对其进行验证；此外，在建议 niche tools 时，最初未能考虑到 community popularity。

Learnings#

Key Learnings#

  • 对于一篇具有公信力的 CVPR 级别 robotics 论文，严格分离 development, validation, 和 testing sets 是必不可少的。
  • 可以通过经由 environment variables 手动提供 graphics libraries 和 ICD files，在 compute-only containers 中启用 NVIDIA GPU rendering。
  • Robotics 中的 scientific novelty 通常在于 perception 与 action 之间的 interface 设计（例如 visual memory tokens），而不仅仅是 raw success rates。
  • LLMs 中的 extended reasoning/thinking processes 可能导致 ‘silent’ failures，即在生成任何 response 之前就达到了 token limit。
  • 在未经验证的领域选择 agentic scientific skills 时，High star counts 和 active maintenance 是衡量 reliability 的重要指标。
  • 在描述涉及 minor versioning 的 datasets 时，专注于 generation methodology 和 source pools 比在正文中引用 absolute counts 更安全。
  • 使用 MCP 作为 plugin standard 可以使 central orchestrator 具有可互换性，并降低 custom tools 的 integration complexity。
