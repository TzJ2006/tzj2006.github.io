Problems & Solutions#

Critical Issues#

1. π0.5 target task group (libero_goal) 显示 0% 成功率。#

Solution: 发现 W4A8 (SpinQuant) 表现良好，表明问题在于 RMSNorm 的 quantization range 而非 bit-width；已启动 I-052 进行 TF-Enhanced 修复。

Key Insight: 特定层中的 activation precision 至关重要，其重要性往往超过 weight precision。

2. Idea graphs 与实际 codebase 之间的差异（行号、描述和实现细节）。#

Solution: 使用 ccscan 及 companion engines 进行深度 repository 扫描，以使 YAML graphs 与真实的 code state 同步。

Key Insight: Idea graph 必须被视为一份 living document，需要定期与实际的代码实况进行同步。

3. 论文引用不准确及 documentation 不一致。#

Solution: 使用 agentic workflows 重新验证 arXiv 位置，并更新了 documentation（例如 AGENTS.md）以反映真实的实现逻辑。

Key Insight: 自动化扫描可以主动揭示架构缺陷和 documentation decay。

4. 无效的 test cases (False Positives)，即代码 merge 后测试代码不再触发函数。#

Solution: 在 model.py 中识别了失效的测试，并将其标记为待进行 ccfix 或 refactoring。

Key Insight: Merge 操作需要审计现有的 test coverage，以防止 silent failures。

General Issues#

5. Security guard 在受限环境中拦截 shell commands（重定向、‘cp’ 或裸环境变量）。#

Solution: 切换到 ‘Edit’ 工具进行文件移动，并对环境变量使用 ’env’ 前缀以确保兼容性/访问权限。

Key Insight: Security guard 对并发文件访问和标准的 shell patterns（如重定向）非常敏感。

AI Limitations#

General Limitations#

  • AI 的 security guard 限制了标准的 shell 操作（重定向、‘cp’）并阻止修改项目目录之外的文件。
  • 在 creative writing 任务中，AI 倾向于在不同版本和语言中重复相似的 stylistic motifs 或 sensory details。

Learnings#

Key Learnings#

  • 维护一个层级化且同步的 idea graph 对于防止技术债、确保技术改进逻辑性地贡献于项目 milestones 至关重要。
  • 在 quantization 研究中，‘zero-shot’ framework 的价值在于从相同的输入提供多个多样化的 readout，而不是在单一指标上竞争。
  • 故事创作中的 indirect characterization 在与角色的特定历史或前职业相结合时最为有效。

Practical Learnings#

  • 在 Windows 上，使用某些 shell 执行方法时，用于 test execution 的环境变量必须带有 ’env’ 前缀。
