问题与解决方案#

关键问题#

1. cchypothesis 缺乏运行时调试能力 — 所有假设仅通过静态代码分析验证，缺少动态状态/时间/数据流问题#

解决方案： 实施第三阶段智能分类：静态假设保持并行只读；运行时假设使用顺序化的仪器化探测，带有 [DEBUG Hx] 标签日志、Git 安全检查点以及通过 git restore 自动清理

关键洞察： 双路径调查在保持速度的同时（并行静态），仅在需要时添加深度（仪器化探测）——避免降低所有调试会话的效率

2. 仪表板持续 1-2 Hz 的垂直抖动由三层正反馈循环引起：数据刷新 → UI 重渲染 → 窗口缩放 → 数据刷新#

解决方案： 多层阻断：(1) 窗口层：16ms→100ms settles 延迟 + 每3次操作500ms 速率限制；(2) 数据层：浅层PayloadEqual 以跳过冗余的 .set()；(3) 解析器层：2分钟过渡期用于 is_active 边界，防止五小时成本波动

关键洞察： 自振荡问题需要在所有反馈层同时干预；单独修复某一层只会削弱问题，无法消除循环

3. Git stash 栈冲突：ccplan 提案在现有第四阶段 stash 之上添加了第三阶段 stash，导致弹出顺序混乱，可能掩盖用户未提交的工作#

解决方案： 移除第四阶段的 git stash，改用 git restore（非破坏性清理）；现在只有第三阶段使用 stash（单层 stash 模型）

关键洞察： 自动化工作流中的多个 stash 层级会导致状态管理脆弱——在可能的情况下，优先使用无状态清理（git restore）而非有状态撤销（stash）

4. TokenMonitor 窗口出现在屏幕中心而非系统托盘附近；缩放导致窗口向下延伸至任务栏，而不是保持底部边缘#

解决方案： 实现 Win32 API 直接定位系统托盘（FindWindowW → TrayNotifyWnd）；将前端缩放从 webviewWindow.setSize() 改为后端 set_window_size_and_align IPC，以实现原子化尺寸+位置更新

关键洞察： Tauri 的跨平台 positioner 插件抽象了平台差异，但精度降低；Windows 系统托盘定位需要特定平台的 Win32 API 以实现像素级对齐

5. 42 Rust 编译错误：commands.rs 包含指向已删除模块的损坏导入（change_stats、integrations、parser）以及来自新命令/子模块的重复代码#

解决方案： 将 commands.rs 重写成仅包含6个 pub mod的80行模块根结构，保留 AppState/UsageDebugReport 和4个共享辅助函数，修复可见性和类型问题

关键洞察： 不完整的重构（混合旧代码和新代码）比单体代码更糟糕；必须完成迁移或回退

6. 窗口锚点检测不可靠：visible:false 初始挂载、position_near_tray 与 GetWindowRect 之间的竞争条件、连续缩放导致锚点翻转#

解决方案： 完全移除动态检测；托盘弹出窗口始终通过 position_near_tray 定位在 work.bottom，因此硬编码底部锚点行为

关键洞察： 对于已知窗口类型，静态配置优于动态检测；运行时检测增加复杂性 và 故障模式，却没有收益

一般问题#

7. Critic 代理识别 git restore，但不清理未跟踪文件（例如，在仪器化过程中创建的 .debug/hypothesis.log）#

解决方案： 每次仪器化周期后明确执行 rm -rf .debug/；将日志输出目录从 .claude/（配置目录）改为 .debug/（临时项目目录），并遵循 gitignore 规范

关键洞察： git restore 仅影响已跟踪文件——自动化清理工作流必须结合 git 命令和明确的文件系统操作，以实现完全整洁

经验教训#

关键经验#

  • 多阶段规划工作流（ccplan）在涉及冲突问题的复杂集成中表现优异——对抗性审查阶段发现了可能导致数据丢失的关键 git stash 冲突
  • 级联反馈循环需要同时进行多层干预：仅修复窗口大小调整问题（16ms→100ms）是不够的，直到数据层（负载相等）和计算层（缓期期）也得到解决
  • Instrumented 调试需要仔细的生命周期管理：每个假设都需要独立的 instrument→运行→分析→清理循环，以避免交叉污染和残留调试代码
  • 不完整的模块重构会产生隐藏的依赖地狱：commands.rs 仍然导入 crate::parser，而 new commands/calendar.rs 导入 crate::usage::parser——两条路径无法共存
  • 动态运行时检测增加了故障模式，而静态配置已足够时无需使用：托盘窗口始终使用 position_near_tray，因此底部锚定应硬编码
  • Tauri 中的跨平台窗口定位：插件抽象牺牲了准确性以换取可移植性；像素级对齐（尤其是系统托盘对齐）需要平台特定的原生 API

实际经验#

  • 全面的测试套件能发现重构问题：218 个 Rust 测试 + 191 个前端测试验证修复未破坏现有行为
  • 自动清理工作流必须区分被跟踪文件和未被跟踪文件：git restore 处理被跟踪文件；未被跟踪文件（日志、临时目录）需要明确的 rm/rmdir
