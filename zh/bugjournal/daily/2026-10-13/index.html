Problems & Solutions#

Critical Issues#

1. Discrepancies in Research Claims & Data (Paper Audits/LIBERO-PRO)#

解决方案： 在 camera-ready 版本中实施了 ‘disclose truthfully’ 策略，使用 intra-model ablations 以避免误导性的比较，并将 benchmark 结果分类为 ‘Standard’ 与 ‘Robust’ 列，以解释 instruction source 的不一致性。

2. System Integration & Communication Barriers (WeChat/VM/UI)#

解决方案： 配置了带有 token-based auth 的专用 VM network interfaces (192.168.77.1) 以绕过 localhost 限制，切换到使用 Unicode 编码的 win32clipboard 以确保文本可靠性，并应用 CSS overflow-wrap 来修复 mobile layout。

3. Multimedia & Model Limitations (Video/GIF/API)#

解决方案： 实现了一种 ‘model-native’ 路由逻辑，优先处理原始媒体，并提供明确的 fallback/sampling 警告，以防止模型对 motion/audio 产生 hallucination。

4. Repository & Operational Efficiency (Git/Staging)#

解决方案： 应用了细粒度的 .gitignore 规则，将 staging 从 1.85GB 减少到 146MB，并使用独立的 audit agents 以确保没有 credential 泄露。

Human vs AI Approaches#

Strategic Level#

Strategic Direction vs. Technical Execution#

Role Approach
Human 提供高层级的架构愿景（将项目整合为统一的生态系统）、战略转向（从研究模式转向投稿模式）以及 UX 哲学（隐藏复杂性）。
AI 专注于大规模的技术执行、multi-agent 研究综合（调研 300+ 篇论文）以及严格的技术验证/测试。

差异分析： Human 充当架构师和战略家，而 AI 则作为高容量的执行者和审计者。

Decision Making & Preferences#

Role Approach
Human 对主观选择保持最终决定权，例如是否追求 ‘Yellow’ 评级的导师或采取哪种具体的学术路径。
AI 提供数据驱动的证据、风险警告和结构化综合，为这些决策提供参考。

差异分析： AI 提供概率性的图景；Human 做出基于价值的选择。

AI Limitations#

Critical Limitations#

  • 当前的模型集成（Codex/Claude/Ollama）缺乏原生的 video/GIF streaming，需要使用 frame-sampling 作为 fallback。

General Limitations#

  • AI 最初未能意识到过于技术化的 UI 描述（例如 ‘queueing tasks’）会对非技术用户造成困惑。
  • 环境限制：缺乏用于 LaTeX 编译的本地 TeX distribution，以及对 repository directories 的 write-access 受限。
  • 测试与 API 限制：GitHub API 的 rate limiting，以及由于 safety guardrails 无法执行直接的 ‘git commit/push’ 操作。

Learnings#

Key Learnings#

  • 在研究中，严谨的 ‘constraint-based’ 叙述必须清晰区分特定输入（例如 drawn glyphs）带来的收益与约束本身带来的收益。
  • 在 rebuttal promises、研究数据与实际 codebase 之间维持一个 ‘source of truth’ 链接，对于成功的 camera-ready 过渡至关重要。
  • 直接读取 WeChat message database 在验证消息历史方面比尝试从 UI 推断 context 要可靠得多。
  • 在集成复杂的 automation 时，‘receive-only’ 阶段对于防止 ‘runaway’ bots 发送错误或重复消息是必不可少的。
  • 更换模型需要调整整个 pre-processing 和 tool-use 逻辑以匹配模型的原生优势，而不仅仅是更换 ‘brain’。
