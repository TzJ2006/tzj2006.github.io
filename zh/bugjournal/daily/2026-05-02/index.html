关键问题#

1. pi0.5 v2 在 Clean Rollout 中整体出现回归（平均 -5.6pp），尽管线程任务表现改善（+24pp）#

解决方案： 使用差值列格式化的对比表格以分离任务特定的性能变化；识别出 pick_place、coffee、stack 和 stack_three 为表现下降的任务

关键洞察： 模型 v2 存在任务特定的性能差异：线程任务的显著改善与操作任务中的广泛回归形成对比，表明这是架构层面的权衡而非均匀退化

2. pick_place 任务在 Error Recovery 场景中出现严重回归：pi0.5 v2 下降 -24.1pp（42.9% → 18.8%）#

解决方案： 在分析总结中将 pick_place 标记为关键调查优先级；未立即实施修复，等待更深入诊断

关键洞察： 即使基础任务完成率尚可，Error Recovery 性能也可能显著下降，表明 v2 对干扰的鲁棒性可能降低

一般问题#

3. TokenMonitor FloatBall 显示 Cursor 使用率为 N/A，因为只有 plan_usage 数据的用户中 extra_usage 字段为 None#

解决方案： 在 tray_utilization_from_rate_limits() 中修改了 Cursor 利用提取逻辑，从仅检查 extra_usage 改为回退链：extra_usage_utilization().or_else(|| primary_window_utilization())

关键洞察： 大多数 Cursor 用户有 plan_usage（基于窗口且包含 auto_percent_used/api_percent_used），但缺乏 spend_limit_usage（基于 extra_usage）；之前的代码仅检查 extra_usage，导致 None → N/A 显示
