问题与解决方案#

关键问题#

1. SameLabel@K 指标返回 0.0，尽管嵌入明显检索到了相同的细胞类型#

解决方案： 根本原因是 eval_mask 通过 ~niche_mask 排除了所有小众区域，导致 Layer_3 区域为零。修复方法是在 all_valid_mask（包括小众区域）上计算 SameLabel，同时保留在 eval_mask 上的 Precision@K（排除小众区域以避免自匹配偏差）。

关键洞察： 不同的评估指标需要不同的排除掩码——检索率需要完整的有效集合，而排名一致性则需要排除查询区域本身。

2. 初始计划要求从头实现 RM-Ideal，但代码审查显示已存在实现#

解决方案： 人类被引导去验证现有实现而非重复工作；进行了全面测试，确认相同/不同的子图分别返回 1.0/0.0，符合预期。

关键洞察： 在实施之前始终应验证现有代码库状态——文档和实际代码可能不一致。

一般问题#

3. 在共享标签字典中合并查询图与参考图时存在节点 ID 冲突风险#

解决方案： 在创建组合标签字典前，将 adata_q.n_obs 的 node ID 偏移应用于所有参考节点 ID，避免键冲突。

关键洞察： 当合并来自不同 AnnData 对象的图时，节点索引会重叠——应使用确定性偏移而非依赖不相交的 ID 空间。

4. Wasserstein 距离求解器的依赖问题——quest conda 环境中未安装 POT 库#

解决方案： 实现了双层求解器：先尝试导入 ot.emd2()（快速的 C 后端），如果失败则使用 scipy.optimize.linprog 与 HiGHS 求解器（无需额外依赖，适用于约 30-100 个节点的小子图）。

关键洞察： 对于可选的性能优化，应始终提供无依赖的替代方案——scipy 无处不在，而 POT 并非如此。

经验教训#

关键经验#

  • RM-Ideal（带有理想标签的区域匹配）使用 WWL 图核：K 次迭代邻居标签哈希 → 汉明成本矩阵（通过 K+1 归一化）→ Wasserstein 距离 → 相似度 = 1-W。能够独立于学习到的嵌入捕捉空间小众结构。
  • 小众查询的评估指标需要精心设计的掩码：Precision@K 使用 eval_mask（排除小众区域以避免自匹配），SameLabel@K 使用 all_valid_mask（包括小众区域用于检索率），Spearman 使用 eval_mask（非自匹配点上的排名相关性）。

实践经验#

– 在框架间迁移图算法时：squidpy.gr.spatial_neighbors() → sklearn NearestNeighbors + scipy sparse，torch_geometric.k_hop_subgraph() → networkx BFS。采用将代码转换为依赖最少的等价形式的方式。

  • 针对昂贵计算的缓存策略：RMIdealEvaluator在初始化时预计算所有k-hop子图（4384个点约需8分钟），保存至.npy缓存，后续运行可立即加载。缓存键应包含空间图参数（n_neighbors、k_hop）。
