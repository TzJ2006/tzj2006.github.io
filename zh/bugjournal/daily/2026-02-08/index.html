问题与解决方案#

关键问题#

1. “SameLabel@50” 指标在生态位检索基准测试中返回恰好为 0.0，因为掩码过滤后没有剩余目标点可供排序。#

解决方案： 修改评估逻辑，允许从同一标签集中查询区域点（例如比较 Layer_3 与 Layer_3），并明确排除自匹配项，仅用于 Precision@K 结构排序对比。

关键洞察： 类型级检索准确率和结构级排名一致性必须使用不同的评估掩码；完全从候选池中移除目标类别会使类型匹配指标变得毫无意义。

2. 在核心算法测试过程中，由于环境依赖过强（例如缺少 ‘umap’ 模块）导致 Python 执行失败。#

解决方案： 独立提取目标函数并通过孤立脚本或 conda run 执行，成功绕过框架级导入开销，同时验证数学正确性（相同自匹配的 RM=1.0）。

关键洞察： 在与 scanpy/scikit learn 等复杂框架集成之前，算法逻辑应在独立环境中从结构上验证，然后再进行整合。

AI 限制#

关键限制#

  • 最初使用严格的空间排除掩码评估 SameLabel 检索率，该掩码排除了所有与查询类型匹配的候选生态位，表明在图查询的边界情况指标行为方面缺乏语义意识。

一般限制#

  • 在配置复杂或不匹配的 conda 环境中直接执行 Python 时遇到持续失败（例如缺少 umap 等核心库），需要低效的回退方案，如隔离脚本和复杂的环境激活循环。

经验教训#

关键经验#

  • 在评估空间感知模型时，结构相似度指标（RM-Ideal）和细胞类型匹配指标（SameLabel@K）评估的是不同的能力；类型匹配必须严格允许检索目标类点，以避免简单的归零情况。
