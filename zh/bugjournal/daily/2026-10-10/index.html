Problems & Solutions#

Critical Issues#

1. 由于任务相关问题（OOD states、物体位移或 latency mismatch）导致的 Robot policy failure。#

Solution: 通过多层方法解决：实施 ’timeout’ 机制以增强鲁棒性，使用 ‘Visual Prompting’ 来绕过语言退化，并利用 JEV 的 ‘decision’ 能力来处理动态环境。

2. 软件工程和自动化稳定性问题（WeChat 重复、race conditions、absolute symlinks 以及 shell execution errors）。#

Solution: 实施了原子执行意图持久化、OS 级文件锁、用于相对路径的 s_relink，并转向专门的 Python ‘Write’ tools 以进行安全的文件修改。

General Issues#

3. 大规模模型/数据传输过程中的资源和权限障碍。#

Solution: 从本地到远程的传输切换为在 Tianhe3 上的快速服务端复制，并使用手动授权来绕过 sub-agent 的权限限制。

4. UI/UX 的清晰度和信息密度。#

Solution: 将冗长的文本标签替换为极简的视觉指示器（ticks/lines）以提高效率。

AI Limitations#

Critical Limitations#

  • JEV 是一个 ‘state switch’ 而不是 ‘drafter’；它本身无法自主 ‘理解并重绘’ 环境变化。

General Limitations#

  • 在没有明确用户指导的情况下，难以区分特定的 VLA ’language degradation’ 和 ‘observation space shift’。
  • 在远程服务器的权限限制方面表现挣扎，并在复杂的 Node.js 文本处理中遇到 syntax errors。
  • 未能遵守硬件约束（例如尝试将 ASR 移至 GPU 而非 CPU），并且在没有直接链接的情况下缺乏验证非常近期的 2026 年文献的能力。

Learnings#

Key Learnings#

  • 一个统一的研究叙事（Failure $\rightarrow$ Awareness $\rightarrow$ Memory）在学术定位方面比列出孤立的项目要有效得多。
  • ’latency gap’ 是 JEV 的核心价值主张：non-pausing agents 在计数任务中失败，是因为机器人的移动速度超过了 VLM 的响应速度。
  • 有效的 robot memory 依赖于识别特定的 ‘completion events’（例如 gripper release），而不仅仅是持续的 observation。
  • 在 VLA 训练中，数据集中缺乏 ‘recovery’ 或 ‘stop’ 动作是导致 OOD failure 时 policy timeouts 的主要原因。
  • 使用 ’timeout’ 机制是一种有效的设计权衡，即使在视觉引导失效时也能确保系统的连续性/鲁棒性。
