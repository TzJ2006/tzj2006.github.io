问题与解决方案#

关键问题#

1. 图表细节面板闪烁以及窗口过早缩小是由被动 DOM 观察导致在悬停过渡期间 Tauri 窗口调整事件引发的。#

解决方案： 从绝对定位转向严格的内嵌块结构。实现了明确的 onDetailToggle 事件系统，在过渡期间手动驱动高度动画，同时暂时抑制观察器传播。

关键洞察： 混合式桌面框架无法依赖被动观察器进行自动缩放；带有状态隔离的事件驱动高度控制器是防止原生重绘级联的关键。

2. Windows 浮球因冲突的 CSS 继承和双 UI 初始化路径导致半透明覆盖重叠、动画卡顿和垂直对齐失败。#

解决方案： 删除了多余的嵌入式面板初始化，强制实施严格的 CSS 范围控制，使用原生 Win32 区域裁剪确保几何完整性，并通过 Rust/TS 补丁统一状态载荷。

关键洞察： 跨平台桌面应用需要特定平台的原生边界而非纯前端样式，以消除持续的覆盖冲突和布局卡顿问题。

一般问题#

3. BOSS 推理导致重复的数据集路径验证警告，以及由于压缩的初始化状态数组在有限的 .pruned_init 文件中循环而产生的索引混淆。#

解决方案： 创建了 _config.yaml_ 中引用的缺失目录结构，并明确说明基于模数的状态循环是故意的基准测试优化。在不改变评估行为的情况下抑制了非功能性的日志噪声。

关键洞察： 评估框架通常急切地验证所有配置键；主动的路径准备或延迟加载可避免基准测试运行中的重复日志记录。
