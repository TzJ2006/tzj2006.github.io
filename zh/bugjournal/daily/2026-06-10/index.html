关键问题#

1. 关键意图不一致：评估代码实施了基于“EVALUATION.md”论文规范的指标（CSR-RSR差距、单一种子），这与权威的“全景摘要”（恢复进度0-1连续、多种子）相矛盾，威胁到实验有效性。#

解决方案： 通过多智能体验证执行了全面的意图与代码记录，证明“全景”是真实来源；放弃500步/差距指标工作，重新规划评估以匹配SR + Bootstrap CI + RP。

关键洞察： 技术文档（论文规范）往往与高层项目策略不一致；始终先根据“全景”或执行摘要验证代码的意图。框架层中的死代码不应假设为活跃状态。

2. Research Gadget LLM失败结果（超时/速率限制）被永久缓存，没有TTL，导致后续运行立即返回所有论文的零分结果，因为缓存键相同。#

解决方案： 通过工作流审计发现；修复方法是在evaluate.py和insight.py中为失败的LLM响应添加TTL或唯一请求哈希键。

关键洞察： 如果失败状态与成功状态在缓存中相同且没有过期时间，临时API错误可能导致持续数据污染。在缓存系统中区分“临时失败”和“永久状态”至关重要。

3. 提交文件如CLAUDE.md和settings.json中的绝对本地路径（例如D:\GitHub\ai-companion）被公开，存在私有路径泄露风险。#

解决方案： 实施三层修复：立即对现有暴露进行git rm –cached，更新.gitignore以阻止未来生成，并设计安装程序增强功能以区分公共与私有仓库的可见性。

关键洞察： 配置文件中的绝对路径本质上不可移植；将其视为“临时”而非“永久”成果需要严格的gitignore执行或环境变量注入。

一般问题#

4. TokenMonitor将新的Anthropic模型（如Fable 5）显示为“未知”，无令牌。#

解决方案： 发现src-tauri/src/usage/pricing.rs缺少特定新模型ID的条目。修复方法是将这些ID添加到ModelFamily枚举中，并更新get_rates()。

关键洞察： 硬编码定价表需要严格维护以跟上供应商发布；回退逻辑通常掩盖缺失数据点而非表明需要更新。

学习成果#

关键收获#

  • 当项目规格与学术论文和内部文档冲突时，内部文档（尤其是 ‘Panorama’ 或 ‘Master Guide’ 文件）应被视为实现细节的权威来源。不应假设死代码仍然处于活动状态。
  • 生成的配置文件中使用的绝对路径必须严格从公共仓库中排除；安装程序应检测仓库可见性（公开/私有），从而动态调整包含策略，防止机器特定的本地路径泄露。
  • 在具身人工智能研究中，‘JEPA’ 和 ‘World Models’ 正在融合；特别是使用视觉动作令牌（如 iMaC）和分层记忆门（HiMem-WAM）来处理长期操控似乎处于前沿水平。
  • 在缓存系统中，区分“临时故障”与“永久状态”至关重要。对 JSON 解析错误或 API 超时进行缓存且没有 TTL 设置，会破坏缓存剩余时间内的数据完整性。
