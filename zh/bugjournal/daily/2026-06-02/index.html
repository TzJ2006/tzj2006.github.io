问题与解决方案#

关键问题#

1. MIHD STAIG 融合结果完全相同（沉默失败），因为原始 HVG 矩阵绕过了基因编码器层，导致基准测试数据无效。#

解决方案： 通过 md5sums 确认数据完整性损失；修改 pipeline_config.yaml 以强制实施 staig_gene_source='encoder'；归档损坏输出，使用正确路径重新运行 SLURM 作业。

关键洞察： 相同的输入对下游 GCN 有保护作用，掩盖了上游编码器的错误；在接受研究输出之前进行经验性二进制验证（md5）至关重要。

2. MIHD 文件夹的意外删除和重新克隆导致两个月未提交的工作和缓存嵌入序列被清除。#

解决方案： 确认 NetApp .snapshot 可用性；使用 rsync 从每日快照（6月2日 08:10）恢复工作树、嵌入序列缓存和配置；将恢复结果提交至 GitHub。

关键洞察： 未提交的高性能计算工作是短暂的；在共享/重克隆环境中，不频繁提交或自动备份的本地树风险极高。

3. AI Dev Companion 构建因 TS5055 错误和 /ccoverview 翻译崩溃而失败，原因是 API 超时/阻塞。#

解决方案： 将根 tsconfig 的 ‘include’ 设置为 [] 以修复工作空间构建；对 /ccoverview 应用 Fix C：批量翻译，切换为顺序执行，并添加 try/catch 处理超时。

关键洞察： 负载大小/并发度比网络延迟更导致 LLM 超时；多项目合并中的根 tsconfig 应始终为纯引用，以避免模块冲突。

4. TokenMonitor 分支自动更新因缺少 uploader-pubkey.txt 和错误的 macOS 签名标志而失败。#

解决方案： 生成新的 Tauri 密钥对，在 GH Actions 中设置正确的 base64 密钥，并修改 workflow.mjs 以将 minisign 更新器的签名与 Apple 开发者 ID 要求分离。

关键洞察： 更新器签名（minisign）和代码签名（Apple）是不同的；将它们混为一谈会破坏跨平台更新的一致性。干净的Base64加密密钥对Tauri工作流程至关重要。

5. TokenMonitor开发服务器出现白屏，Hex-line MCP幻影配置导致困惑。解决方案： 终止了端口 1420 上多余的 Vite 进程；删除了那些模仿 MCP 可用性的过时的 SessionStart 钩子和 Claude settings.json 中的输出样式。#

AI 限制#

一般限制#

  • 如果不在 try/catch 中包装，LLM 包装器实现在超时时经常崩溃，导致与 JSON 解析错误混淆；这是当今项目中常见的模式。
  • 依赖文件元数据（日期/日志）而非二进制内容（md5sums）最初掩盖了 MIHD 中数据损坏的严重程度；需要明确的工件验证来证明字节身份错误。
  • 无法预测本地环境差异（python3 vs python、Tauri 密钥格式）导致 CI/发布脚本失败，需要手动迭代秘密格式和脚本。

经验教训#

关键经验#

  • 在空间转录组管道中，比较编码器分支时用 md5sums 验证嵌入输出；相同的输入可能会隐秘掩盖上游故障。
  • 在 HPC 环境中，应经常提交工作；本地工作树是短暂的，如果目录被重新克隆或删除则非常危险。系统快照是关键的安全网，但不能替代版本控制。
  • 工作空间中的根 tsconfig 应通常是“纯引用”（include: []），以避免模块解析冲突（CommonJS/ESM）导致构建失败。

实际经验#

  • Tauri 更新器签名（minisign）和代码签名（Apple/DigiCert）是独立的；在 CI 工作流中混淆它们会破坏特定平台的自动更新一致性。
  • 使用 LLM 进行结构化数据翻译时，明确执行“保留技术标识符”规则，以防止功能键和路径损坏。
