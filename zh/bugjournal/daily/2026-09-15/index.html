Problems & Solutions#

Critical Issues#

1. conda run wrapper 不将其 spawned python subprocess 的 signals 转发，导致大规模 VRAM leaks。#

Solution: 在 shell trap 中实现了一个自定义的 cleanup() 函数，使用 ‘fuser -k’ 对特定的 TCP port 进行操作以回收内存。

2. 在并发测试执行和 backbone quantization 期间出现机器冻结和 OOM errors。#

Solution: 通过 halving-search 确定了最佳 worker counts，并实现了一个基于 Bash 的 retry driver 来监控 VRAM thresholds (35-42GB)。

3. 在关于 quantization logic 的 collaborator repo merge 过程中出现了复杂的 semantic conflicts。#

Solution: 优先采用了合作者的 float-preservation approach（针对 softmax/rotations），以确保 precision integrity。

4. CUDA indexing 与 nvidia-smi 不一致，导致错误的 GPU pinning。#

Solution: 在 common.sh 中导出了 CUDA_DEVICE_ORDER=PCI_BUS_ID，以强制与 physical bus IDs 对齐。

5. Guardrail system 由于 substring matching 拦截了合法的 Read tools，并通过 ‘unclaimed’ idea nodes 阻止了文件写入。#

Solution: 识别出需要将 MCP tools 与 native tools 进行区分，并使用 ‘companion new’ 来 claim 特定的 idea nodes 以进行文件访问。

6. Overleaf 上的自动化文件上传和 clipboard access 被拦截或无响应。#

Solution: 切换到健壮的基于 clipboard 的方法（粘贴图像数据），并针对私有源代码请求显式的用户授权。

AI Limitations#

Critical Limitations- AI 最初未能考虑到嵌套进程计数（sub-processes）以及 maxWorkers 在不同 session 之间的不可组合性。#

  • AI 高估了 ‘Read’ 操作的安全性，未能意识到 MCP tools 在 guard logic 中会匹配 ‘write’ 子字符串。
  • 由于 sandbox/companion guard 的限制，AI 无法独立执行长时间运行的 benchmarks 或繁重的 shell writes。

General Limitations#

  • 浏览器交互限制：AI 在 Overleaf 等 Web 环境中处理标准的 file chooser dialogs 时表现困难。

Learnings#

Key Learnings#

  • GT-A (tissue) 与 GT-B (cell lineage) 之间的 ranking reversal 表明 neighborhood contrastive learning 对 label granularity 非常敏感。
  • 在高并发环境中，worker limits 必须考虑到 ‘grandchild’ 进程；优化遵循 U-shaped curve，需要进行 empirical testing。
  • 同时实现 ‘cleaning before start’ 和 ‘cleaning at exit’ 对于防止 batch 环境中的累积 memory leaks 至关重要。
  • 将 CUDA device ordering 标准化为 PCI_BUS_ID 对于可靠的 multi-process GPU targeting 至关重要。

Practical Learnings#

  • 在自动化基于 Web 的 LaTeX 编辑器时，基于 clipboard 的插入 (Ctrl+V) 比模拟 OS-level 的 file chooser 交互更可靠。
