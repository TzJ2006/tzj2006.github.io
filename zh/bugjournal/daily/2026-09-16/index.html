Problems & Solutions#

Critical Issues#

1. 量化模型 (w4a4) 在所有 Libero 任务中失败，成功率为 0%。#

Solution: 进行了逐帧运动幅度与视觉差异分析。发现错误并非 attention collapse，而是在初始 action block 期间由于低比特 backbone 精度损失导致的 ‘stop-before-target’ 行为。

2. AI Companion 出现 ‘decision fatigue’ 和重复的审批提示。#

Solution: 重构了 skill 文档和逻辑以实现 ‘authorize-and-proceed’ 模型，区分常规进度与关键决策点 (Ambiguity/Scope/Risk)。

3. 移动 25GB 数据后出现路径断裂和 CI 失败。#

Solution: 开发了一个使用 regex 进行路径重写的自定义 Python 重组脚本，并实现了一个集中的 figure routing 系统。

4. 由于缺失 ’tokenUsage’ 字段，Grok Bot 的使用量显示为 $0。#

Solution: 修改了 parser 以接受 ‘chargedCents’ 字段，并引入了基于回归分析的静态定价 fallback 机制。

5. 与 npm/Node 版本及 lockfile 同步相关的 CI pipeline 失败。#

Solution: 手动修补了 package-lock.json，并在 CI workflows 中固定了 Node 版本，以解决 @emnapi 依赖问题。

6. 由于权限和分支歧义导致 Git history 重写失败。#

Solution: 在本地镜像上使用 git filter-repo，并为用户提供手动 PowerShell 命令以完成 push。

7. 由于精度/位宽不匹配导致 W4A4 的 QAIRT 部署失败。#

Solution: 确定 16-bit softmax/norm scaling 会产生被 QAIRT 拒绝的 ‘activation islands’；结论是 W4A8 是目前可行的目标。

8. Windows 上鼠标光标间歇性漂移。#

Solution: 审计了远程访问进程 (RustDesk) 和 HID 设备。确定 3Dconnexion SpaceMouse 和 M-AI 软件是可能的罪魁祸首。

9. Multi-Agent 并发写入与 Windows 原子写入风险。#

Solution: 引入了 baseDigest (fingerprint) 一致性检查，以及带有临时文件隔离机制的 atomicWrite 循环重试机制。

General Issues#

10. 大规模 Python 编辑导致 CRLF 换行符，破坏了 Vitest。#

Solution: 执行了一个 Python one-liner，强制将所有修改过的文件中的 CRLF 替换为 LF。

Human vs AI Approaches#

Strategic Level#

Agent Autonomy vs. Guarding#

Role Approach
Human 要求一个能够主动追求目标、持续更新且无需频繁审批的 agent (Execution-centric)。
AI 最初侧重于做一个优先考虑严格验证和关卡的 ‘bookkeeper’ (Audit-centric)。

Difference Analysis: 人类优先考虑最小化中断频率，而 AI 优先考虑验证的完整性。

Pi0.5 Failure Analysis#

Role Approach
Human 建议检查任务名称不匹配问题 (semantic direction)。
AI 分析 BDDL 文件和仿真逻辑，为精度损失提供物理/逻辑层面的验证。

Output Reorganization Strategy#

Role Approach
Human 为了长期维护，决定采取“激进的物理移动”（aggressive reorganization）。
AI 提出了非破坏性的双层 symlink 方法，以最小化路径破坏风险。

Difference Analysis: Human 优先考虑清晰的科学结构，而非即时的技术便利性。

UI Layout and Design#

Role Approach
Human 建议将 ‘Rolling Periods’ 合并到 ‘Week Starts’ 中，并要求将 ‘Test All’ 准确地放置在 ‘Sync All’ 旁边。
AI 最初计划使用独立的 toggles，并使用了标准的 space-between flexbox 布局。

Difference Analysis: Human 优先考虑紧凑、直观的 UI 和明确的空间定位。

Git History Cleaning Strategy#

Role Approach
Human 要求在所有 repositories 中彻底清除所有与 companion 相关的路径，包括 ‘ideas/’ 和 docs。
AI 最初建议采取保守的方法，区分程序文件和文档资产。

Difference Analysis: Human 推动完全移除开发者足迹，这需要更复杂的 history rewrites。

AI Limitations#

Critical Limitations#

  • AI 对成功的验证往往是循环的（自我验证其自身的进度报告），缺乏客观证明。
  • 当尝试使用 shell redirection (’>’)、设置环境变量或在分配路径之外进行文件写入时，AI 反复被 security guards (D21/D26) 拦截。

General Limitations#

  • AI 在处理 MSYS 路径转换问题时表现挣扎，并偶尔误解 flexbox 布局中的 ’next to’。
  • 由于 D16/I-147 的限制，AI 无法写入位于当前项目目录之外的项目 memory files。

Learnings#

Key Learnings#

  • VLA backbones 中的 Quantization 可能从第一个 action block 开始就导致系统性的 ‘drift’，使得错误在与环境接触时立即发生。
  • 一个只能看到 tool calls 的 ‘guard’ 无法强制执行对话标准；行为必须直接嵌入到 ‘Skills’（行为指令）中。
  • Grok Bot 实际上是 Cursor 的一个 shell；其使用事件遵循 ‘cents-based’ 模型而非 token-based 模型。
  • 使用单个 dropdown 来驱动多个状态（例如，将 ‘To date’ 作为特殊值）可以显著简化 UI 复杂度。
  • 在使用 ‘idea graph’ 系统时，每个实现细节必须严格映射到一个 ID，以保持验证周期的完整性。
  • 通过在 D33 中将 ‘Main Task’ 与 ‘Progress Four-Items’ 合并，agent 的思考成本和回复长度得以降低，同时信息密度增加。
