问题与解决方案#

关键问题#

1. ARI 从 0.4+ 降至 0.13，不清楚之前配置为何有效#

解决方案： 版本对比显示代码被修改为使用 3000D 原始基因表达而非 50D PCA 嵌入进行 STAIG 训练；恢复使用 PCA 嵌入

关键发现： run_benchmark_core.py 包含了一个错误的“修复”方案，当 gene_encoder=‘pca’ 时通过 raw_gene_expr（3000D）通过，破坏了原本使用 50D PCA 特征的流程

2. 即使修复后测试结果显示 ARI=0.13 而非预期的 0.4#

解决方案： 发现测试是在 base/AI 环境中使用 kmeans 聚类的；历史成功案例是在 General 环境中使用 rpy2+mclust 聚类实现的

关键发现： 聚类方法（mclust vs kmeans）对下游指标有巨大影响；环境配置对于可重复性至关重要

3. 配置文件参数（num_epochs、learning_rate、num_hidden）未被正确读取#

解决方案： 更新 STAIGFusionTrainer.init 以从 staig_alignment_config 中读取所有训练参数，而不仅仅是 tau 和 num_layers

关键发现： 配置解析不完整导致使用错误的超参数进行训练，尽管 YAML 配置正确

4. edge_weight_method 默认值错误（‘softmax_log’ vs ‘softmax_neglog’）#

解决方案： 将默认值从 ‘softmax_log’（距离大 → 权重大）改为 ‘softmax_neglog’（距离小 → 权重大），以匹配已验证的高性能配置

关键发现： 边缘权重方向对基于图的学习有显著影响；STAIG 使用 log(distance) 而最优 MIHD 配置使用 -log(distance)

5. MIHD GCNGeneEncoder 架构与原始 STAIG 实现不一致#

解决方案： 添加 apply_activation_to_last_layer 参数（默认 True），以与 STAIG 设计保持一致，即所有层包括最后一层都应用激活函数

关键发现： 细微的架构差异（最后一层激活）会累积并导致与参考实现不一致

经验教训#

关键经验- 在机器学习回归调试中，环境配置（conda 环境、聚类库）可能比代码层面的修复更为重要；务必确保执行环境与历史成功情况一致。#

  • 在调试性能下降问题时，对比 git 历史与最新正常版本通常比直接修正当前代码更快；版本追溯应尽早进行。
  • 输入维度不匹配（50D PCA 与 3000D 原始特征）可能导致图神经网络性能严重下降；务必验证特征维度符合模型预期。
  • 看似微小的架构差异（最后一层激活函数、边缘权重方向）在复制研究实现时可能会累积导致显著差异；全面参数对齐至关重要。
  • 聚类方法选择（mclust 与 kmeans）对空间转录组评估指标有显著影响；通过 rpy2 集成 R 通常有助于复现生物信息学论文结果。
  • 并行代理部署用于跨代码库比较对系统化的架构分析非常有效；两个同时探索 STAIG 和 MIHD 的代理在一次运行中提供了全面对比。
