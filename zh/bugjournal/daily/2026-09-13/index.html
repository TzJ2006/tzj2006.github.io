Problems & Solutions#

Critical Issues#

1. Removing the interpreter wall allowed agents to bypass ledger protection by passing paths as quoted substrings in command arguments.#

Solution: 在 protectedTargetRefusal 中实现了第三次 scanning pass，使用 mentionedLedger 来将敏感路径作为 substrings 而非 whole tokens 进行检测。

2. Sudden FPS drop to 1-2 and mouse stutter despite low CPU/GPU utilization.#

Solution: 分析了 render thread states，发现它们卡在 ‘glfwSwapBuffers’，这表明是 sync/display bottleneck 而非 processing bottleneck。

3. The removal of the interpreter wall exposed two security leaks where the engine could be invoked via shell prefixes or nested calls.#

Solution: 增强了 ENGINE_INVOCATION regex 以处理 claude-/cursor- prefixes，并实现了用于 nested shell execution 的 NESTED_ENGINE_INVOCATION。

4. Potential driver-induced latency spikes noticed in traces.#

Solution: 调查了 DPC info，发现确实存在 4-16ms 的 spikes，但不足以解释极端的 1 FPS drop，因此将重心转向了 display pipeline。

5. Jump host connection timeout preventing remote deployment/startup.#

Solution: 等待 jump host 稳定。一旦连接恢复，使用 deploy_drawn_memory.sh 通过经允许的 .sh execution 来自动化未来的 deployments。

6. Guard restriction prevents the Agent from running local Python/SCP.#

Solution: 用户必须在本地运行 quad_scan.py (配合 VPN) 并手动 scp training script (或者在连接恢复后通过 deployment script)。

General Issues#

7. The install.ts --update command failed due to a malformed (non-UTF-8) JSON file in an unrelated repository.#

Solution: 识别出了导致冲突的具体文件，并选择仅将更新后的 bundle 安装到当前 repository，以避免数据丢失。

Learnings#

Key Learnings#

  • 依赖 ’layering’ 的 security barriers 可能会产生虚假的安全感；移除一层可能会揭示后续层之所以有效仅仅是因为第一层的存在。
  • 低 FPS 结合低 resource usage 通常指向 thread synchronization 或 display buffer blocking (例如 glfwSwapBuffers)，而非 hardware capacity。

Practical Learnings- ‘Self-test in module tail’ pattern 会产生技术债：立即实施修复会导致 ‘Red’ sign-off 变得陈旧/出现 unexpected-pass。未来的测试应当解耦。#

  • 修改 graph.yaml 中的 symbol 字符串会使现有的 approvals 失效，即使原本只想添加行号。
