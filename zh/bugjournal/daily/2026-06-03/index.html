问题与解决方案#

关键问题#

1. 意外的 302MB 构建文件提交破坏了仓库健康；完全重写历史可能破坏上游同步。#

解决方案： 识别出具体的错误提交，仅对祖先提交进行修改以保留完整性，成功减少了仓库大小，同时保持了与上游的 0-behind 状态。

关键洞察： 在清理分叉时，改变共享历史会改变祖先 SHAs；选择性修改比广泛过滤工具更有助于保持上游关系。

2. MacOS 的“应用损坏”错误和潜在的重复实例冲突最初被误认为是端口耗尽或签名问题。#

解决方案： 明确告知生产环境 Tauri 应用可能不会监听端口，实施了带有原生对话框的同步式预事件循环回环端口锁定机制，确保独占访问并稳健处理启动逻辑。

关键洞察： 跨平台的单实例检查必须独立于应用事件循环，同时考虑进程存在性和端口占用情况以确保完整性。

3. aidev install 的去重性检查失败是由于路径分隔符不一致（反斜杠与斜杠）以及不同平台上的标记文本差异所致。#

解决方案： 对标记进行模糊匹配，并在比较前对路径处理进行规范化，增加预飞行验证步骤以确保状态一致检测。

关键洞察： 跨平台的 CLI 工具必须标准化分隔符并检查目标的状态，而不仅仅是文件存在性，以保证真正的去重性。

4. MIHD Slurm 作业陷入 PD 状态；TokenMonitor 出现白屏是因为孤立的 Vite 端口；QueST 脚本出现 UnboundLocalError。#

解决方案： 通过切换设备类型解决 GPU 调度阻塞问题，清理僵尸进程以建立正常的端口绑定，并修复基准测试脚本中的变量作用域问题。

关键洞察： 在 HPC 中，特定硬件限制往往比分区优先级更阻碍作业；如果开发服务器崩溃后僵尸进程持续存在，Tauri 的严格端口模式会无声地失败。

人类与 AI 方法#

战略层面#

Git 历史管理策略#

角色 方法
人类 用户要求强制推送，但明确选择保留源分析器并拒绝推送发布标签，从而指导清理范围。
AI AI 最初尝试完整的 filter-repo，导致上游同步中断；在用户识别到“落后”状态异常后转向针对性修改。

差异分析： 人类提供了不应更改的内容（标签、共享祖先）的关键边界条件，防止了数据丢失或同步中断，而 AI 仅关注清理效果，未能注意到这些问题。

科学模型验证方法#

角色 方法
人类 人类确定了由于随机性导致输出完全相同是不可能的科学边界，将验证重点放在指标差异（ARI/NMI）上。
AI AI 首先关注代码逐组件差异，然后基于人类的约束条件设计经验验证框架。

差异分析： 人类早期提供了必要的科学有效性检查，避免了对不可复制性目标浪费努力。

单实例与 macOS 错误诊断#

角色 方法
人类 用户将 macOS 签名错误与实例冲突混淆，但正确识别了需要独占访问逻辑的需求。
AI AI 分离了根本原因（签名与锁定），但在实现中将它们合并到单一 robust 机制中。

差异分析： AI 填补了症状与实现之间的技术空白，确保解决方案同时解决环境错误和功能需求。

AI 限制#

关键限制#

  • 首次仓库清理尝试（filter-repo）未能预见对共享提交历史的影响，导致上游同步中断。
  • 最初将 macOS 运行时错误误认为是端口冲突而非签名/Gatekeeper 问题，可能是由于之前故障排除会话的上下文偏差所致。

一般限制#

总结- 由于 SLURM 队列延迟和时间限制，无法在单次会话时间内完成全部科学等价性测试。#

经验教训#

关键经验#

  • 在清理分叉仓库中的大量意外提交时，必须在操作前后验证 behind/ahead 状态与上游版本的差异；仅修改头提交即可保持祖先版本的完整性。
  • 在不同环境间验证科学代码等价性时，应始终以最终输出指标（如 ARI/NMI）作为验证依据，而非追求比特级的一致性。
  • 生产环境中的 Tauri 应用在启动时可能不会监听端口；单实例逻辑必须同步且独立于应用事件循环，才能确保稳定运行。

实际经验#

  • 用于多仓库部署的 CLI 工具必须能妥善处理平台特定的路径差异和现有状态变体（部分安装），以确保真正的幂等性。
