问题与解决方案#

关键问题#

1. 意外提交的约302MB构建文件破坏了仓库健康；完全重写历史可能破坏上游同步。#

解决方案： 识别了具体违规提交，仅对祖先提交进行了修改，成功减少了仓库大小，同时保持了与上游的0-behind状态。

关键洞察： 在清理分叉时，改变共享历史会改变祖先SHAs；选择性修改比广泛过滤工具更有助于保持上游关系。

2. MacOS“应用已损坏”错误和潜在的重复实例冲突最初被误认为是端口耗尽或签名问题。#

解决方案： 明确表明生产环境中的Tauri应用可能不监听端口，实施了带有原生对话框的同步、预事件循环回环端口锁定机制，确保独占访问并有效处理启动逻辑。

关键洞察： 跨平台的单实例检查必须独立于应用事件循环，同时考虑进程存在和端口占用情况以全面验证。

3. aidev install 因路径分隔符不一致（反斜杠与斜杠）以及不同平台上的标记文本差异导致幂等性检查失败。#

解决方案： 实现了标记的模糊匹配，并在比较前对路径处理进行规范化，增加了预飞行验证步骤以确保状态检测的一致性。

关键洞察： 跨平台的CLI工具必须标准化分隔符并检查目标状态，而不仅仅是文件存在性，才能确保真正的幂等性。

4. MIHD Slurm作业陷入PD状态；TokenMonitor出现白屏是因为孤立的Vite端口；QueST脚本出现UnboundLocalError。#

解决方案： 通过切换设备类型解决了GPU调度饥饿问题，清理了僵尸进程以建立正常的端口绑定，并修复了基准测试脚本中的变量作用域问题。

关键洞察： 在HPC中，特定硬件限制往往比分区优先级更阻碍作业；如果开发服务器崩溃后僵尸进程持续存在，Tauri的严格端口模式会无声地失败。
