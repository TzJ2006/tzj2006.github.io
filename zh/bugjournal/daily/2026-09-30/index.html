Problems & Solutions#

Critical Issues#

1. Gemini 驱动的 memory 任务中潜在的 proprioception 泄漏和非视觉窗口推进问题。#

Solution: 启用了 ‘VISUAL_ONLY’ 以剥离 state，并启用 ‘VISUAL_TRACK’ 以基于 VLM tip-detections 而非 TCP/proprio data 来推进 windows。

2. OmniJev PickHighlight 报告的 recall 过低，以及 2B model 在 temporal tasks (Swap/StopCube) 中表现不佳。#

Solution: 修正了 metric frame population，并将架构转向使用 code 处理 temporal logic/identity，而由 VLM 处理 per-frame perception。

3. W4A4 simulation 显示 0% 成功率，而实际 hardware 保持较高的准确率。#

Solution: 确定 simulation 过于悲观，是因为对 hardware 实际以 FP16 处理的 tensors 进行了过于激进的 4-bit rounding。

4. Robotics pipeline 错误，包括 JSON serialization (np.bool_)、BC-RNN 中未裁剪的图像格式以及 human demo state 不匹配。#

Solution: 在 ‘core.py’ 中识别了 serialization 需求，在 ‘policy_adapter.py’ 中要求进行 HWC image 修复，并修正了 ‘replay’ 设置以确保 error-state 恢复。

5. 通过 system tray 退出 Tauri app 后，Vite processes 在 Windows 上仍保持活跃。#

Solution: 用显式的基于 POST 的 notification 取代了 polling 机制，该通知由 Rust backend 发送到专门的 Vite plugin endpoint。

6. WeChat stickers 被作为 images 发送，以及错误的 database confirmation 报错。#

Solution: 实现了基于 UIA 的 panel browsing 用于 sticker similarity 匹配，并禁用了严格验证以处理 WeChat write latency。

7. C2S 在特定 GPU nodes 上出现 NaNs 以及无效的 matrix command arguments。#

Solution: 识别了特定节点的硬件问题 (h36-6) 并将其从 templates 中排除；通过 subagent audit 协调了 command arguments。

AI Limitations#

Critical Limitations#

  • 在模拟 ‘pure visual’ 模式方面存在固有局限性（潜在的 lag/drift），以及基于 UI 的 expression browser 速度较慢（每个 sticker 需 5-7s）。
  • 在 temporal reasoning (identity tracking)、高精度 point generation 以及复杂的 custom data structure 错误 (AttributeError/KeyError) 方面表现挣扎。

General Limitations#

  • 遇到了环境限制（向 memory directories 写入）以及需要人工干预的 shell redirection/tool-call 阻断。

Learnings#

Key Learnings- 一个轻量级的 2B VLM 在识别方面表现出色，但在 temporal reasoning 和 identity tracking 方面需要 code-driven assistance。#

  • 在特定硬件上，由于硬件在某些 ops 上会自动使用 FP16，导致 4-bit simulations 在预测 accuracy 时不可靠。
  • 对所有 randomness 进行 seeding（包括 env resets 和 Python 的 hash()）对于 robotics benchmark 的 reproducibility 至关重要。
  • Visual prompts（将 memory 绘制到 observation 中）在 path-related tasks 中的表现显著优于 text-based memory。
  • 在 Tauri/Vite 等 multi-process environments 中，显式的 exit signaling 比在 Windows 上的 ancestry/polling tracking 更稳健。
