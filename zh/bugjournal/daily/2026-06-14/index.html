问题与解决方案#

关键问题#

1. STAIG 报告的 0.68 ARI 不可复现且依赖于 mclust 初始化种子；scGPT/TEDDY 嵌入在空间聚类中表现不佳。#

解决方案： 进行了 100 种子统计扫描，发现高方差（0.49-0.64），并确认 UNI2 的优越性（最高 0.703 ARI）。发现了“基因-FM 悖论”，即基因基础模型在空间区分信号方面低于 HVG。

关键洞察： 发布的随机算法基准测试需要统计验证；通用基因编码器可能不适合空间领域的图对比学习。

2. ccusage 20.x 统一输出合并了所有代理源，丢失了双轨报告所需的逐源细粒度。#

解决方案： 发现 ccusage <source> daily 允许命名空间查询。通过元数据实现逐源发现，并采用模式规范化进行单独获取，确保向后兼容和未来的可扩展性。

关键洞察： CLI 依赖升级常常会无声地改变 JSON 模式；在架构变更前立即进行新输出格式的本地测试至关重要。

3. 桌面视频画廊缩略图空白是由于沙箱书签范围不匹配和缓存键缺失造成的。解决方案： 实现了双分支书签解析（范围限定 + 备用方案），并更新了缓存键以包含内容修改日期。在 SwiftUI 视图中添加了同步状态初始化，以防止导航过程中出现闪烁现象。#

关键洞察： 异步失败常常会破坏状态机；沙箱化的 macOS 应用需要明确的非范围限定备用方案，以确保旧数据的完整性。

4. NVIDIA RTX 5090 驱动程序失败，原因是安全启动拒绝自签的 DKMS 模块。#

解决方案： 删除了 nvidia-dkms 包，加载了 Canonical 预签名内核模块，无需禁用安全启动即可解决“密钥被拒绝”错误。

关键洞察： 在启用安全启动的现代 Ubuntu 系统中，由发行版管理的签名模块比自定义 DKMS 构建更安全、更可靠。

5. Vite dev-server 在 NTFS 挂载设备上无法加载 FloatBall CSS 模块，原因是 .vite-temp 缓存失效。#

解决方案： 停止 dev 服务器，清除 node_modules/.vite 和 .vite-temp，然后重新启动。根本原因是 Vite 在不稳定的 FUSE 挂载上的原子重命名失败。

关键洞察： Vite 的依赖优化对文件系统稳定性非常敏感；失效的临时文件会导致懒加载组件中的模块图不同步。

6. 历史视图在不同屏幕上显示相同的列表，原因是全局过滤和缺少屏幕说明。#

解决方案： 重构数据模型，在 WallpaperHistoryEntry 中加入 “playedScreens” 映射。为没有屏幕 ID 的旧项目实现了按屏幕分区的清理和迁移逻辑。

关键洞察： 全局数据结构无法支持多租户或多显示器环境；模式迁移必须明确处理向后兼容性和维度限制。

7. 安全漏洞：在 ccusage 迁移过程中，工作流钩子豁免检查和使用文件保存时可能存在路径遍历风险。#

解决方案： 在 check_spec.py 中标记出豁免绕过情况（需要规范路径解析），并建议对 save_usage_file 文件名清理采取多重防护策略，尽管上游的 ccusage 验证已提供了缓解措施。

关键洞察： 基于字符串的路径检查 startswith 存在遍历风险；外部工具退出码不應成为文件系统操作的唯一安全机制。

差异分析： 人类关注感知效果（无闪烁），迫使 AI 超越逻辑延迟，追求数据结构保证。

AI 自主代理基于通用的 Swift 模式猜测基于范围的释放，未能考虑 AppKit/AVFoundation 特定的强引用语义。

差异分析： 人类表现出更好的领域特定上下文意识，用具体代码证据替代 AI 的通用静态分析。

AI 局限性#

关键局限#

  • 初始工作流代理将 AVDataAsset 内存保留错误标记为漏洞，因为对 AppKit 引用语义的上下文有限。

一般局限#

  • AI 最初假设 MIHD 的 niche 采样需要从头构建，未能立即识别 niche_utils.py 中现有的基础设施。
  • AI 在未经实验验证的情况下难以解释 STAIG 的 ARI 差异，依赖文本分析后再转向代码执行。
  • AI 最初假设 Vite 失败的原因是 CRLF 换行或语法错误，需要更多证据才能确定实际的 NTFS 缓存不同步问题。
  • AI 试图为 TokenMonitor 提出基于云的同步解决方案，忽视用户的 “本地优先” 约束，直到被明确纠正。

经验教训#

关键经验#

  • mclust EM 聚类对初始化范围非常敏感（n>2000）；没有多次采样验证，单次运行的 ARI 分数不可靠。
  • 在 Linux 的 NTFS/FUSE 挂载上，Vite 的原子依赖优化可能无声失败，留下 .vite-temp 文件对象，导致懒加载组件中的 dev 服务器模块图不同步。
  • CoreMedia 和 WebKit 沙箱日志通常是无害噪声；日志筛选中的误报可能导致追逐幽灵错误，如果不了解框架语义的话。

实际经验#

  • 按源文件跟踪令牌需要强大的模式规范化 _normalize_usage，因为不同代理 CLI 通常使用不兼容的 JSON 字段名。
  • 全局数据限制在多显示器环境中无效；历史/跟踪系统必须考虑维度，并基于唯一标识符（如屏幕 UUID）进行键控。
