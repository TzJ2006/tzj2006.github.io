Problems & Solutions#

Critical Issues#

1. W4A4 quantization 导致 ‘middle-drawer’ 任务成功率为 0%（目标识别错误）。#

Solution: 隔离了 35 个 RMSNorm 输出 tensors，并应用 AIMET 的 TF-Enhanced range setting 以减轻来自 outliers 的噪声。

Key Insight: 失败原因是 min-max quantization ranges 被均匀分布的 activation tensors 中的 outliers 拉伸，导致每层注入了约 10% 的噪声。

2. NVML/GPU invisibility error 以及 Training/Test mismatch。#

Solution: 清理了孤儿进程以恢复 GPU 访问；从头开始重新启动训练，以确保 policy 学习新的 bottom-right/scene-anchored 分布。

3. Gemini 的 visual prompts/scoring 不一致（过早计数，错误的 identity tracking）。#

Solution: 将优先级从修复 Gemini 的错误转向使用 ground-truth ‘Oracle’ 系统来生成完美的 visual prompts，用于训练机器人。

Key Insight: 对于 memory 任务来说，‘Target Hit Rate’ 是一个危险的指标，因为它将 object detection 与实际的 history memory 混为一谈。

4. 关于 $\pi$0.5 training methodology 的歧义（LoRA vs Full Fine-tuning）。#

Solution: 检查代码以确认对 LLM 和 action expert 进行 full-parameter fine-tuning，同时保持 SigLIP visual tower frozen。

General Issues#

5. Visual elements (icons/badges) 被机器人的 random cropping/rotation 截断。#

Solution: 将坐标从 (3,3) 移动到 (16,16)/(26,26)，以确保在 95% 的 random crop 场景下可见。

Key Insight: Visual prompts 必须具备 ’training-robust’ 特性才能在 augmentation 中存活。

6. Evaluation script 留下了消耗约 230GB VRAM 的孤儿 server processes。#

Solution: 修改了 cleanup logic，终止整个 process tree/PIDs 以确保 GPU 恢复。

Key Insight: 在复杂的环境中，标准的 process termination 通常无法清理子进程。

Learnings#

Key Learnings#

  • 任务复杂度与 quantization 敏感度并不相关；需要在相似目标之间进行细粒度选择的任务（middle vs. top drawer）最容易受到噪声的影响。
  • RoboMME 的 $\pi$0.5 baseline 会 freeze SigLIP visual tower，并对 LLM 和 action expert 进行 full-parameter updates。
  • Visual prompts 必须优先考虑“training-robustness”（在 crop/rotate 后仍能生存）和“policy-utility”（scene-anchored vs. corner glyphs），而非美观度。
  • “Target Hit Rate”对于 memory tasks 是一个危险的指标：它将“知道看哪里”与“记住发生了什么”混为一谈。
