AI Limitations#

Critical Limitations#

  • AI 在处理新的强制性 manual approval (D7) 和 guard (D21) 规则时感到困难，导致 tool 尝试被拒绝以及 shell commands 被拦截。

General Limitations#

  • AI 最初相信 documentation 中的说法（如 per-token quantization），而没有验证底层的 implementation code。
  • AI 通过 heredocs 生成的代码经常因为 escaping issues 和 shell redirection blocks 导致 SyntaxErrors。
  • 由于自动化环境中的 window focus/context mismatches，AI 无法与系统级 file dialogs 进行交互。
  • read 工具无法读取目录 (EISDIR)，导致在扫描 worktree paths 时产生 warnings。

Learnings#

Key Learnings#

  • 在 HTP 上针对 mixed-precision (float islands) 的成功编译并不保证 4-bit execution；它通常会触发整个 operator chains 向 float 的 silent fallback。
  • 对于 partially observable games，一个模拟 ‘cost-to-uncover’ 的 simulation 比纯 RL 或 greedy heuristics 要有效得多。
  • 当在 engine/logic level (setStatus/applyApproval) 而非仅仅在 UI level 实现强制执行时，效果会更好。
  • 通过 AI guardrails 严格执行 ‘idea-first’ 工作流可以防止不受控制的 code sprawl，但这要求 AI 对 graph 的 ‘status’ 和 ‘doing’ 状态具有高度感知。
  • ‘clean’ 和 ‘dirty’ memory 之间的区别对于解释 peak memory metrics 至关重要：weights 是 file-mapped clean pages，不计入 non-clean ‘memory footprint’。
  • 在神经网络中，step function 缺乏 gradient 是至关重要的，因为其导数几乎处处为零，而不仅仅是在 threshold 处。
  • 通过 ‘coord’ 进行 multi-session coordination 是可用的，但 agents 不会自动使用它；需要手动协调以防止同时进行 graph 写入。
  • 在大规模项目中，“container ideas”对于防止认知过载和维持可管理的 graph 层级的重要性。
