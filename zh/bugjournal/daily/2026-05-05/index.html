    关键问题#

    1. NVIDIA RTX 5090 在 5 个月内产生 1010 次 WHEA PCIe AER Unsupported Request 错误，导致间歇性蓝屏。错误集中在空闲期间和启动阶段，而非 GPU 压力测试期间。#

    解决方案： 确定根本原因是 NVIDIA 驱动器的 PCIe 链接状态电源管理（空闲时 Gen5 → Gen1 降档）。在重新协商过程中，GPU 在地址空间完全恢复前发送内存映射 I/O 请求，引发 UR。通过设置 NVIDIA 控制面板 → 电源管理模式 → 优先采用最高性能模式来修复。验证结果：重启后 19 分钟运行期间无新错误，仅有 2 次启动时的错误（硬件初始化，不可避免）。同时解决了 5 秒的 HDMI 音频延迟问题（相同原因：音频控制器 D3cold 睡眠）。

    关键洞察： Windows ASPM Off 设置仅影响操作系统级别的 PCIe 电源策略；NVIDIA 驱动器和 BIOS 仍可独立执行链接状态切换。“纠正错误”这一描述掩盖了严重性——累积的 UR 错误最终会破坏驱动器状态并触发内核错误检查。社区研究证实这是多个主板厂商普遍存在的 RTX 5090 + PCIe Gen5 兼容问题。

    2. 上游维护者担心 statusline 重写和 OAuth/Keychain 移除带来的架构冲突会影响 Codex/Cursor 速率限制。#

    解决方案： 记录这些冲突已通过合并提交 f6e0982 和 4492d2f 解决，Codex 使用 CLI 抓取（而非 OAuth），Cursor 不需要密钥库提示。

    关键洞察： 带有明确功能恢复合并提交的增量合并策略可在采用上游架构变更的同时保留下游创新。

    3. Codex 积分余额显示为单位美元（$2,116.02），导致用户困惑。#

    解决方案： 在 UsageBars.svelte 中替换 formatUsdAmount() 为 Math.round().toLocaleString() + “credits”后缀，确认修复不影响 Cursor 的 extra_usage，后者正确使用美元。

    关键洞察： 多供应商系统需要针对每个供应商单独处理单位——Codex 使用“积分”，Cursor 使用美元；不能假设所有供应商采用相同的货币格式。

    4. Rust 测试 oauth_token_prefers_credentials_file_on_macos 在 CI 中失败，提示“Claude 凭据文件不可用（/var/folders/…/tmp/.claude/.credentials.json）”。测试将文件写入 tmp/.credentials.json，但查找路径指向 tmp/.claude/.credentials.json，表明未遵守 CLAUDE_CONFIG_DIR 环境变量。#

    解决方案： 根本原因是 rate_limits/claude.rs 和 statusline/install.rs 测试使用不同的 mutex 锁（ENV_LOCK 与 env_lock()）保护 CLAUDE_CONFIG_DIR 操作。并行测试执行导致 statusline 测试覆盖 claude 测试的环境变量值。通过修改测试直接调用 read_token_from_credentials_file() 来修复，消除对环境变量解析和 macOS 密钥库回退的依赖，同时修复了未使用的导入项 ‘Local’（测试模块单独重新导入）和 claude_settings_file 的死代码警告（将 #[cfg_attr(not(test), allow(dead_code))] 改为 unconditional #[allow(dead_code)]）。

    关键洞察： 并行测试中不安全的环境变量操作需要所有测试模块共享的单一全局锁——局部模块级锁会产生虚假安全性。#[cfg(test)] 导入可能在测试子模块使用 super::* 后重新导入同一项时使 rustc 困惑。cargo fmt 要求 #[cfg(test)] 导入在常规导入之后排序。

    学习成果#

    关键学习点#

    • PCIe 高级错误报告中的“不支持请求”可能由 NVIDIA 驱动在空闲期间自动进行 Gen5↔Gen1 链接状态电源管理引起。Windows powercfg ASPM 设置（链接状态电源管理）仅控制操作系统级策略；GPU 驱动固件和 BIOS 独立管理 PCIe L 状态。RTX 5090 + PCIe Gen5 存在已知兼容问题，在重新协商期间当 GPU 尝试访问内存映射地址空间时会导致 UR 错误。社区验证的修复方法：强制使用“优先最大性能”或锁定 BIOS PCIe Gen4。
    • 多提供商速率限制系统需要仔细处理每个提供商的单位转换——假设统一货币格式会在提供商使用不同单位时失效（Codex “积分”与 Cursor USD）。
    • 分支维护策略：逐步合并上游架构变更，并添加明确的功能恢复提交；主动记录冲突以维持上游关系。
    • Rust 并行测试套件涉及环境变量操作，需要所有测试模块共享一个全局互斥锁——模块 A 中的本地锁（static ENV_lock），模块 B 中的单独 env_lock() 会在同时修改相同环境变量时产生竞争条件。导入中的 #[cfg(test)] 属性如果测试子模块使用 “use super::*” 则可能导致“未使用”警告，此时重复导入同一项。cargo fmt 要求条件性导入（#[cfg(test)））在无条件导入之后排序。
    • 两层去重（远程 Python 脚本 + 本地 HashSet）能有效防止分布式日志聚合系统中的重复记录，当多个设备向共享存储追加数据时。
