    关键问题#

    1. NVIDIA RTX 5090 在5个月内产生1010次 WHEA PCIe AER Unsupported Request错误，导致间歇性蓝屏。错误集中在空闲期间和启动时，而非 GPU 压力测试期间。#

    解决方案： 确定根本原因是 NVIDIA 驱动器的 PCIe 链接状态电源管理（空闲时 Gen5 → Gen1 降级）。在重新协商过程中，GPU 在地址空间完全恢复前发送内存映射 I/O 请求，引发 UR。通过设置 NVIDIA 控制面板 → 电源管理模式 → 优先使用最高性能模式来修复。验证结果：重启后19分钟运行期间无新错误，仅有2次启动时的错误（硬件初始化，不可避免）。同时解决了5秒的 HDMI音频延迟问题（相同原因：音频控制器 D3cold 睡眠）。

    经验教训#

    关键经验#

    • PCIe 高级错误报告中的“不支持请求”可能由 NVIDIA 驱动程序在空闲期间自动进行 Gen5↔Gen1 链接状态电源管理引起。Windows powercfg ASPM 设置（链接状态电源管理）仅控制操作系统级别策略；GPU 驱动程序固件和 BIOS 独立管理 PCIe L-states。RTX 5090 + PCIe Gen5 存在已知兼容问题，在重新协商期间，GPU 尝试访问内存映射地址空间时会出现 UR 错误。社区验证的修复方法：强制“优先最大性能”或锁定 BIOS PCIe Gen4。
    • 多提供商速率限制系统需要仔细处理每个提供商的单位转换——假设统一货币格式会在提供商使用不同单位时失效（Codex “积分”与 Cursor USD）。
    • 分支维护策略：逐步合并上游架构变更，并附带明确的功能恢复 commit；主动记录冲突以维持上游关系。
    • Rust 并行测试套件涉及环境变量操作，需要所有测试模块共享一个全局 mutex——每个模块的本地锁（模块 A 中的静态 ENV_lock，模块 B 中的单独 env_lock()）会在同时修改相同环境变量时产生竞争条件。导入中的 #[cfg(test)] 属性如果测试子模块使用 “use super::*” 则会导致“未使用”警告，因为重复导入同一项。cargo fmt 要求条件导入（#[cfg(test)））在无条件导入之后排序。
    • 两层去重机制（远程 Python 脚本 + 本地 HashSet）可有效防止分布式日志聚合系统中多个设备向共享存储追加时产生重复记录。
