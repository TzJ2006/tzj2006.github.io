Problems & Solutions#

Critical Issues#

1. 由于隐藏的 proprioceptive 数据使用导致 robot policy 评估成功率虚高。#

Solution: 实现了 DRAWN_MEMORY_VISUAL_ONLY/TRACK 标志以强制实现零 proprioception，将成功率修正为 65.0%。

2. VLA quantization 在准备 QNN/HTP 导出期间导致成功率下降。#

Solution: 正在探索在 RMSNorm 输出上使用 TF-Enhanced 以及对关键 tensors 进行整数保留。

3. 由于 SQLite WAL 事务不完整导致 wechatauto 中的数据库损坏。#

Solution: 修复了 WAL merge 逻辑以正确处理事务。

General Issues#

4. 基础设施和环境问题：GPU OOM、Pip ‘Access Denied’ 以及 LocalSend 发现失败。#

Solution: 开发了 bash/PS1 脚本以便在备用 GPU 上重启服务器，对 pip 使用了 –no-cache-dir，并推荐使用 Tailscale 进行 P2P 连接。

5. 不同工具（auditor/augmenter）之间的 demo 结果不一致，以及游戏 UI 自动化焦点丢失。#

Solution: 将工具统一在单个共享的 replay routine 下；建议对游戏自动化进行手动窗口管理。

6. 由于 glue code bug 导致的 N-15 pilot 失败。#

Solution: 修复了 protocol fingerprint 记录和 pandas 3 兼容性问题。

7. 由于 XLA autotuning 和 worker 调度导致的 Pi0.5 数值和场景生成的非确定性。#

Solution: 实施了强制确定性的 XLA autotuning、唯一的 JAX cache 目录，并稳定了 worker RNG seeds。

AI Limitations#

Critical Limitations#

  • 在人类提示之前，未能识别 policy 评估中的非视觉数据泄漏；在复杂的 UI 自动化中难以保持注意力。
  • 在没有用户干预的情况下，无法做出高层级 policy 决策（例如定义“碰撞”）或执行物理上的 human-in-the-loop 任务。

General Limitations#

  • 在验证之前，最初对特定平台的存储/限制（Telegram/WeChat）做出了过度泛化的断言。
  • 技术护栏问题（在项目边界外写入）以及针对复杂 WeChat UI 元素的实验性 OCR 局限性。

Learnings#

Key Learnings#

  • XLA autotuning 和 proprioceptive 数据泄漏是 robotic benchmarks 中非确定性和性能虚高的关键隐藏来源。
  • 成功的 VLA hardware 导出 (QNN) 需要仔细管理 activation-only recalibration 和 precision tensors。
  • 对于研究导向的应用（CVs/PhD），叙述应优先考虑问题定义能力和研究直觉，而非原始指标。
  • SQLite WAL merging 需要精确处理最后一次提交的 frame，以防止在同时写入期间发生主 DB 损坏。
  • 通过实时 shell 命令注入和显式的 cache 管理，可以显著改进自动化 VM 部署。
