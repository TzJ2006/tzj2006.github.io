AI Limitations#

Critical Limitations#

  • Agent 难以执行 file writes 或 shell commands，因为它无法在没有用户于 IDE 中干预的情况下诊断 “fail-closed” security hook。
  • Assistant 试图使用外部 web service (Google Translate) 处理敏感的项目文本，这违反了 security protocols。
  • AI 通过在记录 “red” 状态后修改 test files 导致了逻辑死锁，使得记录变得 “stale” 并阻塞了 implementation。
  • AI 最初未能识别出 engine 的 “serve” command 缺少 “–git-sync” flag，导致 sync workflow 中出现 silent failure。

General Limitations#

  • AI 用于运行 writer script 的 command 存在 path inference bug，导致多个 task failures。 | - AI 的 grep commands 最初过于宽泛 (substring matches)，导致 audit report 中的计数不正确。

Learnings#

Key Learnings#

  • “Four-Quadrant” 分类法 (Who moves x When it moves) 对于 VLM memory generation 是一种非常有效的 prompt structure。
  • 对于高风险的写作 (SoP)， “generic core” 必须足够强大，能够连接多个不同的 “customized hooks” 以防止 logical drift。
  • Funding 通常由 institution 保障，但研究资源 (robots/GPUs) 严格依赖于 advisor；实现 advisors 的多样化比研究课题的多样化更为关键。
  • 系统设计中的复杂度往往源于文档中 “unclaimed ideas”；有必要对所有新想法严格执行 “8-question” framework。
  • 在迁移大量小文件 (pkls) 时，按 filename-prefix 进行 parallelization 比标准的 directory-tree rsync 效率显著更高。
  • Visual prompting 需要 task-specific markers (path, ring, badge)，而非统一的 rendering primitive，以避免 “false memory” 错误。

Practical Learnings#

  • 在迁移 environments 时，仅复制 binaries 是不够的；必须验证并一同移动 RPATH 和 shared library dependencies。
  • 使用本地 LLM (Gemma 4) 进行大批量文本翻译 (130k+ characters) 对于在技术项目中保持 data sovereignty 是可行的。
  • 低 CPU/GPU utilization 并不排除 system lag；DWM compositor contention 和高分辨率 scaling (4K) 会导致显著的 frame latency。
