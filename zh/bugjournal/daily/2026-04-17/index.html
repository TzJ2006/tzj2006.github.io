问题与解决方案#

关键问题#

1. 修改 config.yml 后网站菜单布局完全损坏（垂直堆叠而非水平导航栏）#

解决方案： 发现自定义 header.html 使用 class=‘nav’ 类，而 PaperMod 主题 CSS（更新后）期望 class=‘header-nav’ — 将模板改为与主题一致

关键洞察： 自定义主题覆盖必须与主题更新保持同步 — CSS 选择器不匹配会导致无声的布局失败，而无需构建错误

2. faster-whisper 在 macOS 上仅使用 CPU（无 CUDA），导致推理速度慢#

解决方案： 迁移至使用 Apple Silicon Metal GPU 的 mlx-whisper，从 WhisperModel API 改为使用 mlx_whisper.transcribe() 并包含预热步骤

关键洞察： CTranslate2 基于模型需要 NVIDIA CUDA；在 Apple Silicon 上，mlx 类替代方案提供原生 Metal 加速

3. 当捕获键盘输入声音时，Whisper 产生重复幻觉（“Meh Meh Meh…”）#

解决方案： 将 silence_threshold 从 0.008 调整为 0.02，添加 compression_ratio_threshold=2.4 和 no_speech_threshold=0.6 以过滤非语音音频

关键洞察： 较低的静音阈值会导致非语音声音产生 ASR 幻觉；VAD 预过滤或更严格的阈值对于嘈杂环境至关重要

4. 单语言 ASR 参数不足以处理混合语言会议（中文+英文）#

解决方案： 设计了 –language 参数，包含三种模式：zh（强制中文）、en（强制英文）、zh+en（Whisper 使用 initial_prompt 处理混合语言，Qwen3-ASR 自动检测）

关键洞察： 混合语言支持需要针对不同后端的策略：Whisper 使用 initial_prompt，Qwen3-ASR 使用语言参数，Sherpa 采用原生双语模式

5. 无预处理情况下的嘈杂环境中 MeetingHelper ASR 精度下降#

解决方案： 实现了使用 noisereduce 库的 NoiseSuppressor 类，通过频谱门控（stationary=True, prop_decrease=0.8），在捕获前 0.5 秒自动校准噪声轮廓，集成到 ASR 前的 sd.InputStream 管道中

关键洞察： 实时音频处理需要在捕获和 ASR 之间进行去噪，而非之后；基于 RMS 的静音检测应在去噪后进行以准确设定阈值

6. Hugo 构建失败可能导致 public/ 目录为空或部分缺失，但 update.sh 仍会尝试 git push 部署#

解决方案： 在 hugo 命令后添加 if [ ! -f “$PUBLIC_DIR/index.html” ]; then exit 1; fi 检查

关键洞察： 关键构建步骤需要在不可逆转的 git push 操作前进行合理性检查 — 仅使用退出代码不足

7. compress_video.py 使用模块级代码，如果 HandBrakeCLI 失败会产生临时文件且无法清理，导致不可安全导入#

解决方案： 添加了 if [ ! -f “$PUBLIC_DIR/index.html” ]; then exit 1; fi 检查解决方案： 重构为 compress_video() 函数，使用 try/finally 处理临时文件清理，将 CLI 逻辑移至 main() 函数中

关键洞察： 适用于 CLI 和导入使用的 Python 脚本必须将副作用分离到函数中，并使用 if __name__ == '__main__' 保护机制

常见问题#

8. update.sh 中的 run_translation_phase() 使用 shift 移除第一个参数，但调用点传递描述字符串，导致参数处理混乱#

解决方案： 从函数中移除 shift 操作，并从所有调用点移除描述字符串参数

关键洞察： Shell 函数无需显式消耗描述参数——让调用者只传递函数实际使用的参数即可

9. stop.sh 无法可靠终止子标题窗口进程，导致孤立的 Python 进程残留#

解决方案： 实现两阶段终止：发送 SIGTERM 信号，等待 3 秒，若进程仍存活则升级为 SIGKILL，并基于 pgrep 清理孤立进程

关键洞察： PyObjC 的 app.run() 可能不响应基本信号；可靠的进程管理需要超时、升级机制和进程扫描

经验教训#

关键经验- 自定义 Hugo 主题覆盖必须与上游主题变更进行审核——主题中的 CSS 类重命名会无声地破坏自定义模板，不会产生构建错误，只会导致运行时布局失败#

  • 昂贵的后台操作（大文件下载、项目扫描）应作为明确的用户操作并带有进度指示，而非隐藏的自动 fallback
  • Apple Silicon ASR 优化：CTranslate2（faster-whisper）需要 CUDA，在 macOS 上使用基于 mlx 的替代方案实现 Metal GPU 加速
  • 音频流处理去噪必须在捕获之后、ASR 之前进行：在 data.flatten() 之后但 stream.accept_waveform() 之前插入 NoiseSuppressor，可最大化效果。使用初始静音期（0.5 秒）进行噪声指纹校准，无需预训练模型即可减少静态噪声
  • 基于浏览器的视觉调试（DevTools inspect → 检查应用样式 → 追踪选择器不匹配）比服务器端文件验证更能解决 CSS 布局问题
  • 混合语言 ASR 需要针对不同后端策略：Whisper 需要 initial_prompt 引导，Qwen3-ASR 可通过 language=None 自动检测，Sherpa 拥有原生双语模型
  • ASR 幻觉（重复输出）通常源于低静音阈值捕获非语音声音；VAD 预过滤或更严格的阈值可解决此问题
  • .claude/settings.json 可以共享给团队（应提交到版本控制），而 .claude/settings.local.json 是个人使用（应被 gitignored）
  • Bash set -e 不会传递后台任务的退出码——必须使用 wait $pid || fail_flag=1 模式来捕获并行任务错误
  • Claude Code 钩子系统只能执行 shell 命令，不能直接调用技能；在钩子触发后，使用 JSON 输出提示 Claude 执行技能

实用经验总结#

  • 进程终止的鲁棒性需要超时 + 信号升级（SIGTERM → 等待 → SIGKILL） + 清理扫描（pgrep）
  • ANSI 终端转义码如果从彩色 CLI 输出中复制粘贴到配置文件中，会污染配置文件，破坏期望纯文本的解析器
  • 用于 CLI 和导入的 Python 脚本必须使用 if name == ‘main’ 保护，并将副作用封装在函数中——模块级代码中的资源分配会导致清理风险
  • Hugo 的 public/ 目录通常是一个独立的 git 仓库用于部署（GitHub Pages）——在缓存清理时删除 rm -rf public/ 会破坏部署历史
