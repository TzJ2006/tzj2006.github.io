问题与解决方案#

关键问题#

1. revalidate_demos.py:96 中的漏洞：obj_orientations 四元数数据被错误写入 obj_positions 字典，导致数据丢失#

解决方案： 将第96行从 ‘obj_positions[key[4:-5]]’ 改为 ‘obj_orientations[key[4:-5]]’，以将四元数写入正确的字典

关键洞察： 数据加载代码中的复制粘贴错误可能会悄无声息地破坏多字段数据结构

2. determine_counts_toward_target 在字段存在时返回缓存的 counts_toward_target 值，导致在新配额规则下无法重新评估#

解决方案： 在重新验证过程中调用 determine_counts_toward_target 前清除 counts_toward_target 和 quota_reason 字段

关键洞察： 需要重新计算时，检查预计算值的函数必须明确清空缓存

一般问题#

3. NumpyEncoder 类在4个独立文件中重复存在（resegment_recovery_demos.py、3_mimicgen_recovery_augment.py、2_collect_recovery_demos.py、revalidate_demos.py）#

解决方案： 将 NumpyEncoder 移动到 shared script_utils.py 中，并更新所有消费者从那里导入

关键洞察： 共享的JSON编码逻辑应存在于通用工具中，以避免漂移和维护负担

4. 对正确CLI语法存在初始不确定性——仓库README提到/plugin命令，但实际CLI使用‘claude plugin’结构#

解决方案： 在执行命令前通过 ‘claude –help’ 和 ‘claude plugin –help’ 验证实际CLI功能，确认正确语法为 ‘claude plugin marketplace add’ 和 ‘claude plugin install’

关键洞察： 外部文档可能与本地CLI语法不完全一致；在执行安装命令前务必通过本地帮助文档确认

5. tag_npz_validation 和 save_manifest 函数在 revalidate_demos.py 和 2_collect_recovery_demos.py 中重复存在#

解决方案： 将这两个函数移动到 shared recovery_collection_validation.py 模块中，并更新消费者从那里导入

关键洞察： 验证和持久化逻辑应集中在验证框架模块中
