问题与解决方案#

一般问题#

1. AI 最初建议在 Lighthouse 的 settings.json 中编辑 env_disabled_aws，违反了 JSON 模式验证。#

解决方案： 用户提供了错误输出；AI 通过复制原始文件作为备份，然后完全移除无效的 env 块来纠正策略。

关键洞察： 在修改结构化配置文件之前，始终需验证 JSON 模式约束。

2. 环境变量已在活动会话中加载，因此配置文件更改在重启前无效。#

解决方案： AI 明确指示用户重启 Claude Code 进程以使更改生效。

关键洞察： CLI 工具通常在启动时加载环境变量；运行时配置修改需要服务重启。

3. Lighthouse 会话丢失了关于特定认证机制的信息，导致 AI 提出不必要的重新安装建议。#

解决方案： 用户说明“我没有注销选项，因为我使用配置文件”，使 AI 正确识别根本原因是静态配置标志而非有状态登录令牌。

关键洞察： 无头或基于配置的工具通常忽略标准的 /logout 命令；认证直接绑定在配置文件上。
