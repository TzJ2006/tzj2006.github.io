经验教训#

架构 (architecture)#

  • 无约束领域适应会破坏几何特征；明确的结构先验和温和的域内方差约束对于保留层次信息至关重要。将内容生成与本地化层分离，并强制隔离 UI/有效载荷区域可防止级联故障。动态解析架构相比静态数组大幅减少维护负担，特定平台约束需要架构重构而非迭代调试。

调试 (debugging)#

  • 自动化审计通常包含推测性结论；在优先修复前，实时文件系统枚举和运行时状态三角测量至关重要。微小的依赖版本不匹配会破坏低级张量操作，需要严格的环境隔离。静态正则表达式解析无法处理复杂元数据/引用，需要明确的验证循环。并行数据生成器需要明确排序的上游准备以防止静默数据缺失。

工具 (tools)#

  • 临时上下文在长期重构期间会退化；分块上下文合并结合明确的磁盘存储和生命周期感知钩子显著优于迭代提示修补。macOS ML 工作负载根本需要基于原生硬件的框架（MLX/CoreML），而非依赖 CUDA 的端口。本地 vLLM/卸载提供确定性推理，避免 Python 层面瓶颈。框架原生评估 API 应始终优先于自定义包装器，以避免张量布局冲突。

领域知识 (domain)#

  • 跨化学泛化需要基于变化的公式和几何连续性约束，而非绝对状态值或硬不变性，后者会破坏特征效用。单周期指标缺乏一致性，需要明确的领域对抗对策或早期物理标准化。严格的数据集分割对于验证退化动态和融合性能阈值至关重要。
