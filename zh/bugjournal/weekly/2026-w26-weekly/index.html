问题与解决方案#

1. 后台守护进程启动（‘collect-report-data.ts’）导致严重的CPU拥塞和静默资源消耗。[AI Companion框架]（2026-06-24）#

解决方案： 实现了文件锁定单例保护机制，防止重复执行；通过CLI追踪进程树以隔离并终止根源。

2. AI根据上下文压缩伪象而非实际文件系统状态报告完成不存在的功能。[AI Companion框架]（2026-06-25）#

解决方案： 强制使用直接CLI验证（‘git log’, ’ls’），确保AI输出符合现实；通过审计跟踪重置操作上下文并建立信任。

3. 冻结的VLM（Cosmos-Reason1）在零样本空间推理方面失败，输出静态坐标而不受输入文本影响。[机器人与Cosmos3-Nano评估]（2026-06-27）#

解决方案： 放弃直接生成方式，转向候选选择架构，并优化推理参数（标准化提示词、放大输入、温度=0）。

4. GeneJEPA嵌入式模型表现出高各向异性及库大小偏差，在空间聚类方面不如PCA。[MIHD空间转录组分析]（2026-06-23）#

解决方案： 进行了SVD/相关性诊断；得出结论，对于小样本领域，JEPA不可行，因此选择PCA并设计基准模型作为更优方案。

5. 远程Cosmos3-Nano模型权重被截断，导致vLLM启动失败和过时评估数据。[机器人与Cosmos3-Nano评估]（2026-06-24）#

解决方案： 使用Safetensors头信息识别损坏片段；通过跨设备同步获取替代版本，并在重新部署前验证完整性。

经验教训#

架构（architecture）#

  • 在静态托管上实施客户端加密并结合‘noindex’指令，为私有工具提供了无需基础设施分裂的实用安全模型。
  • 单仓库后台自动化必须实施单例锁定或速率限制，以防止突发事件或手动重试导致的静默资源耗尽。

调试（debugging）- Git 合并标题并非内容包含情况的可靠指标；需要以树级方式验证。此外，仅依赖 AI 摘要而不进行外部真实数据检查会带来严重的状态差异风险。#

  • 远程模型文件可能悄无声息地损坏；在提供权重之前务必验证文件完整性（头信息/大小）。在重新启动服务前，必须通过网络工具跟踪进程状态，以避免端口冲突。

工具（tools）#

  • 使用非交互式标志用于自动化测试管道，以防止进程卡住。语义版本控制需要数值比较逻辑，且像 PROXY_BYPASS 这样的环境变量必须在启动时通过程序设置。

领域知识（domain）#

  • 在细胞数据上预训练的基础模型由于领域差异，往往无法应用于空间转录组分析。通用推理 VLM 缺乏零样本机器人迁移能力，需要微调或候选集选择策略。

AI 使用注意事项#

有效模式：

  • ✓ 多智能体并行审计能够有效隔离大型代码库中的逻辑错误，并加速修复过程
  • ✓ 通过强制直接系统命令验证来减轻上下文压缩带来的问题，从而可靠地缓解任务摘要的误差
  • ✓ 参数化推理（归一化、温度控制）能够成功将不可用的 VLM 输出转化为可用的评估工具

限制：

  • ✗ AI 始终低估了明确状态基准化的需求，当上下文窗口缩小时会导致任务幻觉现象
  • ✗ 远程执行工具在 SSH 模式匹配和间歇性的代理隧道方面存在困难，需要人工干预来稳定系统
  • ✗ 自动化脚本生成偶尔会引入细微的字符串格式错误（例如符号链接路径），这些错误会绕过验证逻辑
