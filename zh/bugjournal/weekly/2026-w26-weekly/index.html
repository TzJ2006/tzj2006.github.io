经验教训#

架构 (architecture)#

  • 后台自动化工具需要严格的单例锁机制以防止资源过载；跨平台 AI 助手需要专用的适配器层而非强制一致性。在静态托管中采用客户端加密（StatiCrypt）可以有效保护私有工具，同时避免基础设施范围扩大。实施宽松的读取路径与严格的执行路径相结合，为早期规划工作流提供强大的安全保障。

调试 (debugging)#

  • 永远不要信任 AI 对状态变化的文本总结；始终通过直接 CLI 验证提交和文件创建（git log, ls）。上下文压缩经常引入跨会话持续的幽灵约束。Git merge 标题不是内容包含的可靠指标——务必验证树结构。远程进程终止需要仔细的正则表达式模式隔离，以避免自终止或不完整的终止。

工具 (tools)#

  • 容器化的 HPC 计算 Pod 将 CUDA 计算与 OpenGL 图形分离；通过 glvnd 手动部署 NVIDIA GL 用户空间库即可启用 GPU 渲染，无需 root 权限。CUDA 小版本兼容性允许在 535 驱动程序上运行 12.8 版本轮子（CUDA 12.2）。对于本地主机健康检查，始终绕过外部代理，并使用 printf %q 进行安全的 SSH 变量序列化，而非直接插值。

领域知识 (domain)#

  • 基础模型在跨样本细分检索方面表现优异，但在空间转录组数据上的单片聚类效果不如原始 HVG 基线。复杂的基模型（如 JEPA）在小样本领域通常因领域偏移和各向异性而表现不佳。目前冻结的 VLMs 无法可靠地进行零样本像素定位；研究必须转向候选集选择或微调。对于移动相机机器人评估，时间上下文是必不可少的，因为静态设置与基于片段预测会趋同。

AI 使用说明#

有效模式：

  • ✓ 使用 TypeScript 适配器来协调不同 LLM 客户端的事件模式
  • ✓ 采用 Safetensors 头信息验证和跨设备同步来确保模型权重的可靠恢复
  • ✓ 实现文件锁单例保护机制以稳定高频守护进程
  • ✓ 应用归一化坐标提示([0,1000])和温度=0，用于确定性的 VLM 消融研究

限制：

  • ✗ 上下文压缩伪影导致 AI 产生虚假任务和幻影需求，需要立即通过 CLI 重置

  • ✗ 在通过 SSH 和远程进程正则表达式处理复杂的 bash 参数序列化时存在困难，通常需要手动调整模式
  • ✗ 初始网络搜索和 HPC 代理隧道对于大文件传输不可靠，需要直接 HTTP/SCP 解决方案
