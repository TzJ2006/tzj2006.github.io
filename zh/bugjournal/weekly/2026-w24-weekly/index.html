2. 研究模块 call_llm_raw 允许子进程超时逃逸，导致管道崩溃；失败的 LLM 响应被永久缓存而不设置 TTL，造成持续的数据污染。Gadget 生态系统与 ccusage 迁移#

3. TokenMonitor 在仅内容追加时因过于广泛的缓存失效而每2秒触发全树统计和昂贵的重新解析；SSH/Cursor 数据从导出中缺失。TokenMonitor#

解决方案： 使用基于变更类型的增量更新替代广泛的缓存失效；扩展遥测导出，包含 SSH 和 Cursor 源，同时确保跨机器同步兼容性。解决方案： 重构了解析器逻辑，能够区分目录结构变化（全量重新扫描）与内容追加（增量更新）；增加了明确的远程刷新机制，并支持源键路由以完成完整遥测快照。

经验教训#

架构 (architecture)#

  • 分布式或外部API工作流中的失败状态不得在没有明确TTL或验证机制的情况下被缓存；区分临时错误与永久状态对长期数据完整性至关重要。
  • 针对基于文件的监视器和实时统计聚合器，采用广泛扫描模式进行增量无效化对于性能至关重要，以防止仅内容变更导致的CPU瓶颈。
  • 在CLI工具迁移过程中（例如ccusage 20.x），架构规范化层是必需的，以在保持每个源的细粒度性和向后兼容性的同时bridge不兼容的输出格式。

调试 (debugging)#

  • NTFS或FUSE挂载驱动器上的旧依赖缓存（Vite .vite-temp）经常导致模块图同步中断；原子重命名失败需要手动清理缓存，而非重启开发服务器。
  • 高端GPU上的WHEA事件17“可纠正错误”通常是软件引起的PCIe配置探测噪声，而非硬件退化；直接解析事件日志的XML比二进制解析更快。
  • 包含绝对本地路径的公共仓库工件存在数据泄露风险；安装程序和同步生成器必须根据仓库可见性（公开 vs 私有）动态调整gitignore/配置策略。

工具 (tools)#

  • 多智能体审计工作流显著加速大规模错误发现，但缺乏自动化的范围完整性检查；仍需手动验证边缘案例和未分配项目。
  • 在AI辅助开发早期就必须建立明确的本地优先约束，以防止智能体过度设计混合云或外部API架构，当内部结构足够时即可。

领域知识 (domain)#

  • 内部项目全景图和执行摘要必须取代学术论文协议作为实现对齐的权威来源；死代码或旧规范不应被假设为活跃状态。
  • mclust EM聚类对复杂数据集中的初始化范围非常敏感；单次ARI/ARI基准测试在统计上不可靠，需要多种子验证以描述方差。
  • 通用基因基础模型在与图对比网络（GCN）融合时经常失去空间区分信号，因此像UNI2这样的专用嵌入更适合高维空间转录组聚类任务。
