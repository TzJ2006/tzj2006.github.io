问题与解决方案#

1. MIHD STAIG融合中的沉默数据损坏，原始矩阵绕过编码器，导致基准测试数据无效，无明显错误。[MIHD研究管道]（2026-06-02）#

解决方案： 通过md5sum验证确认；更新pipeline_config.yaml以强制编码器路由；归档损坏输出，使用验证后的路径重新运行作业。

2. AI Dev Companion构建失败和/ccoverview翻译崩溃由根tsconfig冲突和负载过载引起。[AI Dev Companion & TokenMonitor]（2026-06-02）#

解决方案： 将根tsconfig包含设置为[]以隔离模块；采用批量翻译并按顺序执行，同时处理 try/catch 超时处理。

3. TokenMonitor 分支自动更新失败，原因是将 MiniSign 更新器的签名与 Apple Developer ID 代码签名混淆了。[AI Dev Companion & TokenMonitor] (2026-06-02)#

解决方案： 生成新的 Tauri 密钥对，修正 base64 机密信息，并修改工作流程以分离各平台的独立签名系统。

4. Git 历史重写导致上游同步中断，造成不同的提交 SHA 和发布标签不一致。[AI Dev Companion & TokenMonitor] (2026-06-03)#

解决方案： 在确认远程源的前后状态后，从广泛的过滤器仓库转向针对特定提示 commit 的修改操作。

5. RecoverBench 文档中引用的 48.6% 主要指标与实际的可复现检查点分数（45.7%）相矛盾，导致验证存在模糊性。[Error Recovery Benchmark / RecoverBench] (2026-06-06)#

解决方案： 执行并行深度读取器以明确真实数据，在主文件中记录差异，并实施“先测试后调整”协议，在对齐变化发生前锁定当前行为。

经验教训#

架构 (architecture)- 跨平台CLI工具和可移植应用程序必须依赖供应商依赖项或使用相对路径；绝对路径注入会破坏不同克隆环境的部署。Tauri更新器签名（minisign）和应用程序代码签名（Apple/DigiCert）是独立系统，必须在CI工作流中分离。#

  • 单仓库中的根tsconfig文件应作为纯引用使用，以避免CommonJS/ESM模块的级联解析冲突。自动化预编辑机制必须依赖不可变的外部信号（git历史记录、用户提示），而非内部标志，以防止自我授权安全风险。

调试（debugging）#

  • 下游模型相同的输入可能会悄悄掩盖上游编码器或处理流程的故障；在接受研究结果之前，经验性二进制验证（md5sums）至关重要。如果未使用try/catch处理，LLM包装器经常会在超时时崩溃，系统会误判为JSON解析错误。
  • 并行AI代理管道极易受到速率限制（429）；限时的顺序执行能保持分析质量。在异构GPU分区中，严格的硬件字符串请求会导致队列死锁；需要精确的节点状态诊断。

工具（tools）#

  • 未提交的高性能计算工作在共享环境中是临时性的；过度依赖本地代码树而不频繁提交或自动备份可能导致不可逆转的数据丢失。针对代码库自动验证文档工件对维护“先测试后开发”方法的信任至关重要。

领域知识（domain）#

  • 科学模型等价性应通过度量差异（如ARI/NMI）来验证，而非由于随机生成器波动导致的完全相同可复现性。“先测试后开发”在复杂管道中是不可妥协的：在尝试调整过时的文档与实际系统行为之间，需通过特性测试锁定当前真相。

AI使用注意事项#

有效模式：

  • ✓ 用于结构化架构规划的/ccplan和ultracode工作流
  • ✓ 对抗性验证脚本，以验证自动生成的文档与实时代码库是否一致
  • ✓ 用限时的顺序LLM管道替代激进的并行输出，以避免速率限制
  • ✓ “先测试后开发”方法将经验性研究基准与软件工程严谨性相结合

局限性：

  • ✗ 外部API能力激增（529个错误）以及组织层面的速率限制会完全中断交互式开发
  • ✗ 初始基于上下文的跨平台运行时错误误判以及git历史记录差异影响
  • ✗ 在有限的单会话时间限制内无法执行完整的HPC经验性验证集
