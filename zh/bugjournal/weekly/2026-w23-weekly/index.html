问题与解决方案#

1. MIHD STAIG 融合结果为字节级相同（静默失败），因为原始 HVG 矩阵绕过了基因编码器层。[MIHD Research]（2026-06-02）#

解决方案： 通过 md5sum 确认数据完整性损失；修改 pipeline_config.yaml 以强制使用编码器路径；归档损坏输出并重新运行具有正确路径的 SLURM 作业。

2. TokenMonitor 自动更新因签名错误失败，原因是 minisign 更新器密钥与 Apple 开发者 ID 要求混淆。[TokenMonitor]（2026-06-02）#

解决方案： 生成新的 Tauri 密钥对，修正 CI 中的 base64 机密信息，并将 minisign 更新器逻辑与 Apple 签名标志解耦。

3. AI Companion 工作流因绝对路径注入导致可移植性受损；并行 AI 代理触发 API 速率限制（429）。[AI Dev Companion]（2026-06-04）#

解决方案： 设计了 Vendor-Tier-1 架构，使用相对路径并外部化重负载引擎；将扇出改为限流的顺序后台工作流。

4. RecoverBench 文档中列出的指标为选择性选取的（48.6%），与可复现的单检查点结果（45.7%）不一致。[RecoverBench]（2026-06-06）#

解决方案： 跨环境映射所有来源；创建合并差异报告；使未来报告与实际基线工件保持一致，而非理想化的论文数据。

5. Git 分支清理因广泛历史重写导致上游同步中断。[TokenMonitor]（2026-06-03）#

解决方案： 识别特定违规提交，通过针对性修改 tip 来保留祖先完整性，同时回收约 302MB 的工件。

经验教训#

架构（架构）- 位于单仓库中的 Root tsconfigs 应使用纯引用方式，以防止 ESM/CommonJS 模块冲突的连锁反应。自动预编辑机制必须依赖不可变的外部信号（git 历史记录），而非内部标志，以避免自我授权风险。#

  • Tauri 更新器签名（minisign）和代码签名是独立系统；将两者混为一谈会破坏跨平台发布的一致性。生产级 CLI 需要采用供应商提供的相对路径或 npx 风格的解码方式，以实现真正的环境可移植性。

调试（debugging）#

  • LLM 包装器常常将超时错误伪装成 JSON 解析错误；有效载荷大小与并发度对延迟的影响比网络速度更大。相同的输入给下游模型可能会悄悄掩盖上游数据损坏，因此经验性二进制验证至关重要。
  • Orphan Vite 开发服务器处理不当或关闭方式错误会导致虚幻的白色屏幕阻塞；跨平台端口锁定必须同步且独立于应用事件循环，以防止重复实例冲突。

工具（tools）#

  • 大规模并行 LLM 分析会迅速触发速率限制；使用人工真实数据进行受限顺序批处理能提升可靠性。Git fork 清理应优先选择选择性提示修改，而非广泛过滤工具，以维持上游同步。

领域知识（domain）#

  • 科学模型等价性必须通过度量差异（ARI/NMI）来验证，而非因 RNG 波动导致的比特级完全相同复现。未提交的高性能计算工作具有临时性；本地树状结构需要频繁提交或快照备份，以防止不可逆转的数据丢失。

AI 使用注意事项#

有效模式：

  • ✓ 利用 /ccplan 和 ultracode 工作流进行结构化架构设计
  • ✓ 采用对抗性经验验证（md5sums、测试优先指标）来抵消描述性 AI 的置信度问题
  • ✓ 使用并行深度读取器进行跨源审计，结合顺序限制来管理 API 速率限制

局限性：

  • ✗ LLM 包装器实现在超时时崩溃，导致误认为这是 JSON 解析错误；无法预测本地环境差异（python3 与 python、Tauri 密钥格式）
  • ✗ 初始 Slurm GPU 查询缺乏精细度，导致可用性评估不准确
  • ✗ 外部 API 529 错误导致整个工作流停止，需要手动 fallback 策略
