Problems & Solutions#

1. NeurIPS submission 与实际 codebase 之间的差异 (SHA, platform counts)。 [NeurIPS Submission]#

Solution: 采用了侧重于数据 trustworthiness 的 ‘Changes since submission’ disclosure 策略。

2. LLM 误解图像中的文本并在长截图时丢失清晰度。 [PersonalAgent (WeChat)]#

Solution: 使用本地 CPU OCR engine 将文本提取与语义解释进行解耦。

3. 研究叙述感觉像是一篇论文列表，而不是一个凝聚的方向。 [Academic Research]#

Solution: 围绕核心问题进行重构：‘Robots can perform recovery, but cannot recognize when it is needed’。

4. JEV latency 导致时间敏感型任务的性能大幅下降。 [RoboHarness]#

Solution: 确定了约 0.5s 的阈值；为低延迟 JEV 实现了 ’non-pausing’ 优势。

5. DLPFC ‘gene-only’ arms 在静默状态下回退到了 KMeans，导致结果偏差。 [NCL Project]#

Solution: 添加了专门的 ‘kmeans’ cluster_backend mode 以进行显式控制匹配。

6. 导师对 ‘handcrafted’ 任务特定 prompts 的担忧。 [CVPR Submission]#

Solution: 开发了一种统一的形式化表达：在 grounded points 处绘制的 (Glyph, Predicate, Anchor) 三元组。

Learnings#

Architecture (architecture)#

  • 有效的模型隔离需要一种 ‘Provider-mediated’ 架构，其中 host 处理 tool execution 并仅向 model 提供经过清洗的结果。
  • 融合方法 (如 Concat) 非常容易受到来自高方差输入 (如 images) 的 ‘modality dominance’ 影响。

Domain Knowledge (domain)#

  • 在 robotics 领域，战略性的 ‘division of labor’ (VLM 用于 reasoning, Code 用于 execution) 弥合了 SOTA 与 ground-truth 性能之间的差距。
  • 对于多模态助手，将 ‘what is written’ (OCR) 与 ‘what it means’ (LLM) 分离对于减少 hallucinations 至关重要。
  • 当将技术局限性 (例如 Markovian properties) 与特定的问题领域联系起来时，研究叙述最具说服力。

Debugging (debugging)#

  • WeChat/VM 环境中的 UI automation 对 IME 状态变化和窗口焦点转移高度敏感。

AI Usage Notes#

Effective Patterns:

  • ✓ 用于大规模 literature surveys (300+ papers) 的 multi-agent workflows
  • ✓ 用于检查报告中数值一致性的 adversarial verification agents
  • ✓ 为人类执行提供结构化逻辑/架构愿景

Limitations:

  • ✗ 无法在 sandboxed environments 中进行实时的 UI/JavaScript testing
  • ✗ 倾向于根据本地测试通过率而非实际环境交互，过度自信地报告 ‘fix success’
  • ✗ 会 hallucinate 出用户计划中并未明确提及的研究联系
