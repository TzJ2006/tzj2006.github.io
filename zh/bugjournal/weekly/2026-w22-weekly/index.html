经验教训#

架构（architecture）#

  • 对于确定性智能体工作流程，严格分离不可变的规划输出（ECL）和可变的执行逻辑至关重要；钩子必须强制执行这些边界以防止耦合。
  • 跨 monorepo 和跨设备设置的配置管理需要单一的可执行真实来源（例如 launcher.py 或注册表脚本），而不是分布式 shell 包装器，以消除差异。

调试（debugging）#

  • 测试质量取决于断言强度（验证特定的业务规则和状态转换），而非原始覆盖率指标；弱的负面断言通常可以掩盖逻辑回归问题。
  • 经验性隔离测试优于基于假设的调试。在 Windows 上，shell=True 在子进程调用中会静默死锁，当子进程继承管道句柄时；需要直接测试变量以识别问题根源。

工具（tools）#

  • 如 Tauri 这样的桌面框架维护独立于内存存储的磁盘缓存。状态变化必须触发双层无效化（内存 + 磁盘），以防止远程同步期间视觉数据失效。
  • linting 和 doctor 工具通常将解析失败与语义/模式问题混为一谈。直接字节级或基于 AST 的验证必须在配置故障排除之前进行，以避免追逐虚幻语法错误。

领域知识（domain）#

  • AWS Activate 积分严格排除 Marketplace SKU，除非明确列为第三方 Bedrock 模型。扩展云 API 使用需要手动验证积分条款和配额权益，以防止意外收费。
