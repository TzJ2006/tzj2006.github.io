反复出现的问题#

1. Linux FloatBall几何位置Bug多轮迭代无法收敛 (出现 5 次)#

日期: 2026-04-01, 2026-04-02, 2026-04-03, 2026-04-04, 2026-04-05 根本原因: 根本原因是架构性平台约束而非计算Bug：Linux WM、GTK、WebKitGTK三层几何系统各自独立且异步，任何基于动态resize的方案都会在三层之间产生不一致。早期修复（锚点计算、last_rect状态、GTK resizable时序）均在症状层面修补，未消除resize行为本身。直到第5天才认识到’固定窗口尺寸+GDK Input Shape’才是根治方案。 状态: ✅ 已解决

2. AI首轮修复遗漏底层根因，聚焦于前端/算法层而忽略OS/WM层 (出现 4 次)#

日期: 2026-04-01, 2026-04-02, 2026-04-04, 2026-04-05 根本原因: AI在无运行时验证环境下倾向于从代码逻辑推断行为，首先在应用层（前端坐标换算、动画时序）寻找根因，而底层平台行为（GTK bottom-up协商、WM clamp策略、WebKitGTK transparent buffer）需要日志实证才能发现。每次都需要用户提供backend.log或实测反馈才触发正确修复路径。 状态: 🔄 持续中

3. conda activate在非交互shell环境中失效 (出现 3 次)#

日期: 2026-04-01, 2026-04-02, 2026-04-06 根本原因: conda activate只修改交互式shell的PATH，子进程（SLURM作业、Claude Code后台bash、CI环境）不继承交互shell的激活状态。应统一使用conda run -n ENV python替代activate&&python模式。 状态: 🔧 有变通方案

4. 跨平台Rust/GTK API行为与预期不符，引入新平台特定细节问题 (出现 4 次)#

日期: 2026-04-02, 2026-04-03, 2026-04-04, 2026-04-05 根本原因: GTK/Tauri的多个API在Linux上有隐式约束：resizable(false)同时阻止编程式resize、with_webview()是异步派发（后续API在回调前入队）、GTK gravity并非所有WM支持、GDK input shape在X11层拦截早于setPointerCapture。这些框架内部行为未在官方文档中明确说明，需实测或阅读GTK源码才能发现。 状态: ✅ 已解决

5. 大型分布式实验的输出覆盖与超时设计问题 (出现 3 次)#

日期: 2026-04-01, 2026-04-03, 2026-04-06 根本原因: HD数据集(17502 spots)的计算时间从DLPFC(~3900 spots)线性外推严重低估；多个实验共享同一输出文件（summary.csv）导致后续结果覆盖前者；pipeline的skip_completed机制在文件存在但内容无效时无法检测。根本上是实验管道缺乏per-pair输出目录和幂等性保护设计。 状态: 🔧 有变通方案

本月收获精选#

架构 (architecture)#

  • Linux透明无边框Tauri/WebKitGTK浮窗的正确架构：固定大尺寸native window + 内部纯CSS展开收起，不依赖频繁resize外层窗口。WM、GTK、WebView内容区三者尺寸/位置不会自动同步，动态resize是所有位置Bug的根源。GDK input_shape_combine_region是控制点击穿透的正确机制，在X11层拦截早于setPointerCapture，拖拽时需在Rust侧临时扩展到全窗口。 (来源: 2026-04-04, 2026-04-05)
  • GTK窗口尺寸控制机制：GTK bottom-up协商取max(window_requested, widget_natural_size)，WebKitGTK natural size≈200x200，Tauri的set_size/set_min_size对WebKitGTK窗口无效，必须通过with_webview()回调调用widget.set_size_request()突破；with_webview()是异步派发，后续Tauri API在回调执行前入队（FIFO），set_resizable(false)会锁死回调中设置的尺寸；WebKitGTK滚动条属于GTK widget层，必须用set_policy(Never,Never)而非CSS禁用。 (来源: 2026-04-04)
  • Wayland协议层面禁止客户端设置绝对窗口位置，任何set_position()重试策略都无效。正确解法：检测WAYLAND_DISPLAY后强制GDK_BACKEND=x11回退XWayland。现代Linux桌面（Ubuntu 22.04+）已默认Wayland，跨平台窗口追踪须以GNOME Introspect D-Bus(org.gnome.Shell.Introspect.GetWindows())为主路径，xdotool/xprop只能作为XWayland回退。 (来源: 2026-04-02, 2026-04-04)
  • 激进简化（换掉引擎）往往比渐进修补更有效：Thin Adapter + MCP Server + Skills三层模式替代专有路由逻辑，删除代码远多于新增（-6061 vs +3238行）；多CLI系统设计中，利用约定文件（CLAUDE.md/AGENTS.md/GEMINI.md）比运行时注入更简单可靠；统一history ring buffer比适配各CLI的session机制更可靠。 (来源: 2026-04-04)
  • Hugo站点部署有三个必须同时到位的独立依赖（hugo二进制、主题仓库、部署git仓库），任何一个缺失导致不同阶段失败；bash set -e脚本对可选目录的find操作必须加目录存在性检查；并行后台任务（& + pids追踪）代码必须与if/else控制流边界精确对齐，公共代码放分支外部会引入重复PID追踪和文件替换遗漏Bug。 (来源: 2026-04-07)

工具 (tools)#

  • Claude CLI -p（session-less）模式的MCP完整配置须两步：(1) –mcp-config 显式加载项目级工具；(2) –permission-mode bypassPermissions 绕过非交互模式下无法完成的权限确认。–allowedTools通配符因与MCP server初始化存在竞争条件不可靠。bypassPermissions是后端服务调用的正确标准模式。 (来源: 2026-04-05)
  • ccplan + Critic子代理对抗审查的最佳实践：在所有复杂功能规划前执行发散探索（6方案）+对抗审查+可行性探测流程。本月Critic阶段共发现Wayland兼容性、lark-oapi线程阻塞、ThoughtStore非单例、4个隐藏代码依赖等高价值风险，每项若遗漏都会导致功能在生产环境失效。ECL文档将设计决策结构化持久化，是跨会话复杂功能开发的关键工程实践。 (来源: 2026-04-04, 2026-04-05)
  • conda run -n ENV python是非交互shell中运行Python脚本的标准方式，conda activate只修改交互式shell PATH，SLURM作业/后台bash/CI环境均不继承激活状态。后台进程输出为空时应先用ps aux确认进程是否在运行，而非直接重新提交（避免资源浪费和结果覆盖）。 (来源: 2026-04-01, 2026-04-06)
  • lark-oapi WebSocket正确架构：Client.start()是阻塞式的，必须用独立daemon线程+asyncio.run_coroutine_threadsafe()桥接；structlog包装stdlib时extra={}字段需显式添加ExtraAdder() processor才能出现在输出中，否则静默丢失无报错；Google Calendar OAuth验证应用events.list(calendarId=‘primary’)而非calendarList.list()。 (来源: 2026-04-04, 2026-04-05)

调试 (debugging)#

  • 运行时日志是底层系统调试的根本手段，优于代码推理：当涉及GTK/WM/OS层时，backend.log的实证数据（如+305px=expanded宽度的系统性规律）能直接定位架构性根因；多轮修复失败后应主动分析日志寻找模式而非继续尝试新方案。调试嵌套进程CLI工具时，先记录实际传递的命令行参数逐一隔离验证，比猜测参数行为更高效。 (来源: 2026-04-04, 2026-04-05)
  • Rust生产代码安全模式：(1) assert!()/unwrap()在接受外部输入路径上是定时炸弹，统一改为Result传播；(2) 锁跨异步await边界是隐性性能/死锁隐患，在await前Clone出所需数据提前释放锁；(3) Python await同步方法产生TypeError若被except Exception吞掉会导致功能静默降级，极难排查；(4) ‘功能已实现参数接口’≠‘参数已被传递’，验证时要检查调用侧。 (来源: 2026-04-02, 2026-04-04)
