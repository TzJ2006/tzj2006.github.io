Lessons Learned#

Architecture - Cross-platform CLI tools and portable applications must rely on vendor dependencies or relative paths; absolute path injection destroys deployment across different clones. Tauri updater signatures (minisign) and application code signing (Apple/DigiCert) are independent systems and must be separated in the CI workflow.#

  • The root tsconfig file in a single repository should be used as a pure reference to avoid CommonJS/ESM module cascading parsing conflicts. Automated pre-editing mechanisms must rely on immutable external signals (git history, user prompts) rather than internal flags to prevent self-authorization security risks.

Debugging#

  • Inputs with the same downstream model may quietly mask failures in upstream encoders or processing steps; empirical binary verification (md5sums) is crucial before accepting research results. If try/catch handling is not used, LLM wrappers often crash during timeouts, leading the system to misjudge as JSON parsing errors.
  • Parallel AI agent pipelines are highly susceptible to rate limits (429); sequential execution with time limits maintains analysis quality. In heterogeneous GPU partitions, strict hardware string requests cause queue deadlocks; precise node status diagnosis is required.

Tools#

  • Uncommitted high-performance computing work is temporary in shared environments; over-reliance on local code trees without frequent commits or automatic backups can lead to irreversible data loss. Automated verification of documentation artifacts for code repositories is crucial for maintaining the “test first, then develop” approach.

Domain Knowledge#

  • Scientific model equivalence should be verified through metric differences (e.g., ARI/NMI) rather than identical reproducibility caused by random generator fluctuations. “Test first, then develop” is non-negotiable in complex pipelines: between trying to adjust outdated documentation and actual system behavior, the current truth must be locked via feature testing.
