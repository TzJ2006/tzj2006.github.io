Solution: Use pre-trained Foundation Model (scGPT): all slices share the same model weights, output is naturally in the same coordinate system; SL@50 increased from 0.013 to 0.416, hit rate 100%. Root cause is inconsistent coordinate systems (mathematically impossible to normalize), not insufficient gene feature information

2. CompositeBodyObject breaks during env.reset() (lid floating, base offset), but normal during HDF5 playback (set_sim_state_flat covering body position hides the problem) [Error Recovery Benchmark] (2026-03-16)#

Solution: Add locations_relative_to_corner instance attribute in generated_objects.py__init__, restore coordinate transformation logic from corner to center (aligned in commit 398af01b); all 139 unit tests pass

3. Learning Insights#

Architecture#

  • Pipeline contract alignment must track the complete data flow: not only modify processing logic but also ensure data is persisted at the storage layer (e.g., segment_interactions() results written to NPZ); output transform is an implicit filter in the inference chain, and any field not in the return dict is silently discarded; CLI parameters in multi-stage pipelines must be explicitly passed to each downstream stage, not relying on implicit sharing. “Passing unit tests ≠ E2E correctness”
  • In multi-object robot manipulation tasks, target_object must pass through all three stages (detector/injector/validator) as a primary citizen; objects[0] is the first object in dictionary insertion order, and using it in multi-object scenarios causes complete semantic errors without errors, leading to systematic misjudgments based on object state. graspable objects and fixtures must be distinguished by the grasp_geoms field, and target selection cannot rely solely on distance/position
  • Independent processing per section (PCA/training) produces non-comparable embedding spaces, which is a fundamental architectural limitation and cannot be fixed through normalization or post-processing. The only correct zero-shot solution is pre-trained Foundation Model (shared weights). Gene FM (scGPT 100%) outperforms Vision FM (UNI2 71%) because gene expression has stronger cross-sample consistency due to the batch effect in H&E images
  • Flax NNX extended models: inheritance (class Child(Parent)) is the only way to keep checkpoint path compatibility; combination (self.pi0 = Pi0(…)) adds a prefix before all parent module parameter paths, causing pytree merge to fail completely. The freezing mechanism (freeze_filter+nnx.DiffState) in existing frameworks usually considers scalability—prioritize reuse over creation
  • Facing architectural design flaws, “bypassing” is more fundamental than “fixing”: the single-object phase detection assumption cannot be fixed through parameter tuning; directly bypassing it with InteractionSegmenter is a more elegant solution. Do not fix but bypass the flawed abstraction level

Debugging#

  • State machine design principle: completing an event must do two things simultaneously—reset trigger conditions (clear current_prompt) and broadcast state change (_publish_state(‘idle’)). Doing only one of them leaves hidden bugs like infinite loops or upstream perception failure. None checks must precede any property access (defensive programming)
  • When diagnosing behavior of unknown third-party libraries, writing a minimal test script is more reliable and efficient than static code analysis (robosuite gripper polarity case); log counter statistics are more effective for locating systematic bugs than reading each entry (1698 occurrences of ‘gripper not closed’ directly point to target_object ambiguity); troubleshoot implicit filtering bugs by tracking upward from the data flow
  • Experiment naming conventions must strictly match actual implementation; inconsistent naming like “pca_uni2_staig_fusion” leads to long-term misunderstandings, and actual configuration must be confirmed by reading logs rather than just experiment names. Benchmark data quality issues (uneven distribution, all phase annotations as pre_reach) should include monitoring mechanisms during pipeline design

Tools#

  • subprocess.run(capture_output=True) redirects stdin to DEVNULL, and CLI tools with interactive prompts (npx, etc.) must use –yes/-y, otherwise they hang indefinitely instead of timing out. capture_output=True is the high-level cause of hanging
  • Slurm HPC cluster’s pam_slurm_adopt policy kills all related processes at job end, and SSH nohup cannot bypass this; long training tasks must submit formal jobs with sbatch. MuJoCo physics simulation (enable_camera=False) is a pure CPU task, and MUJOCO_GL=disabled can completely bypass OpenGL, with worker count exactly matching –cpus-per-task
  • JAX has_aux mechanism: nnx.value_and_grad supports has_aux=True, compute_loss returns (loss_array, aux_dict) after which gradients are calculated only for loss_array, and aux_dict transparently carries monitoring metrics; stop_gradient strictly limits aux loss to MLP parameters, and the numerical ratio of action/aux loss does not indicate training imbalance
  • Hugo best practices: .Title is the most stable field for identifying specific sections (.Section and.RelPermalink case sensitivity varies across platforms); static directory names matching content page base names cause path conflicts; auto-generated frontmatter should not use current system time as date; project-level layouts/partials can cover themes partially without forking the theme
  • Spatial data nearest-neighbor query: Large point clouds (>10K points) should prioritize KD tree (O(N log N) preprocessing) instead of cdist (O(N²) memory); in HD spatial transcriptomics (17K+ cells), differences can reach OOM vs normal operation. Single truth source principle: constants referenced across multiple files must be imported from the only defined place

Domain Knowledge- Recovery Behavior Group (RBG) grouping strategy: 29 error subtypes are clustered into 5 groups based on motor primitives, and demos within the same group can be cross‑augmented. MimicGen generates over 1,000 demos from 10 source demos; 1,740 simple requirements are compressed to 329 (saving 81%). This is a paradigm applicable widely to robot recovery data engineering.#

  • π₀.₅ computational graph characteristics: Reasoning follows a natural two‑step process (VLM prefix forward → action expert denoising). During training, Exp1–4 can be combined into one joint forward using teacher forcing. The from_hidden mode introduces circular dependencies due to the dependence on model output for conditioning, requiring an additional prefix‑only forward. Mean pooling of prefix_output is more suitable for classification tasks than suffix_output of action expert (for encoding global state understanding).
  • The depth of LLM understanding in academic trajectory analysis exceeds expectations: It can automatically identify advanced features such as ‘infrastructure‑thinking researchers’ and ‘technical prerequisites for paradigm shifts’. The why_not_before field (attributing each breakthrough to data, compute, and insight across three dimensions) is the most valuable feature in researcher profiling. The recognition of conference awards has very low ROI with current LLM capabilities; it should be replaced by an external data source solution (exact title matching JSON library).

AI Usage Notes#

Effective Patterns:

  • ✓ Parallel multi‑agent code review (independent analysis of reuse, quality, and efficiency across three dimensions for the same diff): Issues that do not overlap are found in all three dimensions, and parallel execution saves time.
  • ✓ Systematic code tracking to locate root causes: Tracing upward from the data flow end point reveals silent bug elimination in output transform and S2 speed limit recursive loops.
  • ✓ Proactive quality checks beyond task boundaries: Automatically identifying混淆 with the same name (abnormal ratio of h‑index to paper count, impossible domain span, etc.) during researcher profiling, without explicit requirement in the prompt.
  • ✓ Academic trajectory analysis reaches the level of academic review: Automatically identifying advanced features such as ‘infrastructure‑thinking researchers’, and the why_not_before field exceeds expected value.
  • ✓ Log aggregation and statistics to locate systematic bugs: Counter statistics of 1,698 “gripper not closed” events directly point to the ambiguity root cause of target_object, which is more efficient than individual analysis.

Limitations:

  • ✗ Tendency to locate isolated bugs when dealing with complex system problems; lacks the ability to analyze contract inconsistencies from the full data flow perspective, requiring human guidance at the architecture level.
  • ✗ Lack of proactive global data flow verification after local fixes are implemented; passing unit tests gives a false sense of completion, and multiple omissions (e05/e06/e09, target_pos transmission, collect script not integrated) require systematic human review.
  • ✗ Environment configuration not pre‑verified leads to full batch failure over multiple rounds (Agent sub‑agent lacks Bash permissions, conda activation fails, PYTHONPATH missing, API key type issues); individual tasks should be validated before batch expansion.
  • ✗ Failure to actively identify efficiency bottlenecks: Only setting waiting periods when generating in serial mode, without proposing parallelization; no consideration of resource isolation due to Slurm job expiration when starting SSH with nohup.
  • ✗ Insufficient anticipation of framework‑specific behaviors: No prediction of the impact of Flax NNX inheritance vs. combination on checkpoint paths; no realization that JAX/NNX TrainConfig mechanisms can be directly reused.
  • ✗ Lack of knowledge about latest tool features (effortLevel: max only known after discovery), resulting in knowledge lag compared to rapidly evolving AI tool ecosystems.
