Issues and Solutions#

1. ARI (0.21/0.4849) of MIHD staig_fusion is far lower than that of original STAIG (0.562), root cause unknown [MIHD / STAIG Fusion] (2026-02-06)#

Solution: System comparison of two code paths, identifying five root causes and prioritizing them: ① Mixed coordinate scales for full-resolution images (13332×13332) still multiply by the hires scaling factor (0.15), patch points deviate significantly from tissue areas (most critical); ② mclust silently degraded to kmeans when unavailable on HPC; ③ Reversed gene preprocessing order; ④ 300 vs 80 pseudo-label clusters; ⑤ Hyperparameters not fully aligned.

2. Plotly bar chart rendering error: high scores correspond to short bars, visual logic inverted [Benchmark Tool] (2026-02-06)#

Solution: Root cause is that Plotly 6.x uses binary-encoded arrays for serialization, which is incompatible with older CDN. Solution: Lock the CDN version to match the Python package version (3.3.1), force input as a Python list, and set rangemode=‘tozero’.

3. strict STAIG mode forces visual encoder to UNI, user thinks UNI2 is used, behavior unclear [MIHD / STAIG Fusion] (2026-02-06)#

Solution: Add clear encoder coverage hints in logs; the progress bar for UNI2 does not display because UNI is actually running.

4. create_trend_chart AttributeError: method is commented but still called in generate_html [Benchmark Tool] (2026-02-06)#

Solution: Add a stub method that returns an empty chart and completely remove the calling code.

Learning Insights#

Architecture#

  • The correct layered architecture for public GitHub Pages submissions: public users → relay (validation/throttling/ masking) → repository_dispatch → queue file → daily batch processing (duplication/cleaning/append CSV) → commit/push → automatic Pages deployment. The relay layer is a key isolation layer that protects repository write permissions.
  • Semantic consistency between interface names and actual behavior must be strict: the name ‘staig_fusion’ naturally promises the same meaning as STAIG; allowing significant differences in default behavior can cause many hidden errors; global coverage behaviors (e.g., forcing encoder to UNI) must be clearly indicated in logs.

Debugging#

  • Plotly 6.x defaults to binary-encoded arrays for serialization, causing bar length parsing errors when incompatible with older CDN. Solution: Strictly lock the CDN version to match the Python package version, force input as a Python list instead of pandas Series.
  • Low CPU and GPU utilization simultaneously indicates the program is waiting on single-thread I/O, not CPU; performance bottlenecks in visual feature extraction usually occur in data preprocessing (patch extraction) rather than model forward pass.
  • Errors in R interfaces (e.g., mclust) are not intuitive in Python; sufficient pre-validation should be added at the Python level and clear error messages with shape information provided; when R packages are unavailable, silent degradation must be clearly warned against, and algorithm behavior should not be changed without notice.

Domain Knowledge#

  • There are five quantifiable key implementation differences between MIHD and original STAIG (prioritized): ① Mixed coordinate scales for full-resolution images (most critical); ② Silent degradation of mclust; ③ Reversed gene preprocessing order; ④ Difference in number of pseudo-label clusters; ⑤ Hyperparameter and image transform differences. The ARI gap (0.21→0.56) is mainly determined by ①②③.

  • ✓ Architecture design supplementation: humans propose core security intuitions (confirmation before upload, secure isolation), AI translates them into complete executable technical architectures.

Limitations:

  • ✗ Insufficient thoroughness in fixes: when removing trend charts, only the call was removed initially, and a second fix is needed.
  • ✗ Easy to overlook existing global coverage logic: when adding UNI2 tqdm, not realizing that strict mode will force encoder coverage.
  • ✗ No pre-check of HPC environment modules (e.g., scanpy) before verification, leading to ModuleNotFoundError during validation, increasing debugging rounds.
  • ✗ Multiple options for low GPU utilization issues, but no active suggestion to use profile tools (py-spy, nvprof) to precisely locate the actual bottleneck.
