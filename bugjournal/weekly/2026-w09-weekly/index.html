Issues and Solutions#

1. Pi0.5 full fine-tuning training requires ~62GB/GPU, and JAX FSDP=4 cannot effectively reduce VRAM (only slicing storage does not reduce activation memory), repeatedly causing OOM [Error Recovery Benchmark] (2026-02-23)#

Solution: Switch to the gemma_2b_lora+gemma_300m_lora architecture, reducing training parameters by ~90% and reducing VRAM to ~22.5GB/GPU. Job 46553 runs stably at 2.0s/step.

2. All three-way evaluations of M14 crashed on scene 122/649: ~130 natural_* scenario XML hashes are incompatible with the current Mimicgen environment, triggering EnvironmentMismatchError without detection, causing the entire evaluation process to crash [Error Recovery Benchmark] (2026-02-23)#

Solution: Add a try-except for EnvironmentMismatchError in collector.py’s collect_on_scenes()for each scene, skip incompatible scenarios and log warnings, and restart with–resume`. The actual valid evaluation scenarios are about 519.

3. Training logs are severely distorted due to stdout buffering: Pi0.5 training shows only ~580 steps, but actually reached step 3000, leading to misjudged training termination and unnecessary restart [Error Recovery Benchmark] (2026-02-23)#

Solution: Add PYTHONUNBUFFERED=1+stdbuf -oL to the training script and sbatch submission scripts; use sbatch for long-term training and decouple the independent batch job from the interactive session lifecycle.

4. The success rate of Pi0.5 evaluation is 0%, misjudged as model quality issues [Error Recovery Benchmark] (2026-02-26)#

Solution: Confirmed that the training task (MimicGen 5 task) and the evaluation task (PickPlace) do not overlap at all; change to evaluating on the training tasks (Coffee/Stack/Threading/Assembly).

5. Observation dimension mismatch in BC-RNN evaluation (Expected 65, got 37) [Error Recovery Benchmark] (2026-02-26)#

Solution: Add a import mimicgen registration for the _D0 environment in create_env(); stop stripping the _D0 suffix and retain all MimicGen observables (_D0 environment provides additional object state observables).

6. scGPT TransformerModel.__init__ omits self.use_fast_transformer, causing the key remapping in load_pretrained() to never execute, and 17.7% attention weights are randomly initialized; strict=False silently skips without error [MIHD] (2026-02-28)#

Solution: Add a single line self.use_fast_transformer = use_fast_transformer in model.py. After fixing, ARI improved by 44.4%, and all 11 DLPFC slice embeddings were extracted again.

7. WebSocket client always reports ConnectionRefusedError; attempts with different address formats (localhost/127.0.0.1/0.0.0.0) all fail [Error Recovery Benchmark] (2026-02-28)#

Solution: Found that the http_proxy environment variable is set to 127.0.0.1:10087; the websockets library fails due to connection through the proxy.After unsetting all proxy variables at the beginning of run_eval.sh, the connection was established successfully.

8. CoffeeMachineBodyObject lacks the get_bounding_box_half_size() method, causing an AttributeError during the initialization of the MimicGen Coffee task rollout (An interface gap between MimicGen and the current robosuite version) [Error Recovery Benchmark] (2026-02-28)Solution: Trace the entire call chain (coffee_machine.py→CoffeeMachineBodyObject→CompositeBodyObject→MujocoXMLObject), and implement get_bounding_box_half_size() in three different base classes.#

9. The HD data uns[‘spatial’] image is a full-resolution image, but its coordinates are in the cropped fullres pixel space, resulting in a mismatch during visualization; moreover, since X has been logged transformed, the pipeline will again normalize_total+log1p, causing a double transformation [MIHD] (2026-02-28)#

Solution: Replace the uns[‘spatial’] image with cropped_fullres.tif in load_hd_data() and recalculate the scalefactor; add the skip_log parameter to preprocess_data(), and pass skip_log=True for HD data only for HVG filtering.

10. The Coffee BC-RNN loss converges normally (-7.66→-15.4), but SR remains 0% all the time. With the same configuration, epoch 20 already reaches 64%, showing a high similarity to insufficient model capacity [Error Recovery Benchmark] (2026-03-01)#

Solution: Compare with the actual obs key structure of the HDF5 dataset, and find that Coffee requires a 57-dimensional object state (required for multi-stage precise operations), and the configuration template lacks this field; add extra_low_dim=[‘object’] for all 9 tasks and regenerate the configuration.

11. The robomimic BC-RNN image observation access fails at four consecutive levels: the detection logic of enable_camera/checkpoint config is in JSON string format/image resolution acquisition/HWC→CHW format conversion all have issues [Error Recovery Benchmark] (2026-03-01)#

Solution: ① Detect the rgb modality from the JSON string of checkpoint config (needs json.loads); ② Read the actual 84×84 size from shape_metadata; ③ Manually transpose HWC→CHW and convert uint8→float32/255 normalization (ObsUtils.process_obs automatically handles it in the standard rollout).

12. Pi0.5 LoRA training starts with four consecutive blocking bugs: ① Setting JAX_PLATFORMS=cpu separately is ineffective; ② Wrong path for norm_stats; ③ Boolean parameter–overwrite=False is ineffective; ④ Access to W&B external network on HPC nodes is blocked [Error Recovery Benchmark] (2026-03-01)#

Solution: ① Set CUDA_VISIBLE_DEVICES=""+JAX_PLATFORMS=cpu simultaneously; ② The actual path for norm_stats is assets//benchmark//norm_stats.json; ③ Use–no-overwrite instead; ④ Predefine WANDB_MODE=disabled.

13. VisiumHD HD data pipeline path adaptation: The image path lookup in the vision encoder and spatial coords loading during fusion fail because they assume the DLPFC directory structure [MIHD] (2026-03-01)#

Solution: Add the cropped_fullres.tif pattern recognition to find_spatial_image(); pass the crop_dir.parent as data_root when calling the vision encoder; directly load coordinates from adata.obsm[‘spatial’] during fusion to bypass path lookup.

14. When calculating norm_stats, GPU util=0 but memory is fully used, and the task progresses slowly for a long time; the root cause is that PaligemmaTokenizer loads eagerly on all visible GPUs when calling get_config().model [Error Recovery Benchmark] (2026-03-01)#

Solution: Set CUDA_VISIBLE_DEVICES=""+JAX_PLATFORMS=cpu simultaneously; ② The actual path for norm_stats is assets//benchmark//norm_stats.json; ③ Use–no-overwrite instead; ④ Predefine WANDB_MODE=disabled.

15. Architecture (architecture)#

  • JAX FSDP only splits parameter storage, which does not affect the full model loading and forward activation memory during initialization; the full training state of Pi0.5 requires ~62GB/GPU, and a single A800 with 80GB cannot support full fine-tuning; LoRA (gemma_2b_lora) is the only viable solution for the A800 cluster, reducing memory demand to ~22.5GB. When the warning “Can’t reduce memory use below 62.46GiB” appears, switch to LoRA immediately.
  • The observation keys in BC-RNN configurations must match task complexity: Tasks like Coffee requiring multi-stage precise operations need a 57-dimensional object state, and a 84×84 image cannot provide sufficient spatial precision; the behavior of configuration bugs (normal loss but SR=0) is highly similar to insufficient model capacity, and differentiation requires comparison with dataset structures.
  • Vectorization and batching accelerate significantly: O(n²) nested loops → cdist matrix operation approximately 100–500x, Python逐spot loops → batch GPU forward预计 20–50x. The calculation of norm_stats completely does not require model inference; forcing CPU mode + subsampling + parallelization can reduce the time from 10+ minutes to 2.5 minutes.
  • Methodology for refactoring large repositories: Systematically grep to verify all imported dependencies → execute in the order of “create new module→update references→delete old files” → dry-run verification; before merging multiple functions with the same name, carefully compare boundary conditions (> vs >= vs < can lead to completely opposite functions).

Debugging (debugging)#

  • PyTorch model.load_state_dict(strict=False) silently ignores mismatched keys, and key weights may run as random values for a long time without reporting any errors; production code should actively print missing_keys/unexpected_keys and verify parameter value statistics. Similar bugs may exist in upstream open-source repositories, and the weight loading path needs active auditing rather than blind trust.
  • Key details of robomimic BC-RNN inference: Checkpoint config is stored as a JSON string (needs json.loads, not direct dict access); when bypassing the standard rollout process, manually transpose HWC→CHW and convert uint8→float32/255 normalization (ObsUtils.process_obs automatically handles it in the standard rollout).

Domain knowledge (domain)#

  • Key conclusion from M14: BC-RNN SR=0.28%, Pi0/Pi0.5 SR=0%, and Random’s Recovery Progress (0.0199) is higher than all learning strategies—learning strategies suffer from serious distribution external generalization failure in error injection scenarios, directly proving the necessity of LoRA fine-tuning in M15.
  • The 649 scenario database consists of two types of environments: ~519 impulse/augmented compatible scenarios (xml_hash matching) and ~130 natural_* natural capture scenarios (xml_hash different). Approximately 519 actual valid evaluation scenarios exist in M14, and all document and target episode counts need corresponding updates.
  • STAIG fusion leads comprehensively in RM-IDEAL evaluation (average r=0.396 for 151673, peak r=0.644 for Layer_3), and multi-modal fusion has a much better ability to capture spatial niche structures than single-modal baselines (gene/vision avg r≈0.06–0.12). Vision Refine performance is polarized: beneficial for weak fusion (attention +0.086 ARI), harmful for strong fusion (qformer -0.054); strong fusion already has the ability to handle high-dimensional inputs, and dimensionality reduction loses information.
  • Cross-task evaluation is a common trap in robot learning: Non-overlap between training set tasks and evaluation tasks directly leads to 0% SR; ensure train/eval task consistency during experimental design. The MimicGen _D0 environment provides additional object observables; removing the _D0 suffix reduces the observation dimension from 65 to 37, breaking input consistency during inference.
  • VisiumHD coordinate mapping: r_big//4 of 2um bin gives 8um grid row (same for col); the spatial visualization size parameter in scanpy is a multiple of spot_diameter_fullres; HD 8μm (diameter≈7.3) requires size≈4.0, DLPFC (diameter≈144) uses size=1.0; the Leiden community found that (resolution=1.0) is the default clustering strategy for unlabeled HD data (crop10large k=17, Silhouette=0.302).

Tools (tools)#

  • Best practices for Slurm cluster training engineering: Long-term training requires using sbatch (not srun to avoid session timeout due to SIGTERM); standardize all training scripts with PYTHONUNBUFFERED=1+stdbuf -oL; clean zombie GPU processes with fuser /dev/nvidiaX before starting (monitoring tools like nvitop also hold CUDA context); MUJOCO_EGL_DEVICE_ID corresponds to the physical GPU number rather than the logic of CUDA_VISIBLE_DEVICES.
  • Key configurations for JAX/Pi0.5 training: ① Set CUDA_VISIBLE_DEVICES=""+JAX_PLATFORMS=cpu in CPU mode; ② XLA_PYTHON_CLIENT_MEM_FRACTION=0.95 is effective for A800 80GB (61→77.7GB); ③ HPC nodes must predefine WANDB_MODE=disabled; ④ Use–no-overwrite for argparse boolean flags, not–flag=False; ⑤ The path for openpi norm_stats is assets//benchmark//norm_stats.json.
  • The HTTP/HTTPS proxy environment variable (http_proxy) is transparently proxied by the Python websockets library, so unset the proxy variable when debugging local services on HPC clusters. The MimicGen environment registers via the side effect of import mimicgen in robosuite; explicit execution of this import is required before calling external tools. Fixing methods missing in third-party libraries must be implemented in the entire inheritance chain across all base classes, and fixing only the recently called point will cause errors in other subclasses.
  • The pam_slurm_adopt cluster GPU nodes do not support direct SSH; srun –overlap can attach new steps to existing interactive jobs to reuse node resources; robomimic in a non-TTY environment will exit with EOFError if a checkpoint directory already exists, so clean the directory thoroughly before each start. The checkpoint directory is the most reliable evidence of training completion; a SLURM job crash does not mean training failure.
