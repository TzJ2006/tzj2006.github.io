Issues and Solutions#

1. STAIG two-stage completely ignores gene encoder output, uses raw HVG as GCN input, resulting in scGPT+UNI2+STAIG ≡ PCA+UNI2+STAIG [MIHD] (2026-03-02)#

Solution: Three-layer code tracking (Fusion.py → runner.py → STAIGTrainer.py) confirmed the architecture: gene encoder is decoupled from GNN training, improvement should start with the GNN structure rather than replacing the gene encoder

2. Pi0.5 eval client reports keepalive ping timeout, SR is 0% for all; multi-client concurrency is 24% slower in reverse serial order [Pi0.5/VLA evaluation] (2026-03-02)#

Solution: Add ping_timeout=None to connect() to disable the 20s timeout (JAX JIT compilation takes 30–60s, exceeding the default); confirmed that VLA inference is strictly serial, multi-clients are ineffective, the correct solution is BatchedVLAServer batch inference

3. STAIG fusion embedding training collapses on some sections (all zero), leading to NaN Spearman r in cross-sample evaluation [MIHD] (2026-03-03)#

Solution: Add zero-embedding detection (norm<1e-6) to load_fused_embeddings(), automatically trigger –recompute_fusion to re-train STAIG (about 50 seconds)

4. Pi0.5 LoRA training configuration name contains ‘pi05_libero’, users suspect initialization weights come from libero rather than pi05_base [Pi0.5/VLA training] (2026-03-03)#

Solution: Three-layer evidence (config.py weight_loader field + training log Restoring checkpoint path + comparison group configuration) confirmed both sides use pi05_base correctly; the configuration name describes data loading, weight_loader is the only basis

5. BC-RNN has SR=0% on all normal tasks, completely inconsistent with training rollout [error_recovery_benchmark] (2026-03-04)#

Solution: Code exploration identified a bug in baseline_accuracy evaluation regarding object observation keys, strategy receives empty observations; M14 with nearly 0% Error SR is the core argument of the benchmark (existing strategies lack error recovery capability), comparison with Normal SR clarifies the issue

6. Openpi-moe training feature norm_stats.json lacks prev_actions key but no error; hist_actions (unnormalized) directly concatenated with actions (normalized) causes scale mismatch in VAE [zhaoganlong/openpi] (2026-03-05)#

Solution: Modify compute_norm_stats.py to dynamically detect prev_actions and write statistics; the root mechanism is apply_tree(strict=False) silently skipping missing keys, new training features must force synchronized normalization scripts

7. All background services in CalendarPro never run in production environment, 321 tests all passed but no integration defect found [CalendarPro] (2026-03-05)#

Solution: Add await coordinator.start_all() in on_ready() of discord_bot.py; root cause is decoupled registration pattern and lifecycle management, unit tests cannot detect silent failure at the integration layer

8. Headless Docker container SAPIEN reports Render Error, bare except hides real exception, apt driver version does not match kernel module [VLA-RoboTwin] (2026-03-06)#

Solution: Expose real exception → confirm missing NVIDIA Vulkan ICD → extract user-mode GL library from official 535.104.12 .run package that matches kernel version strictly → inject via VK_ICD_FILENAMES/LD_LIBRARY_PATH environment variable (no root required)

9. Research Scout initial version performs deep evaluation of all papers (50) in a single stage, token waste is severe and low-relevance papers consume a lot of analysis resources [gadget/Research Scout] (2026-03-07)#

Solution: Refactored into a two-stage pipeline: lightweight screening in Stage 1 → deep analysis in Stage 2 (up to 20 high-relevance papers), aligned with real researcher reading habits

10. In code migration for error_recovery_benchmark, 65 symlinks cause indirect layers, removing symlinks requires recalculating sys.path parent chain depth [error_recovery_benchmark] (2026-03-08)#

Solution: 4-way parallel Agents clean all symlinks according to a 9-stage plan without overlap, main thread handles Makefile/Documentation; actively fix two unexpected sys.path depth errors (Path.resolve() no longer passes through symlink folding)

11. VLA-RoboTwin critical region annotation critical_region data is all zero, τ=0.10m threshold is purely based on estimation and does not match actual working space scale [VLA-RoboTwin] (2026-03-08)#

Solution: Do not adjust parameters directly, instead record original ee_target_distances (4–8 distance variables per task), analyze real data distribution first before data-driven calibration of the threshold

Learning Insights#

Architecture- Three standard checks after large-scale implementation: (1) Whether the new service is connected to the startup chain; (2) Whether cross-layer updates (IntentType→route→handler→service) are consistent; (3) Whether silent exceptions (except: pass) hide runtime errors. Passing tests is a necessary condition rather than a sufficient one, and defects in the integration layer can only be detected through end-to-end verification.#

  • Before designing an Agentic system, actively study mature similar projects—OpenClaw’s EventBus/CronScheduler/Plugin registration pattern and GSD’s STATE.md persistent memory/multi-Agent context isolation are highly reusable architectural patterns; related fixes should be merged into a single change rather than implemented in stages to avoid code rework.
  • apply_tree(strict=False) is an implicit risk in ML training pipelines: if new training features that need normalization are not updated simultaneously with the norm_stats calculation script, it will cause silent scale mismatch affecting training quality; the mismatch records of AI systems are free annotation data, and automatically returning them as utterance augmentations can achieve low-cost continuous self-improvement.
  • Two-stage information processing (rough screening + fine evaluation) is better than single-stage full processing in terms of token efficiency and analysis depth: Stage 1 focuses on problem relevance/innovation/authority of source (30 seconds judgment), Stage 2 focuses on key insights driving effects rather than engineering details, and critically examines the baseline and metrics chosen by the author.

Debugging#

  • Analysis of the root cause of low GPU utilization in VLA inference: action chunking makes inference calls sparse (about 8 calls per trial × 2.5 s/200 s total time = 10%); multi-client concurrency does not improve strict serial inference throughput. The correct optimization direction is BatchedVLAServer batch inference + independent deployment on multiple GPUs.
  • Diagnostic path for BC-RNN SR=0%; first check whether the observation key name/dimensions match training, then use historical training logs to distinguish “evaluation bug” vs “training already failed” to avoid misdiagnosis as model capability issues; bare except is the most common debugging obstacle in rendering/simulation frameworks, and should be immediately changed to except Exception: traceback.print_exc().
  • Parameter settings should be driven by experiments rather than intuitive estimation: first collect a small amount of data to verify the actual distribution before setting thresholds; incorrect estimation of key parameters (such as distance threshold, driving version) will cause the entire batch of data to be invalid or installation failure.

Tools#

  • 4-way parallel sub-Agents + the main thread handling non-parallelizable parts can control the large-scale migration of 65 symlink files within a single session; the key is dividing agent task boundaries based on non-overlapping file sets; BatchedVLAServer parallel evaluation (44 minutes/9 tasks) saves about 80% time compared to serial execution.
  • Standard solution for fixing headless HPC nodes’ Vulkan/EGL rendering: extract a user-space GL library from the NVIDIA official .run package that strictly matches the kernel version (no need to install kernel modules), inject it via VK_ICD_FILENAMES/__EGL_VENDOR_LIBRARY_FILENAMES/LD_LIBRARY_PATH, without root; EGL/Vulkan device configuration is independent of CUDA; normal CUDA performance does not mean Vulkan is available.
  • The arXiv comment field is a de facto conference acceptance announcement area; by searching the full text with all:"CVPR 2025" and filtering after comment, a specialized search for conference papers can be achieved; au:"Author Name" AND (kw1 OR kw2) is an effective way to track specific researchers’ latest work in the system.

Domain Knowledge#

  • Learning-based fusion (QFormer) is significantly better than simple concatenation: scGPT 512d representations themselves are valuable but require non-linear projection to be fully activated (+117% vs scGPT-only); STAIG’s gene encoder is decoupled from GNN training, and differences between documents and code can only be found through code tracking; zero-shot capabilities are the core competitive point against methods that rely on training.
  • Pi0.5 LoRA fine-tuning reaches 95–100% on Stack-like tasks (overall 58.9%), while BC-RNN fails completely (0%); task complexity (multiple steps, fine operations) is the main factor determining the success rate gap between VLA and traditional sequence modeling; the Pi0.5 LoRA mode also requires at least 2 × 80GB GPUs (FSDP is a necessary prerequisite).
