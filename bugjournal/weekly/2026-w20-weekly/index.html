Issues and Solutions#

1. Ambiguous user prompts cause AI to go beyond scope or ignore constraints [Unified Agent Workflow System] (2026-05-11)#

Solution: Force use of a Spec template with five required fields (goal, scope, constraint, success criteria, non-goal), which must be confirmed before implementation.

2. Lack of objective verification makes it impossible to determine if changes truly resolve issues [Unified Agent Workflow System] (2026-05-11)#

Solution: Integrate executable success criteria directly into the specification, trigger a validation gate; continue the workflow if passed, otherwise pause and enter structured debugging mode.

3. PyTorch CUDA packages fail standard pip installation due to non-standard hosting method [Development Environment Migration] (2026-05-11)#

Solution: Configure –extra-index-url to point to PyTorch’s official CUDA release index to correctly parse packages.

4. Python packages installed from sources cause pip dependency conflicts during conda reconstruction [Development Environment Migration] (2026-05-11)#

Solution: Adopt a two-stage installation strategy: install only conda packages first, then selectively reinstall pip sources when needed, using –no-deps parameter.

5. 72-day Summarize reports not appearing on GitHub Pages due to pipeline silent failure [Summarize Deployment Pipeline Fix] (2026-05-12)#

Solution: Correct the deployment iteration logic in daily.py, re-initialize public/directory as a separate git clone pointing to tzj2006.github.io.

Lessons Learned#

Architecture#

  • Structured specifications with required fields prevent AI scope expansion and constraint violations; success criteria and validation gates are functionally identical concepts and should be handled uniformly rather than split into independent steps.
  • Cross-session context requires dual formats: human reviewers use narrative/markdown format, programmatic agents read structured JSON format; a single format cannot satisfy both needs.

Debugging#

  • Deployment failures require comprehensive verification of code logic, file paths, git submodules, and remote endpoints; checking only application logs misses infrastructure issues such as missing .git directories in public folders.
  • Recording the original implementation plan in review logs helps analyze the relationship between intent and outcome, highlighting skipped steps, unexpected deviations, and actual failure causes.

Tools#

  • Conda environments with mixed dependencies require a two-stage reconstruction method (install conda packages first, then separately install pip sources), to handle source installations that PyPI cannot natively support.
  • Standard CLI conventions (e.g., using -y/–yes globally) and prioritizing mature community tools over custom implementations reduce cognitive load, accelerate iteration, and improve consistency across repositories.

Domain Knowledge#

  • AI-assisted quality is directly related to prompt specificity; clear instructions with context always outperform simple commands or vague requests. Additionally, background terminal execution in AI coding tools fails easily due to truncation, requiring proactive fallback solutions for diagnosis.

AI Usage Notes Effective Patterns:#

  • ✓ Prioritize using mature community tools (Spec Kit, Entire CLI, git-cliff) as the base layer before writing custom code.
  • ✓ Adopt a hypothesis-based diagnostic flow (“Because X → Therefore Y”) and set confidence levels, rather than blindly retrying loops.
  • ✓ Use the AskUserQuestion protocol for destructive operations and perform end-to-end verification before confirming the fix.
  • ✓ Combine AGENTS.md with cursorrules to maximize cross-agent compatibility between Claude, Codex, and Cursor environments.

Limitations:

  • ✗ Background task output is often truncated, forcing reliance on foreground execution for accurate error diagnosis.
  • ✗ Tendency to initially underestimate the maturity of community tools and overemphasize custom builds to achieve control rather than reliability.
  • ✗ Lack of real-time infrastructure visibility during deployment debugging requires manual verification of final status to detect defects in git/config.
  • ✗ Initial option design sometimes forces trade-offs (e.g., terminal vs. HTML visualization) instead of providing a comprehensive dual-output solution.
