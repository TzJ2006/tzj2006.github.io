Issues and Solutions#

1. STEGO Training loss is NaN throughout, 3639×3639 dense similarity matrix overflows in float32 operations at temperature=0.07 [MIHD] (2026-02-19)#

Solution: Two-step fix: perform L2 normalization on the input image_emb;Change InfoNCE to the numerical stability version (subtract the maximum value of rows before computing logsumexp, and increase temperature to 0.1).

2. MILWRM was incorrectly classified as an Image-Only method; the initial AI summary will mix multimodal methods with image-only results. The initial research conclusion needs significant revision [MIHD] (2026-02-19)Solution: Use WebFetch to read the full PMC text and confirm that MILWRM is actually based on gene expression, specifically mining only image-only data points from ablation experiments on articles like SpaConTDS.#

3. There is a double normalization bug in staig_fusion in eval_scan_fusion.py (STAIGTrainer internally applies StandardScaler again) [MIHD] (2026-02-20)#

Solution: Abandon fixing the standalone script and directly use run_benchmark.py that correctly passes staig_alignment_config, reusing the verified path.

4. run_benchmark.py instantiates the encoder each time to extract embeddings, lacking pipeline-level cache support [MIHD] (2026-02-20)#

Solution: Integrate CacheManager from pipeline/cache_manager.py, load from cache before encoding, and write back to cache after extraction; skip encoder instantiation when a cache hit occurs.

5. Lerobot 0.1.0 is incompatible with datasets >=4.0 (torch.stack reports TypeError: Column object replaces list) [Error Recovery Benchmark / Phoenix pi0.5] (2026-02-22)#

Solution: Downgrade datasets from 4.4.1 to 3.6.0 (<4.0); datasets 4.0 changes the return value of dataset[‘column’] from a list to a Column object, and Lerobot expects a list/tuple of tensors.

6. The official HuggingFace download fails due to proxy (Squid 503), and the Python download script cannot connect [Error Recovery Benchmark / Phoenix pi0.5] (2026-02-22)#

Solution: Use hf-mirror.com + wget; URL format: https://hf-mirror.com/datasets/{repo_id}/resolve/main/{file_path}，通过集群 HTTP proxy reaches 40–200MB/s.

7. Unstable access to SLurm GPU nodes: srun lacks –overlap, causing command hangs; direct SSH connection is unreliable, and multi-partition submissions are rejected [Error Recovery Benchmark / Phoenix pi0.5] (2026-02-22)#

Solution: Standardize the workflow: source set-XY-I.sh → squeue → srun –jobid= –overlap; avoid direct SSH to GPU nodes.

8. Abnormal spatial coordinate dimension in eval_scan_fusion.py (turns into (1,2)), causing errors in multiple fusion methods [MIHD] (2026-02-19)#

Solution: Abandon calling load_spatial_coordinates() (barcode matching fails), and directly read coordinates from adata.obsm[‘spatial’]; fix the unpacking error in load_dlpfc_data return value.

Learning Gains#

Domain Knowledge (domain)#

  • Pure image-only achieves only 0.11–0.16 ARI in DLPFC fine-grained stratification tasks (multimodal reaches 0.45–0.64), which is a combination of extremely small morphological differences between brain layers and mismatch in the Foundation Model training domain; ablation experiments of multimodal methods almost never test image-only separately—this is a noteworthy research gap.
  • Five main reasons for failure in space domain recognition by Foundation Models: ① Training mainly on cancer tissue (domain gap); ② Pre-training task mismatch with inter-layer gradient recognition; ③ Extremely small morphological differences between cerebral cortex layers; ④ High redundancy between image features and gene expression; ⑤ Lack of spatial context in independent encoding of a single patch.
  • STAIG uses BYOL for unsupervised domain adaptation on target dataset H&E patches (keep encoder after training, discard projector/predictor)—this is a direct precedent for introducing unsupervised domain adaptation into spatial transcriptomics; the design of BYOL without negative samples is naturally suitable for small batch ST scenarios (thousands of patches per section).
  • The CV community has a four-stage framework for handling “domain gap + fine-grained task + unlabeled data”: Level 1: direct pre-trained feature clustering → Level 2: STEGO/SCAN feature refinement → Level 3: domain-specific SSL re-training (BYOL/MAE) → Level 4: dedicated Foundation Model; GPFM/CHIEF are the optimal PFM for space domain recognition ARI, and UNI2 are the optimal spot retrieval.

Architecture (architecture)#

  • SCAN is the optimal ARI (0.303, +20.6%) in image-only spatial transcriptomics scenarios. Its core advantage is that offline feature k-NN mining decouples embedding learning and clustering; its 256-dimensional optimized embeddings complement gene features (mean fusion +0.065 ARI).
  • Two-stage fusion is not necessarily better than single-stage: after scanning_cluster compresses visual embeddings from 1536d to 256d, multimodal fusion ARI (0.313) is lower than direct concat (0.387), indicating that self-supervised compression loses the original feature diversity required for fusion tasks, and the optimization objectives of self-supervised clustering conflict with downstream fusion tasks.
  • Internal StandardScaler+PCA preprocessing in STAIG fusion absorbs the external embedding optimization effect (the ARI difference between SCAN and UNI2_raw is only 0.005); embedding cache should store raw embeddings before normalization, and post-encoder normalization should be performed after loading to ensure consistent results across different call paths.
  • VLA baseline evaluation must explicitly state the checkpoint source: using non-target task fine-tuning models (pi0_libero, pi05_base) to evaluate zero-sample cross-domain recovery capacity—the paper must actively declare this experimental setup, and subsequent comparative experiments after fine-tuning are needed to fully demonstrate the usefulness of the dataset.
  • In complex experimental systems, prefer using existing, verified tool paths (such as run_benchmark.py); standalone scripts easily introduce hidden bugs such as inconsistent preprocessing; before calling internal project functions, read the source code in real time to verify the function signature, rather than relying on memory.

Debugging (debugging)#

  • When computing large-scale dense similarity matrix (n>3000) and InfoNCE contrast loss, use numerically stable log-sum-exp (subtracting row maximum), otherwise exponential operations with temperature=0.07 at float32 precision will overflow and produce NaN; this is a key engineering constraint for large-scale contrast learning implementation.

Tools (tools)#

  • Lerobot 0.1.0 has strict constraints on datasets versions; it must be pinned to <4.0 (recommended 3.x); datasets 4.0 change the return value of dataset[‘column’] to a Column object, causing torch.stack to report TypeError; MimicGen is fully compatible with LIBERO obs/action format (84×84 images, 8D state, 7D action)—OpenPI’s LeRobotLiberoDataConfig can be directly reused.
  • The standard solution for accessing HuggingFace on Chinese mainland HPC clusters is hf-mirror.com; URL format: https://hf-mirror.com/datasets/{repo_id}/resolve/main/{file_path}，通过 wget + HTTP proxy reaches 40–200MB/s—this should be used as the default solution.
  • OpenPI’s JAX training naturally supports multi-GPU data parallelism; just specify the GPU list in CUDA_VISIBLE_DEVICES, and JAX automatically builds a 2D mesh parallel—no changes to TrainConfig are needed; Slurm –overlap is a key parameter for running new commands on existing interactive jobs—it is a core technique for calling cluster GPUs in Claude Code environment.
