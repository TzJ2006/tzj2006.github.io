Problems & Solutions#

Critical Issues#

1. ~36px position jump when clicking the Linux floating ball#

Solution: Changed the Left/Right anchor branch in Rust side expanded_rect_from_ball() from “attaching to inner_bounds edge” to “using ball_rect.x as the anchor, minimizing clamping only when overflowing”, ensuring the ball coordinate remains unchanged before and after expansion/collapse.

Key Insight: The x-coordinate of the expanded window should equal ball_rect.x (left expansion) or ball_rect.x-(expanded_width-ball_size) (right expansion), and only push inward when the monitor really cannot hold it; when dealing with cross-platform UI position issues, prioritize asking “which layer is changing the coordinate” rather than “how to convert coordinates”, indicating that the Rust/native layer is more likely to be the root cause than the front-end.

2. Ghosting of the full expanded window when collapsing the Linux floating ball (WebKitGTK transparent window)#

Solution: Changed Linux collapse to native-first order: first invoke set_float_ball_expanded(false) to shrink the native window, then flip Svelte expanded state, avoiding the large transparent window from being exposed on the screen.

Key Insight: WebKitGTK/compositor does not actively clear the old pixel buffer of the transparent window; as long as the native window remains expanded in size, old content is always visible during CSS animations, regardless of how elements are hidden by the front-end.

3. Abnormal ARI=1.0 in STAIG HD experiment results (old cache contamination)#

Solution: Traced the npz file timestamp and found that the STAIG npz comes from Feb 28 old runs; the root cause is the missing staig_gene_feat cache, resulting in silent failure of the experiment but retention of old files. Manually prepared the HD STAIG gene feature cache and deleted the old npz to resubmit.

Key Insight: The pipeline’s skip_completed mechanism cannot detect when the file exists but the content is invalid (all gt_labels are -1), requiring active verification of gt_labels validity.

4. First-round bug fix did not resolve the root cause (AI misidentified the root cause)#

Solution: After user feedback, the AI reviewed again, shifting focus from “front-end coordinate conversion and delayed shrink timing” to “Rust anchor layout itself and Linux native collapse order”, and after locking the true root cause, the fix was implemented a second time.

Key Insight: The first round focused too much on front-end coordinate conversion, ignoring the root cause of the Rust layout function actively changing the position; humans insisting on describing symptoms rather than accepting “requires more complex implementation” is key to triggering the correct fix path.

5. HD learning-based fusion GPU job timeout: Actual runtime on HD dataset (17502 spots) far exceeds expectations#

Solution: Killed the local process and then submitted the GPU job, finding that 6h was still insufficient, so it was changed to 4 independent SLURM jobs, with each fusion strategy submitted separately and sufficient time limit set (24h+).

Key Insight: The training time for learning-based fusion grows superlinearly with dataset size; the time on HD (17502 spots) cannot be linearly extrapolated from that on DLPFC (~4000 spots).

General Issues#

6. Engineering configuration issues: Rust/Cargo not in PATH, SLURM script mistakenly deleting GT cache, conda ToS forced acceptance#

Solution: For Rust PATH: source ~/.cargo/env before building; for SLURM script: remove the line ‘rm -f ground_truth.npz’ and manually rebuild GT cache; for conda ToS: run conda tos accept –override-channels to specify channels.

Key Insight: Rust installation only modifies ~/.bashrc, child processes do not inherit the interactive shell environment; conda 26.x added a forced acceptance mechanism for ToS, and unattended scripts need pre-processing.

AI Limitations#

  • First-round bug fix missed the root cause in the Rust layer: Focus was placed on front-end coordinate conversion and animation timing, ignoring the active position change of the sphere by the Rust layout function itself, resulting in a second feedback step to trigger the correct fix path.
  • Unable to verify in real environments: Cannot execute system configuration commands requiring sudo, nor can UI behavior be actually run and observed in Linux GUI environments.   • When uncertainty is high, it prefers defensive overdesign (introducing last_rect caching, new IPC commands), or delays in recommending more reasonable solutions (after 168 minutes of CPU runtime due to GPU job timeout, a change to SLURM submission is suggested).
  • No continuous memory for large research projects: Each session starts with re-indexing the code architecture and current state; CCPlan needs multiple parallel subagents to fully understand the code status.

General Limitations#

  • Boundaries in knowledge of new hardware features: Predictions about RTX 5090 FP8 support do not match actual benchmark results (PyTorch does not implement addmm_cuda), and the support status of new hardware requires runtime verification rather than relying on specification information in training data.

Learnings#

Key Learnings#

  • Core experimental conclusion: High-quality embeddings are more important than clustering method selection. STAIG+mclust(0.546) > STAIG+Leiden(0.513); Leiden helps significantly with weak embeddings (+29%) but offers little extra benefit for strong embeddings (+6%). The quality of the fusion strategy determines the upper limit.
  • Linux WebKitGTK does not actively clear the old pixel buffer of transparent windows: When the native window remains large, CSS hiding elements cannot eliminate ghosting; the correct approach is native-first collapse (first shrink the native window, then drive front-end state changes).
  • Tauri cross-platform floating window layout should use the actual position of the sphere as the anchor point (not the safe-area boundary) to ensure the sphere appears stationary visually; when debugging UI position issues across platforms, prioritize asking “which layer is changing coordinates”, as the Rust/native layers are more likely to be the root cause than the front-end.
  • HD dimension imbalance issue: Concatenation fusion (1586d = 50d PCA + 1536d UNI2) is worse than PCA in a single modality, with high-dimensional modalities dominating completely; multi-modal fusion requires dimension alignment or weighting, and simple concatenation is not feasible when dimensions differ significantly.
  • HD niche query discovery: Multi-modal attention fusion border queries can capture the mixed micro-environment at tissue boundaries, while gene-only PCA queries tend to focus on the same tissue type, indicating that multi-modal embeddings encode richer spatial context.

Practical Learnings#

  • SLURM GPU job design principle: Learning-based fusion training time grows superlinearly with dataset size; HD(17502 spots) cannot be linearly derived from DLPFC(~4000 spots); each strategy should create independent jobs with sufficient time (24h+).
  • Tauri Linux floating ball right-click should filter at the pointerdown layer (button!==0), rather than relying on preventDefault, otherwise the right-click triggers the same expand/collapse logic as left-click.
