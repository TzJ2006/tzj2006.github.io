Issues and Solutions#

Key Issues#

1. ~36px position jump of Linux floating ball after click#

Solution: Change the Left/Right anchor branch in Rust side expanded_rect_from_ball() from “adhere to inner_bounds edge” to “use ball_rect.x as anchor, minimize clamping only when overflowing”, ensuring the ball coordinate remains unchanged before and after expansion/collapse.

Key insight: The x-coordinate of the expanded window should equal ball_rect.x (left expansion) or ball_rect.x-(expanded_width-ball_size) (right expansion), pushing inward only when the monitor really cannot hold it; when dealing with cross-platform UI position issues, prioritize asking “which layer is changing the coordinates” rather than “how to convert coordinates”, and the Rust/native layers are more likely to be the root cause than the front-end.

2. Ghosting of the full expanded window when Linux collapses the floating ball (WebKitGTK transparent window)#

Solution: Change Linux collapse to native-first order: first invoke set_float_ball_expanded(false) to shrink the native window, then flip Svelte expanded state, avoiding the large transparent window from being exposed on the screen.

Key insight: WebKitGTK/compositor does not actively clear the old pixel buffer of the transparent window; as long as the native window remains expanded in size, old content is always visible on the screen during CSS animations, regardless of how elements are hidden by the front-end.

3. Abnormal ARI=1.0 in STAIG HD experiment results (old cache pollution)#

Solution: Investigated the npz file timestamp and found that the STAIG npz comes from old runs on Feb 28. The root cause is missing staig_gene_feat cache, resulting in silent failure of the experiment but retention of old files. Manually prepared the HD STAIG gene feature cache, then deleted the old npz and resubmitted.

Key insight: The pipeline’s skip_completed mechanism cannot detect when the file exists but the content is invalid (all gt_labels are -1), so active verification of gt_labels validity is needed.

4. First-round bug fix did not resolve the root cause (AI mislocated the root cause)#

Solution: After user feedback, the AI reviewed again, shifting focus from “front-end coordinate conversion and delayed shrink timing” to “Rust anchor layout itself and Linux native collapse order”, and locked in the true root cause before second implementation.

Key insight: The first round focused too much on front-end coordinate conversion, ignoring the root cause of the Rust layout function actively changing the position; humans insisting on describing symptoms rather than accepting “requires more complex implementation” is key to triggering the correct fix path.

5. HD learning-based fusion GPU job timeout: Actual runtime on HD dataset (17502 spots) far exceeded expectations#

Solution: Killed local processes, then submitted the GPU job, finding that 6h was still insufficient. Changed to 4 independent SLURM jobs, submitting each fusion strategy separately with a sufficient time limit (24h+).

Key insight: The training time for learning-based fusion grows superlinearly with dataset size; the time for HD (17502 spots) cannot be linearly extrapolated from that for DLPFC (~4000 spots).

General Issues#

6. Engineering configuration issues: Rust/Cargo not in PATH, SLURM script accidentally deleting GT cache, conda ToS forcing acceptance#

Solution: For Rust PATH: source ~/.cargo/env before building; for SLURM script: remove the line ‘rm -f ground_truth.npz’ and manually rebuild GT cache; for conda ToS: run conda tos accept –override-channels to specify channels.

Key insight: Rust installation only modifies ~/.bashrc, child processes do not inherit the interactive shell environment; conda 26.x added a ToS forcing acceptance mechanism, so unattended scripts need prior processing.

Limitations of AI#

Key Limitations#

  • First-round Bug fixes missed the root cause in the Rust layer: focus was on front-end coordinate conversion and animation timing, ignoring how the Rust layout function actively changes the ball’s position, resulting in users needing secondary feedback to trigger the correct fix path.
  • Unable to verify in real environments: cannot execute system configuration commands requiring sudo, nor can it actually run and observe UI behavior in Linux GUI environments. All verification relies on static code analysis and automated testing, which cannot replace manual testing on real devices.
  • Tendency toward defensive overdesign when uncertainty is high (introducing last_rect cache, new IPC command), or delaying the recommendation of a more reasonable solution (after 168 minutes of CPU running due to GPU job timeout, a change to SLURM submission is recommended).
  • No continuous memory of large research projects: each session starts with re-indexing the code architecture and current status; CCPlan needs multiple parallel subagents to fully understand the code status.

General Limitations#

  • Bound knowledge of new hardware features: predictions about RTX 5090 FP8 support do not match actual benchmark results (PyTorch does not implement addmm_cuda), and the support status of new hardware requires running verification rather than relying on specification information in training data.

Today’s Insights#

Key Insights#

  • Core experimental conclusion: High-quality embeddings are more important than clustering method selection. STAIG+mclust(0.546) > STAIG+Leiden(0.513); Leiden helps greatly for weak embeddings (+29%) but offers almost no extra benefit for strong embeddings (+6%), and the quality of the fusion strategy determines the upper limit.
  • Linux WebKitGTK does not actively clear the old pixel buffer of transparent windows: when the native window remains large, CSS hidden elements cannot eliminate ghosting; the correct approach is native-first collapse (first shrink the native window, then drive front-end state changes).
  • Tauri cross-platform floating window layout should use the actual ball position as the anchor (not the safe-area boundary) to ensure the ball remains visually fixed; when debugging UI position issues across platforms, ask “which layer is changing the coordinates” first—Rust/native layers are more likely to be the cause than the front-end.
  • HD dimension imbalance issue: concat fusion (1586d = 50d PCA + 1536d UNI2) is worse than PCA with a single modality, as high-dimensional modalities dominate completely; multi-modal fusion requires dimension alignment or weighting, and simple concatenation is not feasible when dimensions differ significantly.
  • HD niche query discovery: multi-modal attention fusion border queries can capture the mixed micro-environment at tissue boundaries, while gene-only PCA queries tend toward the same tissue type, indicating that multi-modal embeddings encode richer spatial context.

Practical Insights#

  • SLURM GPU job design principle: learning-based fusion training time grows superlinearly with dataset size; HD(17502 spots) cannot be linearly calculated from DLPFC(~4000 spots); independent jobs should be created for each strategy with sufficient time (24h+).
  • Tauri Linux floating ball right-click should filter at the pointerdown layer (button!==0), rather than relying on preventDefault, otherwise the right-click triggers the same expand/collapse logic as left-click.
