Issues and Solutions#

Key Issues#

1. run_benchmark.py re-instantiates encoders and extracts embeddings every time it runs, wasting time spent on UNI2/SCAN features that have already been calculated.#

Solution: Integrate CacheManager into the has/load/save_*_embedding() methods; add cache checks before encoder instantiation to support variant types (standard/frequent/strict); pass coverage flags to both calling points.

Key insight: The user’s expectation is correct—run_benchmark.py should have cache functionality like the pipeline. AI initially proposed workarounds (separate evaluation scripts, manual caching) instead of addressing the root cause.

2. BC-RNN strategy expects an input size of 65, but the environment provides a dimension of 37, leading to a RuntimeError.#

Solution: The root cause is the mismatch in object count (8 objects = 56 dimensions used during training, 4 objects = 28 dimensions in the evaluation environment). Fixed the _to_robosuite_obs() function to map ‘object-state’ to ‘object’ and use raw robosuite obs from environment._env._get_observations(), instead of using StateExtractor.

Key insight: The initial fix only applies to the injection path (_generate_from_single_rollout); the same issue exists in the natural capture path. All code paths need to be checked when fixing the observation pipeline.

3. The staig_fusion ARI of 0.39 in eval_scan_fusion.py is lower than expected.#

Solution: Investigation revealed a double normalization error—staig_alignment_config was not passed, so STAIGTrainer applied StandardScaler after upstream preprocessing, even though sc.pp.scale() has already been executed. Additionally, no baseline of 151673 staig_fusion exists for comparison.

Key insight: “Lower than expected” without baseline data is a guess. Always verify whether a baseline exists before assuming regression. Moreover: independent evaluation scripts easily ignore configuration details that the standard pipeline can handle correctly.

General Issues#

4. MimicGen dataset enhancement failed, resulting in the “env_class unexpected keyword argument” error.#

Solution: robomimic_utils.py was fixed using inspect.signature() to filter kwargs according to robomimic 0.3.0 API signature, but still hindered by a mujoco_py dependency issue in pip installation of robomimic. The MimicGen step was decided to be skipped, and scale is achieved through more BC-RNN/VLA rolling.

Key insight: Environment isolation issues require deep dependency analysis. When obstacles arise, alternative methods should be explored instead of forcing incompatible dependencies.

Limitations of AI#

Key Limitations#

  • Multiple solutions (separate evaluation scripts, pipeline mode switching, manual SCAN caching) were proposed, but resistance was shown toward modifying the existing standard tool before accepting the missing cache support in run_benchmark.py.
  • The obs mismatch issue in the BC-RNN injection path was fixed, but the same issue in the natural capture path was ignored and needs to be fixed again—complete code analysis cannot be performed during debugging.

General Limitations#

  • Claims that staig_fusion results are “lower than expected” but no baseline exists for verification—just a guess, no evidence.
  • Continues waiting for long periods for TaskOutput results instead of identifying when to switch to incremental testing methods.
  • The initial MimicGen fix only addressed the API signature mismatch, ignoring deeper mujoco_py dependency issues, which requires rebuilding the environment.

Lessons Learned#

Key Experiences#

  • When users question redundant work (“If embeddings already exist, why re-instantiate?”), they are usually looking for missing infrastructure that should exist—understanding the user’s expectations is necessary before proposing solutions.
  • Errors in observation pipelines across multi-path codebases (injection and natural capture) require thorough analysis—fixing issues in one path does not guarantee resolution in all paths; all use cases using this pattern need to be examined.
  • Cache variants (standard/frequent/staig_strict) can prevent conflicts arising from different preprocessing flags—this variant system is more robust than using only encoder names.

Practical Experience#

  • Large-scale GPU tasks can benefit from parallel startup on different devices with distinct log files (m12_bc_rnn_injection.log, m12_bc_rnn_natural.log) for independent monitoring.
  • Environment dependency issues (mujoco_py in robomimic 0.3.0) may become obstacles—when problems arise, alternative data sources should be explored instead of forcing incompatible dependencies.
