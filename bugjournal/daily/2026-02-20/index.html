Issues and Solutions#

Key Issues#

1. run_benchmark.py lacks cache loading functionality, leading to redundant encoding iterations; AI initially suggested writing independent evaluation scripts to resolve inconsistent comparisons.#

Solution: Users corrected the architecture direction: integrating CacheManager directly into the existing benchmark script and adding variant tracking, instead of creating parallel tools that might introduce preprocessing drift.

Key Insight: Utilizing existing process infrastructure is more robust and maintainable than building isolated evaluation wrappers, especially when strict feature normalization consistency is required.

2. The low STAIG fusion ARI score produced by eval_scan_fusion.py is due to the lack of alignment configuration, resulting in dual normalization by external preprocessing and internal StandardScaler.#

Solution: Identified the root cause and recorded that passing the correct staig_alignment_config to apply_fusion() triggers align_staig=True, automatically skipping redundant scaling in the trainer.

Key Insight: When evaluating models using built-in feature alignment or normalization layers, the external preprocessing process must pass a clear override flag or completely skip normalization to avoid signal distortion.

3. BC-RNN policy evaluation crashes during expansion due to mismatched input dimensions (checkpoint expects 65-dimensional, environment provides 37-dimensional) and state_info incorrectly replacing raw observations.#

Solution: Fixed the key mapping in _to_robosuite_obs() to match the training mode, and updated generate_from_single_rollout and capture_single_rollout methods to pass the raw robosuite dictionary during initialization.

Key Insight: The policy inference process must strictly maintain the original observation pattern during expansion, as internal state extractors often lose or compress keys required by pre-trained adapters.

General Issues#

4. Failure of MimicGen data set generation in RoboMimic 0.3.0 is due to passing outdated kwargs to create_env_for_data_processing, causing environment instantiation crashes.#

Solution: Dynamically checked the real-time API signature, updated the wrapper to pass only supported parameters conditionally, and automatically fallback when expected fields are missing from environment metadata.

Key Insight: Version locking of third-party ML environments is crucial; dynamic signature checks or strict version restrictions can prevent hidden API damage during data flow execution.
