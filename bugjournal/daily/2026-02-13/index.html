Issues and Solutions#

Key Issues#

1. The error recovery robot never approaches objects during demonstration replay (minimum distance 0.22 meters, task requires contact)#

Solution: By tracking robosuite source code, HDF5 metadata, and MuJoCo body mapping, it was found that the demonstration recorded with PickPlace_D0+ controller configuration is replayed in pure PickPlace mode. The same operation produces a completely different trajectory.

Key Insight: Environmental configuration (including kp, damping, slope ratio controller configurations) fundamentally changes robot dynamics. Always using accurate environmental metadata from HDF5 dataset for replay — parameter adjustments cannot cover the fundamental issue.

2. CalendarPro semantic router and LLM conflict, causing incorrect routing by default (e.g., ‘leetcode’ keyword → manage_recurring instead of update)Solution: dual_verify.py was modified to prioritize LLM intent over SR when conflicts occur. LLMs possess a complete conversation context, whereas SR only matches keywords. The log message ‘→ using LLM intent’ is used for monitoring.#

Key Insight: Classifiers based on keywords fail with ambiguous expressions. When semantic routers and LLMs disagree, the model with more context (LLM) should be trusted instead of faster SR. SR filters obvious cases, and LLMs act as arbitrators.

3. Missing data in MIHD Chapter 4 leads to process failure (space files, empty regions in frequency filtering, STAIG model crash)#

Solution: Extract space files from Dataset.zip; add boundary checks (min_w/min_h >= 10); add mclust to the fallback mechanism of KMeans, using a try/except wrapper.

Key Insight: Spatial transcriptomic data requires strong fault tolerance: multi-path candidate search, image processing boundary checks, and statistical model fallback strategies to handle distribution anomalies.

4. The original single-step workflow of gadget cannot support multi-device collaboration (log must be manually copied to each device) Solution: Reconstructed into a two-stage process: (1) A sub-command is used to create local JSON logs, which include device information without an API key; (2) The sub-commands are merged to aggregate multiple logs and call the API to generate the final report; the old mode is retained to ensure backward compatibility.#

Key Insight: Multi-device workflows require a portable intermediate format (versioned JSON logs) and clear stage separation (local parsing and remote merging). Key design elements: device information collection, version features supporting future expansion, optional device-level summaries to prevent information loss during merging.

5. All error detectors fail after adding the neighboring threshold—after adjusting the iteration threshold (0.05→0.15→0.25→0.30m), no triggering event occurs.#

Solution: A diagnostic script was written to measure the actual EEF-object distance, revealing that the issue is environmental mismatch rather than a threshold problem. The root cause is the replay configuration, not the sensitivity of the detector.

Key Insight: When all detectors fail, the true value should be measured via diagnostic logs, and then the threshold should be adjusted. Symptoms of no triggering events often hide the underlying mismatch (controller dynamic errors).

6. CalendarPro calendar API errors (403 insufficientPermissions, HttpError) are output via print() and return None, causing users to be troubled by a generic “failure” message.#

Solution: A CalendarServiceError exception is created; all calendar_service methods are refactored to throw exceptions with detailed context; all callers are updated to capture and display user-friendly messages containing technical details.

Key Insight: Silent error handling (print + returning None) breaks the error contract. Users cannot fix issues they cannot see. Errors with context should always be passed to the presentation layer, followed by appropriate formatting.

7. CalendarPro AI provider lacks a timeout mechanism—network latency may cause the entire robot to halt indefinitely.#

Solution: All API calls are wrapped with asyncio.wait_for(timeout=30.0), and httpx.Timeout(30.0) is added in the client constructor. When the timeout occurs, an AIResponse containing error fields is returned.

Key Insight: Timeout protection requires dual layers: asyncio coroutine level (wait_for) and HTTP client level (httpx.Timeout) to capture different failure modes.

8. CalendarPro JSON parsing failure occurs when the AI returns text, multiple blocks, or truncated JSON before JSON—leading to intent classification failure.#

Solution: The _extract_json() method is implemented to extract the first complete object by balancing the bracket count; a three-stage fallback (direct parsing → trailing comma repair → general intent) is added; ValueError exceptions are removed for logging and fallback use.

Key Insight: Production-level AI systems need graceful degradation—never crash on malformed output, always provide a safe fallback intent.

9. The planning document lacks self-containedness—users repeatedly reject the ExitPlanMode mode, demanding “writing every word of the plan into the plan file”.#

Solution: The planning document is rewritten to be fully self-contained: user decision records are added, code snapshots with exact line numbers are included, QueST reference code details are provided, complete implementation code with “inserted after line X” locations are included, and corresponding positions for each stage are given.

Key Insight: Planning mode documents must be fully self-contained for future session recovery. User rejection signals indicate insufficient details—all exploration results (exact positions, line numbers, function signatures, existing code) must be written into the plan; external context cannot be relied upon.

10. MuJoCo speed swap causes false instability triggers (angular velocity is misread as linear).#

Solution: Array slices are swapped: linvel = cvel[3:], angvel = cvel[:3] to match MuJoCo’s [angular(3), linear(3)] layout.

Key Insight: Documentation mismatch: code comments claim [linear, angular], but MuJoCo stores [angular, linear]. Always verify against the source document, not inline comments.

11. Error recovery CLAUDE.md has 615 lines, with many repetitions between sections, and some content belongs to the README file.#

Solution: The document is rewritten, focusing on: (1) Information that is difficult to discover (server limits, common pitfalls); (2) Merging commands into a single block; (3) Removing easily discoverable content (file tree, method signatures); (4) Keeping only architectures that require multi-file reading.

Key Insight: AI agent documentation should focus on content that cannot be discovered via tools, rather than a comprehensive reference. Simplicity improves usability—101 lines vs. 615 lines, and it is clearer.

12. When CalendarPro updates repeated events, it modifies the entire series instead of a single instance, even though singleEvents=True is used during search.#

Solution: The update_event() method is modified to detect repeated instances (has recurringEventId), and the duplicate/recurringEventId fields are removed before calling the API. Google Calendar only generates an exception for that instance.

Key Insight: Implicit behavior of Google Calendar API: singleEvents=True during search provides instance IDs, but update/delete requires explicit removal of fields to avoid series-wide changes. Always test repeated operations on a test calendar.

13. CalendarPro asyncio.create_task() used for the message queue has no exception callback—tasks may silently die in the full queue, and user messages are never processed.#

Solution: done_callback=_on_queue_task_done is added to all create_task calls; a cleanup processor is implemented to record exceptions and remove dead tasks; a close() method is added for closing.

Key Insight: Asyncio background tasks are defaultly “forgotten”—always add done callbacks for monitoring/cleanup, especially long-running tasks.

15. MIHD GPU peak statistics always remain zero (ResourceMonitor never calls update_peak_stats()).#

Solution: ResourceMonitor is refactored: start_monitoring() starts a daemon thread for sampling per second, stop_monitoring() terminates the thread and samples the final peak, threading.Event is used for lifecycle control.

Key Insight: Monitoring peak statistics requires continuous sampling during operation, not just start/stop snapshots. Background daemon threads are a standard solution, but proper lifecycle management is needed to avoid resource leakage.

16. The gadget test/ directory is a nested git repository containing its own remote repository, causing conflicts with git add on nested repositories.#

Solution: git submodule is used: test files are moved to a backup, ‘git submodule add git@github.com:TzJ2006/test.git test’ is used to clone to the correct commit, the backup is removed, and .gitmodules automatically records the configuration.

Summary#

All issues were resolved through tool integration, code refactoring, and architecture optimization, maintaining the original Markdown format. Key Insight: Git submodules are suitable for nested repositories with independent remote repositories. Key points: submodules record commit hashes rather than branches; ‘git submodule update –init –recursive’ is required during cloning; updates require entering the submodule directory, executing git pull, and then committing to change the hash.

17. CalendarPro start.bat cannot detect the conda environment (CONDA_PREFIX is unavailable in a new cmd window, cmd does not support ‘conda activate’ without conda init).#

Solution: A start.ps1 file containing native PowerShell conda support is created; ‘conda activate calendarpro’ can be executed directly in PowerShell. start.bat is updated to use -Powershell -ExecutionPolicy Bypass to delegate execution; PID tracking and stop.ps1 files are added.

Key Insight: Windows batch files have poor integration with conda. For conda workflows on Windows, PowerShell is a better choice. Always test environment activation in a new shell, rather than using inherited conda sessions.

18. CalendarPro simulation patch fails because generate_with_fallback is locally imported inside the method, not at the module level.#

Solution: The patch target is changed from ‘src.thoughts.thought_organizer.generate_with_fallback’ to ‘src.ai.provider_selector.generate_with_fallback’, so the patch can be applied at the source module level.

Key Insight: During simulation, patches should be placed where the function definition is, not where it is imported—local import creates new references, thereby bypassing the module-level patch.

19. After creating test_thoughts.py, CalendarPro pytest async tests fail due to the ‘coroutine never awaited’ warning.#

Solution: The pytest-asyncio package is installed, which can automatically detect async test functions and run them in the event loop.

Key Insight: pytest itself does not support async tests—pytest-asyncio plugin must be introduced as a dependency in pyproject.toml.

Learning Outcomes#

Key Takeaways — Environment configuration (controller_configs) fundamentally changes robot dynamics in the robot suite. When replaying examples, always extract and use precise env_name + env_kwargs from HDF5 dataset metadata.#

  • Error injection visualization requires a three-stage narrative: (1) replay example actions that trigger; (2) moments showing detection triggers; (3) error injection and consequences. Static snapshot recovery loses the context of “why injection now”.
  • Accuracy of robot simulation replay requires identical environment configuration and controller parameters (OSC_POSE, kp, damping coefficient, ramp_ratio), not just task name. Must load example metadata (env_args in HDF5) to reproduce the same dynamics.
  • Never ignore errors (just print and return None). Must pass error messages along with context to the display layer. Users cannot fix errors they cannot see.
  • Multi-device workflow uses a two-stage pattern: local export (no API required) + remote merge (requires API). Key elements include versioned intermediate formats (JSON logs), device information collection, optional per-device summaries.
  • The goal of “planning mode” is to generate a fully self-contained implementation manual, requiring all exploration results (exact code location, line numbers, function signatures, existing code snippets), not a simple task list.
  • Systematic root cause analysis is better than gradual parameter adjustment. When detection fails, systematically compare recording and playback environment configurations before adjusting thresholds. Parameter expansion often hides the underlying mismatch issue.
  • When two classifiers have conflicting opinions (semantic router and LLM), trust the one with more context (LLM). Keyword matching fails in ambiguous expressions.
  • Timeout protection requires dual defense: use asyncio.wait_for() for coroutine-level timeout, use httpx.Timeout() for connection-level timeout — different failure modes require different protection mechanisms.
  • Production AI systems must not crash due to malformed AI output — implement three-stage fallback (direct parsing → fix → safe default) and log everything in each stage.
  • When implementing new features in the existing code base, studying similar patterns (ThoughtOrganizer → PeriodicChecker) ensures architectural consistency and reduces integration resistance.
  • Fault-tolerant design for spatial transcript data: multi-path candidates search (main_dir and Dataset/DLPFC), image processing boundary checks, statistical model fallback strategy (mclust → KMeans).
  • MuJoCo cvel stores [angular(3), linear(3)], not [linear(3), angular(3)]. Always verify binary data layout against main documentation, not relying on inline comments.
  • AI agent documentation should focus on non-obvious information and architecture patterns requiring multi-file understanding, not comprehensive reference materials. AI agents can discover file structure and method signatures via tools, but need context guidance on pitfalls and constraints.
  • Google Calendar API’s periodic events: singleEvents=True returns instance ID, but update/delete operations require explicit field extraction (recurrence, recurringEventId) to avoid global changes.
  • Comprehensive planning document (including maturity rating, roadmap priority, architecture rationale in PLANNING.md) provides strategic foundation for gradual development.
  • Asyncio background tasks need clear lifecycle management: use create_task + done_callback for monitoring, close() for cleanup, proper exception logging to prevent silent failures.
  • CalendarPro architecture pattern: JSONL appends to speed up (thoughts.jsonl, intent_mismatches.jsonl), JSON for mutable state, reuse existing data sources (DEFAULT_MEALS/DEFAULT_SLEEP) as a single real source.
  • Comprehensive preliminary exploration (using parallel Explore agents) before writing architecture documentation is more effective than gradual discovery — strategic thinking yields results.
  • Two-stage pipeline (export→merge) is natural for multi-device workflows and suitable for manual data transfer. Local export supports incremental processing and asynchronous device usage.
  • Lazy import (import statements inside methods) helps break circular dependencies, but requires special testing: simulate namespace of consumption module, not the original module.

Practical Experience#

  • Automate data collection using existing tools (ccusage) instead of reimplementing. Design considerations: subprocess fault tolerance (silently skip on failure), multi-device aggregation strategy (summation/merge), readable display format (tables vs. lists).
  • Use of Git submodule: suitable for independent remote subprojects, records commit hash not branch, clone requires –recursive, update requires cd + git pull + commit hash change.
  • Monitoring peak statistics needs continuous sampling during runtime (background thread), not just startup/stop snapshots. Requires proper thread lifecycle management (Event mechanism) to avoid resource leaks.
  • Windows conda workflow requires PowerShell, not cmd.exe. Batch files lack proper conda integration. Always test environment activation in a new shell.
  • When simulating in pytest, always patch at the source module where the function is defined, not at import — local import creates new references, bypassing module-level patches.
  • Cluster file system semantics: shared storage means identical paths between nodes, but SSH sessions default to home directory — must explicitly execute cd in remote commands.
