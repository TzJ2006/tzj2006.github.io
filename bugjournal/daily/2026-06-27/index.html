Daily Report — 2026-06-27#

Daily Overview#

  • What was done: Executed an A/B evaluation to improve the accuracy of visual instruction arrows generated by Cosmos3-Nano on robot rollout videos.
  • How it was done: Modified inference parameters (normalized [0,1000] coordinates, upsampled input to 480p, set temperature=0) and implemented a simplified single-arrow visualization script for comparative testing.
  • Impact: Transformed ambiguous model outputs into clear, actionable directional instructions, validating the model’s potential as a zero-shot annotator while identifying temporal limitations in static camera setups.

Optimized Cosmos3-Nano visual instruction generation through coordinate normalization, resolution scaling, and temperature control, achieving qualitative usability for robot task annotations.

Tasks#

Architecture & Strategy#

  • ✅ Visual Instruction Parameter Optimization — Diagnosed coordinate misalignment and low-resolution issues, then implemented three specific fixes: normalized coordinates to [0,1000], upsampled inputs to 480x480, and reduced temperature to 0 for deterministic outputs.

Implementation & Fixes#

  • ✅ A/B Testing Execution — Ran base vs. improved configurations on specific rollout videos (success and failure cases), downloaded results, and compared arrow orientations for correctness.
  • ✅ Visualization Simplification — Refined the output visualization to display only a single arrow, removing cluttering elements like circles and multiple step indicators as requested by the user.
  • ✅ Server Resource Management — Downloaded all comparative assets to local storage and safely terminated the Cosmos3-Nano vLLM service on the remote server to free GPU resources.

Problems & Solutions#

Critical Issues#

1. AI-generated arrows were inaccurate and scattered due to a mismatch between the model’s assumed image size (608x480) and the actual video resolution (256x256), compounded by low-resolution details.#

Solution: Implemented coordinate normalization to [0,1000] in the prompt to decouple from absolute pixel values, upsampled input frames to 480p for better feature detection, and set temperature=0 to eliminate sampling noise.

Key Insight: The three modifications proved independently valuable; coordinate normalization and resolution scaling were critical for geometric accuracy, while temperature control ensured deterministic analysis of temporal features.

General Issues#

2. Failed to kill the remote vLLM process initially due to command line pattern matching conflicts (‘vllm serve’ matched the SSH command itself).#

Solution: Adjusted the pkill regex pattern to exclude the current shell context (e.g., using ‘Cosmos3-Na[n]o’), successfully terminating the process and freeing the GPU.

Key Insight: Remote debugging of processes requires caution with regex patterns to avoid self-termination or incomplete kills.

Difference Analysis: Human demonstrated a clear UX-centric goal for clarity and brevity, whereas AI defaulted to providing maximum informational density. The human intervention streamlined the evaluation metric to focus purely on arrow geometry.

AI Limitations#

Critical Limitations#

  • The AI incorrectly assumed the video dimensions (reporting 608x480 instead of actual 256x256), causing systematic coordinate distortion in early outputs.

General Limitations#

  • Unable to demonstrate superior temporal reasoning because the input videos used static third-person cameras, where frame-by-frame predictions converge with clip-based predictions.

Learnings#

Key Learnings#

  • Using normalized coordinates (e.g., [0,1000]) in prompts significantly enhances geometric accuracy for VLMs that have inconsistent internal image size assumptions.

Practical Learnings#

  • To isolate the effect of temporal context in video models, temperature must be set to 0 during ablation studies; otherwise, sampling noise masks the true contribution of the temporal clip.
