Issues and Solutions#

Key Issues#

1. The first test environment synchronization overwrites months of accumulated website/content history#

Solution: Implemented bootstrap_source in sync_staging.py: if the test environment path does not exist but the website path exists, move the website content to the test environment first, then perform normal synchronization; a single migration preserves all historical records.

Key insight: Switching truth sources requires migration paths to retain existing data; the initial run mode makes safe switching possible without manual migration or risk of data loss.

2. Outdated PaperMod theme caused Hugo v0.157.0 build failure due to missing get-page-images section#

Solution: Cleaned up macOS resource folder files (._pack-*) that cause Git corruption, stored local changes, and pulled the latest theme; manually resolved merge conflicts in head.html, retained upstream theme switching, and kept local MathJax and checkboxes scripts.

Key insight: macOS resource folder files (._ prefix) corrupt the Git repository of cross-platform projects; theme updates require careful retention of local custom settings through manual conflict resolution.

3. update.sh script aborts when git commit returns a non-zero exit code#

Solution: Added a git diff –cached –quiet check before committing; when no changes are detected, skip commit and send a friendly message.

Key insight: Shell scripts using set -e must explicitly handle all normal failure cases; relying on command exit codes without status checks makes the automation process vulnerable.

4. /benchmark/ wrapper page cannot be rendered: Hugo identifies content/benchmark.md but does not generate /benchmark/index.html#

Solution: Changed the date of the wrapper page from datetime.now() to a fixed past date of 2025-01-01; moved /content/benchmark/_index.md section to /content/benchmark.md to avoid conflict with the static/benchmark directory.

Key insight: Hugo defaults to ignoring future content; sections with the same name as the static directory produce ambiguous output paths—a single page is more suitable as the wrapper content path.

General Issues#

5. The find command in update.sh fails when accessing subfolders after deleting parent directories during recursive cleanup#

Solution: Added 2>/dev/null || true after find … -exec rm -rf {} + to gracefully ignore expected race condition errors. Key insight: Recursive deletion causes race conditions because find traverses the deleted paths; explicit error suppression is required to achieve this behavior.

6. Hugo URL case normalization: /bugJournal/ is used in config.yml but the generated path is /bugjournal/, which may cause 404 errors on GitHub Pages.#

Solution: Normalized all bugJournal references in config.yml and content preamble to lowercase/bugjournal/ to align with Hugo’s normalization behavior.

Key insight: Hugo’s canonifyURLs and slug generation automatically convert some names to lowercase; mixed-case URLs in config may cause inconsistency on static hosts with case sensitivity issues.

7. Windows PowerShell execution policy blocks the running of py_compile and verification scripts#

Solution: Use python -m py_compile directly, or embed Python code into PowerShell strings to bypass script file execution restrictions.

Key insight: Environment execution policies may block even non-destructive verification commands; Python code passed via stdin can bypass file-based restrictions without elevation.

Lessons learned#

Key lessons learned#

  • For migrating from decentralized deployment targets to a centralized test directory, a guided migration strategy can be used: first run detection during migration from decentralized targets to the centralized test directory, and automatically reposition content (move existing websites to outputs/site), which avoids data loss and eliminates the manual effort before migration
  • A three-layer approach is required when updating Hugo themes: ① integrity of the git repository (cleaning up damaged resource folder files), ② alignment of dependencies (compatibility between theme versions and Hugo versions), ③ saving local custom settings (manually resolving head.html and configuration overriding issues)
  • Edge cases of Hugo content model: chapters with the same name (_index.md) conflict with static directories, leading to unclear paths; a single page(foo.md) is more suitable as wrapper content; future content will be automatically skipped if the –buildFuture flag is not used
  • Principles of robustness for shell scripts: ① check git status before operations instead of relying on exit codes, ② add error handling for file system operations (use 2>/dev/null || true for expected failures), ③ explicitly exclude normal failures when using set -e
  • Link or copy sync mode: when the file system supports hard links, os.link provides zero-copy atomic updates; automatic fallback to shirley.copytree ensures cross-platform compatibility (Windows FAT32, network drives) without manual intervention or user configuration
