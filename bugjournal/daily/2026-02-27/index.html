Issues and Solutions#

Key Issues#

1. All ML strategies failed catastrophically in M14 error recovery evaluations, while random baselines had higher recovery progress#

Solution: Results indicate a need for M15 phase — fine-tuning Pi0.5 through human recovery demonstrations to address distribution differences

Key insight: Models trained only on successful task demonstrations fail catastically under errors (success rate below 1%), indicating severe distribution differences; error recovery requires explicit training for the recovery path, not just normal task execution

2. Direct SSH connection to GPU compute nodes is not possible (pam_slurm_adopt access denied)#

Solution: Resources must first be allocated via salloc or sbatch, then connected using srun or SSH with active job IDs; tmux + salloc workflow is recommended for stable interactive sessions

Key insight: HPC clusters use job-based access control to prevent unauthorized resource usage; direct connection to compute nodes before allocating Slurm jobs is prohibited, requiring a two-step process (allocation → connection)

3. Parallel directory scanning of HDD_POOL storage exceeds 10 minutes for directories larger than 2TB#

Solution: Implemented parallel directory scanning with 600 seconds timeout per directory, allowing most scans to complete smoothly while handling very large directories gracefully

Key insight: Shared HPC file systems require parallel execution with explicit timeouts for directory traversal operations; some user directories (miniconda3, VLA_data, cpx1/2) are very large and require alternative methods such as lfs quotas or –max-depth=1 scanning

Lessons Learned#

Key Experiences#

  • Severe distribution differences exist in error recovery tasks: Models trained on successful task demonstrations fail almost completely under errors (success rate below 1%), while random baselines outperform learned strategies in recovery progress, confirming the need for specific training data collection for errors during M15 phase
  • Parallel execution with task-level timeouts is essential for large shared HPC file systems because individual user directories may exceed 2TB; sequential scanning is not feasible for production-scale analysis
  • HPC clusters use pam_slurm_adopt to enforce job-based SSH access control — resources must be allocated via salloc/sbatch and then connected via ssh/srun; tmux + salloc provides a stable interactive workflow that can withstand connection drops
  • Tianhe-XY cluster has 9 idle A800 GPU nodes (an16, 21, 23, 28-29, 31, 34, 39-40) in the ai partition, each with 56 CPUs and 1TB of memory, capable of providing resources for 4–72 hour tasks without GPU GRES specifications
