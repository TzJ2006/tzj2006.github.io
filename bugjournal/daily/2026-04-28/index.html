Issues and Solutions#

Key Issues#

1. When hovering over chart bars, the detail panel expansion causes window adjustment, leading to the bottom of the window shifting from the task bar#

Solution: Introduced SCROLL_THRESHOLD_CAP = 500 constant; modified resolveScrollThresholdHeight to return a minimum value based on proportion calculation and threshold; content now scrolls within a fixed-height window instead of resizing.

Key Insight: The user-specified fixed threshold (500px) provides predictable behavior across all monitor sizes, while the existing scroll mechanism handles overflow; the proportional method (0.75 * working area) is too loose on larger monitors.

2. The initial v0.12.1 release failed CI checks for cargo fmt and clippy#

Solution: Applied cargo fmt to window.rs to fix import order and line width restrictions; removed unnecessary return statements in config.rs; deleted old tags and re-released to fix the issue.

Key Insight: Pre-release local validation should include a complete CI check suite (fmt, clippy with -D warnings) to avoid tag changes; rustfmt and clippy rules are non-negotiable in the CI pipeline.

General Issues#

3. The editing tool encountered “file not read” errors when trying to update the version number#

Solution: Read all three version files (package.json, Cargo.toml, tauri.conf.json) before editing; the tool needs to perform a read operation before writing.

Key Insight: Claude Code Edit tools have strict “read then write” requirements; the workflow should be: read → edit, not direct editing.

Lessons Learned#

Key Experiences#

  • Pre-release validation must include a complete CI check suite locally; cargo fmt –check and cargo clippy – -D warnings can prevent tag changes and maintain a clean release history.
  • Hard-coded UI thresholds are more predictable than proportional calculations, suitable for cross-device consistency; the 500px limit ensures consistent behavior across 1080p, 1440p, and 4K monitors.
  • Git tag management for public releases requires deletion/rebuild processes (git tag -d, git push –delete, re-tagging, pushing), not force-push or amend, to maintain integrity.

Practical Experiences#

  • MCP tools (mcp__hex-line__edit_file) and standard editing tools have different reading requirements; MCP tools accept the edit_ready flag during reading operations, simplifying the workflow.
