Issues and Solutions#

Key Issues#

1. Rapid window height fluctuation (150–200ms cycle) when hovering over charts, causing the detail panel to flicker in continuous feedback loops#

Solution: Implemented three-layer defense: (1) onLeave timer checks hoveredIdx >= 0 to skip fake leave events; (2) ResizeOrchestrator blocks observer-driven resize during chart hover activation; (3) Shrink protection prevents window shrinking during hover.

Key insight: The fluctuation is a feedback loop; SetWindowPos changing the window position triggers a fake mouseLeave event in the browser; breaking the loop requires intervention at multiple points, not just preventing resize.

2. SetFocus Win32 API requires the calling thread to have foreground window ownership, but the tray click handler lacks it#

Solution: Used SetForegroundWindow, which has implicit foreground privileges in tray icon contexts, and added a 200ms fallback timer in Svelte to handle edge cases.

Key insight: Win32 foreground window rules depend on context: tray icon events grant SetForegroundWindow foreground privileges but not SetFocus; understanding context is crucial.

3. Window bottom edge shifts when resizing, causing visual differences; using current_rect.bottom leads to unpredictable bottom edge movement#

Solution: Changed anchored_resize_origin from current_rect.bottom - height to work.bottom - height; the working area boundary is a stable constant, while current_rect reflects the intermediate SetWindowPos state.

Key insight: In an asynchronous window management system, querying the “current state” during rapid changes returns an intermediate value, causing instability; anchoring should be based on a fixed reference point (working area boundary) rather than the current state.

4. Hardcoded right-bottom anchor causes flicker when the taskbar moves to other positions or user/system repositions#

Solution: Built dynamic anchor detection: comparing window center and working area center, storing the result in AtomicU8, and using the detected anchor in all position adjustment functions.

Key insight: Window anchors must be dynamically detected based on actual position relative to the working area, not assumed to be at the default taskbar position.

5. Even when the rate limiting API works, Cursor usage warnings still appear, causing users to be confused about the actual connection status#

Solution: Downgraded remote usage event API failures from set_cursor_warning to log; warnings only occur when authentication truly fails (both pipelines fail).

Key insight: Multiple data pipelines with different functions should fail independently—do not warn users because one pipeline fails when another works.

6. Mouse position detection using clientX/Y + getBoundingClientRect cannot prevent fake leave events during window movement#

Solution: Abandoned coordinate-based detection; replaced with checking hoveredIdx state in timer callbacks—if hoveredIdx >= 0 after 300ms, re-enter, thus skipping the leave event.

Key insight: When the window moves, pointermove does not trigger (the mouse actually does not move), so tracking coordinates becomes outdated; state-based detection (hoveredIdx) is more reliable than coordinate-based detection.

7. Users must manually reopen Cursor and restart TokenMonitor to resolve the yellow “connected” warning when the authentication token expiresSolution: Implemented cross-platform application launch commands (macOS open -a, Windows .exe path, Linux cursor command) and retry_cursor_auth polling mechanism, which automatically detects token refresh and clears warning messages.#

8. When the window is anchored at the taskbar, the 14px border-radius causes transparent gaps at the bottom edge#

Solution: Queryed the window anchor direction via get_window_anchor_edge IPC at startup, set data-anchor property in , and conditionally remove the bottom border-radius in CSS when data-anchor=‘bottom’.

Key insight: Transparent windows with border-radius create visual gaps at the edge when aligned with the screen border; conditional styling based on runtime anchor position is required.

9. sqlite3 command execution lacks the CREATE_NO_WINDOW flag, causing console window pop-up on Windows#

Solution: Added const CREATE_NO_WINDOW: u32 = 0x0800_0000 and #[cfg(target_os = “windows”)] protected .creation_flags() call in cursor_parser.rs.

Key insight: All Windows process launches require explicit use of CREATE_NO_WINDOW; missing such a launch in any module undermines the overall user experience.

Lessons Learned#

Key Experience – Feedback Loops in UI Systems May Have Invisible Trigger Mechanisms: Window size adjustment → position change → browser event → state change → re-size. Breaking this loop requires identifying multiple correct intervention points.#

  • Win32 foreground window rules depend on context: SetFocus requires the calling thread to have foreground focus, but SetForegroundWindow has default permissions from tray icon event context—this is crucial for system tray applications.
  • Asynchronous window management (SetWindowPos) means querying “current state” (GetWindowRect) during rapid changes returns an intermediate value; a stable anchor point (work area boundaries) is more reliable than querying the current state.
  • Browser mouse events during window movement appear “fake” from the user’s perspective but “real” from the browser’s perspective; state-based detection rather than coordinate detection is needed to distinguish genuine user actions from pseudo-events caused by window movement.
  • Multi-layer data pipeline design: When the pipeline handles different functions (rate limiting and usage events), fault handling should reflect the independence of the functions—do not block one function due to a failure in another.
  • Svelte 5 reactivity mechanism: $state updates update DOM changes via a microtask queue, but CustomEvent distribution is synchronous—measuring before DOM updates may cause race conditions.
  • Automatic retry pattern design: Use onDestroy/cleanup to prevent timer leaks; balance polling frequency (4 seconds) and maximum attempts (8 times) for a 32-second window that covers typical authentication refresh time.
  • Transparent windows with border-radius require careful consideration of anchor positions to avoid visual gaps at screen edges; conditional styles based on runtime anchor detection solve this issue.
  • Tauri v2 IPC command pattern: Use #[tauri::command] to define Rust commands, register them in invoke_handler, and call via invoke() from the frontend; platform-specific handling is needed for external application startup.
