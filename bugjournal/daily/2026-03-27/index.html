Issues and Solutions#

Key Issues#

1. Due to a 1-frame delay between SetWindowPos IPC calls and CSS repaint cycles, the footer and application bottom edge move continuously during window scaling.#

Solution: Move the footer out of the dynamic flex container and apply position: fixed; bottom: 0 to bypass the layout queue. Pre-set #app min-height via JS, then achieve DOM and native synchronization before sending IPC commands, thereby filling the delay gap.

Key Insight: The cross-stack frame delay between native C API window management and WebView2/CSS cannot be fully compensated by Flexbox or CSS transitions; absolute viewport anchoring and pre-layout synchronization are essential for pixel-level stability.

2. The window bottom edge jumps upward after height change, sometimes falling below the taskbar area in Windows systems.#

Solution: Change anchor detection from a fixed threshold to direct gap comparison top_gap <= bottom_gap, use current rectangle boundaries instead of working area limits to correct the bottom anchor Y value calculation, and update cross-platform limit logic.

Key Insight: Edge anchoring must dynamically track the nearest physical boundary rather than relying on static pixel thresholds; limits should retain the initial position and only intervene when crossing a safe area.

General Issues#

3. Chart hover detail panel flickers and jumps during bar changes, caused by DOM destruction/reconstruction and timer race conditions.#

Solution: Shorten fadeout time to 150ms, remove {#key} trigger block to keep DOM elements intact, merge two-stage hide process, and add boundary protection mechanisms for layout measurement effects.

Key Insight: Svelte’s key blocks force complete component destruction; maintaining DOM nodes alive while updating reactive properties avoids visual duplicates during rapid state changes.

Learning Insights#

Key Learning Points#

  • When native window management APIs (such as Win32 SetWindowPos) and web rendering operate asynchronously, absolute viewport anchoring or pre-measuring and applying sizes on the JavaScript side before IPC calls are required to ensure visual stability.
  • Using position: fixed can completely bypass CSS layout repaint queues related to parent container animations, making it the most reliable method for stabilizing UI elements during dynamic host size changes.

Practical Learning Points#

  • A hypothesis-driven debugging workflow significantly reduces confirmation bias by forcing parallel investigation and mandatory evidence recording.
