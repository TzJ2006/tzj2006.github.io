Issues and Solutions#

Key Issues#

1. STAIG report ARI of 0.68 is non-reproducible, relying on mclust initialization seeds; scGPT/TEDDY embedding performs poorly in spatial transcriptomics.#

Solution: Conducted 100 seed statistical scans, found high variance (0.49–0.64), and confirmed UNI2 superiority (up to 0.703 ARI). Identified the “gene-FM paradox” — gene base models perform inferiorly to HVG in spatial discrimination signals.

Key Insight: Published random algorithm benchmarking requires statistical validation; general gene encoders may not be suitable for graph contrast learning in spatial domains.

2. Unified ccusage 20.x output combines all agent sources, losing the source-level granularity needed for dual-track reporting.#

Solution: Found ccusage <source> daily allows namespace queries. Implemented source file discovery via metadata and separate acquisition using pattern normalization to ensure backward compatibility and future scalability.

Key Insight: CLI dependency upgrades often silently change JSON patterns; immediate local testing of new output formats before architecture changes is crucial.

3. Blank thumbnails in desktop video gallery due to mismatched sandbox bookmark ranges and missing cache keys. Solution: Implemented dual-branch bookmark parsing (range limitation + fallback), and updated cache keys to include content modification dates. Added sync state initialization in SwiftUI views to eliminate flickering during navigation.#

Key Insight: Asynchronous failures often disrupt state machines; sandboxed macOS apps require explicit non-range-limited fallback strategies to ensure old data integrity.

4. NVIDIA RTX 5090 driver fails due to security boot rejecting self-signed DKMS modules.#

Solution: Removed nvidia-dkms package and loaded Canonical pre-signed kernel modules, resolving “key rejected” errors without disabling security boot.

Key Insight: In modern Ubuntu systems with security boot enabled, signature modules managed by the distribution are safer and more reliable than custom DKMS builds.

5. Vite dev-server cannot load FloatBall CSS module on NTFS mounted drives due to .vite-temp cache expiration.#

Solution: Stopped dev server, cleared node_modules/.vite and .vite-temp, then restarted. Root cause was atomic rename failure of Vite on unstable FUSE mount.

Key Insight: Vite’s dependency optimization is highly sensitive to file system stability; expired temporary files cause module graph asynchronous behavior in lazy-loading components.

6. History view displays the same list on different screens due to global filtering and lack of screen attribution information.#

Solution: Refactored data model and added “played on screen” mapping in WallpaperHistoryEntry. Implemented screen-divided cleanup and migration logic for old projects without screen IDs.

Key Insight: Global data structures cannot support multi-tenant or multiple monitors; pattern migration must explicitly handle backward compatibility and dimensionality limits.

7. Security vulnerability: During ccusage migration, workflow hook exemption checks and file save may involve path traversal risks.#

Solution: Marked exemption bypass behavior in check_spec.py (requires standardized path parsing), and recommended multiple defense mechanisms for save_usage_file filename cleanup, although upstream ccusage validation already provides mitigations.

Key Insight: String-based path checks in startswith are vulnerable to traversal attacks; external tool exit codes should not be the only security barrier for file system operations.

Lessons Learned#

Key Experiences#

  • mclust EM clustering is highly sensitive to the initialization range (n>2000); without multiple sampling verifications, the ARI score from a single run cannot be used as a reliable benchmark.
  • On Linux NTFS/FUSE mounts, Vite’s atomic dependency optimization may fail silently, leaving .vite-temp residues that cause synchronization issues in lazy-loaded component modules.
  • CoreMedia and WebKit sandboxes usually produce harmless noise; false positives in log classification may lead to chasing virtual errors if the framework semantics are not understood.

Practical Experiences#

  • Tracking tokens by source file requires strong pattern normalization _normalize_usage, as different proxy CLI tools typically use incompatible JSON field names.
  • Global data limits are ineffective in multi-monitor environments; the history/tracking system must consider dimensionality and use unique identifiers (such as screen UUIDs) as keys.
