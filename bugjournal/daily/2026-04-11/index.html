Problems & Solutions#

Critical Issues#

1. All MimicGen augmentation verifications failed (0/10 scenes), cubeA not lifted (height 0.82 desktop).#

Solution: Multiple rounds of diagnosis revealed the root cause: subtask fragmentation (6 subtasks = 5 independent warp boundaries, cumulative error) + lack of post-grasp buffer + gripper detection bug (search for first continuous closure) + retract subtask not warped + path parsing bug. Fixed one by one: simplified to 2-subtasks, added 15-frame buffer, improved gripper detection, merged retract into re_acquire, fixed path parsing.

Key Insight: Original MimicGen design principle: minimize the number of subtasks (2) + post-grasp buffer + start from home position. Each subtask boundary is a source of error, so it should be reduced as much as possible.

2. success_demos.hdf5 cannot serve as MimicGen source — missing env_interface_name and env_interface_type attributes.#

Solution: Added ensure_env_interface_attrs() helper, automatically completing the attributes in filter_valid_source, augment_success_demos, and generate_success_from_error; patch fixed HDF5 files for 7 existing tasks.

Key Insight: MimicGen DataGenerator relies on specific datagen_info attributes to identify environment interfaces; absence of these causes getenv_interface_info_from_dataset failure;Ensure integrity at each output point in the generation chain.

3. No response from the BetterSSH front-end button — WebSocket messages are silently discardedSolution: Traced to the null return value in the onMessage() placeholder in index.ts. Instantiated SessionManager, loaded SSH/BetterSSH configurations, connected to the full message routing (get_sessions, create_session, destroy_session, send_input, resize)#

Key Insight: The backend has a complete implementation of SessionManager (500+ LOC) but was never instantiated—a skeleton code trap; the interface exists but was never connected

4. Token usage data disappears when deleting JSONL logs#

Solution: Implemented a hourly append-only aggregation archive under {app_data_dir}/usage-archive, using time-based partitioning (archive covers [0..frontier], live source covers (frontier..now)) to prevent duplicate counting

Key Insight: Time-based partitioning eliminates overlap between archives and real-time data, ensuring zero duplicate statistics with minimal storage overhead (about 1KB/day/provider)

5. Claude Code frequently requires permission confirmation in exploratory projects, affecting development efficiency#

Solution: Simplified the permission for 80+ Bash commands listed one by one into a tool-level wildcard “Bash” that covers all Bash commands

Key Insight: Claude Code supports a tool-level wildcard (“Bash” matches all Bash commands), enabling relaxed permissions with minimal configuration, while retaining confirmation mechanisms for dangerous operations via the ask array

6. Anti-corruption review found WebSocket PTY writes without authentication (ATK-007)#

Solution: Added REQ-009: 127.0.0.1 binding + 256-bit session token (randomly generated and printed at startup), all WS upgrade verification require query string token

Key Insight: Security issues have the lowest cost to fix during requirement phase; red-blue confrontation should be enforced in Phase 8 (after architecture is determined, before coding begins)

7. OpenReview API returns 403 Forbidden, preventing access to NeurIPS paper review data#

Solution: Diagnosed double-layer blocking: (1) OpenReview API now forces all requests to require a authentication token (anonymous access disabled); (2) Frequent probes trigger nginx rate limiting. Used user OpenReview credentials (tongtongtot@163.com) via openreview-py SDK, successfully retrieved 61 reviews (7 Oral papers: 29 reviews + 7 AC decisions; 8 Spotlight papers: 32 reviews). Added delay between requests to avoid rate limiting

Key Insight: OpenReview’s authentication strategy has changed—even access to public content API requires a login token. The /login endpoint remains accessible (returns 400 validation error) while all data endpoints return 403, indicating application-level authentication is enforced. Web frontend work relies on Next.js RSC server-rendered usage of internal credentials

8. Poor terminal rendering quality—blurred fonts, slow scrolling, invalid middle-click paste#

Solution: Identified xterm.js as the industry standard (used by VS Code/Replit); the issue is the lack of plugins. Added WebGL renderer (GPU acceleration), Unicode11 (CJK), improved theme (Catppuccin Mocha), better font stack (Cascadia Code fallback chain)

Key Insight: xterm.js alone is insufficient—production terminals require a complete plugin ecosystem. WebGL provides 10x rendering improvement and clear fonts. Unicode11 prevents CJK width calculation errors

9. GLM5.1 and DeepSeek-Reasoner display $0.00 pricing, despite the OpenRouter integration being added#

Solution: Added a version field to the PricingCache structure (CACHE_VERSION=2), causing outdated caches (containing only LiteLLM data) to automatically expire when new pricing sources are introduced

Key Insight: The caching system needs explicit version control to handle mode evolution—relying solely on TTL allows outdated data to persist after code changes

10. Terminal session switching discards all terminal content—no rollback history#

Solution: Changed terminal lifecycle: create xterm instances once in useEffect([], []) and reuse across sessions. During switch: term.clear() → subscribe to new session → backend sends RingBuffer refill → term.write()

Key Insight: Terminal instances are expensive and store rollback state—should not be destroyed during session switching. The backend RingBuffer (2MB) provides a replay buffer

General Issues#

11. tianhe cluster git pull fails, reporting ‘GnuTLS recv error (-110): The TLS connection was non-properly terminated’#

Solution: Diagnosed proxy configuration mismatch: git global config points to 172.16.31.200:3138, while environment variable (from proxy_on) uses 127.0.0.1:10087. Used git -c http.proxy=http://127.0.0.1:10087 -c https.proxy=http://127.0.0.1:10087 pull to override proxy settings per command, successfully pulling data

Key Insight: Git has two independent proxy configuration layers (global vs environment variables) that may diverge. Using the -c flag per command provides an immediate solution without modifying persistent settings

Learnings#

Key Learnings#

  • Power of Superpowers skill chain: Brainstorming (requirement analysis) → ccplan (ECL-driven implementation) → optimize (quality improvement) form a complete software lifecycle. ECL documents serve as persistent ‘design contracts’ across sessions, enabling context consistency across multiple conversations, agents, and even different models.
  • Value of adversarial review: Among the 9 issues identified by the Critic agent, 2 are CRITICAL (no authentication PPTY writing, SSH parameter injection) and 4 are HIGH (token brute-force attack, prototype contamination) — exposing them in a production environment would cause a security disaster. Repair costs at the requirement stage « at the code stage « at the production stage.
  • Nature of object-centric warping: T_eef_new = T_obj_target × T_obj_src⁻¹ × T_eef_source is an invariant relative to object motion patterns. Two-step understanding: (1) eliminate the absolute position of the source object; (2) remap using the new object position.
  • Wisdom in the original MimicGen design: (1) minimize the number of subtasks (only 2 in Stack); (2) post-grasp buffer of 10–20 frames ensures stable gripping; (3) env.reset() to home position reduces pose gap; (4) quasi-closed-loop execution (target_pose_to_action calculates delta per step).
  • Core design of MimicGen is source demo + env.reset() randomization: Error scenes should be treated as fixed ‘initial states’, and variants should be generated using placement_initializer, rather than injecting errors for each target.
  • Priority of NeurIPS DB Track review (based on 61 reviews): The most valued qualities are ‘comprehensive’ (17 mentions), ‘community’ (17), ’novel’ (15), ‘clear’ (28), ‘well-designed’ (13). Common criticism: ’lack of comparison’ (insufficient baseline), ‘insufficient detail’ (unclear methodology), ’limited scope’ (narrow application). The best paper (Artificial Hivemind) has the lowest average score in oral presentation (4.75) — AC decisions outweigh review scores. Oral average (5.00) < Spotlight average (5.16), confirming that scoring is not the only acceptance factor.
  • Parallel agent scheduling mode: Independent modules (Config/Parser/LocalPTY) are assigned to different subagents for parallel execution, then aggregated for verification, increasing development efficiency by 3–5 times. The key is identifying leaf nodes in the dependency DAG with no dependencies to maximize parallelism.
  • Claude Code –output-format stream-json: Through research, it was found that Claude natively supports structured output (newline-separated JSON), eliminating the need for regular expression parsing of PPTY. This improves Parser reliability from ‘heuristic’ to ‘deterministic’. Always research before reinventing.
  • Return on investment of TypeScript strict mode: 195 tests + 0 type errors = production-ready code. The type system provides significant protection during refactoring (after extracting parsed-state-utils, all call points undergo automatic type checking). Spend 20% more time on types in the early stage, and save 80% of debugging time later.
  • xterm.js is the industry-standard browser terminal (used by VS Code, Replit, Vercel, ttyd). Quality depends on a complete plugin stack: WebGL for GPU rendering, Unicode11 for CJK, Fit for resize, SearchAddon, WebLinksAddon. Only the basic xterm.js is insufficient for production.
  • MimicGen-ready datasets require specific metadata structure: Each demo_*/datagen_info must contain env_interface_name and env_interface_type; otherwise DataGenerator cannot initialize the environment correctly.
  • Human demonstration data quality verification should be前置 to collection stage: Simply teleop success is insufficient; replay stability and augmentability must be verified simultaneously, otherwise a large amount of unusable data will be collected.
  • Time boundary partitioning (archive covers completed hours, live source covers current hours) elegantly solves duplication without explicit level tracking — zero overlap means zero duplicate counts.
  • Claude Code permission system supports tool-level wildcards (e.g., “Bash” matches all Bash commands), allowing simple configuration instead of dozens of individual rules.
  • Cost of subtask fragmentation: Each subtask boundary involves independent ‘check object pose → re-warp → 5-step interpolation’, leading to cumulative errors. 6 subtasks = 5 error sources, far more than the original 1.
  • OpenReview API authentication architecture (2026): All data endpoints require login token; only the /login endpoint allows anonymous access (returns validation error). Web frontend uses server credentials via Next.js RSC. Rate limiting is handled at the nginx layer (based on IP), triggered by about 30 requests in a short time. Academic paper review API is increasingly locked down — institutional or personal credentials are required.
  • Terminal resize synchronization requires full-chain coordination: ResizeObserver (frontend) → term.onResize → WebSocket message → SessionManager → PPTY.resize(). Mismatch causes line breaks in the wrong column. Debounce prevents flooding during resize dragging.
  • Terminal instances should not be destroyed during session switching — they preserve a rollback buffer (10,000 lines). Correct pattern: create once, refill with clear() + backend RingBuffer (2MB) across sessions for reuse.
  • The cache system must include explicit version fields when data sources can evolve — only TTL expiration is insufficient to handle mode/source changes.
  • The allow/deny/ask three-tier permission mechanism can balance security and efficiency: allow enables automation, ask retains confirmation for dangerous operations, deny allows absolute prohibition.
  • Claude Code configuration does not inherit automatically (independent configuration per project) — a standardized initialization process can be implemented via automated scripts (e.g., init-claude.sh).
  • Complex robot system documentation should distinguish between developer and operator audiences: Structured questions clarify target readers, structure, language, and content retention to prevent ambiguity.
  • React closure trap ref pattern: Registers in useEffect capturing expired props from third-party libraries (xterm.js onData) is a common bug. General solution: props → ref, sync ref.current in useEffect, read ref.current in callback. This is the best practice in the React ecosystem.
  • Three pillars of WebSocket robustness: Reconnect (exponential backoff), backpressure (bufferedAmount check), heartbeat (not implemented but should be considered). The network layer of distributed systems must assume ‘connections may break at any time’ rather than ‘connections should be stable’.
  • Importance of continuous closure detection: Robot gripping may have multiple attempts; the first gripper_closed > threshold may fail. Continuous closure (≥10 frames) must be detected to confirm successful grasping.
  • Complexity of multi-process debugging: (1) Each worker requires independent env+augmenter instances; (2) path parsing is more error-prone (relative paths may miss levels); (3) absolute paths like demos_dir must be explicitly passed; (4) robosuite WARNINGs need to be suppressed separately in worker functions.
  • Quota counting logic should reflect real availability: augmentable_only is stricter but more reasonable than replay_only, as non-incrementable demos cannot expand the training set even if replay is possible.
  • Frontier ASR model landscape (2026): True streaming models are rare. Moonshine v2 (73–107ms latency, 34–245M parameters) and Voxtral-Mini-4B-Realtime (480ms, 4B parameters) represent the state-of-the-art. Moonshine uses a callback-based API suitable for real-time transcription; Voxtral requires manual chunking but offers higher accuracy. Both support Apple Silicon native acceleration (Moonshine via CoreML, Voxtral via MLX).
  • Different permission requirements for exploratory and production projects: Exploratory projects prioritize efficiency (loose permissions), while production projects prioritize safety (strict confirmation).
  • Step-by-step accumulation configurations easily cause inconsistency (e.g., 80+ long rules, diverse project styles); regular use of templates can improve maintainability.

Practical Learnings#

  • Git proxy configuration operates in two independent layers: global configuration (git config –global http.proxy) and environment variables (http_proxy, HTTP_PROXY). Mismatch leads to cryptic TLS errors; using the git -c flag for each command provides an immediate solution while preserving existing configurations.
