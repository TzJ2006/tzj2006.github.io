Issues and Solutions#

Key Issues#

1. MuJoCo simulation instability caused by cvel memory layout inversion and incorrect EEF target object allocation, resulting in phantom trigger events.#

Solution: Corrected the original pointer slicing to [angular(3), linear(3)], re-applied cyclic recovery xfrc_applied step by step, resolving the name parsing issue for force injection targets.

Key Insight: Physical engine memory layouts often conflict with official documentation; reliance on unverified annotations or static thresholds leads to simulation errors across all related pipelines.

2. Automatic API cost tracking silently returns $0 costs under certain model variants, masking actual consumption.#

Solution: Tracked LiteLLM database mapping to detect version suffix differences claude-4-6 vs 4-5-v1, implemented fallback pricing dictionary, and filled corrected financial logs.

Key Insight: Billing aggregation scripts that rely on exact string matching are highly vulnerable to supplier metadata updates; graceful degradation and version tolerance mapping tables are essential for financial accuracy.

3. ARI scores reset due to Uni2/HIPT coordinate extraction and AnnData cache corruption.#

Solution: Forced high-resolution coordinate downsampling to match patches, bypassed degradation barcode matching, and directly injected cache space index into VisionEncoder base class, isolating both failure modes.

Key Insight: Interleaved data structure degradation (string-to-integer index inversion) and spatial scale mismatch are often mistaken for downstream metric issues. Layer-by-layer verification is required before adjusting fusion parameters.

4. VLA/Pi0 server integration failed due to strict observation key pattern mismatch and manual normalization conflicts. Solution: Abandoned manual norm_stats conversion logic, adopted openpi.create_trained_policy() official wrapper, and cross-referenced internal libero policy sources, mapping agentview keys to observation/image dictionary.#

Key Insight: Third-party policy orchestration libraries abstract much of the preprocessing pipeline; direct guessing of signatures leads to invisible tensor dimension mismatches, and tracking standard examples is faster than trial-and-error debugging.

AI Limitations#

Key Limitations#

  • Relative path blindness in HPC environments: Repeating SSH commands from incorrect working directories without metacognitive self-correction requires repeated manual CWD overwriting.
  • Initial search strategy is too localized: Failed to explore distributed cache directories or historical checkpoints, requiring clear global scanning prompts to resolve integration issues.

General Limitations#

  • Over-reliance on program approval mechanisms (ExitPlanMode) in pure documentation and drafting tasks conflicts with the preference for immediate execution once a architecture context is established.

Lessons Learned#

Key Experiences#

  • Separating high-latency feature extraction from the caching directory before fusion evaluation is the most reliable way to control multimodal computation costs and prevent duplicate GPU cycles.
  • MuJoCo physical cache and model attributes (geometry, friction, xfrc) are not synchronized via set_sim_state_flat(); the persistent injector must explicitly clear state across all exit paths, requiring approximately 100 initialization steps.
  • macOS hardware-accelerated video layers (CoreVideo/Metal) are completely bypassed by standard AppKit sampling; successful overlay rendering requires independent transparent windows combined with .behindWindow synthesis and explicit NSVisualEffectView wrapping.
  • Lightweight periodic task scheduling effectively utilizes asynchronous cycles in JSONL persistence last_scheduled_date as a reliable, idempotent cross-system state management alternative without a database.
