Issues and Solutions#

Key Issues#

1. SwiftUI .ultraThinMaterial displays a fixed color in the video, rather than transparent glass#

Solution: The SwiftUI material used the .behindWindow blending mode (displaying the desktop content behind the window) instead of .integralWindow mode (displaying on the same window content). NSVisualEffectView was replaced with NSViewRepresentable, and .integralWindow mode along with the clearBackgroundColor property were explicitly specified on NSHostingView.

Key insight: The abstraction level of SwiftUI hides the key rendering process details; for complex visual effects, such as transparency in windows, control at the NSView level is required.

2. All STAIG fused embeddings of 151676 are zero (embedding similarity is all 0, Spearman r is NaN), causing the model to crash completely#

Solution: np.allclose(embeddings, 0) detection was added to load_fused Embeddings; if this condition is detected, a warning is printed and –recompute_fusion is automatically triggered to reload the gene/visual embeddings from the cache and retrain STAIG (300 cycles, about 50 seconds on RTX 2080 Ti); after fixing, the embeddings return to normal (64 dimensions, norm = 1.0).

Key insight: Due to unstable training, the STAIG fused embeddings saved in the second stage may become zero; active detection and automatic recalculation should be performed in the benchmark script to avoid manual intervention.

3. The old video is still played when switching videos after selection in NSOpenPanel#

Solution: FileAccess must parse each screen’s bookmark as the URL of the old video, rather than the new request URL. A conditional check is added to compare the parsed URL with the requested URL; if different, the original URL is returned (this URL has the temporary sandbox permissions provided by NSOpenPanel).

Key insight: Bookmark storage per screen conflicts with multi-video history; a conditional check is needed to detect whether the bookmark points to an expired file.

4. The BC-RNN success rate for the coffee task is shown as 0%, likely due to an evaluation error#

Solution: The training logs were checked, confirming that the BC-RNN training for the coffee task reached a 0% success rate at all stages (600 cycles of training). This is not an evaluation error; the task actually failed during training.

Key insight: Before debugging the evaluation process, train metrics must be verified first; zero values downstream may reflect failures in upstream training.

5. The an53 node crashed at 08:30, causing the tmux session to be lost and job 46798 to fail#

Solution: Investigation via sacct logs determined that the crash was caused by resource overload (8 GPUs at 100% utilization, high CPU load). AI operations were excluded as the cause (the last completion was at 05:07, 3 hours before the crash). The SSH keygen -R an53 was used to resolve the SSH host key mismatch.

Key insight: The slurm report provided minimal details about the crash, but there is no ability to access system logs via root.

6. The CUDA kernel of the P100 GPU (sm_60) is incompatible with PyTorch (requires sm_70+ version); torch.cuda.is_available() returns True, but asynchronous operations fail#

**Key insight:**Solution: Initially, trying to catch the torchzeros(1).cuda() exception with try/except failed, as the asynchronous failure on P100 cannot be captured. The user succeeded after switching to RTX 2080 Ti (sm_75). Finally, the CUDA_VISIBLE_DEVICES="" environment variable was added so that CPU is forced in the script.

Key Insight: torch.cuda.is_available() only checks whether the driver and library exist, without checking whether the GPU’s computational capability is compatible with current PyTorch. CUDA operations may fail asynchronously and cannot be caught by Python’s try/except. The most reliable approach is to switch GPUs or use environment variables to force use of CPU.

7. The JSON generated by the LLM is truncated (…truncated marker), causing parsing failures in daily_summary.py on 2026-02-14 and other dates#

Solution: Send the truncated raw text as an independent prompt to the AI, asking it to only fix/extract valid JSON parts; the AI successfully restored the complete JSON structure.

Key Insight: Ultra-long JSON generated by LLMs is at risk of being truncated (especially when multiple paragraphs are merged); a truncation detection mechanism and automatic JSON repair retry logic should be added during merging, rather than relying entirely on manual discovery and intervention.

8. When the screen saver clock text updates, the previous numbers leave a 0.2-second ghosting effect#

Solution: CALayer has an animation effect of approximately 0.25 seconds for changes to content properties by default. In CATransaction, update blurView.layer?.mask and set setDisableActions(true) to force immediate replacement.

Key Insight: CALayer has an animation effect for almost all property changes; explicit transaction control is needed to achieve immediate visual updates.

9. The BC-RNN strategy evaluation crashes due to “cannot handle data type <class ’numpy.float64’>”#

Solution: robomimic’s TensorUtils.to_tensor() cannot handle numpy scalar types. The_to_robosuite_obs function was modified to filter out keys in raw_obs dictionary that contain only array/image values, and then it is passed to the robomimic strategy.

Key Insight: Robomimic expects a structured obs dictionary with array values; numpy scalars from robosuite (such as gripper width float64) must be filtered before being passed to TensorUtils.

10. The visualization script fails multiple times: Bash’s heredoc uses != instead of != (SyntaxError), the file name prefix does not match (151673_filtered_feature_bc_matrix.h5 vs filtered_feature_bc_matrix.h5), spatial/data path errors (located in Dataset/DLPFC, not directly in section directory), load_dlpfc_data() return value parsing error (returns 1 instead of 2), and read_10x_h5 lacks uns[‘spatial’], causing sc.pl.spatial() to fail#

Solution: Use an independent script/_viz_rm_ideal.py file instead of the heredoc format; use glob “*filtered_feature_bc_matrix.h5” to find the correct file name; directly use sc.read_visium("/path/to/Dataset/DLPFC/151673") for loading (automatically handles spatial/subdirectory); the unpacking method of load_dlpfc_data() was fixed, now returning a single value; abandon use of load_dlpfc_data and directly use sc.read_visium to ensure uns[‘spatial’] exists.

Key Insight: Bash’s heredoc is sensitive to special character escaping; complex scripts should be written as separate files; the name of DLPFC data files has a chapter prefix; spatial data is located in Dataset/DLPFC/{chapter}/spatial instead of {chapter}/spatial; load_dlpfc_data uses read_10x_h5 instead of read_visium, resulting in missing spatial metadata; sc.pl.spatial heavily relies on uns[‘spatial’], and must be loaded using read_visium.

Common Issues#

11. The edge of the screen saver clock text shows a gray ghost ghosting effect#

Solution: Root cause: The font weight mismatch between ScreensaverClockHighlight (.light) and renderTextMask (.regular) causes the mask to become thick, exposing the frosted glass edge of hudWindow. This issue is resolved by unifying the font weight to.pdf-regular.

Key Insight: The visual effect layer must achieve pixel-level alignment; even minor weight differences will expose the underlying content.

12. Batch processing 13 days of historical data requires frequent switching of date parameters and manual confirmation of export/merge status, which is very cumbersome and error-prone#

Solution: Manually execute the export –date YYYY-MM-DD command of daily_summary.py, and execute the merge command separately for each date, confirming the integrity of the output file via the file system.

Key Insight: The summarize tool lacks a batch mode (e.g., –date-range 2026-02-07..2026-02-19 auto-iteration); batch processing support and progress recovery mechanisms should be added in the future.

When using relative paths with nohup, it fails if SSH is started in the project directory rather than the user’s home directory#

Solution: Change the command from ‘ssh an53 “nohup bash scripts/…”’ to ‘ssh an53 “cd $PROJ && nohup bash scripts/…”’, ensuring the working directory is correctly entered before executing the script.

Key Insight: SSH’s non-interactive session starts from $HOME, not from the current local directory. Always switch the directory to the project root or use absolute paths in remote commands.

- Details of the WWL (Wasserstein Weisfeiler-Lehman) graph kernel algorithm: ① Perform K rounds of WL message passing, collect multiple sets of neighbor labels per round → sort and merge → search/assign new integers in a global hash table; ② Query subgraphs and reference subgraphs use the same hash table to ensure consistent label encoding; ③ Output the (K+1)-dimensional feature vector [a^0, a^1, ..., a^K] for each node; ④ The cost matrix uses standardized Hamming distance (different bits/total number of bits); ⑤ The ot.emd2() function in the POT library can efficiently calculate the Wasserstein distance (10 times faster), and if scipy linprog is not available, other methods are used; ⑥ RM score = 1 - W, where W ∈ [0, 1].
- Explanation of the evaluation metrics for cross-sample niche queries: ① The Spearman correlation coefficient ≈ 0.44 (p<1e-150) indicates a moderate positive correlation between cosine similarity of fused embeddings and RM-IDEAL topology scores, showing that the embedding data can indeed capture cross-section niche structure information; ② A P@K close to 0 indicates a large head difference between the two rankings (embedding similarity and topology measure different information dimensions), but the overall ranking trend is consistent; ③ A low label similarity rate indicates a low proportion of identical labels among the top K, possibly because the embedding spaces of different regions are not fully aligned; ④ The r=0.63 in the direction of 151673→151673 is significantly better than the reverse r=0.39, indicating better embedding quality for 151673.
- The long-term value of AI dialogue logs: By generating 13 historical reports batchwise using the gadget/summarize tool, the complete technical evolution process in three directions—robot simulation, spatial transcriptomics, and AI assistant—over two weeks is systematically recorded (including key bug sources, architectural decisions, and human-machine collaboration patterns).
