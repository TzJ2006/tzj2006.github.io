Issues and Solutions#

Key Issues#

1. RecoverBench script uses “first frame success” logic, leading to exaggerated metrics and deviation from the documentation requirement of 10 frames consecutive.#

Solution: Implemented ConsecutiveSuccessTracker, first wrote L2 specification tests, then refactored all evaluation loops to enforce strict time limits.

Key Insight: Single-frame success validation severely overestimates reliability; strict time windows are crucial for accurate recovery rate calculation.

2. New Anthropic models appear “unknown” or “$0.00” due to standardization differences and outdated archive data covering real-time logs.#

Solution: Updated the new family’s normalize_model, added clear pricing indicators, and modified the parser logic to prioritize real-time log data over historical archives.

Key Insight: Without indicators, zero cost display cannot be distinguished from missing data; standardization fixes must be combined with cache invalidation to prevent historical data corruption.

3. Avoid expanding the scope during literature review by distinguishing video generation from robot control papers.#

Solution: Conduct strict filtering based on relevance to “robot perception, planning, and operation,” retaining only video papers that provide direct architectural inspiration for JEPA.

Key Insight: Potential spatial memory in diffusion models shares structural similarities with JEPA, allowing analogical architecture transfer across different fields.

General Issues#

4. Research Scout pipeline timed out when processing a large batch of 100 LLM base filters.#

Solution: Refactored the pipeline, using smaller batches (50 papers) and increasing timeout thresholds to ensure reliable completion of JEPA/World Models search.

Key Insight: LLM tool calls have strict time limits; large-scale processing must be done in blocks to ensure reliability of long-term workflows.

AI Limitations#

General Limitations#

  • LLM tool calls via subprocess have strict time limits; large batch processing requires chunking for reliability, as shown in the Research Scout process.
  • DLL/runtime issues in local Windows environment prevent actual Rust testing, forcing reliance on compilation validation.
  • AI initially failed to identify outdated archive data covering real-time logs in TokenMonitor, instead guessing logical errors rather than checking the persistence layer, until prompted.

Lessons Learned#

Key Experiences#

  • Potential spatial interaction is a new trend in robot perception; V-JEPA’s potential space outperforms video diffusion baselines in intuitive physical modeling.
  • Adopting “test first” approach (adversarial/unit tests) when aligning code and technical documentation is very effective, ensuring immediate compliance and avoiding regression issues.
  • When fixing model normalization issues, always check the data persistence layer (archive/cache), as outdated historical data easily covers real-time improvements.

Practical Experiences#

  • Using clear indicators (e.g pricing_available) is more effective than sentinel values to distinguish “zero cost” from “missing price data”.
