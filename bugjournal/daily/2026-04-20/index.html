Issues and Solutions#

Key Issues#

1. The 1.8B translation model cannot translate long Chinese summaries into English and always outputs in Chinese#

Solution: Modified build_translation_prompt()—when target_lang==‘en’, use English instructions instead of fully Chinese instructions, allowing the model to break out of the Chinese context and switch to English output.

Key Insight: Small translation models (1.8B) are context-sensitive—Chinese prompts lock them into Chinese output mode; using target language instructions helps switch the output language.

2. Preflight fixes (summary language, chart links) were undone by sync_staging.py during update.sh#

Solution: Modified all repair functions (fix_language_issues, fix_title_issues, fix_chart_links) to repair both staging source files (outputs/site/content/) instead of just the website/content/.

Key Insight: In the two-stage staging process, repairs must apply to both sides simultaneously to avoid simultaneous overwriting. The staging source files are authoritative copies.

3. Despite being generated in outputs/images/summarize/, daily charts are missing from the website#

Solution: Added chart filling logic in cmd_deploy()—after filtering out deployed dates, scan for missing charts in staging and regenerate them without re-translating content.

Key Insight: The “deployed” check in Deploy only checks if the content exists, ignoring the staging status of charts. Resource deployment should be independent of content deployment status.

4. Image link replacement in Deploy (../images/ → /images/daily/) does not match the actual markdown (pure file names)#

Solution: Modified the replacement rule to align both modes: (../images/xxx) and (xxx-usage.png) → ‘/images/daily/xxx’, executed before translation, ensuring absolute paths for both en/zh.

Key Insight: String replacement must match the actual data pattern, not assumed patterns. Image link rewriting should be done before translation to ensure consistency across language variants.

General Issues#

5. The x-axis of charts shows only one platform (Claude Code), and Codex is compressed to the right when no data exists#

Solution: Fixed the platform list to always include [‘Claude Code’, ‘Codex’], added ax.set_xlim(-0.5, 1.5) to center the bars, and displayed ‘0.0M’/’$0.00’ when missing data.

Key Insight: Matplotlib’s tight_layout + right legend cause x-axis compression when the dynamic platform list appears. Fixing xlim and platform order prevents layout deviation.

Learning Outcomes#

Key Learnings — For multi-stage pipelines (staging → deployment), repair measures must apply to authoritative sources (staging) rather than just deployment targets, to support synchronization operations#

  • Small translation models (about 1–2B parameters) are highly context-sensitive: language instructions are more important than explicit target languages. Using target language instructions enables better output switching.
  • When debugging recurring issues, it is necessary to track the full data flow from generation → staging → sync → deployment to find where states are overwritten.
  • Asset deployment (images, static files) should be independent of content deployment status. Use independent “asset exists” checks instead of inferring from content existence.
  • For bilingual content, normalize paths (relative paths → absolute paths) before translation, ensuring consistent referencing between languages. URL/path rewriting is language-independent and should be done before translation.
