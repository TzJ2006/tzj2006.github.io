Problems & Solutions#

Critical Issues#

1. Advisor concerns that the method looks ‘handcrafted’ due to different questions for different tasks.#

Solution: Developed a unified formalism where every task is a triplet of (Glyph, Predicate, Anchor) drawn at a grounded point.

Key Insight: Different task behaviors are just different parameter selections (statement, region, view) from a closed library applied to a single unified loop.

2. DLPFC ‘gene-only’ arms were silently falling back to KMeans during mclust runs, invalidating comparisons.#

Solution: Added a dedicated ‘kmeans’ cluster_backend mode to the seed_matrix pipeline to produce explicitly matched controls.

3. Cloud models (Astra/Claude) were failing validation because the Codex call entry was disabled to prevent file access.#

Solution: Implemented a dedicated, isolated Codex call implementation that explicitly strips all tools and file access before routing.

4. JEV latency (Version B) caused significant performance drops in time-sensitive tasks like SwingXtimes and ButtonUnmaskSwap.#

Solution: Identified that the drop was due to the delay in visual feedback (approx. 26 steps) rather than the model’s reasoning quality; discovered the ’non-pausing’ advantage only holds if latency is below ~0.5s.

Key Insight: The ’non-pausing’ advantage only holds if JEV latency is kept below ~0.5s; larger delays cause the policy to overshoot targets.

5. The meeting summary contained numerical discrepancies and overstated claims (e.g., claiming a result was true for ‘all’ when it was 7/8).#

Solution: Deployed an adversarial verification workflow (agent harness) to check every number against CSV data, then manually corrected the draft.

6. Automated sending failed because the WeChat input box name was appended with IME (Input Method Editor) status text.#

Solution: Modified the logic to strip the IME input status string while maintaining strict contact name validation.

7. The assistant failed to respond to @ mentions in group chats despite the text being received.#

Solution: Identified that WeChat metadata was Zstandard compressed and updated the parser to correctly decompress and extract the mention list.

8. Semantic Scholar API rate limiting (HTTP 429) prevented full abstract retrieval for all papers.#

Solution: Implemented a fallback mechanism using OpenAlex and arXiv to recover abstracts for missing entries.

9. The agent incorrectly identified contact changes due to UI focus shifts or window activation during the sending process.#

Solution: Implemented input box reuse logic to prevent repeated re-positioning and re-searching of the UI element.

Learnings#

Key Learnings#

  • A unified system story for CVPR should emphasize that task-specific protocols are emergent properties of a generalized formalism (Plan + Pointer).
  • Fusion method rankings (e.g., NCL vs Concat) can be volatile depending on the clustering algorithm used; a single clusterer is insufficient for robust benchmarking.
  • NCL’s performance gain over gene-only methods is derived from spatial topology, not the visual features themselves, as evidenced by the lack of significance in image-shuffled trials.
  • Effective model isolation requires a ‘Provider-mediated’ architecture where the application handles tool execution and only feeds the text/result back to the model.
  • Scaling data retrieval for large datasets requires robust multi-source fallback strategies (Semantic Scholar -> OpenAlex -> arXiv) to handle API rate limits.
  • UI automation in WeChat is highly sensitive to IME status changes which can mutate element names/attributes unexpectedly.
