Problems & Solutions#

Critical Issues#

1. Initial Cosmos deployment attempt targeted wrong model architecture; Predict 2.5 is the relevant baseline for RoboCasa, not Cosmos 3.#

Solution: Conducted deep technical analysis to map action spaces and weights. Pivoted strategy to Predict 2.5, educing user on world model vs. policy distinctions.

Key Insight: Newer base models may lack direct compatibility with specialized benchmarks; checking specific policy checkpoints is critical.

2. STAIG ‘Original’ panel mislabeled UNI2 features as BYOL, invalidating ablation comparisons.#

Solution: Audited code paths to verify feature sources, located true BYOL embeddings, and re-ran evaluation. Confirmed published STAIG scores are irreproducible without specific unshared optimizations.

Key Insight: Assumptions about baseline features must be verified by code inspection; high-level labels can be misleading.

3. TokenMonitor UI data remained stale due to missing frontend timers and static backend cache keys for rolling windows.#

Solution: Implemented time-bucketed caching keys in Rust, disabled disk cache for 5h views, and added startup refresh logic. Fixed Codex JSON-RPC parsing to handle interleaved notifications.

Key Insight: Rolling time windows require dynamic cache keys; static keys freeze temporal data.

4. ErrorRecoveryBenchmark augmentation failed due to disk quota limits and EGL rendering errors on headless HPC.#

Solution: Diagnosed quota vs. physical space distinction; cleaned corrupt files and restarted parallel loop with chunked saving. Fixed LeRobot conversion by exporting MUJOCO_GL=egl and adjusting PYTHONPATH for hybrid environments.

Key Insight: HPC quotas are distinct from disk usage; headless rendering requires explicit backend configuration.

General Issues#

5. RoboCasa asset downloader failed in Slurm batch jobs due to interactive stdin prompts.#

Solution: Modified setup scripts to suppress interactive prompts and handle headless downloads automatically.

Key Insight: Simulation environments often have legacy downloaders assuming interactive terminals; these must be decoupled for HPC deployments.

Learnings#

Key Learnings#

  • NVIDIA’s RoboCasa ecosystem clearly splits Predict 2.5 Policy (baseline) from Cosmos 3 (general world model); always verify specific policy checkpoints for benchmark compatibility.
  • True Original STAIG results (~0.54 ARI) are significantly lower than published figures (~0.70 ARI), indicating unshared optimizations in original runs.
  • For rolling time windows, caching keys must include a time-bucket component; static keys serve stale data.
  • Headless HPC environments require explicit MUJOCO_GL=egl export to prevent GLFW errors in MuJoCo/Robosuite workflows.

Practical Learnings#

  • On HPC clusters, always check for interactive prompts in dependency installers/asset downloaders when using Slurm batch jobs.
