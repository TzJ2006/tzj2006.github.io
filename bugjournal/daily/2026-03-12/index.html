Problems & Solutions#

Critical Issues#

1. macOS non-sandbox applications cannot persist file access permissions; old videos in historical records report Operation not permitted error#

Solution: Enable App Sandbox permissions (com.apple.security.app-sandbox and files.user-selected.read-write), fix ensureFileAccess to add non-scoped bookmark fallback parsing, and add NSOpenPanel reauthorization mechanism to showVideo/showImage.

Key Insight: The macOS TCC mechanism requires App Sandbox to create security-scoped bookmarks. Non-scoped bookmarks can only parse URLs but do not grant access permissions, resulting in inability to open old files. A combination of sandbox + downgrade path is required.

2. Incompatibility between torch 2.7.1 and torchvision 0.21.0 ABI causes failure to register torchvision::nms operators#

Solution: Upgrade torchvision to 0.22.1+cu126 to match torch 2.7.1.

Key Insight: Custom operators in torchvision are linked to the C++ API of torch during compilation; version mismatch leads to invalid operator registration interface. torchvision 0.21.0 corresponds to torch 2.6.x and cannot be used with torch 2.7.x.

3. Pre-compiled .so files of curobo are incompatible with the current PyTorch ABI; JIT compilation fails to find cuda_runtime.h#

Solution: Remove old.so files, install ninja compiler tools, set CUDA_HOME=/path/to/conda/env and CPATH=/path/to/targets/x86_64-linux/include, and recompile using pip install -e .

Key Insight: C++ extensions require recompilation after PyTorch version upgrade. The nvidia package installed via conda in the environment places CUDA headers in non-standard paths (targets/x86_64-linux/include/), and environment variables need to be correctly configured for JIT compilation to find them.

General Issues#

4. The GPU monitoring tool output has excessive width and duplicate process displays, making it difficult to read#

Solution: Limit output to 80 columns, aggregate GPUs per process, and filter noise sub-processes such as multiprocessing workers.

Key Insight: The original implementation grouped by GPU caused a multi-card process to appear repeatedly across multiple GPUs. Aggregation per process and display of all used card numbers in the GPU column are needed.

  • Misunderstood the GPU monitoring requirement, simplifying the multi-to-many relationship into a one-to-many aggregation, leading to information loss. Inaccurate understanding of visualization needs for complex data relationships.

Learnings#

Key Learnings#

  • macOS TCC permission mechanism: Non-sandbox applications cannot create security-scoped bookmarks; only non-scoped bookmarks (only parsing URLs without access permissions) can be created, causing historical file access to fail after app restart. App Sandbox must be enabled to persist file access permissions.
  • PyTorch C++ extension ABI compatibility: Custom operators in torchvision (e.g., torchvision::nms) are linked to the C++ API of torch during compilation; versions must match exactly (torchvision 0.21→torch 2.6, torchvision 0.22→torch 2.7). Version mismatch leads to operator registration failure.
  • Conda environment CUDA toolchain configuration: The nvidia package installed via pip places CUDA headers in targets/x86_64-linux/include/ instead of standard include/ paths. JIT compilation of C++ extensions requires setting CUDA_HOME to point to the conda env and CPATH to include the targets path.
  • Defensive programming principle: A combination of sandbox + reauthorization is more robust than a single solution. Sandbox addresses the root cause (persistent permissions), NSOpenPanel provides a downgrade path (temporary authorization), and their combination ensures users can always access files.
