Solution: Switch GLM to a green color system (hue around 130), using 3-level brightness gradients, maintaining a difference of over 30 degrees with all existing colors

Key Insight: Color systems need sufficient hue difference (not just saturation/brightness) to achieve brand differentiation; comparison with official logo ensures user recognition

4. macOS CI failed due to unused Import warning, but Windows/Linux CI passed#

Solution: Found that these imports were cfg-gated on macOS, but all uses follow full paths (std::sync::atomic::Ordering::SeqCst); since they are dead code on Mac and invisible on other platforms, these imports were completely removed

Key Insight: Platform-restricted imports may hide dead code issues; cfg attributes cause lint warnings that are platform-specific; always check the full file context to understand actual usage patterns

Learning Outcomes#

Key Learnings#

  • Before long data collection sessions, verify script targets against actual file systems (e.g., list targets vs. filesystem reality); mismatches waste human remote operation time
  • Multi-stage data pipelines typically have inconsistent path conventions; different tools expect different root directories; data may exist in multiple locations; need clear directory lists before and after transfer for verification
  • UI color systems benefit from multi-level organization: brand series use hue, versions use saturation/brightness, with a minimum distinguishable threshold (about 30-degree hue) to ensure recognition

Practical Learnings#

  • Platform-restricted imports (cfg attributes) hide dead code warnings on some platforms but show on others; always verify the full file context for actual usage patterns
  • rsync background tasks require regular progress checks (viewing output files) to estimate completion time; transfer speed via SSH is between 200–700 KB/s, so 1–2GB data transfer takes 20–40 minutes
