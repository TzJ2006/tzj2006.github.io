Issues and Solutions#

Key Issues#

1. Robots cannot classify multi-task status updates (e.g., “A is completed, B is also solved, C needs time adjustment”), and even with substantial user input, they fallback to “I don’t understand”.#

Solution: BATCHUPDATE intent was added, including semantic routing (21 expressions), enhanced keyword scorer for 2+ completion verbs, LLM prompt snippets for learning update array patterns, and handlers for searching calendar, deleting completed tasks, rearranging/receiving notes for other tasks, recording completion status, and sending EventBus events. Additionally, the GENERAL fallback mechanism was improved, using substantive LLM responses instead of discarding them.

Key Insight: Intent classification failures usually stem from three issues: (1) absence of enumeration members, (2) lack of semantic routing examples, and (3) absence of LLM prompt snippets. Solving these three issues plus keyword scoring can create strong classification capability. The GENERAL fallback mechanism should retain useful LLM responses rather than blindly using templates.

2. Semantic router scores for batch updates are approximately 0.20, below the 0.50 threshold, resulting in LOW_CONFIDENCE classification.#

Solution: BATCHUPDATE_ROUTE entries with multiple Chinese/English expressions (“A is completed, B is also done”, “Tasks A and B are completed, C needs rearrangement”) were created, and a keyword scoring rule was added: 2+ different completion keywords → increased score by 0.30 to capture batch update features.

Key Insight: Embedding-based semantic routing cannot recognize multi-entity status patterns. Explicit keyword counting (2+ completion verbs) is a simple but effective batch detection heuristic that can complement embedding similarity.

3. The LLM classifier does not allow use of batch_update intent; it defaults to GENERAL with type clarification, triggering a fixed “I don’t understand” template and discarding useful AI-generated responses.#

Solution: BATCHUPDATE intent was added to INTENT_PROMPT_FRAGMENTS, including update array patterns (task name, operation, note, new time), and added to the allowed intent list in build_prompt(). The GENERAL handler was improved to check whether replies with type clarification contain substantive LLM content (>20 characters, not template phrases), and it is used instead of the fixed template.

Key Insight: Fallback templates should be a last resort rather than a default option. When the LLM generates substantive responses, even if the confidence is low, they should be retained. Template overriding wastes the LLM’s reasoning ability and leads to worse user experience.

Learning Outcomes#

Key Learnings#

  • Multi-layer intent classification requires collaborative updates across 8+ files: enumeration file (models.py), semantic routing file (intent_routes.py), keyword scorer (keyword_scorer.py), LLM prompt file (prompts.py), context assembly file (context_assembler.py), double verification default (dual_verify.py), handler and route files (discord_bot.py), and derived data (route JSON). Missing any layer leads to classification failure.
  • Parallel agent exploration (3 agents for intent routing, task processing, and overall protection) is more efficient than sequential file reading, suitable for complex diagnostic tasks. Each agent provides a focused perspective, ultimately leading to a complete understanding.
  • Fallback templates in AI systems should retain useful LLM-generated content rather than blindly replacing them. Before replacing hardcoded fallback content, check whether the LLM response contains substantive content (>20 characters, not template phrases).
  • Keyword scoring can capture patterns that embedding similarity cannot detect: 2+ different completion verbs is a simple batch update heuristic that can complement semantic routing. In neural systems, explicit pattern detection remains valuable.

Practical Learnings#

  • When implementing the user-provided plan, parallel reading all affected files first instead of one by one helps understand dependencies and enables Claude to edit files more efficiently in batches.
