Critical Issues#

1. Early memory marks in ButtonUnmask tasks causing policy to skip subgoals.#

Solution: Added a ‘prerequisite_done’ latch in writer_probe/gemini_v2_env that requires 3 consecutive ‘done’ signals after the first step is sensed visually/physically before enabling marks.

2. StopCube has low training loss but low success rate.#

Solution: Recomputed phase-specific loss and analyzed error distribution, discovering that loss is dominated by ‘waiting’ phases and misses the critical, short-duration ‘pressing’ timing error.

3. Refreshing all data at once caused CPU spikes and UI stuttering.#

Solution: Designed a scheduler that spreads independent jobs (archiving, pricing, budgeting) evenly across the refresh interval and uses a single atomic publish.

4. API quota exceeded on Duke LiteLLM proxy.#

Solution: Awaiting quota reset or new key injection by user.

5. The initial budget estimation was too imprecise due to the fixed ±20% error margin.#

Solution: Implemented a ‘stretch-based’ calibration method that uses discrete segments where one model is dominant to calculate the true cost per percentage point.

6. InsertPeg failure mode is unclear.#

Solution: Analyzed loss and video to determine it is a contact-precision problem rather than a memory or learning issue.

7. Codex limit estimation lacked historical data for new installations.#

Learnings#

Key Learnings#

  • Average loss can be misleading in long-horizon tasks where success depends on a single, brief, critical action window (e.g., StopCube timing).
  • Calculating budget from ‘stretches’ of single-model usage provides a self-correcting accuracy mechanism that adapts to provider changes.
  • Rank correlation between training loss and success rate can be low (-0.51), especially when ’easy’ phases dilute the loss.

Practical Learnings#

  • For Minecraft servers, CPU core count (physical cores vs hyperthreads) and single-core speed are more critical for stability during chunk generation than raw vCPU numbers.
  • When a script fails at a certain line, other later assertions in the same script might also be stale; manual probing of individual test functions is necessary to ensure full coverage.
