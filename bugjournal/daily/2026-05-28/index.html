Issues and Solutions#

Key Issues#

1. The main interface of TokenMonitor displays outdated costs because the disk cache is never cleared after SSH sync, only the memory cache is emptied.#

Solution: Added disk_cache.clear_prefix("usage-view:") calls in sync_ssh_host, clear_usage_view_cache, and the background SSH sync loop to ensure latest data is recalculated always. Confirmed that although previously concerned about “Tianhe” device records, no original data loss occurred.

Key Insight: In a persistent desktop environment like Tauri, simultaneous destruction of state in one layer (memory cache) and another layer (disk cache) leads to inconsistent views; both must be synchronized during invalidation.

2. Claude CLI continues to timeout (120 seconds) when handling complex calendar requests with no output, due to shell=True on Windows causing stdio deadlock when generating sub-MCP processes.#

Solution: It was found that inherited pipeline processing causes hidden deadlocks. By setting shell=False in subprocess calls and using native session persistence (--resume) to manage context, reliable execution and memory retention are ensured.

Key Insight: Popen and subprocess inheritance in Windows cmd.exe behavior may cause hidden stdio deadlocks that are invisible in advanced logs; empirical isolation testing is needed to determine the cause.

General Issues#

3. Multiple ways to start servers in LifeCopilot lead to configuration drift, and new SSH devices in TokenMonitor have default exclusion statistics due to mismatched configurations.#

Solution: All pre-check logic was centralized in launcher.py for LifeCopilot. Standardized default flags in the Rust/TS layer of TokenMonitor to ensure “connected” devices are automatically included in cost reports, unless explicitly excluded.

Key Insight: Configuration management should be encoded as a single executable script or unified storage, rather than decentralized management, to reduce cognitive load and prevent configuration drift.

Lessons Learned#

Key Experiences#

  • On Windows, simultaneously starting subprocess.Popen and shell=True to generate their own subprocesses (e.g., MCP servers) may cause stdio deadlock due to handle inheritance. Avoid shell=True unless absolutely necessary for command parsing.
  • In Tauri/desktop applications, always clear both disk cache and memory cache when state changes to prevent old data leakage; remote sync caches are invalid and cannot be persisted.

Practical Experience#

  • When debugging CLI tools or UI anomalies, always verify the original payload and cache keys through visual evidence to distinguish the cache layer from computational logic, rather than relying solely on code tracing.
