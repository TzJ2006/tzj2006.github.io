Issues and Solutions#

Key Issues#

1. The scGPT spatial clustering ARI score is very low (about 0.10), despite using pre-trained checkpoints; colleagues suspect flash attention incompatibility causing checkpoint loading problems#

Solution: The root cause is that TransformerModel.init never saves use_fast_transformer as an instance attribute, so getattr(model, ‘use_fast_transformer’, True) always returns True, preventing the Wqkv→in_proj key remapping. This issue was fixed by adding self.use_fast_transformer = use_fast_transformer. After fixing, the average ARI increased from 0.118 to 0.170 (+44%), and NMI increased from 0.208 to 0.277 (+33%).

Key insight: When an instance attribute is missing in a PyTorch model class, even with strict=False, checkpoint loading may fail, causing partial parameter initialization failures (17.7% random weights), manifested as performance degradation rather than obvious errors. Always verify whether the checkpoint key matches the model state dictionary and clearly record mismatches.

2. Visium HD data lacks real labels, making traditional ARI/NMI metrics unsuitable for benchmark evaluation#

Solution: Use the Leiden community detection algorithm to automatically estimate the number of clusters from k-NN plots, outputting only cluster visualization results with contour scores. Modify compute_metrics() to conditionally skip supervised metric calculation when labels are unavailable. The Resolution parameter can control the granularity.

Key insight: Unsupervised spatial transcriptomics data require different evaluation strategies — focusing on visual consistency and internal consistency metrics (contour scores) rather than external validation. Tracking data sources is crucial for detecting pre-applied transformations.

3. In the multi-screen wallpaper application, powerSave and powerSavePlus video pause modes do not work, despite an occlusion detection infrastructure#

Solution: Identified 4 critical function vulnerabilities: allOverlaysCompletelyCovered() and anyOverlayCompletelyCovered() are hardcoded to return false; reassignAllWindows() and windowScreenDidChange() have no effect. The automatic mode is a viable template. These four functions were implemented using the existing overlayWindows.values and .occlusionState.contains(.visible) patterns.

Key insight: To-do comments in production code may disrupt functionality, while it appears to compile successfully but fails at runtime. This is a dangerous technical debt that may have gone unnoticed. The occlusion detection infrastructure already works in the automatic mode; only the connections need being established.#### 4. An error occurred during the Pi0.5 server evaluation, indicating that the WebSocket connection was rejected, even though the TCP port is open and the server is listening on localhost:8000.Solution: The proxy environment variables (http_proxy=127.0.0.1:10087, https_proxy, HTTP_PROXY, HTTPS_PROXY, no_proxy, NO_PROXY) interjected into WebSocket connections, even those to localhost. The problem was resolved immediately by removing all proxy variables. Key Insight: Even if the original TCP layer works properly, proxy environment variables may quietly interfere with localhost connections—they intercept at the application layer before socket creation. When debugging WebSocket issues on a development machine or shared cluster, be sure to check and remove the values of proxy variables.

5. HD adata_8um.h5ad has been transformed via logging (range [0, 6.05]), but preprocess_data() defaults to applying log1p, resulting in double transformation and data corruption.#

Solution: Add the skip_log parameter to preprocess_data() and preprocess_for_encoding(). Detect HD datasets through metadata checks, and set skip_log=True to skip redundant normalization operations. Use theadata.uns[’log1p’] flag or X.max() heuristic for detection.

Key Insight: Preprocessed external datasets need clear tracking of transformation history to prevent pipeline corruption. The HD point diameter (7.3px) is 20 times smaller than that of Visium, so dynamic adjustment of visualization parameter sizes (size=4.0 vs 1.0) is required to avoid invisible points.

6. When trying to load the 50.7 GiB Pi0.5 model on a GPU cluster, CUDA memory was insufficient—existing processes on the GPU consumed most resources.#

Solution: Run nvidia-smi and ps to identify the zombie server process (PID 2413737) that is already loaded and listening on port 8000. Reuse existing server instances instead of restarting new ones to avoid OOM issues and save 3–5 minutes of startup time.

Key Insight: When loading models exceeding 50GB on shared GPUs, be sure to check nvidia-smi and existing processes before attempting to restart. Reusing zombie servers is more efficient than killing and restarting them, and also ensures resource utilization and proper behavior for multi-user clusters.

7. Initial confusion about the Pi0.5 training state—Slurm job 46553 crashed at step 5000, and it is unclear whether 100k steps were completed.#

Solution: Directly check the checkpoint directory and find that the timestamp in the checkpoint records goes up to February 24, confirming successful training, even though the job crashed early (possibly recovering from a checkpoint). It was also noted that there was never an evaluation performed.

Key Insight: Slurm job logs do not reflect everything—they only show execution history, not the completeness of results. Always verify completion by checking actual checkpoint files and their timestamps, rather than relying solely on log tail information. Training completion does not mean evaluation completion.

8. The Robosuite environment lacks the get_bounding_box_half_size method, and env.seed() API is incompatible when evaluating Pi0.5 Phoenix.#

Solution: Configure PYTHONPATH to use zhaoganlong’s robosuite/mimicgen from the deps/ directory, rather than the local mimicgen_workspace version. For effective evaluation, the environment must have exactly the same library versions as the training environment.

Key Insight: VLA policy evaluation requires identical library versions to the training environment—even minor differences in robosuite/mimicgen versions can cause API incompatibility (missing methods, signature changes). Version mismatches may render benchmark results invalid.

9. Exploration of GPU acceleration for visualization widgets—cuML/FAISS is not installed, and mclust is unavailable (problem related to R_HOME).#

Solution: Analysis shows that the clustering process (100–300 milliseconds) is not the bottleneck; data loading and matplotlib rendering consume most time. Multiprocess parallel processing should be used instead of solely optimizing GPU performance.

Key Insight: Overly early attempts at GPU optimization—analysis indicates that I/O and rendering are the limiting factors, not computation. For this I/O-dependent workload, parallel CPU processing is more effective than GPU. Analyze before optimizing.

Lessons Learned#

Key Experience – When using PyTorch to load checkpoints, if strict=False is set, the system silently skips mismatched keys; if instance attributes are missing, more than 17% of parameters may be initialized randomly without error messages. In this case, due to the absence of self.use_fast_transformer, the mapping of Wqkv→in_proj keys failed, causing issues with flash attention weight mapping.Therefore, it is essential to verify whether the keys in the state dictionary match, clearly record any mismatches, and validate whether the model behaves properly after loading it.- Pi0.5 Phoenix LoRA was fine-tuned on 9 MimicGen tasks (total 4500 samples, 500 samples per task), but when evaluated under the same training environment, the success rate was only 0–24%. This significant gap between training and evaluation suggests possible overfitting to training data, insufficient training iterations, fundamental architectural limitations, or quality issues with training data, requiring further investigation.#

  • Completion of training does not equate to completion of evaluation. A model trained with 1 million steps may be left unevaluated during the research process. In high-performance computing systems, job logs reflect execution history rather than completion status—it is essential to verify completion by checking timestamped artifacts (checkpoints, output files) rather than merely looking at the end of the log. When discussing model performance, it is necessary to confirm the existence of evaluated artifacts.
  • Proxy environment variables (http_proxy, https_proxy, HTTP_PROXY, HTTPS_PROXY) can intercept and disrupt WebSocket connections to the local host, even when the original TCP layer functions properly. These variables act at the application layer before socket creation. When debugging local services on a development machine or shared cluster, make sure to disable these proxy variables.
  • The RM-IDEAL Spearman correlation benchmark shows that the STAIG fusion strategy (r=0.396) is significantly better than simple fusion strategies (Concat/Mean ≈0.25), as it can explicitly model spatial dependencies in gene expression embeddings. The learned fusion method always outperforms simple concatenation or averaging methods.
  • The Leiden community detection provides powerful automatic clustering capabilities for unlabeled spatial transcriptome data, implemented through k-NN plots where the resolution parameter controls the granularity. Combined with contour scores, unsupervised evaluation can be performed without real labels (common in Visium HD and other high-resolution spatial datasets).
  • Placeholder functions in production code marked with TODO comments may completely break functionality without causing compilation errors or type checking issues. In the macOS wallpaper application, 4 placeholder functions prevent the powerSave/powerSavePlus function from working for months. Therefore, these placeholders must be implemented or removed before release, rather than being retained as technical debt.
  • When loading a model exceeding 50GB on a shared GPU, check nvidia-smi and existing processes first, then attempt new startup. Reusing zombie servers can prevent CUDA memory exhaustion, save 3–5 minutes of startup time, improve resource utilization, and respect the etiquette of multi-user clusters. This is particularly important in shared high-performance computing infrastructure.
  • Preprocessed external datasets (such as Visium HD provided by collaborators) require clear tracking of transformation history to prevent pipeline damage. The dataadata.uns[’log1p’] flag or X.max() heuristic can be used to detect already applied transformations and skip redundant normalization operations. In multi-stage analysis workflows, data sources are crucial.
  • For a continuously evolving experimental research codebase, planning framework compatibility in advance is very important. Asking “What features might be needed in the future?” helps avoid architectural lock-in. In the BC-RNN case, the standard robomimic checkpoint format (model.pth + config.json) can automatically inject errors through the existing PolicyAdapter without additional work.
  • VLA strategy evaluation requires ensuring that library versions are exactly consistent with the training environment—even minor differences in robosuite/mimicgen versions can lead to API incompatibility (e.g., missing get_bounding_box_half_size method, or changed signatures such as env.seed()). Version mismatches may result in invalid benchmark test results or runtime crashes.
  • The performance of spatial transcriptome visualization workflows is often affected by I/O processing (such as scanpy AnnData loading) and rendering (such as matplotlib), rather than clustering computation. For this I/O-dependent approach, multi-process parallelism across independent samples is more effective than GPU acceleration. Perform performance analysis before optimization.
  • High-resolution spatial transcriptomes (Visium HD 8µm and Visium 55µm bin spacing) require dynamic adjustment of visualization parameter sizes—spot size must change with bin spacing to avoid invisible or overlapping points. The spot diameter in Visium is 7.3px, so size=4.0 is required, while the default size in Visium is 1.0, allowing proper coverage of the spatial plot.
  • When discussing multivariate models in research, it is better to first explain the data source (which data, how many samples, which tasks) rather than focusing on checkpoint paths. Training data is the conceptual foundation; checkpoint paths are technical details. This helps better determine what to evaluate and compare.
