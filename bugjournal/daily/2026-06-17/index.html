Problems & Solutions#

Critical Issues#

1. TokenMonitor single-instance startup failure when lock port is occupied by un-terminatable processes.#

Solution: Implemented a Windows named mutex (Local\TokenMonitor-SingleInstance) as a robust fallback lock mechanism alongside the TCP port check, preventing access denied errors.

Key Insight: OS-level primitives like named mutexes provide reliable single-instance enforcement where TCP ports fail due to legacy or protected processes.

2. Ambiguity in MIHD staig_fusion outputs regarding gene encoding source.#

Solution: Implemented content hashing (MD5) of embedding arrays; true encoder-paths produce unique hashes per gene, while HVG-path baselines match a gene-less baseline hash, conclusively proving provenance.

Key Insight: Metadata is unreliable for scientific provenance; direct content hashing against known baselines is the only trustable verification method in ML pipelines.

3. Duplicated device entries in TokenMonitor Settings due to volatile slug metadata (e.g., OS tags, hashes).#

Solution: Created deviceIdentityKey helper in format.ts to strip suffixes and hashes, using the normalized string as the canonical identity for deduplication.

Key Insight: Raw identifiers should not be used for matching; canonical representation is required early in the display pipeline to prevent duplication.

General Issues#

4. GitHub CLI (gh) authentication failure during automated PR creation.#

Solution: Detected gh auth invalidity, bypassed direct API push, and generated title/markdown body for manual verification or alternative MCP connector usage.

Key Insight: Automated agents must anticipate local token mismatches and fall back to generating executable code/text rather than relying on potentially invalid session contexts.

5. Cursor Remote SSH server installation failure on ’tianhe2’ due to proxy mismatches and corrupted archives.#

Solution: Identified conflict between local SSH RemoteForward (10087) and remote proxy (127.0.0.1:18080); cleaned corrupt files, aligned ports, and manually transferred the correct server package via tunnel.

Key Insight: Proxy environment variables persist across sessions; mismatches between local tunnels and remote configs cause silent connectivity failures for development tools.

AI Limitations#

General Limitations#

  • Rust unit tests failed due to local DLL environment issues rather than code bugs, preventing immediate verification of backend logic changes within the log context.

Learnings#

Key Learnings#

  • For single-instance applications on Windows, relying solely on lock ports is brittle; combining TCP-based IPC with a named mutex provides robust redundancy against occupied or protected ports.
  • When auditing scientific outputs where metadata is missing, content hashing against known baselines is the most robust way to prove provenance of embedding arrays.

Practical Learnings#

  • Repositories using git worktree for local dev should explicitly ignore .claude/worktrees/ or similar agent workspace folders in .gitignore before commitment to prevent future repo bloat.
  • When debugging remote tool failures, always check for proxy environment variables in both local and remote shell profiles, as mismatched ports are a common silent failure point.
