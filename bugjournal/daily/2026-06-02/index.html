AI Limitations#

General Limitations#

  • If not wrapped in try/catch, LLM-wrapped implementations often crash during timeout, easily confused with JSON parsing errors; this is common in many projects today.
  • Dependence on file metadata (dates/logs) rather than binary content (md5sums) initially masked the severity of data corruption in MIHD; explicit artifact verification is needed to prove byte-level identity errors.
  • Unable to predict local environment differences (python3 vs python, Tauri key formats) causes CI/publish script failures, requiring manual iteration of secret formats and scripts.

Lessons Learned#

Key Lessons#

  • In spatial transcriptomics pipelines, verify embedded outputs with md5sums when comparing encoder branches; the same input may silently mask upstream failures in downstream GCNs.
  • In HPC environments, work results should be submitted regularly; local trees are temporary, and re-cloning or deletion of directories is highly risky. System snapshots are important security measures but cannot replace version control.
  • Root tsconfig in a workspace should often be set to “pure reference” (include: []) to avoid CommonJS/ESM parsing conflicts that cause build failures.

Practical Lessons#

  • Tauri updater signature (minisign) and code signing (Apple/DigiCert) are independent; mixing them in CI workflows disrupts automatic update consistency across platforms.
  • When using LLMs for structured data translation, explicitly enforce the “retain technical identifiers” rule to prevent function key and path corruption.
