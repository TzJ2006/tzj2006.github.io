Issues and Solutions#

Key Issues#

1. Co-auth analysis showed zero student counts for all tested professors (Sergey Levine, Pieter Abbeel, Chelsea Finn), despite correct implementation.#

Solution: Teacher homepages with human confirmation explicitly list student information; a homepage-based discovery and extraction of student names function was implemented, using co-auth data only as supplementary information while providing source tracking to ensure transparency.

Key insight: Teacher homepages are the authoritative source for student lists, more reliable than inference from co-auth patterns. When heuristic algorithms fail due to data sparsity, one should rely directly on the information source (professor’s webpage) rather than debugging the scoring algorithm. Real data is better than inference.

2. Semantic Scholar matched 6 researchers with incorrect results due to ambiguity in names (Ming Yu → explosive chemist, Xiaolong Wang → veterinary scientist/geologist/natural language processing researcher; 5 out of the initial 6 queries failed).#

Solution: Human-provided full names for clarification (Mingyu Ding); relying on ArXiv paper matching is more accurate; AI can identify incompatible research fields due to data quality issues and return clear warnings instead of generating incorrect trajectories; verification with ORCID+institution is recommended for common Chinese names.#### 3. Output files were scattered in tool-specific subdirectories (e.g., summarize/logs/, research/cache/, test/benchmark_results.csv), and a hardcoded Path(file).parent pattern was used, leading to tight coupling and difficult disk space management.

Solution: A unified output/hierarchical structure was designed, organized by type (reports, logs, cache, data) and tool, standardized path constants were introduced in common/paths.py, all hardcoded paths were replaced, and the environment variable fallback mechanism was updated.

Key insight: When multiple tools have similar output patterns, a structured by-type structure is easier to maintain than by-tool. Centralized path management makes refactoring atomic—changing one constant affects the entire system without breaking code. Phased execution and setting validation checkpoints can prevent cascading failures.

4. Two overlapping research tools existed in the same directory (monolithic research_scout.py and modular profiler package), leading to code duplication, unclear single entry point, and no functional records. Solution: Users provided a detailed 9-step integration plan including precise feature signatures, line count statistics, and architectural decisions. Key insight: For complex architectural changes, a detailed written plan can prevent scope creep and ensure AI follows the plan. Hybrid integration (maintaining a stable CLI while refactoring internal logic) reduces migration risk more than full rewrite. Lessons Learned#

Key Experience – For large-scale architecture rewrite, a detailed written plan including function signatures, line numbers, and architectural decisions can significantly improve the accuracy of AI execution and prevent scope drift. The human architectural perspective combined with AI tactical execution yields better results than AI’s improvisation.- Large-scale refactoring should be processed in parallel by phase or domain: The 7 phases of CalendarPro are implemented by 5 concurrent agents, each responsible for a portion of the changes, and then combined with testing and validation. Phase-based execution and verification checkpoints can prevent hard-to-diagnose cascading failures.#

  • The academic figure analysis system must prioritize name disambiguation as a priority—common Chinese names can cause serious disambiguation issues, requiring mandatory ORCID/institution matching. Aggregation of same-name figures generates completely incorrect researcher data that appears reasonable until domain experts identify incompatibilities. Instead of spreading misinformation, it is better to return “data unavailable”.
  • Multi-source data integration (website page scraping, co-author relationships, ArXiv, Semantic Scholar) combined with clear source tracking can handle failures or inaccuracies in a single data source. Teacher profiles are more accurate at identifying students than co-author analysis because they explicitly list current and past students along with their status.
  • Through delayed import and re-export adjustments, backward compatibility can be maintained during large-scale code refactoring, avoiding circular dependency problems. Centralized infrastructure modules (paths.py, cache.py, llm.py) enable atomic refactoring—changing a constant affects the entire code without breaking downstream dependencies.
  • The modular architecture enables clear integration: using research_scout.py as a single CLI entry point and the profiler package as an independent library code allows different functions to be well separated. Hybrid integration methods (preserving a stable CLI while refactoring internal code) reduce migration risks more easily than complete rewriting.
  • Academic research analysis tools can quickly understand the current state of the field: the researcher analyzer can quickly reveal the leader trajectory, current development directions, and breakthrough achievements in the field. A systematic framework can track the latest research directions.
  • When multiple tools have similar output patterns, organizing files (reports/, logs/, cache/) by type priority is easier to maintain than by tool priority. Centralized path management enables atomic refactoring of the entire code library.
  • Parameter transmission in nested call chains requires backward-compatible default values (backend=‘claude_cli’) and incremental syntax testing (py_compile) to prevent cascading errors. Default values can maintain backward compatibility when adding parameters to deeply nested call chains.
  • Before making architectural decisions, use parallel agent exploration to fully understand the code library; sequential exploration will miss connections between components. As functions increase, document files like CLAUDE.md become quickly outdated, so active maintenance or automatic detection of unrecorded code paths is necessary.
  • Documentation-driven development is very effective: updating CLAUDE.md and TUTORIAL.md immediately after code changes can prevent documentation obsolescence and ensure knowledge is passed on to future users. Document synchronization is important for maintenance.
  • Heuristic algorithms rely heavily on data quality: when data is insufficient, using Semantic Scholar for student discovery fails; multiple sources or real data (such as teacher profiles) are needed. When the heuristic algorithm fails, one should directly turn to the information source instead of debugging the scoring algorithm.
  • The upgrade process of LLM fixes (from haiku to 14-line poetry to masterpieces) is limited; continuous JSON parsing failures may indicate issues with prompts or context, not model capabilities. When all three model layers fail, the input structure or problem decomposition should be re-examined.
  • Always ask users about design trade-offs (scoring weights, automatic vs manual functions, performance and convenience) instead of assuming default settings; user context can reveal some hidden priorities, such as a preference for automatic reference analysis over cost optimization.
  • When extracting shared common functions, it is better to choose the most reliable implementation method (select the most robust implementation from each source), which is more effective than any arbitrary choice. API search behavior is not always intuitive; multi-source data acquisition is more reliable than a single API query.

Summary of Practical Experience#

  • Hugo’s content organization benefits from semantic separation: reference materials (researcher data) and temporal content (daily reports) should be placed in different sections to improve navigation and user experience.
  • The input point of Python packages is important: ‘python -m package’ is more robust than executing scripts directly, especially in complex module structures with internal imports. Using the -m flag ensures correct module parsing.
  • Polite web scraping (requested every 2 seconds) with rate limiting is very important, so when scraping academic homepages at scale, it can avoid being blocked or causing server overload.
