Issues and Solutions#

Key Issues#

1. During decoding of enhanced video frames, DataLoader encountered RuntimeError: InvalidDataError due to damaged MP4 files generated during HDF5 conversion.#

Solution: Two-layer fix approach was implemented: 1) Static fix via scripts to re-encode damaged episodes from the original HDF5 source; 2) Dynamic handling including pre-check (disabled after fix) and try-except blocks to skip damaged frames without interrupting training.

Key Insight: Damaged videos in the LeRobot dataset usually have no issues at the file level, but fail during specific decoding operations; diagnosis requires explicit PyAV decoding, not just checking file headers.

2. JAX JIT compilation limitations prevented conditional skipping of forward computation at runtime based on the damaged mask status.#

Solution: Computation of damaged samples still runs, but their loss contributions are set to zero to prevent gradient contamination without breaking static graph requirements.

Key Insight: Static graph frameworks like JAX require control flow to be independent of tensor values at compilation time; the solution must comply with these compilation-time restrictions.

General Issues#

3. Initial error handling masked errors in clean datasets by only fixing damage in the enhanced dataset, leading to InvalidDataError for clean data (boss44_lerobot).#

Solution: Realized that damage extended beyond the enhanced set; applied diagnostic and repair logic to all involved LeRobot datasets.

Key Insight: Data pipeline errors may occur across multiple dataset versions; fixes for part of the system might expose issues in other parts, which cannot be resolved without overall validation.
