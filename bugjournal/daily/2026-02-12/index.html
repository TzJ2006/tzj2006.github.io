Issues and Solutions#

Key Issues#

1. Inconsistent standardization in MIHD — UNI2/scGPT uses L2 norm, while HIPT/ResNet50/MLP/GCN does not, and no post-fusion standardization is applied.#

Solution: Designed a three-point normalization system (after encoding, before fusion, after fusion) and can configure different methods (L2, standard scaling, none) via the new utils/normalization.py module. Key insight: Inconsistent standardization across different encoders affects downstream clustering performance; the three-point normalization method provides fine-grained control.

2. QueST uses adversarial training for batch correction, but it is unclear whether this works for spatial transcriptomics.#

Solution: Developed a BatchCorrection plugin module based on QueST’s discriminator/generator pattern and evaluated its effectiveness. **Key insight:**移植 batch correction into the MIHD environment requires empirical validation rather than assuming applicability.

General Issues#

3. User idea 3 is not clear enough — “Q-Former similar to LLaVA”, but LLaVA uses a simple MLP, while Q-Former comes from BLIP-2.#

Solution: Proposed clarifying the issue; users chose to implement both (Q-Former with cross-attention and a 2-layer MLP for LLaVA) to compare lightweight and heavy fusion effects. Key insight: Clarifying architectural ambiguities early avoids wasting implementation resources in the wrong direction.
