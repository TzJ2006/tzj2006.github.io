Learnings#

Key Learnings#

  • A ‘Four-Quadrant’ classification (Who moves x When it moves) is a highly effective prompt structure for VLM memory generation.
  • For high-stakes writing (SoP), the ‘generic core’ must be robust enough to bridge multiple distinct ‘customized hooks’ to prevent logical drift.
  • Funding is often guaranteed by the institution, but research resources (robots/GPUs) are strictly advisor-dependent; diversifying advisors is more critical than diversifying research topics.
  • Complexity in system design often stems from ‘unclaimed ideas’ in documentation; a strict implementation of the ‘8-question’ framework for all new ideas is necessary.
  • When migrating large numbers of small files (pkls), parallelization by filename-prefix is significantly more efficient than standard directory-tree rsync.
  • Visual prompting requires task-specific markers (path, ring, badge) rather than a unified rendering primitive to avoid ‘false memory’ errors.

Practical Learnings#

  • When migrating environments, copying binaries is insufficient; RPATH and shared library dependencies must be verified and moved together.
  • Using a local LLM (Gemma 4) for high-volume text translation (130k+ characters) is viable for maintaining data sovereignty in technical projects.
  • Low CPU/GPU utilization does not rule out system lag; DWM compositor contention and high-resolution scaling (4K) can cause significant frame latency.
