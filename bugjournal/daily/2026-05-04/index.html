2. The floating ball and main application use different usage percentages for the same limit data, causing users to be confused about actual usage#

Solution: Fixed three extraction issues on the Rust side: (1) implement primary_window_id() via ID selection instead of windows[0]; (2) add a 60-second grace period for Codex; (3) change Cursor to read from auto_composer window instead of extra_usage

3. Despite available data, Codex weekly limits and points cannot be displayed — command_in_path(‘codex’) is parsed as npm’s POSIX shell shim on Windows, and CreateProcessW cannot execute (error 193)#

Solution: Modify command_in_path() to prioritize .cmd and .exe extension names on Windows, ensuring use of codex.cmd wrapper instead of pure scripts. Now Codex returns main/secondary windows + $861 points

Key Insight: Global npm installations on Windows generate shell shim and .cmd wrappers. Rust process creation requires an actual executable. Platform-specific path parsing must account for this difference.

4. The Statusline module collects server-authoritative limit data, but is not integrated into the display process — although statusline is the new upstream architecture, OAuth/CLI remains the only data source#

Solution: Add fetch_claude_from_statusline() to read JSONL event files and perform a 10-minute freshness check. Reorder claude_future: first try statusline (zero-cost, server-authoritative) → OAuth (macOS) → CLI detection (cross-platform). All 39 tests passed

Key Insight: A proper fallback chain prioritizes free/authoritative sources; statusline provides more accurate server-level limit status than client detection.

5. Three independent locations perform date range calculations independently, leading to synchronization risks, and parser_payload_for_period, apply_period_context, attach_local_stats contain approximately 150 lines of duplicate code#

Solution: Introduce the PeriodBounds structure and a single resolve_period_bounds() function. Fully remove apply_period_context() (approximately 50 lines). All date calculations now occur through a single authoritative source

Key Insight: Independent date calculations pose synchronization risks under timezone-sensitive logic. Refactoring to a single authoritative source eliminates approximately 150 lines of code

6. CSS Grid’s grid-template-rows: 0fr/1fr causes leakage of child elements’ padding/borders outside the collapsed container, even though the children set overflow: hidden#

Learning Outcomes#

Key Learning Outcomes#

  • Adopt hybrid git merge strategies for different branches: By isolating conflicting modules and merging invoke_handler registration, rather than choosing one implementation, we retain both sides’ innovations. Maximize value and reduce rewrite costs
  • Data consistency between different UI interfaces requires logical mirroring, not independent reimplementation. Use the mismatch due to Rust/frontend window selection logic. A single authoritative source or clear synchronization notes can avoid divergence
  • Windows npm global installation produces double paths (shell shim + .cmd wrapper). Rust process startup requires an actual executable. Platform-specific command parsing must use .cmd/.exe extensions on Windows
  • Statusline architecture provides server-authoritative rate limiting status via JSONL event stream; it should be the main data source, with OAuth/CLI as a fallback. The correct fallback chain should prioritize free/authoritative sources over paid/client estimates
  • Special cases in data pipeline protection (e.g., “if period != 5h”) accumulate into technical debt. System refactoring to a unified code path eliminates minor inconsistencies, reduces maintenance burden, and may remove ~90+ duplicate lines
  • CSS Grid grid-template-rows: 0fr cannot fully limit the box model of child elements like max-height: 0—padding and borders may cause issues. For reliable collapsible sections, using parent element maximum height + overflow: hidden is more robust and works across all browsers
  • Multi-choice chip mode is better for scalable options than segmented control. When feature set may grow (add providers), chip-based selection avoids UI rewrite, allowing any combination without hardcoding logic
  • Tauri app type system synchronization: When adding fields like barProviders, parallel updates are needed in TypeScript interfaces, Rust structures, and #[serde(rename_all = ‘camelCase’)] migration logic, defaults, and all test environments
  • Defaults should be derived from standard provider registries: Hardcoding [‘claude’, ‘codex’] causes missing cursor; use […RATE_LIMIT_PROVIDER_ORDER] to ensure defaults update with addition/removal of providers

Practical Learning Outcomes#

  • Tauri v2 forces strict major.minor version alignment between Rust crates and npm packages; inconsistency leads to build errors. npm lifecycle hook (pretauri) automatically installs matching versions by parsing Cargo.lock, achieving frictionless automation
  • Tauri intercepts stdio and redirects output to framework-managed log files ($APPDATA/…/logs/backend.log). When debugging Tauri apps, check framework logs instead of assuming stderr is valid
  • When implementing collapsible UI borders, place border-top on the hidden content rather than the collapsible container—allowing overflow: hidden to naturally clip borders during collapse, avoiding conditional logic
