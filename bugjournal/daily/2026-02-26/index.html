Issues and Solutions#

Key Issues#

1. Despite completing 99,999 steps, Pi0.5 had a 0% success rate, and the input dimension of BC‑RNN did not match (expected 65, actual 37)#

Solution: Analysis revealed that Pi0.5 was trained on 5 MimicGen tasks (coffee, stack, thread, assembly, stack three), but evaluation was performed on PickPlace, which is not in the training data. The dimension mismatch in BC‑RNN occurred because the create_env() function removed the ‘_D0’ suffix from the environment name, resulting in fewer object observations returned by the base robosuite environment than the MimicGen variant. Solution: mimicgen was imported to register the _D0 environment using the full environment name, and training/ evaluation tasks were adjusted accordingly.

Key Insight: Task distribution mismatch is a critical yet often overlooked issue in robot learning evaluation; environment naming conventions can disrupt observation consistency between training and deployment.

2. BC‑RNN training configuration was in low‑dimensional mode (state‑based), while the MimicGen paper uses image mode (pixel‑based) as the main benchmark#

Solution: All five BC‑RNN configurations were rewritten to adopt image mode: ‘object’ was removed from obs.low_dim, agentview_image and robot0_eye_inhand_image were added to obs.rgb, a ResNet18Conv+SpatialSoftmax encoder was used, the RNN hidden layer dimension was increased from 400 to 1000, the batch size was reduced from 64 to 16, and hdf5_cache_mode was set to ’low_dim’.

Key Insight: Image‑based BC‑RNN requires a completely different architecture (ResNet18 visual encoder, larger RNN, smaller batch size) compared to low‑dimensional mode; the official MimicGen benchmark uses image mode with 600 cycles.

3. The evaluation framework only supports PickPlace task and cannot evaluate the 5 tasks actually trained by Pi0.5#

Solution: A comprehensive multi‑task framework was built: five task YAML configuration files were created, containing task‑specific objects, phases, and thresholds; task_registry.yaml was created to map task names to datasets/checkpoints/prompting; 1.generate_scenes.py, 3.collect_data.py, and 4.analyze_results.py were modified to accept –task parameters and auto‑parse; run_full_eval.sh was rewritten to process tasks cyclically.

Key Insight: The evaluation infrastructure should be independent of tasks from the beginning; adding multi‑task support requires coordinated changes in configuration, scripts, and orchestration layers.

4. It is unclear whether the official BC‑RNN checkpoint or self‑training was used, nor which observation mode is used** Solution: The MimicGen repository was investigated to confirm that they only provide datasets and no pre‑trained checkpoints. Users explicitly wanted image mode (pixel‑based ResNet18 model, 600 cycles) to match the main results of the paper, rather than low‑dimensional mode (state‑based model, 2000 cycles).#

Key Insight: Benchmark papers usually do not provide model weights but only datasets; clear configuration selection (observation mode, training duration) can avoid wasting time on incorrect settings.

5. Complex multi‑repository evaluation infrastructure is needed, including error_recovery_benchmark and Motion-based-Self-Reflection-Framework, which contain interdependent components.#

Solution: Three parallel exploration agents were started, and training settings, evaluation infrastructure, and flowcharts were drawn simultaneously, then results were combined.

Key Insight: Parallel exploration of independent aspects can significantly accelerate understanding of complex systems compared to sequential investigation.

Lessons Learned#

Key Lesson — Task allocation mismatch between training and evaluation is a serious failure mode, manifesting as 0% success rate. In this case, Pi0.5 was trained on {Coffee, Stack, Threading, Assembly, Stack Three} but evaluated on PickPlace, resulting in a system failure despite successful training.- The MimicGen paper only provides a demonstration dataset (HDF5 file), without offering pre-trained model checkpoints. Researchers must train the BC-RNN model using robomimic, which is the official benchmark protocol.#

  • There are two different observation modes for BC-RNN, and their architectures are also completely different: the low-dimensional mode (state-based, 2000 cycles, a larger MLP) and the image mode (pixel-based, ResNet18 encoder, 600 cycles, a larger RNN). The main results in the MimicGen paper use the image mode.
  • The environment naming convention in robosuite/MimicGen has semantic meaning: removing the ‘_D0’ suffix changes which environment category is instantiated, thereby changing the object properties returned. The objects returned by the basic robosuite environment have fewer dimensions than the MimicGen’_D0’ version, resulting in a dimension mismatch (65→37 dimensions).
  • The VLA strategy evaluation requires coordination among multiple components: checkpoint locations, strategy servers (based on websocket/TCP), evaluation scripts, conda environment management, and GPU resources allocated via Slurm — any missing component will hinder the entire process.
  • The multi-task evaluation infrastructure needs coordinated design at different levels: task configuration (YAML), registry mapping (datasets/checkpoints/tips), script parameters (with automatic parsing of –task flags), and orchestration (task loops in bash scripts). Post-final adjustments are much more expensive than early-stage task-independent design.
  • Image-based robot learning strategies require camera rendering functionality during both training data collection and evaluation. The camera resolution must match the training resolution (84×84 for BC-RNN image mode) to avoid a mismatch in the input dimensions of the visual encoder.
  • Parallel exploration agents are very effective for understanding multi-component systems — independently exploring training settings, evaluation infrastructure, and process code, and then integrating this information, allows faster system comprehension than sequential investigation.
  • The Pi0.5 evaluation stack uses a dual-process architecture: the strategy server (openpi05 conda environment) serves the model via websocket, and the evaluation script (mimicgen_env) runs through the network environment and queries the server.
