Problems & Solutions#

Critical Issues#

1. Severe CPU thrashing caused by unthrottled concurrent vitest processes spawned by ai-companion’s background daemon.#

Solution: Traced root cause to ‘collect-report-data.ts’; implemented a file-lock singleton guard to prevent duplicate runs and analyzed process trees to identify the specific culprit.

Key Insight: Background automation tools without rate-limiting or singleton locks can cause immediate system degradation; isolation requires either throttling or explicit user activation.

2. Frozen VLM (Cosmos-Reason1-7B) produces constant, non-anchored coordinates regardless of input task when asked to generate arrow keypoints zero-shot.#

Solution: Abandoned the direct coordinate generation hypothesis. Plan shifted to using ‘candidate selection’ (MOKA/PIVOT-style: generate candidates programmatically, use VLM to rank/select) which removes the hardest localization step from the model.

Key Insight: Direct zero-shot pixel localization is too hard for current frozen reasoning models; indirect grounding via candidate ranking is a more viable path.

3. Cosmos3-Nano model weights on Tianhe2 were corrupted (truncated shards), causing vLLM startup failures and silent data integrity issues.#

Solution: Used Safetensors headers to identify corrupted shards, leveraged host’s internet access to re-download specific files from HuggingFace, verified integrity locally, and SCP’d them to the remote cluster.

Key Insight: Remote model files on clusters can degrade silently; always verify file integrity (headers/sizes) before serving weights, especially in offline or proxy-chained environments.

General Issues#

4. git branch ‘deploy/pi05-gr00t-n16-smoke’ appeared merged but content was missing from main; ai-companion lacked Codex compatibility.#

Solution: Verified discrepancy via tree comparison; created distinct plugin manifests to ensure parity between Claude Code and Codex ecosystems.

Key Insight: Git merge titles are not reliable indicators of content inclusion; different AI assistants require tailored configuration mechanisms for universal distribution.

  • Cosmos-Reason1-7B demonstrated a clear inability to perform zero-shot spatial grounding (pixel accuracy) for visual instructions, outputting static coordinates regardless of input text.
  • AI missed that running collect-report-data.ts in a daemon loop would cause massive CPU spikes without user intervention until deep process analysis was performed.

General Limitations#

  • Initial SSH and wget connections to Tianhe2 stalled due to intermittent network jitters on the local host; Windows/WSL environment prevented native bash verification without virtual environments. AI also struggled with npm ci in Codex sandbox.
  • Tool execution interruption on ‘TzJsDesktop’ and inability to visually inspect rollout videos limited full validation of branch states and qualitative model behavior.

Learnings#

Key Learnings#

  • Background tasks in monorepo setups must have strict singleton locking; concurrent execution of heavy testing scripts is the primary cause of silent background overconsumption.
  • Frozen VLMs (like Cosmos-Reason1-7B) are currently poor at zero-shot pixel localization; research should pivot to candidate-selection or fine-tuning approaches rather than relying on raw generation capabilities.

Practical Learnings#

  • Development tooling scripts (like test collectors) must implement single-instance guards to prevent resource thrashing if triggered by burst events or manual retries. Git subtrees are effective for embedding independent tooling while maintaining history.
  • For MVPs requiring video/audio data, explicitly validating manifest paths against real filesystem objects prevents ‘ghost runs’ that appear successful but evaluate on empty sets. Git merge titles are not reliable indicators of content inclusion.
