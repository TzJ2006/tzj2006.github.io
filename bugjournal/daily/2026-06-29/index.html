Problems & Solutions#

General Issues#

1. SSH host defined in config.d not found in main config file, causing confusion.#

Solution: Identified the Include directive in ~/.ssh/config and resolved the host definition via grepping.

Key Insight: Modular SSH configs (Include) can obscure host definitions; must check included directories to trace full configuration.

2. Stale Python package copies in WSL conda env prevented new parser code from executing.#

Solution: Uninstalled stale package and performed an editable pip install to link directly to the source files.

Key Insight: Non-editable installs mask live edits; using ‘pip install -e .’ ensures environment syncs with working directory changes across isolated environments like WSL.

3. Git clone failed due to DNS resolution failure on remote server and lack of tunneling tools (nc/socat).#

Solution: Implemented a custom Python HTTP CONNECT tunnel script and routed Git SSH through GitHub’s port 443.

Key Insight: Python is often available even in minimal containerized environments where standard network utilities are missing; using port 443 can bypass strict firewall rules for HTTPS/SSH.

4. Codex version mismatch: npm installed latest but CLI still reported old version due to conflicting prefixes.#

Solution: Traced the active binary path via nvm and reinstalled specifically into that prefix.

Key Insight: Multiple node.js installation methods (nvm vs system npm) can lead to conflicting global paths; always verify the actual executed binary.

5. Conda reported duplicate base environments on Windows due to case differences in path strings.#

Solution: Normalizing the string case in the environments registry file.

Key Insight: Windows file systems are case-insensitive but many configuration parsers treat paths as case-sensitive strings, leading to logical duplicates.
