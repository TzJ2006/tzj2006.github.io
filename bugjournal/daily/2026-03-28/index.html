Issues and Solutions#

Key Issues#

1. cchypothesis lacks runtime debugging capabilities — All hypotheses are verified only through static code analysis, missing dynamic state/time/data flow issues#

Solution: Implemented third-stage smart classification: static hypotheses remain in parallel read-only mode; runtime hypotheses use sequential plugin detection, [DEBUG Hx] tagged logs, Git security checkpoints, and automatic cleanup via git restore

Key insight: The dual-track investigation provides depth (plugin detection) when needed, while maintaining speed (parallel static), avoiding slowdown of all debugging sessions

2. Dashboard continuously shows 1–2 Hz vertical jitter due to a three-layer positive feedback loop: data refresh → UI re-render → window resize → data refresh#

Solution: Multi-layer throttling: (1) Window: 16 ms → 100 ms stable delay + 500 ms throttling every 3 operations; (2) Data: shallow payloadEqual avoids excessive .set() operations; (3) Parser: 2-minute active timeout to prevent fluctuations in is_active boundary

Key insight: Self-oscillating issues require simultaneous intervention at all feedback layers; fixing one layer alone weakens the loop but does not eliminate it

3. Git storage stack conflict: ccplan proposal added third-stage storage on top of existing fourth-stage storage, causing chaotic pop order and potentially hiding user uncommitted work#

Solution: Removed fourth-stage git storage and switched to git restore (non-destructive cleanup); now only third-stage uses storage (single storage model)

Key insight: Multiple storage layers in automated workflows lead to unstable state management — where possible, prefer non-stateful cleanup (git restore) over stateful rollback (storage)

4. TokenMonitor window appears in the center of the screen instead of near the system tray; resize causes window expansion downward into the taskbar rather than maintaining the bottom edge#

Solution: Achieved direct Win32 API positioning of the tray (FindWindowW → TrayNotifyWnd); changed front-end resize from webviewWindow.setSize() to backend set_window_size_and_align IPC for atomic size and position updates

Key insight: Tauri’s cross-platform positioning plugin abstracts platform differences but loses accuracy; Windows tray positioning requires platform-specific Win32 API for precise alignment

5. 42 Rust compilation errors: command file contains corrupted imports of deleted modules (change_stats, integrations, parser) as well as duplicate code for new commands/sub-modules#

Solution: Rewritten the command file into a thin 80-line module root structure, declaring 6 public modules, retaining only AppState/UsageDebugReport and 4 shared helper functions, resolving visibility and type issues

Key insight: Incomplete refactoring (mixed old and new code) is worse than monolithic code; either complete transition or fallback is required

6. Window anchor detection is unreliable: visible:false at initial mount, competition between position_near_tray and GetWindowRect, continuous resize causes anchor flipping#

Solution: Completely removed dynamic detection; tray pop window always uses position_near_tray to work.bottom, thus hardcoding the bottom anchor behavior

Key insight: For known-type windows, static configuration is better than dynamic detection; runtime detection adds complexity and failure modes but offers no practical benefit

General Issues#

7. Criticism that git restore does not clean up untracked files (e.g., .debug/hypothesis.log created during plugin execution)#

Solution: Explicitly run rm -rf .debug/ after each plugin cycle; changed log output directory from .claude/ (configuration) to .debug/ (temporary project) with a gitignore note

Key insight: Git restore only affects tracked files — the automated cleanup workflow must combine git commands with explicit file system operations for complete cleanup

Lessons Learned#

Key Experience#

  • Multi-stage workflow (ccplan) is very effective for complex and conflicting issues — adversarial review stage detected critical git stash conflicts that could cause data loss
  • Cascade feedback loops require simultaneous multi-layer intervention: fixing only window size adjustment (16 ms → 100 ms) is insufficient; data layer (load equality) and computation layer (timeout) also need handling
  • Debugging with metrics requires careful lifecycle management: each hypothesis needs independent instrument→run→analyze→cleanup cycles to avoid cross-contamination and residual debugging code
  • Incomplete module refactoring leads to hidden dependency hell: commands.rs still imports crate::parser, while new commands/calendar.rs imports crate::usage::parser — these two paths cannot coexist
  • Dynamic runtime detection adds failure modes; when static configuration is sufficient, such detection is unnecessary: tray windows always use position_near_tray, so the bottom anchor should be hardcoded
  • Tauri’s cross-platform window positioning: plugin abstraction sacrifices accuracy for portability; perfect pixel positioning (especially system tray alignment) requires platform-native APIs

Practical Experience#

  • Comprehensive test suite can detect refactoring issues: 218 Rust tests and 191 front-end tests verified that fixes do not break existing behavior
  • Automated cleanup workflow must distinguish tracked and untracked files: git restore handles tracked files; untracked files (logs, temporary directories) require explicit rm/rmdir operations
