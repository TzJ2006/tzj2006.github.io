Issues and Solutions#

Key Issues#

1. Desktop manager geometric competition caused continuous jumping/flickering in Linux floating-point UI, combined with GDK input mask intercepting pointer events during active dragging.#

Solution: Design fixed-window benchmarks, dynamically expand the click area only during dragging via RPC, completely bypassing WM resize functions instead of fixing symptom loops.

Key Insight: Platform geometric mismatch is an architectural fault; dynamic interaction boundaries should be driven by state, not staticly bound to component size.

2. Remote operation success threshold accepted physically unstable states, while the data pipeline silently fallback to mismatched dataset paths, and state files (.npz) differed significantly between macOS ARM and Linux x86_64 environments.#

Solution: Replace static coordinate checks with continuous frame stability counters and mandatory physical release verification; completely rewrite the environment registry loader to implement strict failure mechanisms for fingerprint mismatches; treat MuJoCo constraint solver differences as hardware-level floating-point accumulation issues. Key Insight: Floating-point physical simulation requires dynamic physical state verification, not position threshold detection; silent default configurations always destroy data integrity regardless of process completion.

3. Copied Crossformer and LiPM metrics differed significantly from published papers, despite correct architectural implementation, indicating programmed anomalies rather than code defects.#

Solution: Generate diagnostic scripts to simulate unit scaling, loss function changes, and aggregation methods; verify MAE ≤ RMSE relationship under sample-average processes; develop structured technical inquiry templates for direct author verification.

Key Insight: Published academic metrics often violate basic mathematical inequalities or contain unrecorded preprocessing steps; systematic scenario mapping is more effective at identifying methodological flaws than blind re-training.

4. Claude CLI -p mode silently rejected MCP tools with authorization bypass and ignored local project configurations, while default JSON serialization of structlog discarded stdlib extra upper and lower text fields, causing critical robot dialogue logs to be truncated.#

Solution: Inject explicit configuration flags and bypassPermissions mode into the CLI adapter, integrate custom structlog processor to explicitly convert opaque context buckets into final JSON data.

Key Insight: Headless AI agents enforce strict interaction boundaries and require explicit bypass flags; serialization frameworks discard non-native dictionaries unless explicitly merged during process execution.

5. Large model initialization caused subprocess pipeline deadlock and socket timeouts during parallel VLA server startup, causing inference requests to be discarded before warm-up completion.#

Solution: Redirect heavy stdout/stderr to direct file streams, expand connection timeout to accommodate JIT compilation phase, inject explicit warm-up calls before batch cycles, and implement fault-isolation GPU scheduling.

Key Insight: ML infrastructure I/O pipelines must separate connection establishment from computation warm-up; standard buffer limits cannot safely handle kilobyte-level model loading outputs.

General Limitations#

  • Default use of subprocess.PIPE for heavy model loading, generic academic table extraction methods, leading to silent I/O deadlock and dependence on manual data input due to built-in parsing limitations in complex formats.
  • Initially attributed simulation trajectory differences to numerical drift or controller limitations, without verifying environment versions; multiple forced adjustments were required to highlight simulator differences, until it was recognized that cross-architecture floating-point accumulation was the root cause.

Lessons Learned#

Key Experiences#

  • Platform geometric structure mismatches and headless CLI authorization require architectural bypasses and explicit flags, not symmetric patches or default assumptions; dynamic interaction boundaries in X11/GDK architecture must be driven by state.
  • Floating-point physics simulators exhibit hardware-dependent drift; success criteria must use dynamic physical verification, and serialized state files cannot be trusted across OS/CPU architectures, requiring native re-computation.
  • Heavy I/O operations in ML infrastructure (model loading, context transfer) require explicit buffer management, out-of-band logging mechanisms, and JIT-aware socket timeout configurations to prevent initialization deadlock and connection state corruption.
  • Academic metric differences usually stem from unrecorded preprocessing, unit normalization errors, or structural symbol violations, not architectural flaws; hypothesis-driven scenario mapping is more effective at isolating faults than blind re-training.
