Issues and Solutions#

Key Issues#

1. Domain adversarial training on the battery base model caused potential norm collapse to a constant value, destroying information about coding degradation.#

Solution: High-balls constraints inspired by CADT were implemented: the center point of specific bin was initialized, compactness/separation losses were added to enforce geometric structure preservation.

Key Insight: Unconstrained domain adaptation may inadvertently destroy critical geometric structures; clear structural priors are needed during cross-domain alignment to retain hierarchical information.

2. In revalidate_demos.py, quaternion data were incorrectly assigned to the obj_positions dictionary, causing direction loss and position corruption during NPZ parsing.#

Solution: Dictionary key assignment was corrected during iteration, directions and positions were properly separated, and target offsets in the script were used for verification.

Key Insight: Manually written dictionary keys during file parsing easily cause variable name confusion; automated cross-file pattern matching helps detect logical errors early in the refactoring cycle.

3. The batch re-counting script failed to update demo status because the explicit counts_toward_target flag in manifest JSON entries bypassed dynamic strategy evaluation.#

Solution: Logic was added to explicitly remove this explicit flag before calling determine_counts_toward_target, allowing the new only-replay rule to accurately re-evaluate all entries.

Key Insight: If explicit status flags in configuration data are not reset during re-evaluation, they will prevent dynamic calculation indefinitely.

4. AI initially rejected Claude Opus 4.7 due to delayed training data, requiring user intervention and web search to confirm release status.#

Solution: Users requested real-time verification via a search proxy; AI updated guidance and continued migration after model availability was confirmed; Key Insight: Internal knowledge deadline of AI caused delays in confirming new software releases; real-time verification must use tools directly, not rely on static training data.

5. Attempting to automatically terminate long-running GPU training during suggested optimization might cause unrecoverable loss of experimental data without explicit permission.#

Solution: Users enforced a clear authorization protocol for resource-intensive operations; AI adjusted the workflow, delaying kernel-level modifications until after experiment validation.

Key Insight: In scientific computing scenarios, autonomous tools must respect the user-controlled research process, and a preference should be given to explicit authorization over aggressive optimization heuristics.

6. API error 400 occurred when trying to use Opus 4.7 with Bedrock configuration due to implicit override settings by the provider.#

Solution: Bedrock IAM/model override settings hindered consumer API access; all environment variables and specific model strings were systematically removed from CLI settings.

Key Insight: Cloud provider configurations implicitly override local subscription settings; clear cleanup is needed to avoid authentication conflicts.

7. The state machine rejected the conversion because the wrong assumption that checkpointPhase would automatically advance led to invalid conversion errors.#

Solution: Runtime required explicit calls for advancing operations after checkpoints; the execution flow was redesigned, separating phase persistence from state advancement.

Key Insight: Deterministic coordinator separates observation (checkpoint) from variation (advance), preventing race conditions; clear conversion commands are needed in automated scripts.

General Issues#

8. During center initialization and feature extraction, GPU utilization remained at approximately 10% because the Python loop processes one sample each time, ignoring the batch_size configuration.#

Solution: Code for init_centers and extract_and_verify was rewritten using DataLoader-based batch tensors, reducing inference overhead by 50–100 times.

Key Insight: PyTorch DataLoaders must be integrated explicitly throughout the process; default batch configurations only affect the defined training loop when helper functions are not modified.

9. The remote operation replay record warned about missing clean trajectory NPZ files, causing a fallback to direct state loading and skipping visual animations.#

Solution: The injection_replay module was analyzed, confirming that the fallback mechanism can safely load injected states; this behavior is non-blocking and does not affect data accuracy.

Key Insight: Anti-failures should be explicitly classified as non-blocking to avoid unnecessary debugging on harmless warnings.

10. Runtime rejected the worker summary load because additional fields were not defined in the strict worker contract pattern.#

Solution: Keys that do not meet requirements were removed, and the load was rebuilt using only state, target, change, warning, and detail fields that match the coordinator contract.

Key Insight: Strict load validation prevents state leakage between workers, but runtime checks are needed when the default template deviates from the specification schema.

11. ln-014 list uses full description names instead of short codes, causing empty reference errors during runtime registry lookup.#

Solution: The skill field was corrected to fully match the registry key; AI adopted this fix for subsequent sub-runtime that requires precise naming.

Key Insight: Worker dependencies driven by the registry rely on exact string matching rather than human-readable identifiers, making list generation highly sensitive to naming conventions.

Lessons Learned#

Key Experiences#

  • Unconstrained domain adaptation may inadvertently destroy task-critical geometric features; preserving hierarchical information during alignment requires explicit structural priors (such as hyperball constraints), while essential environmental variables must be removed to prevent implicit permission overrides.
  • When migrating validation rules or quota systems, always look for default parameter allocation and configuration fallback schemes; they are common points of inconsistency, and new configurations must be validated using real-time search tools rather than internal knowledge.
  • Cross-agent environment synchronization requires strict adherence to deterministic state machine protocols and precise inventory key mappings; deviations from the registration contract immediately disrupt sub-runtime parsing, requiring manual review of large guidance guidelines before automation.
  • In persistent data structures (such as JSON inventories), explicit state flags may bypass dynamic calculations indefinitely if not explicitly cleared or overridden during the refactoring cycle.

Practical Experiences#
