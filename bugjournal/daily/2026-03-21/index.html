Issues and Solutions#

Key Issues#

1. When calling npx @ccusage/codex@latest from a Python subprocess, it gets suspended indefinitely.#

Solution: Added the –yes flag to the npx call to skip the interactive “Are you sure? (y)” prompt, as capture_output=True in the subprocess execution cannot receive standard input.

Key insight: Subprocess executions with captureOutput=True have no standard input, so any interactive prompt will freeze permanently; always use –yes or -y flags for package managers in automated scripts.

2. Although Codex token usage is collected daily, the monthly summary does not summarize or display it.#

Solution: Added a separate summary path for codex_token_usage in aggregate_token_usage(), created combine_usage_summaries() for merging, and updated format_monthly_markdown() to display the Codex section.

Key insight: When adding a new data source to the summary process, not only must the input parsing be updated, but the summarization logic, LLM input cleaning (removing mechanical fields), and output format also need to be updated.

General Issues#

3. Windows Path().parent produces backslashes, causing problems with rclone remote paths (e.g., ‘gdrive:gadget/website\personal’).#

Solution: Used Path.as_posix() to convert Windows paths to forward slashes for building rclone remote paths.

Key insight: Even on Windows, rclone remote paths must use forward slashes; when constructing remote URI, the Path operation requires explicit.as_posix() conversion.

4. The PowerShell execution policy blocks the npx and codex.ps1 wrapper programs.#

Solution: It is recommended to use .cmd wrapper programs (npx.cmd, codex.cmd) as a temporary solution, and use Set-ExecutionPolicy -Scope CurrentUser RemoteSigned for a permanent fix.

Key insight: On Windows, npm installations create both .cmd and .ps1 wrapper programs; when the PowerShell execution policy is restricted, .cmd wrappers can be used universally, while .ps1 wrappers require policy changes.

5. Git merge conflicts occur after pulling changes from remote.#

Solution: Use git stash, then git pull, and finally resolve the remaining conflicts by accepting the upstream version and discarding the stash.

Key insight: When syncing to remote after local cleanup, accepting the remote version with –theirs is simpler than manually resolving conflicts, especially if local changes are intended to be discarded.

Learning Outcomes#

Key learning points#

  • The captureOutput=True parameter in subprocess.run causes no stdin issue — any interactive prompt will freeze indefinitely; for package managers and other CLI tools in automated processes, always use –yes/–non-interactive flags.
  • When adding new data sources to the aggregation pipeline, (1) input collection, (2) aggregation logic, (3) LLM input cleaning (removing new fields from prompts), and (4) output rendering must all be updated — missing any step will result in data loss.
  • Windows path objects produce backslashes; when building URI or remote paths that require forward slashes (e.g., rclone, URLs, Unix paths), use Path.as_posix() to ensure cross-platform compatibility.
  • The Claude Code plugin architecture consists of 5 layers forming a closed loop: skills (passive knowledge) → agent (professional reasoning) → command (user-facing) → hook (automation trigger) → continuous learning (feedback capture) → skills.

Practical learning points#

  • On Windows, due to limited PowerShell execution policy, commands installed via npm have both .ps1 (blocked) and .cmd (runnable) wrappers; .cmd is a universal alternative.
  • ECC’s effortLevel has 4 levels: low/medium/high/maximum; ‘maximum’ level includes recently added features, allowing up to 31999 thought tokens and the deepest inference capabilities.
