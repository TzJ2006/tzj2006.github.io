Issues and Solutions#

Key Issues#

1. QCVLA: The second round of Dagger only improved by 1 percentage point (60%→61% SR), indicating saturation. The bridge can only see the error distribution it generates naturally, and diversity is limited.#

Solution: Perturbation and bridge data augmentation methods were proposed: during the Dagger propagation process, short action sequences were randomly injected, followed by reverse recovery actions. This captures larger deviations that the bridge never generates naturally, thereby expanding the training distribution range. Both the bridge function (feature prediction for perturbation states) and the action head function (recovery action sequences) are trained simultaneously.

Key Insight: When a model only sees its own error patterns, self-supervised training becomes saturated. Injecting synthetic but realistic deviations (inspired by FLARE’s perturbation strategy) can expand the distribution range. Compared to Gaussian noise per frame, coherent action perturbations are more effective in robot control.

2. VLA Inference: The task is completed, but due to unresetting current_prompt, infinite loops occur, the chunk_count remains non-zero, and the model continues to output high scores.#

Solution: After task completion, current_prompt = "" should be set, and publish_state(“idle”) should be called to prevent immediate triggering in the next round; a None check should be added before task_completed.item() to avoid crashes on non-pi05 models.

Key Insight: The state machine needs to explicitly reset all related variables at each termination node, otherwise unpredictable loops may occur. Multi-device compatibility (pi05 and non-pi05) requires handling boundary conditions in advance.

3. MIHD: The NEEDS_COORDS_FUSIONS tuple appears repeatedly in pipeline/runner.py and pipeline/evaluation_planner.py, and both lack adaln_attention (potential error), making it difficult to maintain consistency when adding new fusion strategies.Solution: Store NEEDS_COORDS_FUSIONS as a constant in models/Fusion.py, which is imported by two files. The missing adln_attention was added to the tuple, fixing the bug where this fusion strategy cannot handle spatial coordinates.#

Key Insight: Constants reused across modules lead to inconsistencies and make maintenance difficult. A single source ensures potential errors are avoided and simplifies maintenance.

4. MIHD: In refine_labels_spatial_majority in utils/clustering.py, scipy.spatial.distance.cdist is used with an memory complexity of O(N²), which causes OOM on Visium HD data when the data size exceeds 17K points.#

Solution: Replace cdist with scipy.spatial.cKDTree.query, which has a complexity of O(N*k) and is suitable for k-nearest neighbor search. Instead of computing the full distance matrix, query radius neighbors as needed.

Key Insight: For large point clouds, tree-based structures (such as KDTree, BallTree) should be used for spatial queries to avoid memory explosion. For high-definition spatial data (10K+ points), algorithm selection is more important than implementation details.

5. During training, combined_action_loss and task_loss were merged into a single value and recorded in wandb, making it impossible to monitor them separately. Solution: The compute_loss function was modified to return a tuple containing (combined_loss, {“action_loss”: …, “task_loss”: …}). The training loop uses the nnxn.value_and_grad() function and sets has_aux=True to parse auxiliary metrics, which are then added to the info dictionary.#

Key Insight: The JAX/Flax has_aux=True mechanism allows graceful extraction of additional monitoring metrics from the loss function without affecting gradient computation. All implementations of compute_loss (pi0 and pi0_fast) need to be synchronized to maintain interface consistency.

6. The error benchmark thread task can only inject collision_empty errors; other types of errors cannot be generated.#

Solution: Analysis revealed that all clean trajectories phase_labels used for threads are ‘pre_reach’, with the grasp/lift/transport stages missing, causing errors dependent on these stages (such as drop_in_transit) to not be injected. The get_task_phase logic or thread task definition needs to be checked.

Key Insight: Error injection depends on the segmentation of task stages. If stage identification is incomplete, certain types of errors may be exposed. All tasks need to be verified during the opportunity graph generation process to ensure they cover the expected stages.

7. gpumon.py counts bash/ffmpeg/claude processes. These processes inherit CUDA_VISIBLE_DEVICES as GPU processes and display DDP worker processes separately, rather than merging them with parent processes.#

Solution: The_get_proc_gpus() function was modified to require both the CUDA_VISIBLE_DEVICES environment variable and the open/dev/nvidia* file descriptor. The get_gpu_procs() function added a parent chain traversal feature to merge child processes with the same GPU set and their ancestors.

Key Insight: Detecting GPU usage in processes requires checking both environment variables inheritance and actual device file descriptors to avoid misjudgment.

8. All 317 RoboCasa tasks encountered errors when downloading MimicGen data. It is unclear whether it is a code issue or a data availability issue.#

Solution: System analysis revealed that 257 tasks did not register mg_path (yellow warning), and 60 tasks had mg_path, but box_links_ds.json contained 0 MimicGen download links (red error). This confirms it is an upstream data release issue, not a code defect.

Key Insight: When all project downloads fail systemically, the data availability should be checked before attempting code fixes. A grep search for ‘/mg/’ in box_links_ds.json found no matches, proving that the download links are indeed missing.

9. The CALVIN RLDS dataset conversion failed with KeyError: ‘image’. The actual field names should be ‘rgb_static’ and ‘rgb_gripper’.#

Solution: features.json was read to confirm the actual pattern, the key name for frame extraction was modified, and the non-existent environment_state and relative_action field definitions were removed from the dataset.

Key Insight: The pattern of source data must be verified before converting the dataset format. RLDS features.json is the authoritative source for determining actual field names.

10. How to implement interactive keyboard navigation in a monitoring tool that requires regular updates, while avoiding input blocking.#

Solution: Use the select.select() function for non-blocking keyboard input detection and set a 0 timeout. Use termios/tty for terminal control in the original mode. Store selected_idx and scroll_offset states for use in different rendering processes. Apply reverse video (\033[7m) for highlighting.

Key Insight: Using select() for non-blocking I/O allows real-time interaction in monitoring tools while maintaining an update interval. The original terminal mode requires careful management of states to capture arrow keys without echoing.

Limitations of Artificial Intelligence#

Key Limitations#

  • It is impossible to directly determine the root cause of why there is only a pre_reach stage in the thread task; further analysis of the get_task_completion_stages implementation is needed.
  • It is impossible to directly run code to verify the fix; error fixes require waiting for user feedback, which introduces risk (for example, the loss separation function needs actual training to confirm whether wandb display is correct).
  • Dataset key names require multiple attempts to determine; the initial attempt using ‘image’ failed, and then features.json revealed ‘rgb_static’, making it impossible to infer accurately at once.

General Limitations- During the RoboCasa diagnosis process, artificial intelligence extensively explores the code logic before examining the data file (box_links_ds.json). A more effective approach is to verify data availability early on, as download failures are usually due to missing data rather than code errors.#

  • The understanding of the project’s historical background is limited, and it needs to be gradually gained through git logs and documentation (e.g., the background of the recent commit c2c998a). It is not possible to quickly locate issues like human engineers familiar with the project.
  • Passwords cannot be entered interactively in the terminal; users must manually execute ssh-copy-id to set up the initial SSH key, after which automated operations can continue.
  • The user rejected three parallel Agent tool calls for code review, possibly due to large differences (33K lines) or long waiting times caused by permission settings. It is not possible to diagnose the reason for the rejection or adjust the strategy in real time.
  • When users only want the.md file rather than code changes, multiple ExitPlanMode attempts are rejected. It is not until the issues are clearly corrected that the user’s preference for analyzing outputs only is recognized — large-scale code refactoring should use parallel multi-agent multi-dimensional review (reusability, quality, efficiency) to systematically identify issues. This method identified 9 issues, including potential errors, performance bottlenecks, and maintainability problems that a single review cannot detect.
  • When Dagger-style training reaches saturation, the data distribution should be expanded through structured perturbations (coherent action sequences and recovery) rather than frame-by-frame noise. In robot control, temporal coherence is very important — physical rules and inertia make continuous perturbations more realistic than independent identically distributed noise.
  • The state machine implementation must explicitly reset all related variables at each termination node; the implicit assumption that “the next cycle will naturally change” can lead to unpredictable behavior, such as infinite loops.
  • Code review should be proactive rather than passive; even if the user only asks “how to implement it,” they should also be asked “are there any issues?” Proactively identifying potential errors is more valuable than users fixing them after encountering problems.
  • Cross-project technology transfer requires distinguishing between “direct application” and “conceptually adaptable” differences. The transfer from FLARE to QCVLA is mainly conceptual (perturbation thinking, expert mixing), not at the code level, because FLARE focuses on strategy robustness, while QCVLA focuses on feature prediction efficiency.
  • A tree structure must be used when performing spatial queries on large point clouds (more than 10K points). An O(N²) distance matrix leads to memory overflow. cKDTree’s neighbor query complexity is O(N*k), making it suitable for high-dimensional space-genome data.
  • The JAX/Flax function value_and_grad(…, has_aux=True) can gracefully return additional monitoring metrics from the loss function without affecting gradient computation, which is the standard pattern for multi-metric monitoring.
  • The quality of error injection benchmark tests depends on the completeness of task phase segmentation; incomplete phase identification causes some error types to be hidden, and all tasks need to be verified in the opportunity graph phase to ensure they cover the expected phases.
  • Monitoring GPU usage in the detection process requires checking both environment variable inheritance and actual device file descriptors to avoid false positives caused by shell processes.
  • Diagnosis of download failures should adopt a data-first approach: when systematic failures occur, verify data availability before deeply analyzing code logic (searching for expected patterns in the configuration file).
  • Dataset format conversion must read pattern files (such as RLDS features.json) to confirm actual field names, and then assume common conventions or guess.
  • Non-blocking terminal I/O mode: using select.select() with a timeout of 0, combined with the original mode and state persistence of termios, can implement interactive functions in real-time monitoring tools without sacrificing refresh rate.
  • Parent process chain traversal effectively removes duplicate layers of process structures (DDP workers, PyTorch sub-processes) in monitoring tools. When the GPU settings match, sub-processes can be folded into the parent process.
