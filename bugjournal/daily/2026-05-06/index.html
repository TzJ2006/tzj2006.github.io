Issues and Solutions#

Key Issues#

1. FloatBall cannot display codex/cursor rate limiting utilization, although the main window shows it correctly#

Solution: Removed the is_window_expired() filtering mechanism from primary_window_utilization, changed the logic from selecting the main window ID to selecting the window with the highest utilization across all windows, regardless of type or expiration status, and synchronized the use of Math.max() strategy on the front end.

Key insight: The expired window filter in the tray logic is too aggressive for idle sessions; FloatBall should always display the most critical limit (highest utilization) so users can recognize the most urgent constraint issues.

2. Repository structure is messy, containing over 90 scripts, many of which are special cases for specific GPUs or experiments#

Solution: Classified scripts systematically by pipeline stage and purpose, removed about 40 redundant variants (specific GPU launchers, one-time debugging scripts, SLURM wrappers), and retained only the core entry scripts that define reproducible pipelines.

Key insight: The research codebase accumulates many experimental scripts over time; public release requires active simplification, keeping only the specification execution paths that define reproducible benchmarks.

3. Paper mentions “frame stage labels” but does not explain their source or necessity#

Solution: Humans questioned its source, and it was found that if can_inject() directly uses physical state conditions, stage labels may be unnecessary, avoiding claims of unimplemented features.

Key insight: Every technical term in academic papers needs clear definition and verification to avoid reviewer questions; before spreading dependency relationships across chapters, confirm whether they are actually used.

4. SSH synchronization takes too long after adopting two-stage progress feedback#

Solution: Eliminated duplicate SSH connections by removing independent test stages; sync_ssh_host already includes internal connection tests, so a single iteration with gradual UI updates can achieve the same user experience without additional performance overhead.

Key insight: Overly aggressive optimization may introduce new bottlenecks. Before adding wrapper logic, ensure that downstream functions provide the required functionality.

5. AI modified the wrong file (replaced neurips_2026_zgl.tex with neurips_2026_tzj.tex), requiring full rollback for about 30 edits.Solution: Manually rolled back all changes by restoring the placeholder values, then re-applied edits to correct the file.#

Key insight: The file goal must be confirmed before batch editing; lack of a git repository makes rollback work tedious and error-prone.

6. The coverage of stage 3 in RBG C/D/E matches the injection stage in Table 2 but is inconsistent#

Solution: Detailed comparison shows C lacks pre_reach/pre_grasp, D incorrectly includes pre_reach, and E lacks reach/pre_grasp/grasp/lift stages.

Key insight: Visual summaries must be generated automatically from detailed tables to avoid manual drawing inconsistencies; charts and tables must maintain strict bidirectional consistency.

7. The v3 version created by users reverts BibTeX changes back to manual references format#

Solution: Explained the difference and provided suggestions for re-applying BibTeX format, but respected the user’s choice to keep manual format during drafting.

Key insight: Authors may prefer manual references during collaborative drafting due to workflow reasons (easier to share, no need for BibTeX toolchain dependence, simpler merging); formalization can be done after final submission.

8. Uncertainty about repository structure (local 3-part reorganization vs. single server directory structure)#

Solution: User decided to use the server’s authoritative structure (error_benchmark/single directory), and re-synced from the server to abandon local reorganization.

Key insight: When multiple versions exist, clarify which one is the authoritative version before making modifications; avoid speculative reorganization without confirming the actual source.

General Issues#

9. Unable to use rsync command on Windows to sync files from Linux server#

Solution: Used ssh + tar pipeline: ssh tianhe ’tar cf - –exclude=pattern files’ | tar xf - to achieve selective file transfer with exclusion patterns.

Key insight: Windows lacks many Linux tools, but ssh + tar provides a similar remote file synchronization function with selective exclusion.

10. “Sub-module already exists in index” error occurs when trying to add submodules after re-synchronization#

Solution: Used git rm -rf –cached to clear cache entries, deleted .git/modules/shared directory, and then added submodules cleanly.

Key insight: Git sub-modules are recorded both in the index and .git/modules/; both need cleaning to restart.

11. Complex regular expressions fail when grep searches LaTeX citation commands#

Solution: Simplified to a basic pattern ‘\cite{’, instead of trying to capture groups with escaped braces.

Key insight: ripgrep (rg)’s regex syntax differs from standard grep—a simpler pattern is more reliable in LaTeX escaping scenarios.

Lessons Learned#

Key Experiences#

  • The rate limit of expired window filtering should be a presentation-level issue (UI underline/color), not a data-level filter; filtering at the source would deprive users of the ability to view the full state and make informed decisions.
  • When the UI displays a single value in multi-window data (FloatBall bar), choosing the maximum utilization provides better user experience than any window selection, as it highlights the most critical constraint.
  • NeurIPS 2026 renamed the “Datasets and Benchmarks” track to “Evaluation and Datasets” (E&D) track, and introduced new mandatory requirements for Croissant metadata (JSON-LD format) describing dataset structure and RAI fields.
  • Academic paper writing requires claims to strictly match reality; terms such as “extended,” “proposed,” and “novel” carry specific expectations of proof, thus distinguishing application from contribution.
  • Double-blind submission anonymization requires checking not only author names but also: usernames in paths (pytest output), hard-coded server paths, institutional names (abbreviated and full names), and any language that exposes geographic identity.
  • For publication, cleaning up research code needs distinction between: (1) the core entry script defining reproducible processes; (2) convenient wrappers for specific hardware; (3) one-off experiment scripts—only the first category should be published.
  • When filling template data, always verify cross-references: if Figure X claims to show Y, mechanically verify that Y is presented in Figure X and the value is correct; visual summaries must be derived from detailed tables.
  • Academic paper workflows usually prefer simpler reference management during drafting—manual references allow easier collaboration without dependency on BibTeX toolchain; formalization can be done after final submission.
  • Version comparison reveals user intentions: when users independently rollback changes, it indicates preference or constraint rather than negligence—ask for reasons to understand workflow needs.
  • For complex data-driven papers, maintaining a single real data file (e.g., per_subtype_results.csv) can ensure consistency across tables, figures, and narratives in all chapters.
  • Tauri IPC commands expose backend data structures (StatusWidgetSummary), causing tight coupling; changing the meaning of “main” requires coordination between backend and frontend changes and comprehensive testing updates.

Practical Experience#

  • Git submodules are stored in three places: .gitmodules (configuration), .git/modules/ (repository data), and work tree (checkout); conflicts need to be cleaned up in all three locations.
  • Reference research workflow: for robotics/machine learning papers, arXiv ID is the most reliable identifier; conference papers may be published months later than preprints.
  • Windows does not have rsync, but ssh + tar pipe can achieve a similar function: ssh remote execution “tar cf - –exclude=pattern files” | tar xf - provides selective transmission with exclusions.
  • Svelte 5 CSS scope settings need to be copied explicitly in subcomponents or :global() wrappers to reorganize component hierarchy; parent styles do not cascade into subcomponents.
