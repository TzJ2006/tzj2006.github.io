Issues and Solutions#

Key Issues#

1. CalendarPro robot cannot understand subsequent messages, such as “What time did you schedule?”Solution: Identified three layers of problems: (1) General keyword pre-checking occurs before the AI sees dialogue history; (2) The pre-check uses overly broad keywords like “What time is it now”; (3) Historical data parameters are not passed in provider calls. The designed fix removes pre-check bypass behavior and passes the complete dialogue history to the AI.#

Key Insight: Context loss is usually a multi-layer issue: data not collected → data not passed → data not used. One must trace the entire call chain from storage, through provider interfaces, to prompt construction.

2. SAPIEN encounters “rendering error” in headless Docker container — RuntimeError: Could not find rendering device#

Solution: Found that the NVIDIA Vulkan/OpenGL rendering library (libGLX_nvidia.so, etc.) is missing. The container has CUDA computation libraries but no rendering stack. Downloaded matching NVIDIA driver version 535.104.12 to match the kernel driver, extracted the library into the user directory, and configured VK_ICD_FILENAMES and LD_LIBRARY_PATH environment variables in eval.sh.

Key Insight: Docker containers with NVIDIA GPU require CUDA runtime and Vulkan/OpenGL libraries for graphical simulation. The driver version must fully match both the kernel module and user-space libraries; otherwise, Vulkan ICD cannot be loaded.

3. Phoenix training checkpoints exist in zhaoganlong’s directory; unclear whether they should be reused or retrained#

Solution: Users suggested checking existing checkpoints and creating symbolic links if available, training the missing parts only on the free GPU of an53.

Key Insight: Before designing the training plan, one must inventory existing resources (checkpoints, datasets, configurations) to avoid wasting computational resources. First establish a checkpoint reuse strategy.

4. Users believe standardized data comes from STHD workflow, but data characteristics do not match the workflow code#

Solution: Code analysis revealed that STHD does not perform standardization—it uses raw counts directly. The standardized data users see comes from external scanpy preprocessing (normalize_total + log1p).

Key Insight: It is necessary to distinguish internal workflow processing from external preprocessing. Code inspection is more reliable than assumptions based on data appearance.

General Issues#

5. Missing pre-training configurations for 3 of the 9 MimicGen tasks in OpenPI configuration#

Solution: Used add_finetune_config and add_inference_config helper functions to add fine-tuning and inference configurations for coffee_task_D1, stack_three_task_D1, and three_piece_assembly_task_D1.

Key Insight: Use configuration generation functions to maintain consistency in task configurations instead of manual copying.

6. FrozenInstanceError: Unable to assign values to the field ‘asset_id’ in policy_config.py#

Solution: DataConfig was defined as @dataclasses.dataclass(frozen=True), making it unchangeable. Used dataclasses.replace(data_config, asset_id=value) to replace direct assignment (data_config.asset_id = value), creating a new instance.

Key Insight: Frozen data classes enforce immutability at the language level—modifications require using dataclasses.replace() to create a new instance, rather than modifying in place.

7. FileNotFoundError, path duplication: assets/norm_stats.json/norm_stats.json#

Solution: When providing robotwin_repo_id, asset_id was incorrectly set to ’norm_stats.json’ (file name instead of directory). The modified code directly uses normalize.load() from the assets/ directory to load data, without adding the asset_id subdirectory.

Key Insight: Path construction errors usually occur due to mixing directory identifiers with file names. Explicitly handling special cases (local files and remote repositories) can prevent path duplication.

8. MulticoreTSNE build failed due to incompatible CMake version (system 3.26.4 is incompatible with required version <= 3.18)#

Solution: Found that MulticoreTSNE is only used for optional TSNE visualization, not core training/ evaluation. Suggested disabling dependencies to allow continued installation (user refused this approach).

Key Insight: It is necessary to distinguish critical dependencies from optional visualization tools. In research code, skipping non-essential dependencies that cause build issues is usually feasible.

Lessons Learned#

Key Experiences#

  • Context loss requires tracking the complete call chain: data collection (conversation_history.json storage) → data transfer (provider call signature) → data usage (prompt construction). Missing any layer leads to context loss.
  • Before designing a training plan, existing resources should be counted (checkpoints, datasets, configurations) and reuse strategies established to avoid wasting computational resources. Ask “what exists?” before “what should be built?”
  • Running Docker containers for NVIDIA GPU work requires two different library sets: CUDA runtime (computation) and Vulkan/OpenGL (rendering). Many GPU-supported containers only have CUDA. For simulation frameworks like SAPIEN, the graphics API must be used, so both libraries must match the kernel driver exactly.
  • In spatial transcriptomics data processing, adata.X can be a normalized value (scanpy pipeline) or raw counts (STHD pipeline)—code must be checked instead of assuming the data type based on context.
  • Parallel multi-agent exploration can speed up understanding of complex codebases, but careful planning is needed to avoid redundant work. Use agents for independent dimensions (history management, message flow, provider interfaces) to avoid overlap.
  • Two-stage data collection (seed discovery + deterministic replay) is a robust pattern in robot simulation: the first stage filters data that successfully completes tasks and saves the trajectory plan, the second stage uses the saved plan to re-execute and collect clean training data. This separates randomness from data quality.
  • Dependency sharing via symbolic links can significantly reduce disk usage in large research projects (from 78GB to 37MB) while maintaining independent project structures. The key is using symbolic-linked data directories instead of copying, and using relative paths for portability.
  • Core principle of documentation optimization: remove content that can be obtained otherwise (e.g., ‘make help’ for commands), and keep “global” insights that require cross-file understanding.
  • Discovery of Vulkan ICD (installable client driver) requires the existence of nvidia_icd.json list and actual driver library, along with version matching. The VK_ICD_FILENAMES environment variable can override system search paths in containerized environments.

Practical Experiences#

  • Python frozen data classes provide guaranteed runtime invariance, but explicit modification via dataclasses.replace() is required. Direct assignment triggers FrozenInstanceError. This pattern forces configuration objects to adopt functional programming style.
