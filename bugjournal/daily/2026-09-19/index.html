Problems & Solutions#

Critical Issues#

1. W4A4 quantization leads to 0% success in ‘middle-drawer’ tasks (misidentifying targets).#

Solution: Isolated 35 RMSNorm output tensors and applied AIMET’s TF-Enhanced range setting to mitigate noise from outliers.

Key Insight: The failure was caused by min-max quantization ranges being stretched by outliers in uniformly distributed activation tensors, injecting ~10% noise per layer.

2. NVML/GPU invisibility error and Training/Test mismatch.#

Solution: Cleared orphaned processes to recover GPU access; restarted training from scratch to ensure policy learns new bottom-right/scene-anchored distributions.

3. Gemini’s visual prompts/scoring were inconsistent (early counting, incorrect identity tracking).#

Solution: Shifted priority from fixing Gemini’s errors to using a ground-truth ‘Oracle’ system to generate perfect visual prompts for training the robot.

Key Insight: The ‘Target Hit Rate’ is a dangerous metric for memory tasks as it conflates object detection with actual memory of history.

4. Ambiguity regarding $\pi$0.5 training methodology (LoRA vs Full Fine-tuning).#

Solution: Inspected code to confirm full-parameter fine-tuning of the LLM and action expert while keeping the SigLIP visual tower frozen.

General Issues#

5. Visual elements (icons/badges) were being cut off by robot random cropping/rotation.#

Solution: Moved coordinates from (3,3) to (16,16)/(26,26) to ensure visibility under 95% random crop scenarios.

Key Insight: Visual prompts must be ’training-robust’ to survive augmentation.

6. Evaluation script left orphan server processes consuming ~230GB VRAM.#

Solution: Modified cleanup logic to terminate the entire process tree/PIDs to ensure GPU recovery.

Key Insight: Standard process termination often fails to clean up child processes in complex environments.

Learnings#

Key Learnings#

  • Task complexity does not correlate with quantization sensitivity; tasks requiring fine-grained selection between similar targets (middle vs. top drawer) are most vulnerable to noise.
  • The $\pi$0.5 baseline for RoboMME freezes the SigLIP visual tower and performs full-parameter updates on the LLM and action expert.
  • Visual prompts must prioritize ’training-robustness’ (surviving crop/rotate) and ‘policy-utility’ (scene-anchored vs. corner glyphs) over aesthetics.
  • The ‘Target Hit Rate’ is a dangerous metric for memory tasks: it conflates ‘knowing what to look at’ with ‘remembering what happened’.
