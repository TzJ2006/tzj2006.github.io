Problems & Solutions#

Critical Issues#

1. Tauri’s set_position() is completely ignored by the synthesizer on Linux/Wayland, causing the window to appear in the center of the screen#

Solution: Detect WAYLAND_DISPLAY environment variable at the run() entry, and force GDK_BACKEND=x11 if in a Wayland session, allowing the application to run through XWayland.

Key Insight: The Wayland protocol design prohibits client-controlled absolute window position; any retry strategy is ineffective; must revert to the X11 protocol layer.

2. The floating ball expansion layout uses the screen boundary rather than the ball’s position as the anchor, causing visual displacement after clicking expansion#

Solution: Change expanded_rect_from_ball to ball-anchored mode: x = ball_rect.x when Left is anchored, x = ball_rect.right - expanded_width when Right is anchored, with clamped_y to maintain y stability.

Key Insight: The reference point for expanding windows should be the ball’s position itself, not the screen border, to ensure consistent visual position before and after expansion.

3. host_cache_dir() in ssh_remote.rs uses assert!() to panic and crash the entire program when path validation fails#

Solution: Change the function signature to Result<PathBuf, String>, propagate all calls via Result, and use unwrap_or_default() at the call point.

Key Insight: assert!() is equivalent to a time bomb in production; errors on external input paths must be propagated using Result.

4. After setting GTK resizable(false) for Linux windows, programmingmatic set_size() is rejected by the WM, preventing the floating ball from collapsing#

Solution: In the Linux branch, set_resizable(true) temporarily to unlock before set_size, and set_resizable(false) to lock back after the operation.

Key Insight: The WM hint resizable(false) blocks both user drag and programmingmatic calls, not limited to user interactions.

5. FloatBallState does not store window geometry; reading outer_position/outer_size from the WM each time causes outdated values during expansion/collapse, leading to layout errors#

Solution: Add FloatBallState.last_rect, create an apply_and_store_rect helper function to synchronize window and state writing; add a get_float_ball_position command for front-end use.

Key Insight: The application layer maintains authoritative geometry status, completely bypassing the WM reading timing uncertainty.

6. sync_ssh_host holds a RwLock read lock while waiting for SSH I/O across several seconds, blocking all readers#

Solution: Add #[derive(Clone)] to SshCacheManager, clone the manager before await, and release the lock in advance.

Key Insight: Lock crossing asynchronous boundaries is a common risk in Rust asynchronous programming;The solution is to clone the required data before await.

7. The provider parameter is not validated, which can be used for path traversal attacks (e.g., passing '../../../etc' to construct a malicious path).Solution: Add a whitelist function validate_provider() to only allow ‘claude’ and ‘codex’; return Err for other values.#

Key Insight: Any user input that is a path to a file path must be validated as a whitelist at the system boundary; a whitelist is more reliable than a blacklist.

8. load_cached_records silently returns an empty Vec for all I/O errors (including permission denied), hiding the real error.#

Solution: Change it to return a Result, clearly distinguishing ErrorKind::NotFound (legal, returning Ok(vec![])) from other I/O errors (returning Err).

Key Insight: The absence of a file and inability to read are fundamentally different states; mixing them up makes debugging extremely difficult.

9. ssh_command is considered successful when SSH exits with a non-zero code but some stdout is available, accepting error results.#

Solution: Strictly check the exit code first; accept stdout only when success() is true; record stderr to the log when the exit code is non-zero.

Key Insight: partial stdout + non-zero exit is a common pattern for SSH errors; one cannot use the presence of stdout as a criterion for success.

10. In Svelte 5 components, both onMount and $effect are used to trigger data requests, leading to double requests during mounting.#

Solution: Remove the onMount call and keep $effect (which is executed once automatically during mounting in Svelte 5).

Key Insight: The $effect in Svelte 5 is different from the reactive statements in Svelte 4; it executes immediately during mounting and does not require onMount.

11. In the onMount of the FloatBall component, there is a race condition when asynchronously registering Tauri event listeners: the component may be destroyed before listen() resolves, causing the cleanup function not to be called and leading to memory leaks.#

Solution: Introduce a destroyed boolean flag; if the component has been marked as destroyed when the Promise resolves, immediately call unlisten().

Key Insight: All asynchronous patterns for obtaining cleanup handles in front-end components need to consider the scenario that “the component lives shorter than the Promise”.

Learnings#

Key Learnings#

  • The Wayland synthesizer prohibits clients from setting absolute window positions at the protocol level; any retry strategy for set_position() is ineffective; the correct solution is to detect WAYLAND_DISPLAY and force a return to XWayland by setting GDK_BACKEND=x11.
  • In Rust production code, assert!() and unwrap() are potential crash points on paths that accept external inputs (file paths, user parameters, SSH output); a unified pattern is to change the function signature to Result and use ? for propagation; use unwrap_or_default() at the call boundary.
  • GTK’s resizable(false) WM hint prevents both user dragging and programming-based set_size(); for transparent floating windows that need dynamic size adjustment, resizable must be temporarily unlocked before resize.
  • The geometric state of transparent overlay windows should be managed by the application layer (via last_rect) rather than re-read from the WM each time; outer_position/outer_size in the WM may have temporal delays after resize, and reading outdated values during expand/collapse timing can cause layout errors.
  • The layout of floating windows should be based on the ball itself (ball-anchored) rather than the screen safe zone boundary to ensure consistent visual position before and after expansion, and avoid user perception of jumping.
  • In Rust asynchronous code, locks across await points are potential performance/deadlock risks; the solution is to Clone or Arc::clone the required data before await to release the lock in advance.
  • Any user input that is a path to a file must be validated as a whitelist at the system boundary; a “only allow known values” policy is more reliable than “reject dangerous characters”, effectively preventing path traversal attacks.
  • In Svelte 5, $effect is executed once automatically during component mounting, which, when used together with onMount, leads to double requests; when front-end components asynchronously obtain cleanup handles, a destroyed flag should be introduced to handle the race scenario where “the component lives shorter than the Promise”.

Practical Learnings#

  • git reset --soft <base> is an efficient way to organize commit history: it does not require interactive rebase and can compress any number of commits into a single semantic commit, suitable for CI environments and automated tools.
  • After adding a new directory structure in rclone sync configuration, these directories are not automatically created if no data has ever been pushed to the remote; when pulling, it is necessary to distinguish between “remote does not exist” (normal, treated as success) and “pull failure” (error) to avoid false reports.
