Problems & Solutions#

Critical Issues#

1. extract_teddy() used a non-existent Tokenizer class and incorrect model API (input_ids, last_hidden_state), making the script completely unrunnable.#

Solution: By reading the Teddy source code, the correct APIs were confirmed: GeneTokenizer, gene_ids parameters, outputs['cell_emb'] output key, and added Ensembl ID mapping.

Key Insight: The TEDDY vocabulary uses Ensembl IDs instead of gene symbols, and the model forward signature differs from the HuggingFace standard interface; direct source code reading is required rather than relying on conventions.

General Issues#

2. GPU OOM (32GB VRAM) occurs when batch_size=32 because each sequence has up to 2048 tokens.#

Solution: Reduced batch_size from 32 to 8, allowing controlled memory usage.

Key Insight: Rank-value encoding retains the top 2048 genes as token sequences, making the sequence longer than those in scGPT and requiring higher VRAM.

3. Claude cannot recall the conversation history from the previous Teddy test.#

Solution: The user provided the arXiv link again, and Claude re-analyzed the paper.

Key Insight: Persistent memory across sessions is not properly saved, leading to context loss; active memory saving is needed at key research milestones.

Learnings#

Key Learnings#

  • TEDDY-G outperforms TEDDY-X (rank-value encoding is better than binned expression), and performs 8% higher on held-out donor multi-class tasks than Nicheformer, but competes with Nicheformer in held-out disease binary tasks; linear probe is far superior to fine-tuning (RA: 0.56→0.93) indicating high embedding quality but overfitting risk from fine-tuning.
  • Significant differences exist between single-cell base models in the HuggingFace ecosystem (TEDDY, scGPT, etc.) in their forward interfaces; standard HuggingFace interfaces cannot be assumed, and source code must be read to confirm gene_ids parameter names and output dictionary structure.

Practical Learnings#

  • TEDDY vocabulary uses Ensembl IDs (43808 tokens); 60% of genes (20044/33538) in the DLPFC dataset can be mapped to the vocabulary, with the rest being non-protein-coding genes like lncRNAs — this is normal coverage.
