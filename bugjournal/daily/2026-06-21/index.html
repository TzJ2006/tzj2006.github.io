Problems & Solutions#

Critical Issues#

1. Daily export was silently skipping sync because rclone binary was missing and config lacked the path, causing silent returns in _rclone_upload; Recovery model showed 0/1000 success due to incorrect normalization statistics loading.#

Solution: Downloaded static rclone binary to ~/.local/bin/ and updated config; fixed VLA server norm_stats by setting PI05_POLICY_DATASET_SUFFIX=merged_recovery_v2.

Key Insight: Silent failures in CLI tools often stem from missing environment variables or binaries; checkpoint validation requires specific environment variables matching the training dataset suffix, not just the checkpoint path.

2. /ccdiscuss produced an ECL with aligned intent but no executable functions: DAG, blocking /ccedit execution; Initial DAG visualization interpretation was inverted (milestone vs layer); Translator pipeline experienced silent slowdown on Windows due to NVIDIA driver system memory fallback.#

Solution: Manually authored the functions: section and created verify-dag.ts; user corrected via specific feedback on layer summaries; added torch.cuda.set_per_process_memory_fraction(0.9) and token-budget batching.

Key Insight: ECL format distinguishes between semantic alignment and executable plans; ambiguous requirements like ’tech tree’ require human-defined structure first; Windows WDDM drivers mask OOM by using shared RAM, trapping error-handling logic based on exception catching.

General Issues#

3. verify-dag.ts failed with ‘Top-level await’ error under tsx cjs transform.#

Solution: Wrapped the script entry point in an async function and called it explicitly.

Key Insight: Node.js/tsx environment compatibility issues often arise from ESM/CJS module resolution differences; always test verification scripts directly before relying on them.

AI Limitations#

Critical Limitations#

  • AI initially misinterpreted high-level pagination structures (layer vs. node) and over-relied on standard PyTorch OOM handling, missing Windows-specific driver behaviors that suppress exceptions in favor of memory swapping.

General Limitations#

  • The /ccdiscuss workflow outputted a planning ECL lacking the schema required by /ccedit; initial DAG sync attempts struggled to parse new context, requiring multiple tool calls.

Learnings#

Key Learnings#

  • When using structured development workflows (like ECL), ensure planning output includes executable tasks if downstream tools require them; for complex visualizations, having the human define the structure before implementation prevents significant rework.
  • On Windows with NVIDIA drivers, always consider system memory fallback as a cause for unexplained latency; enforce hard VRAM limits. M16 success was proven via Fisher exact test (p=1.2e-12), confirming recovery efficacy.
