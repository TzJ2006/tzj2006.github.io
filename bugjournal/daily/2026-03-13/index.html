Issues and Solutions#

Key Issues#

1. When Haiku repair fails, JSON parsing crashes, causing loss of original LLM response and inability to debug.#

Solution: A cascading repair chain (Haiku→Sonnet→Opus) was implemented; _try_parse_json helper function was used to avoid recursion, and failed responses were saved to output/logs/json_repair_failed/.txt for debugging.

Key insight: When using LLM-based repairs, pure parsing logic (_try_parse_json) and repair logic (parse_json_response) must be separated so the original output can be retained in case of total failure.

2. ArXiv only returns the last 100 papers, while Semantic Scholar has 500 papers with citation data, but the merging logic discards S2 papers without ArXiv matches, causing most historically high-impact works to be lost.#

Solution: The priority of data sources was reversed: S2 became the primary source (with year/citation/journal/abstract), ArXiv was supplemented via arxiv_id/pdf_url/categories, and then the lone ArXiv paper was added. As a result, a comprehensive Timeline coverage was achieved.

Key insight: When merging datasets with different biases (ArXiv = latest, S2 = comprehensive), the more complete data source should be used as the basis, and information should be supplemented from professional sources, not the other way around.

3. Papers sorted only by citation count lose time research trajectories, making it impossible to understand changes in researchers’ research focus at different career stages.#

Solution: Year-level grouping was implemented: papers were grouped by year and ranked by award weight and citation count within the year; ≤10 works per year were selected, and they were presented chronologically. While preserving the narrative of works, the best works from each period were highlighted.

Key insight: For longitudinal analysis, the time structure is often more valuable than global rankings; stratifying by year allows both dimensions to be considered simultaneously.

4. Collected data contain negative manip_progress_distance_left/right values and values greater than 1.#

Solution: np.clip(progress_dist, 0.0, 1.0) was applied to limit left/right progress distances within the valid [0,1] range.

Key insight: Curved robot trajectories may cause the current EE position to temporarily exceed the distance from start to target during interpolation, breaking the assumption of 1 - |current-final|/|start-final|. For progress metrics, setting clear boundaries is necessary.

5. ArXiv and Semantic Scholar APIs cannot provide award data (best paper, highlight, etc.), but this is crucial for identifying breakthrough works.#

Solution: Users suggested using LLM training data: paper titles and conference locations were sent to the LLM to recall known awards. This approach was implemented as a new analysis stage with a separate caching mechanism.

Key insight: LLMs can serve as auxiliary knowledge bases to obtain data that APIs cannot provide, especially well-known but unstructured metadata such as conference awards.

6. Even after removing the override method, critical_region still appears in HDF5 files.#

Solution: Analysis of base class base_task.py:510 revealed that get_obs() unconditionally writes pkl_dic[‘critical_region’]. A post-processing step was added to remove this key from the repaired pickle file.

Key insight: Removing the override only changes the return value; the path of the base class code must be tracked to ensure the key is truly removed from the output. Post-processing the pickle file before conversion to HDF5 can effectively remove unnecessary keys.

Common Issues#

7. Log message ‘[S2] 获取论文: 1736651’ is ambiguous — it seems that 173,300 papers were obtained, but actually it is the author ID. Users immediately identified this issue.#

Solution: It was changed to ‘[S2] 获取作者1736651的论文…’ and ‘[S2] 作者1736651: 获取到500篇论文’. A clear subject-verb-object structure eliminated ambiguity.

Key insight: Log messages must be clear even when read in irrelevant contexts. Numbers should always have a clear label to indicate their semantic type.

8. Detailed mode only downloads the top 10 most cited papers, but after year-level grouping, there are already ≤10 papers per year — all papers should be analyzed in detailed mode.#

Solution: The ‘sorted(…, reverse=True)[:10]’ filter was removed, and ‘papers_for_download = [p for p in papers if p.arxiv_id]’ was used. Now all filtered papers’ full texts are downloaded.

Key insight: When quality thresholds are enforced upstream by selection logic, downstream should not use different standards for re-filtering — this leads to inconsistency between modes.

Limitations of Artificial Intelligence#

Key Limitation – Using a smaller dataset (ArXiv 100 latest) as the base for merging, rather than a comprehensive dataset (S2 500 historical data), emphasizes algorithm simplicity over semantic completeness in trajectory analysis#

  • Static code analysis is insufficient to track data flow: Claude removed the coverage method for get_critical_region_label(), but cannot track the unconditional writing of pkl_dic[‘critical_region’] by the base class get_obs(), requiring user testing at runtime to detect this issue.
  • The traditional data pipeline approach (API extraction, structured datasets) was initially used to obtain award information, ignoring the fact that LLMs already “know” the awards of famous conferences from training data.
  • A single-stage LLM fix mechanism was implemented (only for haiku), rather than a multi-stage upgrade mechanism, treating error recovery as a binary issue rather than a progressive cost-benefit issue.
  • Lack of physical reasoning about edge cases: no expectation was made that curved robot trajectories may cause progress_distance to exceed [0,1], so geometric constraints of the trajectory were not considered in the formula implementation.
  • Over-reliance on method inheritance logic: it was assumed that removing the coverage method would remove variables from the output, but all code paths that write data structures were not verified. Experience testing is needed to discover the unconditional writing behavior of the base class.

General Limitations#

  • Failure to anticipate ambiguity in log messages: the string ‘[S2] Get paper: 1736651’ was written, but the ambiguity of naked numbers for readers was not considered. Users need to correct it to make the subject-verb-object structure clearer.
  • No active verification that the paper selection logic in the detailed mode matches the annual stratification selection — allowing a upper limit of ≤10 years, but downloading summaries of the top ten globally is inconsistent.

Learning Outcomes#

Key Learning Points#

  • For researcher trajectory analysis, maintaining the time structure (annual stratification sampling) is more valuable than global citation rankings. This indicates that sampling strategies specific to a particular field are more important than the general “sort by metric” approach.
  • For the post-processing method of “future dependency” variables: when each frame variable needs to understand the state of move(), it is usually recorded that the frame number was taken, and then the pickle file is repaired after move() is completed. This is simpler than using a complex state machine during frame capture.
  • LLMs can serve as a knowledge base for unstructured metadata (conference awards, paper reputations) when APIs cannot provide this information. This “LLM as auxiliary database” pattern has not been fully utilized yet — prompt design skills are needed, but no additional infrastructure is required.
  • When implementing LLM-based fixes in recursive parsing logic, the non-LLM stage must be extracted to avoid infinite loops. The pattern is: _try_parse (pure) and parse_response (with fix).
  • Merging multi-source data: when sources have different biases (latestness and comprehensiveness), the most complete data should be used as the base, and supplemented from professional fields. ArXiv = latest, S2 = historical → S2 as base, ArXiv for supplementation.
  • Error recovery should implement a cost-increasing upgrade mechanism (cheap model → expensive model → manual intervention via logs), rather than binary failure/success. This maximizes automatic recovery efficiency while retaining debugging information.
  • Base class data flow requires deep tracking: in a complex object-oriented hierarchy with data collection per frame, removing the coverage method may not remove variables from the output. The execution path of the base class (e.g., get_obs() → _take_picture() → pkl file) must be tracked to ensure variables are truly excluded.
  • Physical quantities require mandatory semantic ranges: progress indicators derived from geometric formulas should be clearly limited within their semantic range [0,1], even if the formula theoretically produces valid values, because real-world trajectories introduce edge cases.

Practical Learning Outcomes#

  • ArXiv’s HTML rendering is now more suitable than PDF for full-text extraction: faster, without OCR errors, and preserves structure. For pre-Html papers, PDF is a alternative option. This indicates that infrastructure evolution requires regular re-examination of “best practices”.
  • Numerical logs without semantic tags produce ambiguity: ‘1736651’ may be a count/ID/size. Always use clear labels: ‘Author 1736651’ or ‘1,736,651 papers’. The extra two words cost little, but can avoid entire category interpretation errors.
  • For academic analysis tools, the narrative part prefers Chinese output, while technical terms prefer English output. Dual-language method: write structure in English (breakthroughs, why not before, impact), and explain in Chinese.
  • When there is upstream selection logic (annual stratification → ≤10 years), downstream stages should not use different standards for re-filtering. This leads to inconsistent patterns (fast mode sees papers different from detailed mode).
  • Multi-agent exploration pattern: use Explore agent to understand the code library → use Plan agent for design → implement sequentially through user verification. This clearly separates concerns and allows review of the plan before execution.
