Lessons Learned#

Key Lessons – The combination of EventBus, BackgroundCoordinator, and ContextAssembler is a powerful pattern for building modular AI assistants: EventBus enables service decoupled communication (publish-subscribe), BackgroundCoordinator manages the lifecycle of cron tasks uniformly (CronScheduler+conditional loading), and ContextAssembler dynamically loads the context layer based on intent type (avoiding full data transfer each time). These three components together support collaboration among more than 16 independent services.#

  • Spearman correlation of RM-IDEAL shows significant directional asymmetry: The ρ coefficient of Layer_4 between 151508→151673 is 0.657, while the reverse relationship between 151673→151508 is only 0.275. This indicates differences in fused embedding space for structural representations of the same label across different samples, which may be related to sample point density, noise level, or annotation quality.
  • The topological ranking of intermediate layers (Layer_3/6) in the embedding space shows negative correlations (ρ -0.21 to -0.36): This may be because these layers are confused with adjacent layers (Layer_2/4/5) in the embedding space, resulting in the RM-IDEAL ranking based on embedding being opposite to that based on topology. This indicates that boundary layers (Layer_1/WM) and central layers (Layer_5) are easier to distinguish, while intermediate transition layers require stronger discriminative features.
  • The data preprocessing process needs clear verification to ensure all expected features have standardized statistical information. Silent skipping (strict=False) may propagate scale mismatch issues throughout the training process without causing errors.
  • For large refactoring projects, referring to mature open-source project architectures (such as openclaw’s ACP spawn/Gateway/plugin SDK, get-shit-done’s wave execution/context engineering/200K window) is more reliable than zero design; however, it is necessary to adapt to idioms of the target language (such as async/await from TypeScript→Python, singleton factory functions, dataclass), and direct copying is not possible.
  • Unit tests (isolated components, simulated dependencies, rapid feedback) and integration tests (real Discord bot interactions, end-to-end experience) are two complementary dimensions: the former ensures code correctness (319 test cases passed), while the latter ensures user experience meets expectations (29 manual test items); passing 68 unit tests does not mean the system is ready, real user scenarios must be verified.
  • Dangerous silent exception handling (only handling exceptions: pass) is a technical debt poison: it makes the system appear operating normally, but actually the state is incomplete (situation_monitor’s energy/diet/exercise/thinks/reminders may all be empty), and the source of errors cannot be found during debugging (Schrödinger state); exceptions should always be logged (logger.error/warning), distinguishing key functions (errors) from secondary functions (warnings), and diagnostic information should be retained.
  • Large-scale refactoring should gradually verify key integration points (service startup, event connection, data persistence) rather than implementing all features first and then testing. The “implement all features first, then test” approach creates systems that exist but cannot run properly (services exist but never start).
  • Project description narrative strategy: External communication should start from aspects relevant to the target audience’s application scenarios (such as clinical patch query knowledge transfer), then explain the technical path and key differences (zero-sample vs end-to-end training), and finally elevate to domain value. Technical details serve the narrative logic, not the opposite. Control each sentence within double short clauses to reduce cognitive load.
  • Background services need explicit calling of start() in application lifecycle hooks. Class definitions and dependency injection are insufficient—coordinator.start_all() must be called in on_ready() or similar functions.
  • Method to solve Python loop import issues: use lazy imports at the package level (only using all, no eager imports, adding explanatory comments), import inside functions at the module level (import only when truly needed), and do not call site during testing of patch source modules (since lazy imports do not create new bindings at the site call); three-layer defense ensures scalability.
  • Parallel proxy execution greatly accelerates the development of independent modules. Four background proxies (context_detector, checkin_service, learning_service, energy_projection) complete complex enhancements simultaneously, while the main thread handles joint modules. Total time is about 140 seconds, whereas sequential time is about 560 seconds (4 times faster).
  • Effective code audit requires multi-dimensional analysis: syntax level (TODO/FIXME/NotImplementedError), behavior level (exception handling patterns, empty loops, stub methods), structure level (missing test coverage, unused exports), and operation level (service registration, startup hooks). Single-dimensional audits will miss issues across the entire category.
  • Creation of large test suites benefits from parallel proxy execution and shared fixture patterns. The reusable mockers in conftest.py (mock_settings, mock_notification) make testing across more than 20 files more consistent.

Practical Experience#

  • Strategy for monitoring long-running background tasks: For hourly computing tasks, use run_in_background and monitor progress in a cache file system (file modification time, number of completed sub-tasks), rather than relying on potentially failing standard output redirection. Results should be read from persistent output directories, not temporary log files.
  • UNI/UNI2 standardization mechanism: Both perform L2 normalization at the output layer (F.normalize(features, dim=-1)), ensuring the L2 norm of feature vectors is 1, and the input layer uses ImageNet normalization by default (unless skip_normalize=True). This double-layer normalization ensures geometric consistency in the feature space, facilitating cosine similarity calculation.
  • Conda installed CUDA toolkits place header files in specific architecture paths (targets/x86_64-linux/include), rather than in the top-level include/ directory.
