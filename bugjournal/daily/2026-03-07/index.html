Issues and Solutions#

Serious Issues#

1. BC-RNN RP(0.003) is far lower than random RP(0.020), making the evaluation result completely unreasonable#

Solution: Code review identified 4 errors that distorted the metrics: demo_len=0 damaged SPL, trigger_step=0 further damaged SPL, transport always set the RP upper limit to 0.5, and successful episode RP not being 1.0 caused a baseline bias. Fixed collector.py:487 by changing the field name from demo_length to demo_len, changed collector.py:488 to read trigger_step from scene_dataset, added _get_target_pos() to envwrapper.py for dynamic target position retrieval, and added if success: rp=1.0 in collector.py.

Key insight: Distorted evaluation metrics are usually not due to a single error, but a chain of multiple errors. The RP upper limit of 0.5 reveals failure in the transmission stage, while demo_len=0/trigger_step=0 reveal field propagation errors.

2. WKWebView in browsing mode cannot receive mouse/keyboard events, even with ignoresMouseEvents=false; .desktopWindow layer causes non-interactive windows#

Solution: Set the window level to .normal during enterBrowseMode (not at the top but interactive), and restore .desktopWindow KeyForWindowLevel in exitBrowseMode.Key Insight: In macOS, the .docdesktopWindow layer lies beneath the Finder desktop icon layer. Windows on this layer cannot receive any input events at the system level; setting ignoresMouseEvents=false is ineffective for this layer. .normal(level=0) is the lowest level, providing interactivity without覆盖ting other applications.

3. The download of the LLaVA base model is hindered due to proxy bandwidth limitations (about 50KB/s, downloading a 14GB model takes several weeks); GPU nodes cannot be directly connected; xet’s CDN timeout via the proxy#

Solution: It was found that there is nyw of HF format llava-1.5-7b-hf (safetensors) in the cluster. A convert_hf_to_llava.py script was written to convert the HF format into the original LLaVA pytorch_model.bin format (including vocabulary truncation repair, changing from 32064 to 32000). The entire process can be completed locally without network access.

Key Insight: Do not assume that downloading is necessary—first try to find existing model copies on the cluster. Even models in different formats can be converted. Converting the HF model format involves more than just renaming keys; it also involves semantic differences (such as vocabulary size).

4. During Phoenix diffusion strategy training, GPU utilization is only 5–6%: DataLoader num_workers=0 causes the GPU to wait for the CPU to randomly read data from the NFS HDF5 file#

Solution: Preload all HDF5 data into memory once in the init method (uint8 type saves 4 times more storage space), close file handles, and then perform all getitem operations from a numpy array; set DataLoader’s num_workers to 8 and pin_memory to True

Key Insight: h5py file processing cannot be shared across subprocesses (this is a limitation of PyTorch DataLoader). The only safe solution is to fully load it in the main process before forking subprocesses. Random reading from NFS is much slower than sequential reading; one-time loading is 10 times faster than on-demand loading

5. After starting Phoenix MPM training, the estimated training duration is severely incorrect (actual 13.5 days, expected a few hours), and the dataset size estimation is wrong (160K→1M)#

Solution: The user must pause training and replan and optimize (possibly reducing training steps, increasing GPU count, optimizing data loading, etc.)

Key Insight: Before starting large-scale training, it is necessary to verify the actual dataset size, step time, and total number of steps to avoid resource waste. Incorrect dataset size estimation can lead to weeks of computational resource waste

6. CalendarPro intent classification is ambiguous due to the pre-check by general_keywords: “What time have you arranged?” → “What time is it” fits general_keywords → forced GENERAL → error#

Solution: Divide general_keywords into always_general (always forced GENERAL, such as ‘weather’) and context_dependent (only forced GENERAL when there is no active session, such as ‘what time is it’); add confirmation_words (‘ok’, ‘good’, ‘yes’, etc.) and provide a fast path via is_confirmation_input(); rewrite _process_input() to make it a 6-step process

Key Insight: Context-aware intent classification requires combining session state (session_id, last_activity_at) and conversation history. Simple keyword matching leads to ambiguity; when there are active proposals, confirmation phrases (‘ok’) should be routed directly

7. The current research reconnaissance paper evaluation process handles all 50 papers simultaneously, wasting labels and lacking in-depth analysis#

Solution: A two-stage process was designed: the first stage quickly filters all papers (only title + first 1000 characters of abstract, classified as high/low relevance); the second stage conducts in-depth analysis on high-relevance papers (up to 20 papers, extracting 3 highlights + detailed scoring + direction suggestions)

Key Insight: Mimicking the paper-reading workflow of human researchers (quick filtering → deep reading of high-value papers) can significantly improve the efficiency and quality of LLM evaluation, while generating literature reading records for low-relevance papers for future reference

8. Due to the ID (‘robot-manipulation’) in project.json not matching the directory name, the pipeline cannot read overview.md#

Solution: The ID field in project.json was updated to match the directory name; the pipeline uses project[‘id’] to build the path for overview.md

Key Insight: The directory name and the ID in project.json must be consistent; _extract_current_methods() uses project[‘id’] to locate overview.md

9. During the second-stage evaluation, the evaluation result of the current method is ‘(no record yet)’, because the title of the overview.md section ‘## 3. Current technical approach’ does not match the pipeline’s regex pattern ‘##\s*Current method and progress’#

Solution: The title of the overview.md section was changed to match the OVERVIEW_TEMPLATE format; the numbering prefix and section separator were removed

Key Insight: The pipeline uses a strict regex for section extraction; the template format must be strictly followed

10. FLARE specification statistical calculation fails: After importing openpi in the specification statistics script, the version installed by Zhang Jialong cannot be found, nor can the new configuration name of Tang Zhijia be found#

Solution: In the script, PYTHONPATH=/HOME/…/tangzijia/shared_deps/openpi/src:$PYTHONPATH was set to prioritize loading Tang Zhijia’s openpi source code, bypassing the old version in the conda environment

Key Insight: When multiple users share the same conda environment, their source code modifications cause import priority conflicts. PYTHONPATH is a minimally invasive solution that does not affect other users

11. The WKWebView scroll bar tracking becomes transparent (ineffective through CSS injection of background color) + sandbox applications cannot load any network resources#

Solution: webViewsetValue(false, forKey: “drawsBackground”) was removed; the default opaque background was restored, making scroll bar tracking visible; com.apple.security.network.client=true was added to.entitlements

Key Insight: drawsBackground=false makes the entire WKWebView rendering layer transparent, but the semi-transparent style on the transparent layer remains transparent. The fix must be applied at the rendering layer rather than the CSS layer

12. The LLM output contains too much English content, while users expect Chinese; the output language cannot be configured#

Solution: A three-layer language system was implemented: _DEFAULT_LANGUAGE constant, __language_instruction() generator, and {language_instruction} in all prompts; the configuration order is CLI > project.json > config.json > default

Key Insight: Language instructions must be injected at the prompt level, not later in processing; different parts require different language rules (JSON keys and content)

13. It is impossible to create a project from the existing overview.md, unless keywords/categories are manually extracted#

Key Insight: The LLM can reliably extract structured metadata from unstructured text; the existing __call_llm() and __parse_json_response() tools are reused

Lessons learned#

Key experience – Zero-shot base models perform significantly lower in clustering tasks than PCA: FM is designed to optimize generalization across tasks (pre-training goal is language modeling/contrastive learning), not to maximize variance; PCA performs task-related dimensionality reduction, and maximizing variance corresponds to maximizing cluster separation. This conclusion is validated by Microsoft and multiple papers, as well as MIHD’s own data (PCA has ARI of 0.261, while scGPT has 0.170, a 54% difference).#

  • The bias in evaluation metrics is usually not a single error, but a chain reaction of multiple errors: BC-RNN has demo_len=0, trigger_step=0, transport always False, and the successful scenario RP drops to 0.5 due to four errors, actually reaching 0.003. End-to-end validation is needed, not isolated unit tests.
  • The macOS window layer not only controls visual Z order but also controls event routing permissions: .desktopWindow layer (below desktop icons) does not receive user input events, and the .normal layer at a higher level must be used for true interactive “browsing mode”; this is a system-level constraint, not an API configuration issue.
  • In a GPU cluster environment, prioritizing searching for existing model copies and performing format conversion (e.g., HF format → raw LLaVA format) instead of downloading via a proxy can save several weeks of time; successful cases of converting from HF format to raw LLaVA base model (including vocabulary truncation, from 32064 to 32000) prove this.
  • When designing automated paper management tools, the actual cognitive process of human researchers should be imitated: quick screening (relevance + novelty + source authority) → deep analysis (core insights + problem definition + experimental design + limitations), rather than a full evaluation at once.
  • h5py file processing cannot be shared between fork subprocesses (this is a limitation of PyTorch DataLoader); the only safe solution is to pre-load the main process into numpy before forking. NFS random read speed is much lower than sequential read speed, and loading once is 10 times faster than on-demand loading; using uint8 type can also save 4 times more memory.
  • Before starting large-scale training, the size of the actual dataset, time per step, and total number of steps must be verified to avoid resource waste; in the Phoenix MPM training case, the dataset size estimation was incorrect (160K → 1M), resulting in a training time of 13.5 days—a serious error, highlighting the importance of early validation.
  • Context-aware intent classification requires combining session state (session_id, last_activity_at) and conversation history; simple keyword matching can lead to ambiguity (e.g., “what time is it?” could be a query time or a request for schedule time); CalendarPro solves this problem through context-dependent keyword classification and confirmation of a fast path.
  • research_scout.py architecture: a single-file with 1871 lines, divided into sections numbered 0–10; two-stage LLM process (screening → deep analysis); three backends (claude_cli, anthropic, openai); parameter parsing chain is CLI > project.json > config.json > default; cache validity is verified through keyword hash.
  • Command-line tool parameter configuration should use a layered parsing strategy: CLI flags > specific project configuration > user-level global configuration > hard-coded defaults, which provides flexibility while maintaining reasonable defaults.
  • The design of batch document generation tools requires a two-stage architecture: the export stage locally parses raw data on each device, and the merge stage combines data across devices; when the number of daily sessions is particularly large, an “internal merge” step is needed to eliminate duplicate content and combine multiple outputs from the same day.
  • The solution to priority conflicts in conda environments shared by multiple users is: set PYTHONPATH=/path/to/user/src:$PYTHONPATH during script execution, loading user’s own source code copies first without affecting other users, and no need to create a separate environment.
  • Language configuration for LLM processes should be injected at the prompt level, not later in processing; different parts of the output require different rules (e.g., JSON keys remain in English, content is expressed in the target language).
  • Extracting structured data from documents is very suitable for LLMs; OVERVIEW_EXTRACT_PROMPT can reliably parse overview.md, extracting title/keywords/categories/problems.
  • Pipeline regular expression patterns must match exactly; “## 3. Current technical route” will not match “##\s*Current methods and progress”; template-driven architecture needs strict format compliance.
  • arXiv search results are returned in reverse chronological order; a continuous known paper counter is an effective early stopping heuristic because it indicates that the processed time range has been reached.
