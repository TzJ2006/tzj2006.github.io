Problems & Solutions#

Critical Issues#

1. Gemini struggled with precise temporal tasks (counting, timing, and event detection) using generic visual prompting, leading to performance plateaus and policy failures.#

Solution: Implemented a ‘Task-specific Redesign’ (Hybrid Logic): Gemini is used only to answer simple visual questions, while counting, trajectory tracking, and timing are offloaded to deterministic code and robot proprioception.

Key Insight: Offloading temporal and logic-heavy tasks from LLMs to code significantly boosts reliability in robotic manipulation.

2. Potential evaluation bias and ‘contamination’ of the test set (episodes 10-49) due to parameter tuning/calibration.#

Solution: Proposed a formal validation workflow using the unused RoboMME ‘val’ partition to ensure true generalization.

Key Insight: Scientific rigor requires testing on a truly unseen validation set rather than relying on development episodes.

3. Audit revealed bugs in launch scripts (case-sensitive env scrubbing, broken retry logic in launch_i168_val.sh, and silent exits in eval_batch_all16.sh) and resource oversubscription on the tianhe3 pod.#

Solution: Implemented v2 of launch scripts with improved sanitization, reliable process-group retry mechanisms, and a staged rollout plan to optimize CPU utilization.

Key Insight: Large-scale batch jobs require retry logic that distinguishes between single client exits and entire process group completions.

General Issues#

4. Robot state lag in the evaluation loop causing VideoRepick to fail.#

Solution: Fixed a closed-loop bug where the state buffer was cleared too frequently, causing the writer to fall behind reality.

5. Early Gemini versions drew visual cues before prerequisites (e.g., button presses) were met, causing policy failure due to sequence errors.#

Solution: Implemented a rule-based latch requiring Gemini to confirm the prerequisite event occurred before drawing the prompt.

Key Insight: Sequence-sensitive tasks require temporal gating for visual feedback.

Learnings#

Key Learnings#

  • The gap between ‘Oracle Memory’ and ‘Gemini Prompting’ can be closed by moving from ‘Asking LLM to decide everything’ to ‘Asking LLM simple questions and using code for logic’.
  • A hybrid approach (Vision + Proprioception + Rules) is vastly more robust for robotic memory than relying solely on a Large Multimodal Model’s generative capabilities.
  • Retry logic for large-scale batch jobs must be aware of the difference between a single client exit and the entire process group (arm) completing, or it will attempt to restart active jobs.
