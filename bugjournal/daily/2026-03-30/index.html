Problems & Solutions#

Critical Issues#

1. Teddy gene-only ARI (0.186) is inferior to PCA (0.255); the Foundation Model failed to surpass simple baselines in clustering tasks.#

Solution: Analyzed the root cause: Teddy optimized for disease classification rather than variance maximization; the 1024d high-dimensional space degraded KMeans performance; the training data is dissociated scRNA-seq, different from spatial transcriptomics distributions.

Key Insight: There is a fundamental tension between “generalized representation” and “clustering adaptability” in the Foundation Model embedding: PCA directly maximizes data variance and naturally adapts to KMeans; while the Foundation Model learns disease-specific representations, systematic transfer loss occurs in downstream clustering tasks.

General Issues#

2. evaluation_planner.py’s cache check for 151676’s staig_gene_feat caused a false positive, leading to termination of Phase 2 with sys.exit(1).#

Solution: Modified the has_staig_gene_feat check logic to dynamically parse the actual number of top_genes in slice configuration (151676 uses 5000 instead of the default 3000), correctly identifying the presence of a cache entry.

Key Insight: Sliced-specific configurations (top_genes from staig_utils.py’s num_gene field) differ from the planner’s hard-coded default values; such “config implicit fork” easily leads to unnoticed false negatives.

3. Model collapse occurred in 151676 slices during STAIG fusion evaluation, preventing valid clustering results.#

Solution: Skipped this slice and reported the result using the average of 10/11 slices (ARI=0.495).

Key Insight: 151676 is a known difficult slice for STAIG; its STAIG collapse has nothing to do with the gene encoder, and it is a systematic issue due to slice-specific data characteristics.

4. TokenMonitor cannot be built on HPC (missing rust, webkit2gtk4.1-devel etc., no sudo privileges).#

Solution: Suggested three paths: build on a locally accessible machine and copy the binary, ask the HPC administrator to install dependencies, or use GitHub Actions CI to build a Linux release package.

Key Insight: Tauri applications depend on GTK/WebKit system libraries, which are typically unavailable in HPC environments, and the module system does not provide such libraries; HPC is not inherently a target deployment environment for GUI applications.

AI Limitations#

General Limitations#

  • Failed to detect the hard-coded staig_gene_feat top_genes issue in evaluation_planner.py beforehand; only traced the root cause when sys.exit actually triggered.
  • Inefficient progress monitoring for background tasks: using multiple sleep + ls polling, rather than more elegant solutions (e.g., inotifywait or structured progress files), resulting in extensive waiting time.
  • Syntax error occurred when constructing multi-line Python f-string in bash commands (unterminated string literal), requiring recompilation of the command to run.

Learnings#

Key Learnings#

  • The STAIG fusion framework is highly robust to gene encoders: Teddy 1024d (ARI=0.495) and PCA 50d (ARI=0.497) perform almost identically under STAIG, indicating that the spatial graph contrast learning mechanism dominates clustering performance, greatly reducing the impact of gene embedding quality.
  • Systematic transfer loss in cross-domain downstream tasks for the Foundation Model: Teddy achieves SOTA in disease classification (ACC=0.72), but is inferior to PCA in spatial transcriptomics clustering (0.186 vs 0.255); the root cause is the mismatch in optimization goals (differentiation vs variance maximization).
  • HVG1500 (direct concatenation of raw high-variability genes, no dimensionality reduction) achieves ARI=0.330 on 151673 single slices, outperforming all Foundation Models; this suggests that high-dimensional raw features may benefit from retaining more local variance information in certain slices.

Practical Learnings#

  • Implicit configuration fork between slice-specific configurations (e.g., staig num_gene) and global pipeline defaults is a high-risk bug; it should be dynamically parsed in cache check logic rather than hard-coded.
