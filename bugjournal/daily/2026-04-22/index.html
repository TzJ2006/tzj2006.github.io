Issues and Solutions#

Key Issues#

1. Existing market products (AudioPen, Voicenotes, Ideaflow) only provide one-time voice-to-text conversion, without interactive AI brainstorming or network research functions#

Solution: RefineEngine was designed to support multi-round dialogue sessions, providing lightweight (automatic) and deep (user-triggered) verification, filling the market gap in network research.

Key insight: The interactive optimization layer with network research is a core innovation not available in existing products.

2. 6 active source code files (circuit_breaker, config_watcher, data_lifecycle, health_manager, dreaming_service, insight_store) are not tracked by git, although used by BackgroundCoordinator#

Solution: These 6 source code files and 3 related tests were put into git tracking; F-001 was confirmed through repo-audit.

Key insight: Services dynamically loaded via BackgroundCoordinator._start_all() bypass static import analysis; clear tracking and verification are needed for modules loaded at runtime.

3. discord.py lacks a native voice reception API for real-time voice channel interaction (suitable for Neuro-sama-style robots)#

Solution: A phased approach was adopted: first, voice message detection was implemented (simple, compatible with discord.py), using message.attachments; real-time voice channel interaction was postponed to phase 2, with py-cord migration evaluation.

Key insight: Voice message detection provides 80% of the value, but complexity is only 20%; after verifying the core pipeline, voice channels should be treated as independent functions.

4. semantic-router and sentence-transformers are declared in pyproject.toml and requirements.txt, but no longer used in code (semantic routing was removed in commit 1b9f084)#

Solution: These two packages were removed from both list files; anthropic and lark-oapi were added to synchronize pyproject.toml with requirements.txt.

Key insight: Removing code during refactoring without updating list files leads to dependency drift; regular checks are needed to ensure actual imports match declared dependencies.

5. Priority for multi-platform input requirements (Discord, mobile, desktop) is unclear#

Solution: Structured questioning clarified that voice is prioritized, text is a fallback, Discord voice messages are processed first, followed by iOS Shortcut (using REST API), and desktop is treated as future enhancement.

Key insight: Prioritization is determined through questioning instead of overdesign; REST API will become the unified backend for all future frontends.

General Issues#

6. The large discord_bot.py file (1060 lines) makes integration difficult#

Solution: Voice detection logic was directly inserted into the existing on_message process before text processing, and slash commands were postponed to a separate task, avoiding scope expansion. Key insight: Incremental integration through clear insertion points maintains code quality in large files.

7. repo-tidy cannot modify file content (only moves/archives files), causing manual operation required for dependency list synchronization#

Solution: mcp__hex-line__edit_file was used to precisely remove invalid dependencies, and both list files were synchronized; duplicate playwright lines generated during initial editing were fixed.

Key insight: Separation of responsibilities: repo-tidy handles file-level operations (move/archive/gitignore), but content editing requires independent tools or manual intervention.

Lessons Learned#

Key Experiences#

  • Audit-driven cleanup workflow: repo-audit generates machine-readable JSON (with confidence scores, discovery IDs, and file paths); repo-tidy uses these data for intelligent decisions beyond pattern matching; establishes repeatable baselines for incremental maintenance
  • Sub-agent-driven development and two-stage review (compliance with specifications + code quality) enable high-speed parallel execution while maintaining quality—7 tasks were completed in a single session, with 66 tests passed
  • Market research before implementation is crucial: it was found that no existing product offers interactive AI optimization features based on online research, validating the uniqueness and value proposition of core functions
  • Open-source technology research (for Discord voice, kimjammer/Neuro) revealed mature architecture patterns: py-cord + Silero VAD + RealtimeSTT + edge-tts, saving a lot of design and debugging time
  • Dependency drift detection method: searching the code repository for actual imports (from X import / import X) and comparing them with declared dependencies in pyproject.toml/requirements.txt to identify broken dependencies; this is especially important after major refactoring like semantic router removal
  • Phased delivery strategy (voice message detection → real-time voice channel) balances speed, value, and technical complexity, allowing verification of features before major architectural decisions such as framework migration
  • TDD workflow is implemented through a planning structure (write tests → run failures → implement → run through → submit); reliable and thoroughly tested code can be produced even when parallel sub-agents execute
  • Defect in dynamic service loading pattern: BackgroundCoordinator loads services via lazy imports in the _start_all() method, bypassing static dependency analysis; it is necessary to explicitly verify whether dynamically loaded modules are tracked
  • The evolving Constraint Language (ECL) documentation implements cross-session persistence and multi-agent handover in ccplan for complex features, but this session completed it before requiring a complete ECL workflow

Practical Experiences#

  • Advantages of hex-line MCP tool: mcp__hex-line__inspect_path provides a compact directory tree with file counts; mcp__hex-line__outline displays function/class structures without full file content; mcp__hex-line__edit_file uses anchor-based editing to enable precise modifications in large files
