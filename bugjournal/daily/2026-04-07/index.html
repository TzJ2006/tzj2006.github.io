Key Issues#

1. Linux window manager cannot atomically handle transparent window dynamic scaling, resulting in systemic position offset, detection/repair flicker, and WebView/Native window size mismatch. Solution: Abandon adaptive layout, adopt fixed boundaries with internal CSS extensions; call widget.set_size_request() in webview callbacks to override GTK negotiation locking, thereby completely eliminating compositor conflicts.#

Key Insight: Transparent floating UI components function properly across three independent real layers (Rust/WM/Compositor); architectural boundaries in the Linux environment are always superior to iterative coordinate fixes.

2. Stage 3 enhanced recovery demonstrations were generated, but due to CLI flag failure, path mismatch, and loss of quaternion direction data, Stage 4A/4B training conversion completely ignored these demonstrations.#

Solution: Explicitly load manifest files in the conversion script, extend Pydantic schema to capture complete 4x4 EEF/object pose, and rewrite _warp_actions to apply rotation increments via quat_slerp instead of identity matrix.

Key Insight: Data lineage integrity requires preserving the original simulator state during data input; loss of spatial metadata forces downstream mathematical algorithms to use invalid alternatives and disrupts pipeline connectivity.

3. Long-running parallel data generation pipelines lose all progress logs and mapping states after interruption mid-run, making crash recovery mathematically impossible.#

Solution: Reconstructed execution flow to implement incremental per-BDDL-variant JSON persistence after each processing cycle, and added startup state merging logic for fault-tolerant recovery.

Key Insight: Distributed HPC workloads require task-unit atomicity for logging; the single final save mode is inherently fragile and may cause silent data loss during unpredictable execution failures.

4. Open loop action replay always fails, while state verification passes in collected robot demonstrations, raising uncertainty about environment drift and simulator physics.#

Solution: Performed trajectory validation to distinguish real recovery from early termination false positives; confirmed that high-level OSC uncertainty and contact chaos inevitably disrupt open loop replication without affecting the basic success state.

Key Insight: Simulation verification pipelines cannot rely on post-hoc boolean flags or closed-loop replay for high-contact physical phenomena; explicit state logging or trajectory incremental mapping is required to separate controller drift from actual task success.

5. Non-interactive CLI -p mode silently rejects MCP tools due to authentication scope isolation and initialization time conflict, while initial Claude Code wildcard suggestions dangerously allow destructive Bash commands.#

Solution: Forced explicit project-level mcp-config loading via --permission-mode bypassPermissions, optimized IDE allowlist to prevent deletion operations, and retained safe iterative command auto-approval.

Key Insight: Cross-layer agent orchestration requires atomic boundary authentication; permission default settings must balance security standards and workflow speed to avoid potential execution risks.

6. CI translation pipeline causes infinite synchronization loop and build failures due to Hugo v0.154 strict symbolic link isolation, silent failure of headless conda activation, and reverse translation mismatch.#

Solution: Replaced os.symlink with shutil.copy2 in staging scripts, replaced conda activate chain with immutable conda run wrapper, and implemented direction state tracking to standardize old-style file associations.
