Issues and Solutions#

Key Issues#

1. A vulnerability in PyTorch 2.9/CUDA 12.9 cuBLAS on RTX 2080 Ti causes crashes during the backpropagation of large matrix operations (the comparison loss requires 3639×3639 logical labels). Multiple architectural rewrites were attempted before finding the root cause.#

Solution: Redesigned the comparison loss function, using small batch sampling (512 samples per batch) to avoid full N×N matrix calculations. Added gradient clipping and LayerNorm to improve stability. For cross-sample visualization tasks, when GPU compatibility is confirmed, switching to CPU training as a fallback (PyTorch 2.9.0+cu129 with CUDA 13.1 driver).

Key Insight: Model architecture alone cannot resolve GPU hardware/driver compatibility issues—algorithmic workaround measures at the loss function level are required. Mismatches between PyTorch CUDA versions and driver versions occasionally cause “illegal memory access” errors, which can be detected by basic tests but fail in complex training loops. For medium-scale training (3460 positions), using CPU as a fallback is an effective strategy.

2. Corrupted MCP server stdout: The gadget tool uses too much print(), but MCP uses stdout as a JSON-RPC transmission method.#

Solution: Created a capture_stdout() context manager to redirect print() output, wrapping all tool calls in _safe_call(), capturing stdout/stderr and converting SystemExit to RuntimeError, returning the captured logs to the _logs field of the JSON response.

Key Insight: Isolating stdout is important when integrating existing CLI tools into protocol-based systems. The context manager provides a clean, recoverable redirect method without modifying the original code.

3. research_scout hardcodes arxiv_id throughout the code repository, hindering multi-source data expansion.#

Solution: Introduced paper_id as a canonical ID with a source field, keeping arxiv_id as a backward-compatible alias, created _paper_id()/_paper_url() helper functions, updated prompts to use paper_id, and checking both fields when matching LLM responses.

Key Insight: When expanding from single-source data to multi-source data, introducing a new abstraction level while keeping old fields as aliases. The helper functions centralize the logic for IDs/URLs, making future data source addition simple.

4. In the 151673-151508 cross-sample query, Layer_3 has low relevance (ρ=-0.21/-0.36), while Layer_1/4/5 show high positive relevance (ρ>0.4).#

Solution: Analysis shows that Layer_3 is the largest DLPFC layer with high internal heterogeneity, preventing embeddings from capturing a unified spatial structure. Smaller and well-defined layers (Layer_1: ρ=0.62, Layer_4: ρ=0.66) perform best.

Key Insight: The size and internal heterogeneity of organizational layers significantly affect the quality of spatial structure embeddings. Different layers with clear boundaries achieve better cross-sample matching than large heterogeneous regions.

5. When each point has only one gene vector and one image vector, single-label cross-attention degrades to a linear projection.#

Solution: Used spatial k-NN neighbors to build K/V sequences, allowing cross-attention to operate in a neighborhood context. Reused the batch-neighbor construction infrastructure of QFormerFusion.

Key Insight: Spatial transcriptomics data provide natural sequence context through neighborhood structures. Utilizing spatial adjacency allows meaningful attention mechanisms to be implemented even without time or batch dimensions.

6. RoboTwin demo_clean data (14-DOF, based on directory) is incompatible with the existing LeRobot conversion script (16-DOF, based on zip).#

Solution: Created a new script convert_robotwin_democlean_to_lerobot.py: directly reads data from the data/instruction directory, changes ACTION_DIM/STATE_DIM to 14, uses LeRobotDataset.create() and passes the root parameter, instead of using the HF_LEROBOT_HOME environment variable for modification.

Key Insight: Changes in robot data format (number of DOF, storage format) require specialized conversion scripts. Directory structure and HDF5 key names are project-specific.

7. Due to JSON parsing failures in LLMs, the motivation/innovation fields in research_scout’s filtering stage are empty.#

Solution: Added a empty field detection function after _screen_papers() and _screen_papers_chunked(), recorded warning messages including the number and detailed information for each paper at DEBUG level, improved _try_repair_result() function, and recorded a preview of the original response when fixing fails.

Key Insight: The silent.get() fallback mechanism hides data quality issues. Clear validation and logging at the aggregation point (after batch processing) can provide useful debugging information without complicating the logic of each project.

8. The original CrossModalEnhancer design triggers cuBLAS GEMM failures during the projection from 128→1536 when outputting the original modality dimension (image is 1536d).#

Solution: Redesigned the architecture to output in the hidden dimension space (128d), avoiding the problem of large matrix projections. Used a projection head in the comparison loss while maintaining the compactness of the core output.

Key Insight: Engineering constraints (GPU errors) may force architectural decisions different from ideal semantic designs. Real systems must balance theoretical elegance and implementation robustness.

Lessons Learned#

Key Lesson – RM-IDEAL uses the WWL (Wasserstein Weisfeiler-Lehman) graph kernel to compute spatial niche matching: through iterative neighbor tag hashing → node feature distribution → optimal transfer between subgraphs (Wasserstein distance). This provides a topological-based benchmark for evaluating embedding quality.#

  • Cross-attention processing on a single token degrades to linear projection. Spatial transcriptomics offers a natural solution: k-NN neighbors form a K/V sequence, encoding neighborhood context. This pattern (using spatial neighbors as attention context) applies to various spatial omics architectures.
  • PyTorch 2.9 + CUDA 12.9 has errors in cuBLAS on RTX 2080 Ti, leading to illegal memory access issues during large-scale matrix operations (e.g., gemm failures occur when the shape is 128→1536, and problems also occur in N×N operations when N>3500). Solution: use small batch processing to keep the matrix size small. The PyTorch CUDA build version (e.g., cu129) must match the GPU driver’s CUDA version.
  • The scGPT base model performs worse than traditional methods (PCA, scVI, Harmony) in zero-shot clustering benchmarks (Genome Biology 2025). The AvgBIO score on the Pancreas/PBMC dataset shows that scGPT scores are between 0.52–0.60, while HVG baseline scores are between 0.60–0.77. scGPT-spatial requires fine-tuning and is only compared with weaker baselines (SpaGCN, stLearn), not with state-of-the-art models. Independent benchmark results are more reliable than those described in the original paper.
  • Conditional flow matching for robot action generation: learning vector fields u_t via linear interpolation path x_t = t·noise + (1-t)·actions, using Beta(1.5,1) time sampling to maintain stability near noise endpoints, and using Euler integration for reasoning. The key idea is: time conditioning via sine embedding and MLP (or adaRMS for Pi0.5).
  • Design principles of the MCP tool: tools in Claude Code should default to returning content (Markdown reports, JSON data) and allow optional file persistence. This allows direct use of these tools without passing through the file system. Summary/research is “skill enhancement”, not just file generation tools.
  • When wrapping existing CLI tools for protocol-based systems (MCP, JSON-RPC), isolating stdout/stderr is a top priority architectural consideration, not a later issue. Using a context manager enables clean, reversible redirection without modifying the original code.
  • When expanding a single-source system to multiple sources, introduce a new abstraction level (paper_id) while retaining the old field (arxiv_id) as an alias. Helper functions (_paper_id, _paper_url) can handle cross-source logic centrally, making future expansion simple.
  • The characteristics of the DLPFC organizational layer directly affect cross-sample matching of embedded data: Layer_1 (surface, thin layer) and Layer_4 (granular, cell-dense) show Spearman ρ>0.6; Layer_3 (maximal, highly heterogeneous) shows ρ<-0.2. The quality of embedded data is related to structural uniqueness and boundary clarity, not the size of the layers.
  • RoboTwin data format: 14-degree-of-freedom action space (6 degrees of freedom for left arm + 1 degree of freedom for gripper + 6 degrees of freedom for right arm + 1 degree of freedom for gripper), stored in HDF5 format, containing joint_action/vector information; observation data is stored in compressed image format. Demo_clean directory structure: data/episodeX.hdf5, instructions/episodeX.json, including language variants seen/unseen.
  • STAIG fusion training for spatial omics: UNI2 (1536-dimensional visual data) + PCA (50-dimensional gene data) → STAIG fusion encoder (64 dimensions). Key findings: alignment mode uses tau=26, softmax_log edge weights, 300 pseudo-clusters, 550 training cycles. If training fails, the model may collapse (all embeddings are zero).
  • UniVLA training process: divided into three stages (LAM stage 1/2, VLA pre-training, fine-tuning for each benchmark). CALVIN training: DiskCalvinDataset loads auto_lang_ann.npy to get episode language mapping, reads episode_*.npz window data (12–13 frames), extracts rgb_static → LAM → latent_action_idx → VLA input → ActionDecoder → relactions.
  • Cross-environment tool invocation (conda run -n ) provides a clean isolated environment for sibling projects with conflicting dependencies. Setting cwd as the root of the tool repository is very important because many Python scripts use relative imports and sys.path operations.
  • Production-level logging requires two processors: StreamHandler (INFO level) for user-visible progress information, RotatingFileHandler (DEBUG level) for diagnostic details. The print() function is retained in interactive UI commands, but all operations/diagnostic messages are migrated to logger.
  • Structure of the CALVIN evaluation dataset: only validation/.hydra/merged_config.yaml files are needed for environment initialization. During evaluation, the episode_.npz file is not read (online simulation generates observation data). Data extraction can reduce dataset size from 1.3GB to 600KB.
  • A zero-dependency API client (urllib.request + xml.etree) is suitable for production tools when avoiding new dependencies is crucial. bioRxiv and PubMed use only the standard library to implement these clients, maintaining the minimal dependency principle.
  • Python package distribution for MCP servers: for stateless tools, the standard mode uses PyPI + uvx; when the server depends on the repository’s data directory, pip install -e . is required (editable installation). The entry point [project.scripts] in pyproject.toml is used, followed by Claude mcp add gadget –gadget-mcp.

Practical Experience#

  • When integrating a new fusion strategy into the existing process: (1) register in apply_fusion() scheduler, (2) add needs_coords tuple in runner.py and evaluation_planner.py, (3) add configuration dictionary entry in runner.py, (4) define the experiment in pipeline_config.yaml. This four-step integration pattern applies to all trainable fusion methods.
  • When updating documentation, use grep to find CLI flags and function names so that missing items can be systematically identified, rather than relying on manual code review.
